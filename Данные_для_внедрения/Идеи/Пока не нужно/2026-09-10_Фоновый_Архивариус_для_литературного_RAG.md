# Идея: фоновый Архивариус для литературного RAG

Дата сохранения: 2026-09-10.

Источник: исследование, переданное пользователем в диалоге.

Статус: исследовательская идея, не утверждённое ТЗ. Названия моделей, размеры и заявленные возможности ниже сохранены из сообщения пользователя; в рамках сохранения документа они независимо не проверялись. Документ сам по себе не означает решения скачать или внедрить перечисленные модели.

## Подход

Не использовать отдельную Chat/Instruct-LLM как основной обработчик памяти. Вместо неё рассмотреть набор специализированных небольших моделей, работающих преимущественно на CPU.

## Принцип работы

Пока пользователь редактирует текущую главу, фоновый конвейер постепенно готовит её будущую RAG-разметку в отдельном `staging`. При нажатии «Завершить главу» результат по возможности уже готов: проверяется соответствие последней версии текста, после чего данные фиксируются в RAG/Qdrant. Если подготовка не успела — обычная обработка выполняется после завершения главы.

Исходный `.txt` всегда остаётся **источником истины**. Нейросетевая разметка — только дополнительный индекс, который можно удалить и построить заново.

## Что потенциально извлекать

Персонажей, места, предметы, организации/кланы, события, смысловые границы сцен, связи между сущностями и поисковые признаки. Не пытаться заранее извлекать всё возможное — расширять конвейер только по результатам практических тестов.

## Кандидаты

- `urchade/gliner_multi-v2.1` (~209M) — основной кандидат для open-type NER; можно задавать собственные классы: персонаж, место, предмет, артефакт, событие, клан, техника и т. п.
- `creat89/NER_FEDA_Ru` — русскоязычный NER, включая варианты с событиями; кандидат для сравнительного теста.
- `RaguTeam/BertRE` — Relation Extraction для русского; подключать, если понадобится извлечение отношений между сущностями.
- `RuCo-BERT` — coreference resolution для русского («он», «она», «графиня» → конкретный персонаж); стек старый, поэтому только как исследовательский кандидат.
- `ai-sage/Giga-Embeddings-instruct-480M-0826` (~480M) — основной кандидат для русскоязычных embeddings → Qdrant.
- `sergeyzh/rubert-mini-retriever` (~26M) — очень лёгкий вариант embeddings/retrieval для сравнения по скорости и памяти.
- `DiTy/cross-encoder-russian-msmarco` (~200M) — reranker найденных фрагментов; добавлять только если простой vector search даёт слишком много нерелевантных результатов.

## Первый минимальный стенд

`GLiNER multi-v2.1 → Giga-Embeddings-480M → Qdrant`.

Остальные модели добавлять только если тесты покажут конкретную проблему:

- плохие связи → BertRE;
- потеря местоимений → coreference;
- плохая сортировка результатов → cross-encoder.

## Измерения и ограничения

Сначала измерить реальное потребление RAM/CPU/диска самим Qdrant, embedding-моделью и базовым RAG. Размер и состав фонового конвейера выбирать уже после этих замеров.

Chat-LLM 1–4B пока не добавлять: она оправдана только если специализированные модели не смогут качественно решить нужные задачи.
