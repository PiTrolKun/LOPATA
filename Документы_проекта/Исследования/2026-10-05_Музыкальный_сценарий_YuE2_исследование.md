## Проверенный контекст ЛОПАТЫ

Сверены AGENTS/CODEX, CONTEXTHUB, история диалога, обзор документации, ROADMAP, REESTR, МОДУЛИ, АРХИТЕКТУРА, РУКОВОДСТВО, НАСТРОЙКИ_И_ТРЕЙ, ПРАВИЛА_БЕЗОПАСНОСТИ, ФОНОВЫЕ_ОПЕРАЦИИ, ТЗ музыкального сценария и исходная концепция; также общий сценарий фона из архива.

Новый сценарий должен использовать существующие навигацию, ядро, лицензионное согласие, проверяемую докачку, AI-хранилище и общий фон. Планирование и музыкальный runtime включаются последовательно в одну управляемую тяжёлую операцию. Подтверждённые результаты этапов сохраняются до освобождения собственных процессов; восстановление не должно повторять уже сохранённый результат.

Текущий узкий FFmpeg собран для захвата. Наличие FFmpeg не доказывает поддержку всех музыкальных форматов. NAudio уже есть; отдельную цепочку экспорта необходимо проверить по фактическим кодекам и лицензиям. Новые зависимости не внесены в REESTR как установленные компоненты.

## Что уже умеет YuE2

Официальный API разделяет создание символического плана, семантических кодов, акустических представлений и декодирование. План можно сохранить, восстановить и передать дальше; вход ABC позволяет исполнить подготовленную композицию. Сохраняются промежуточные артефакты, параметры и сведения о моделях. Готовый воспроизводимый файл может быть обрезан лимитом: необходимо проверять `truncated`. Один вызов создаёт одного кандидата; выбор лучших кандидатов в опубликованных оценках — отдельная процедура. [Генерация](https://github.com/multimodal-art-projection/YuE/blob/main/docs/generation.md).

Нативная партитура содержит две одноголосные линии: Vocal и Ins; аккорды обозначены символами. Ins не описывает все инструменты аранжировки по отдельности. Правила знаков альтерации и связей нот имеют особенности. Официальный помощник проверяет ограниченный диалект ABC, а не весь стандарт: отказ на неподдержанной конструкции не доказывает музыкальную ошибку. MIDI не может автоматически считаться полной и точной заменой такого плана. [Формат и проверка ABC](https://github.com/multimodal-art-projection/YuE/blob/main/skills/yue2-music/references/abc-editing.md).

Изменение нот, аккордов, темпа или формы выполняется через новый план и новый запрос. Удаление куплета требует согласованного изменения партитуры и слов. Получается новая полная запись: неизменные ноты не гарантируют сохранение прежнего голоса, тембра и аудио вне исправленного фрагмента. [Редактирование](https://github.com/multimodal-art-projection/YuE/blob/main/docs/editing.md).

## Дополнение: ручное указание ударения в русском тексте

Пользователь предложил сохранять combining acute accent после гласной, например `молоко́`. Источник community-механики найден: TS Song Creator в `AlexYez/comfyui-timesaver`. В документации есть команда **Mark stressed** для выделенной гласной или гласной у курсора. [Описание редактора](https://github.com/AlexYez/comfyui-timesaver/blob/ccbf63952ef7a604c52ad38f318be2b0ca3eaa08/js/docs/TS_SongCreator/en.md).

В исходном коде подтверждена вставка U+0301 после гласной; повторное действие снимает знак, есть очистка всех знаков. Это редактирование строки, а не специальный параметр музыкальной модели. Формулировки community-автора об интерпретации моделью не считаем доказательством гарантированного соблюдения ударения. В просмотренных upstream-материалах YuE2 обещания такого жёсткого управления не найдено. [Реализация операции](https://github.com/AlexYez/comfyui-timesaver/blob/ccbf63952ef7a604c52ad38f318be2b0ca3eaa08/js/text/song_creator/_song_stress.js).

Согласованное направление интерфейса: позже отдельная кнопка буквально превращает выбранную гласную `о` в `о́`. Автоматическая расстановка ударений не согласована. Конкретное расположение кнопки и дополнительные действия пока не определены.

Для будущей реализации сохранять U+0301 при редактировании, копировании, сохранении и передаче текста в backend. Гласная со знаком должна обрабатываться как единый видимый элемент; знак не создаёт дополнительного слога. Сравнить русский вокал без знака и со знаком на нескольких примерах и seed; записывать фактический текст запроса. Одинаковый seed при изменённом тексте не означает ту же запись с исправленным произношением. Модели для этой проверки пока не запускались.

## Какой runtime проверить первым

| Кандидат | Роль в исследовании |
|---|---|
| Официальный Python | Контрольный вариант. Зависимости фиксировать в отдельном окружении, не менять рабочее окружение SwinIR. |
| yue2.cpp | Первый кандидат на нативное подключение в Windows. Нужна проверка соответствия официальному варианту и сохранения этапов. |
| audio.cpp | Альтернативный нативный кандидат; внедрение двух движков одновременно пока не обосновано. |
| ComfyUI | Изучение workflow и полезных исправлений; обязательная поставка всей среды пока не обоснована. |

У `yue2.cpp` документированы сборки Windows с CUDA/Vulkan/CPU, CLI создания плана и исполнения, серверная очередь и отмена, повторное исполнение из сохранённых семантических кодов. Рекомендуем для пробы отдельный CLI/worker; HTTP при необходимости ограничить локальным интерфейсом, поскольку сервер по умолчанию слушает `0.0.0.0`. Публичный контракт не принимаем за готовую реализацию общего pause/resume ЛОПАТЫ. [Архитектура native backend](https://github.com/ServeurpersoCom/yue2.cpp/blob/master/docs/ARCHITECTURE.md).

Официальная модельная карточка описывает Linux/Python и рекомендует 24 GB VRAM плюс 24 GB доступной RAM. Опубликованные замеры не включают первоначальную загрузку и сохранение; VAE для оценок и VAE для прослушивания различаются. Это не универсальная оценка Windows и не запрет работы на меньшей карте. [Карточка YuE2-3B](https://huggingface.co/m-a-p/YuE2-3B).

У [YuE2-ComfyUI](https://github.com/pytraveler/YuE2-ComfyUI) интересны проверки ABC, разделение планирования и исполнения, MIDI-адаптеры и работа с памятью. Дополнительное редактирование готового аудио использует собственную обработку и дополнительные модели; это не следует объявлять встроенной возможностью YuE2.

## Предложение более простой структуры

1. Ядро превращает описание в ограниченное структурированное задание: стиль, текст, части, вокал и желаемая длительность. Возможности текущего Qwen проверяются отдельно.
2. YuE2 создаёт собственный ABC-план. Отдельная MIDI-модель-композитор первой версии пока не требуется.
3. Программа проверяет структуру плана, согласованность частей и слов, длительность и поддерживаемые конструкции. Музыкальный вкус такой проверкой не доказывается.
4. Подтверждённый план становится сохранённым исходником версии, затем идёт исполнение и проверка аудиофайла/завершённости.
5. Будущий редактор кривой работает с нотными событиями нативного плана. MIDI добавляется как адаптер импорта/экспорта; исходный ABC сохраняется для воспроизводимости.
6. Изменения словами сначала формируют ограниченное описание изменений. Числовые операции над нотами/временем выполняет программа; свободное переписывание всей партитуры ядром не становится единственным способом правки.

Пользовательский экран остаётся элементарным. Один исходный технический профиль можно скрыть; смысловые темп, метр, форма и настроение должны адаптироваться к заданию. Одни числовые значения для всех жанров не доказывают универсальное качество. Длительность согласуется с планом, семантическим бюджетом и контекстом; число минут не гарантируется одним лимитом токенов.
