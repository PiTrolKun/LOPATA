## Файлы и восстановление

Проект получает `Materials/*` (снимки выбранных книг) и `Rag/Source/{text.json,sources.json,vectors.jsonl,manifest.json}`. JSONL содержит текст, источник, раздел, смещение, тип `reference`, нормированный вектор. Смещения worker — позиции Unicode code points в извлечённом разделе. Источник и извлечённый текст сохраняются отдельно от индекса; индекс воспроизводим.

Каждая подготовка имеет коллекцию `lopata_source_<UUID>`. `%LOCALAPPDATA%/AI_HUB/Literary/RagStaging` содержит временные снимки, lease и журнал намерения. Незаконченная подготовка удаляется при отмене, а при аварии — после следующей подготовки сценария. Успешно зафиксированный проект распознаётся по собственному manifest; его коллекция сохраняется. Очистка после удаления проекта выполняется сразу, при недоступной базе остаётся в очереди. Общая база Qdrant и чужие коллекции не удаляются. Файлы источников вне проекта не изменяются.

## Ограничения и следующий тест

- Giga используется только при добавлении первоисточника. Поиск в чатах, текущие главы, фоновая разметка и NER не подключены.
- 512 токенов на фрагмент, перекрытие 48 токенов. Документы без query-инструкции; masked mean + L2, 1024D. Сама модель допускает более длинную последовательность, но это не размер нашего поискового фрагмента.
- Одноразовый worker использует CUDA при наличии, иначе CPU; его завершение освобождает память. На CUDA ошибке нет скрытой повторной полной обработки на CPU: показывается ошибка, доступны повтор и удаление материала.
- TXT с определяемой BOM/UTF-8 кодировкой, EPUB, PDF с текстовым слоем. OCR не включён. Лимит 100 MiB на исходный файл, 150 MiB распакованного EPUB, суммарно 20 млн символов извлечённого текста. Добавление/удаление книги перестраивает выбранный набор целиком.
- На этапе pip показывается статус установки, а не выдуманный процент. Большие закреплённые модельные файлы используют имеющийся многопоточный загрузчик и глобальную настройку соединений. Транзитивные зависимости pip фиксируются в install-report при установке; это ещё не полный offline lockfile.
- Реальную загрузку Giga, запуск закреплённого окружения, качество семантического индекса, время и RAM/VRAM предстоит проверить пользователю. Механические тесты не заменяют эту проверку.
