## Пользовательское поведение

- Четыре источника: окно ЛОПАТЫ, монитор под курсором в момент запуска,
  все мониторы, выделенная область. Запуск собственным назначенным сочетанием;
  повтор того же сочетания останавливает запись. Отдельный Stop необязателен.
  Остановка также доступна из трея, утилиты и окна управления.
- Окно управления можно отключить; по умолчанию включено. Оно исключено
  из захвата Windows. Микрофон не включается без выбора соответствующего
  режима звука. Устройства выбираются из реальных активных устройств Windows;
  сохранённое отключённое устройство не заменяется другим молча.
- MP4/MKV: H.264 + AAC. WebM: VP9 + Opus. Без звука аудиодорожки нет.
  Режимы звука: выключен, компьютер, микрофон, компьютер + микрофон.
  Для последнего две дорожки захвата сводятся в одну выходную стереодорожку.
  Это простое смешивание с ограничителем уровня, без эхоподавления.
- Качество: исходное / 720p / 1080p / 1440p / 4K. Пресеты ограничивают
  короткую сторону до 720/1080/1440/2160 пикселей и сохраняют пропорции
  источника, включая вертикальный экран и широкое объединение мониторов.
  Маленькая область не увеличивается. Размеры округляются к чётным для YUV420.
- Частота: 15/24/30/60 FPS, default 30. Качество кодирования 1–100%, default 75.
  По умолчанию MP4, исходное разрешение, CPU, звук выключен, устройство
  Windows по умолчанию. Назначения видео пользователь задаёт самостоятельно;
  существующие фото/GIF-сочетания не заменяются.
- Минутного ограничения GIF у видео нет. Выходное имя содержит дату, время
  с миллисекундами, источник и уникальный суффикс. Настройки едины между
  утилитой и глобальным разделом; во время записи используется их снимок.
- Полный выход сначала останавливает и собирает запись. Завершение сеанса
  Windows откладывается существующим обработчиком до сохранения записи.
  Закрытие окна в трей продолжает запись. Активная модель не останавливается
  и не выгружается ради захвата. Скрытое окно возвращается к прежней странице
  и размещению после временного восстановления для съёмки.

## Захват, память и восстановление

Видео выделено в `VideoRecordingSession`, `VideoFrameStore`,
`VideoAudioCapture`, `VideoEncoder`; MainWindow связывает UI и жизненный цикл.
CPU-захват мониторов/области — существующий системный GDI, окно — WGC/WARP.
GPU-путь окна/монитора — постоянная WGC/D3D11-сессия. Auto предпочитает CPU
при зарегистрированной активной ИИ-задаче; иначе допускает GPU. Область
и все мониторы захватываются CPU-путём. Windows-композитор всё равно может
использовать GPU; нулевая нагрузка не обещана.

Очередь ограничена одним кадром, журнал читается потоком. В памяти нет
всего видео или списка всех сырых кадров. JPEG-кадры качества 92 и временные
метки записываются в `.lopata-video-*`; одинаковые кадры ссылаются на один
файл. Это промежуточное сжатие с потерями, не lossless. Кадр сбрасывается
на диск перед добавлением строки журнала. Метаданные заменяются атомарно;
незавершённая последняя строка после обрыва пропускается, повреждение середины
не скрывается. Проверяются размеры, имена и параметры аудиофайлов.

WASAPI сохраняет PCM и QPC-время относительно общего начала записи.
Пропуски времени представлены тишиной. Буфер устройства освобождается
до файлового I/O; при остановке забираются оставшиеся пакеты. При отключении
устройства запись останавливается, материал сохраняется с сообщением.

При отставании кадры пропускаются, CPU-захват адаптивно снижает внутреннюю
детализацию до четверти исходного масштаба и восстанавливает её после
устойчивого ускорения. WGC снижает внутренний размер после readback:
это не устраняет стоимость получения полной GPU-поверхности. Выбранная
итоговая геометрия не меняется. Пропуски и снижение детализации отмечаются
в уведомлении и соседнем JSON; финальная сборка удерживает предыдущий кадр,
сохраняя длительность. Неснятое движение и потерянные детали не восстанавливаются.

На локальном диске проверяется свободное место: при остатке менее 512 МиБ
захват останавливается. Для сетевой папки ошибки записи обрабатываются
без такого локального DriveInfo-порога. Заполненный диск/отказ кодировщика
не выдаются за успешную запись. Отмена сборки оставляет кэш для кнопки
«Восстановить видео из временной папки». Повторная сборка сохраняет исходный
кэш. Успешная обычная сборка удаляет только известные файлы своей сессии;
неизвестные файлы в папке не удаляются. Итоговое имя появляется только
после успешного завершения временного контейнера.

## Кодировщик и поставка

FFmpeg запускается отдельным встроенным helper после окончания захвата,
не конкурирует с ним во время сохранения промежуточного материала.
CPU H.264 — Windows Media Foundation software; резерв OpenH264.
GPU — NVENC, затем Media Foundation hardware; при отказе — CPU с явным
сообщением о переключении. WebM всегда использует CPU VP9.
FFmpeg имеет BelowNormal priority и ограничение программных потоков.
Отмена/таймаут завершает только процесс этой сборки.

Закреплён BtbN LGPL shared x64 **n8.1.3-14-g330caae0c1-20261001**.
`Инструменты/prepare-capture-runtime.ps1` проверяет SHA-256 архива и готовит
9 EXE/DLL, оригинальный LICENSE, NOTICE и provenance.json с хешами.
Размер бинарного комплекта около 159,6 МиБ. Разработчик подготавливает
комплект заранее; пользователь при запуске записи ничего не скачивает.
Сборка с отсутствующим комплектом завершается понятной ошибкой. Папка
CaptureRuntime включается в обычный publish; установщик в этой задаче не проверялся.

Добавлены NAudio.Core / NAudio.Wasapi **2.3.0**, MIT, оригинальный текст
сохранён. Общий каталог: `capture.ffmpeg`, `nuget.NAudio.Core`,
`nuget.NAudio.Wasapi`; штатный ComponentLicenseGate. Записи согласия
пользователя не создавались и не редактировались. Это отдельный bundled
компонент, не ранее существовавший скачиваемый `runtime.ffmpeg`.

Ссылки на закреплённые источники и рецепты:
[NOTICE FFmpeg](../Лицензии/Захват_видео_FFmpeg_NOTICE.md),
[условия FFmpeg](https://ffmpeg.org/legal.html),
[релиз BtbN](https://github.com/BtbN/FFmpeg-Builds/releases/tag/autobuild-2026-10-01-13-06),
[NAudio 2.3.0](https://github.com/naudio/NAudio/tree/v2.3.0).
Ограничение поставки: широкие FFmpeg DLL содержат также другие библиотеки
провайдера. Проверка полного транзитивного состава, соответствующих исходников
и NOTICE для публичного установщика/обновления **ещё не завершена**.
Наличие LGPL-варианта и общего согласия не подменяет эту проверку.
Текущая задача предоставляет локальную dev-сборку и не публикует бинарный пакет.
