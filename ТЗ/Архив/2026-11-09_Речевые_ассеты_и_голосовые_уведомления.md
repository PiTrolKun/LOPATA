## 1. Согласованное назначение и этапы

Это **утилита «Создание ассетов»** по пути **«Утилиты → Работа со звуком → Создание ассетов»**. «Работа со звуком» — новая категория утилит; речевые ассеты — назначение её первого инструмента. Делаем прежде всего для подготовки файлов самой ЛОПАТЫ, сохраняя возможность обычному пользователю озвучить собственный список. Не отдельный основной сценарий или новая аудиостудия.

1. Создать утилиту: загрузить `.md`, представить каждую единицу списка отдельным будущим аудиофайлом; запускать автоматическую последовательную обработку либо полуручную работу с прослушиванием и повтором.
2. Выгрузить каталог всех пользовательских уведомлений/статусов ЛОПАТЫ, подготовить для него звуковые файлы RU/EN через эту утилиту, подключить воспроизведение и настройку детализации. Звуки связать с существующей ручной локализацией, чтобы последующий переводчик мог добавить свой язык и его записи.

**Выбор голоса ручной, в утилите генерации.** Не закреплять заранее голос, пол, «синтетичность» или единственного победителя из старого списка моделей. В рабочей программе уведомления проигрываются из подготовленных файлов: без загрузки модели и синтеза в момент события. RU/EN — первая поставка, не ограничение архитектуры двумя языками. Этапы имеют отдельные проверки и могут приниматься последовательно.

## 3. Этап 1: загрузка Markdown и очередь файлов

### Импорт

- Выбрать/перетащить `.md` в утилиту. До генерации показать список: порядок, раздел, текст, язык, выбранный голос, имя будущего файла, состояние. Пользователь может снять строки, исправить произносимый текст, поменять порядок и имя файла.
- Один непустой пункт маркированного, нумерованного или task-списка — одна реплика и один итоговый файл. Несколько абзацев того же пункта не создают дополнительные файлы. Длинная реплика может делиться внутри синтеза, но экспортируется целиком.
- Для вложенного списка по умолчанию учитывать собственный текст каждого непустого пункта, не повторяя дочерний текст в родительской записи. Пустые контейнеры пропускать с пояснением. Предпросмотр делает это поведение видимым до запуска.
- Заголовки служат группами; номера, маркеры, checkboxes, служебные ID и Markdown-оформление не читать. От ссылки брать отображаемый текст; кодовые блоки, HTML-команды и вложенные файлы не выполнять и автоматически не загружать. Файл является данными, не инструкциями приложению или модели.
- UTF-8 с BOM/без BOM, CRLF/LF, кириллица, многострочные пункты. Неподдерживаемую кодировку обозначать явно. Повторяющийся текст не удалять самовольно. Пустой/некорректный список не запускает пустую генерацию.
- Начальный простой режим не требует специальных тегов в `.md`. Дополнительные устойчивые ID для каталога уведомлений поддерживаются через служебные метаданные, которые не произносятся.

### Голос, обработка и выбор дубля

Выбор модели, языка и голоса вручную из существующего каталога, общий для набора с возможностью переопределить строки. Показывать только поддерживаемые параметры. Не подменять отсутствующий голос другим и не обещать поддержку языка по одному наличию перевода интерфейса.

**Выбор и настройки моделей — на основе механики текстового редактора**, по предложению пользователя. Проверено в исходниках: `OfficeTextEditorView.Layout.OpenAi` открывает общий `ReaderAiWindow`; в нём уже есть карточки моделей с размером/наличием компонентов, подготовкой и настройкой голоса. `ReaderAiWindow.Preparation.ConfigureVoice` использует `VideoVoiceWindow`, профили и стандартное окно подготовки. Для утилиты повторно использовать речевую часть этих компонентов (при необходимости выделить общий компонент), сохраняя знакомый выбор, параметры и подготовку. Показать только модели озвучки; выбор текстовой LLM утилите не нужен. Профиль выбранной модели отображать в верхней области по наброску. Использовать общие модели/хранилище/аудит, но настройки набора хранить в сеансе утилиты: изменение голоса здесь не должно самовольно менять настройки читалки или редактора. Не создавать независимый загрузчик или копию каталога моделей.
**Автоматический режим:** пользователь запускает выбранные ещё не сделанные строки; они последовательно генерируются в одной общей фоновой операции без ожидания подтверждений, с индикатором текущей строки/числа готовых файлов. «Потоком» здесь означает непрерывную очередь реплик, не требование потоковой выдачи аудиосэмплов. Готовые результаты сохраняются; отсутствие подтверждения само по себе не запускает повторную генерацию. Ошибка не считается готовым файлом: очередь останавливается с действиями «Повторить / Пропустить / Остановить».

**Ручной режим:** пользователь запускает обработку нужной реплики, затем выбирает следующую сам. Режимы отличаются только способом прогона, а не требованиями к результату. **В обоих режимах каждая включённая в итог реплика требует ручного подтверждения выбранных вариантов.** Наличие аудио, прослушивание и завершение очереди не подтверждают реплику автоматически. Повтор создаёт новый дубль, сохраняя предыдущие для сравнения. Автоматическое восстановление не заменяет ожидаемое ручное решение.

**Текст каждой реплики редактируется вручную прямо в её строке**, до первой генерации и после получения дублей. Изменения сохраняются в рабочем наборе; исходный `.md` без отдельной команды не перезаписывается. При изменении текста подтверждение этой реплики сбрасывается с `V` на `−`, прежние дубли сохраняются с привязкой к прежнему тексту и пометкой об устаревании. Новый дубль создаётся по исправленному тексту и требует ручного подтверждения. Не включать старую запись в итог как озвучку новой редакции; остальные реплики не затрагиваются.
**Назначение ручных правок — в том числе адаптация произношения к конкретной модели/голосу:** замены «е»/«э», «ё», ударения, запись чисел или сокращений словами. Все такие особенности невозможно заранее предусмотреть; не выполнять универсальные замены автоматически. Хранить исходную фразу отдельно от редактируемого текста для синтеза. Для уведомлений фонетические подсказки не меняют отображаемую строку локализации и устойчивый event ID. Каждый дубль и manifest сохраняют фактический текст, переданный модели, отдельно от исходного текста/его ревизии; это позволяет сравнивать варианты с разными подсказками и не принимать фонетическую адаптацию за новый смысл уведомления. Ручное подтверждение проверяет результат на слух; изменение текста для синтеза снимает подтверждение текущей редакции, но не удаляет историю дублей.
### Рабочий экран по наброску пользователя

Сверху — выбор входного файла с путём/именем, выбор модели и голоса с отображением параметров, общий запуск потоковой генерации ещё не сделанного. Ниже — единый прокручиваемый список строк: слева текст реплики, рядом статус и действия «Подтвердить»/«Перегенерация», справа её аудиоварианты с отдельными кнопками воспроизведения и полосами перемотки. Несколько дублей показываются рядом с соответствующей репликой; число плееров на наброске не является фиксированным лимитом.

Статус `V` означает подтверждённую пользователем реплику, `−` — неподтверждённую. Текущая генерация и ошибка отображаются дополнительно, не подменяя ручное подтверждение. Можно выбрать нужные варианты для итогового набора; изменение текста или выбранного состава дублей требует повторного подтверждения этой реплики.

Подтверждённая реплика визуально приглушается целиком: строка заметно отличается от требующих проверки даже при беглом взгляде. Сохранить читаемость текста, отчётливую отметку `V` и доступность редактирования/плееров; приглушение не означает блокировку. В светлой и тёмной темах подобрать соответствующее оформление. При сбросе подтверждения вернуть обычный вид строки и `−`.

**Согласованные дополнения к экрану:**

- Общий счётчик: всего реплик, сгенерировано, подтверждено, осталось проверить. Считать реплики, а не число дублей; снятые из набора строки не увеличивают число оставшихся. После правки текста и сброса подтверждения значения обновляются.
- Действие «Вернуть исходный текст» у реплики восстанавливает исходную фразу в поле текста для синтеза. Если текст действительно изменился, применяются обычные правила сброса подтверждения и сохранения истории дублей. Автоматическую генерацию возврат не запускает.
- У каждого дубля — компактная подпись фактической модели, которая его создала; при необходимости короткое имя голоса. Не заполнять строку всеми параметрами и полным текстом синтеза: подробные сведения остаются в данных дубля/manifest. Смена текущего выбора модели не переименовывает старые дубли.

Последовательное прослушивание всего выбранного набора отдельной командой не требуется. Дополнительный обзорный экран состава перед ZIP не добавлять; счётчик и построчные статусы показывают готовность в основном экране.
Во время ожидания решения не удерживать тяжёлый исполнитель и модель бесконечно. Сохранить результат, освободить ресурсы по общему жизненному циклу; продолжение не повторяет принятые строки. Изменение текста/профиля делает только соответствующие результаты устаревшими. Для длинной очереди сохранять результаты после каждого пункта; checkpoint связывает ID, текст, язык, параметры, реальные ревизии и контрольную сумму аудио.

### Сохранение

**Итоговый результат — ZIP со слабым сжатием без потерь, содержащий все выбранные и вручную подтверждённые аудиоварианты.** Не складывать в итог все пробные/отклонённые дубли автоматически. Для нескольких выбранных вариантов одной реплики сохранить отдельные файлы и однозначную связь с её ID. Слабое сжатие относится к упаковке ZIP и не ухудшает качество аудио. По умолчанию аудио — WAV PCM16.

В ZIP входят отдельные аудиофайлы с безопасными именами и manifest с ID, текстом, языком, выбранными дублями, фактической моделью/голосом, параметрами и хешами. Коллизии, повторные имена, Windows reserved names и выход за корень набора обрабатывать до записи; чужие файлы не перезаписывать без явного выбора. Не собирать весь список в единственную общую озвучку вместо отдельных файлов. Неподтверждённые реплики видны по счётчику и построчным статусам; не выдавать неполный набор за полностью готовый.

Сохранять редактируемый набор/сеанс, чтобы вернуться к проверке и заменить отдельную запись. Выбранные принятые записи публиковать атомарно. Встроенные метаданные должны описывать именно утилиту речевых ассетов, а не оставлять жёстко заданное `video-editor/narration`. Дополнительные сжатые форматы использовать через имеющийся конвертер после проверки; формат поставки уведомлений выбрать по реальному размеру и доступному декодеру. Не добавлять новый тяжёлый компонент ради проигрывания короткого уведомления.

## 4. Этап 2: каталог реплик самой ЛОПАТЫ

Первое действие — сохранить **полный каталог пользовательских уведомлений и статусов** отдельными файлами: машиночитаемый manifest и удобные для перевода/этапа 1 `.md`. RU/EN — стартовые версии; дальнейшие языки создаются тем же механизмом.

Инвентаризация включает tray, результаты/ожидание ввода/паузы фоновых операций, сохранение и экспорт, подготовку/загрузку компонентов, ошибки, статусы отдельных окон и сценариев. Учесть локализованные и захардкоженные строки, прямые присваивания StatusText и динамические сообщения. Не выдавать regex-поиск по одному имени метода за полный охват.

У записи: устойчивый event ID, исходные места/ключи, категория, важность, тип статуса, параметры, речевой ключ, тексты языков, короткий/расширенный вариант при необходимости, привязка аудио, состояние проверки. Каждая пользовательская реплика должна быть учтена: готова к озвучке либо имеет явное объяснение исключения, согласованное перед закрытием этапа. Заголовки меню и подписи кнопок не превращать в события уведомления.

Список с плейсхолдерами не размножать на все имена файлов, проценты и модели. Для заранее записанного звука подготовить понятную общую речевую формулировку («Файл сохранён», «Загрузка завершена»), сохраняя подробные фактические данные в визуальном сообщении. Не генерировать речь на лету, не читать сырые исключения, пути и токены. Связь с исходным событием сохраняется по ID, а не по совпадению отображённой строки.

Создать RU/EN `.md`, пропустить их через утилиту, вручную выбрать голоса и дубли, прослушать все принятые записи. Смысл речи должен соответствовать событию: ошибка не звучит как успех, отмена не называется завершением. После выбора экспортировать проверенный комплект. Одинаковые формулировки допускают явные aliases на одну запись, но утилита сама не удаляет пункты входного списка.

## 5. Звуки и ручная локализация — один механизм выбора языка

Пользовательское уточнение: любой будущий переводчик ЛОПАТЫ должен иметь возможность перевести **и тексты, и звуки** без правки кода.

### Совместимость существующего формата

Сохраняются плоские `Localization/<code>.json` и пользовательские файлы в `AppDataPaths.LocalizationDirectory`. Нельзя внезапно потребовать ZIP, вложенный объект или аудио для подключения обычного текстового перевода. Язык берётся из действующего `LocalizationService.CurrentLanguageCode`, нормализуется существующими правилами и выбирается существующим общим переключателем. Не добавлять отдельный независимый список языков звуков.

Речевые тексты входят в словарь локализации под устойчивыми ключами, например `VoiceNotifications.Text.project.saved`. Нужен способ узнать не только текст, но и фактический язык/источник его разрешения и ревизию, не меняя существующую семантику `T(key)`. Сейчас пользовательский JSON заменяет встроенный файл этого языка; текстовый fallback ru не является автоматическим разрешением читать уведомление чужим языком.

**Предлагаемое совместимое размещение:**

- встроенные записи: `Assets/VoiceNotifications/<code>/manifest.json` и аудио;
- пользовательские: `<LocalizationDirectory>/VoiceNotifications/<code>/manifest.json` и аудио;
- текст языка остаётся `<LocalizationDirectory>/<code>.json`.

Не класть voice-manifest в корень Localization как `<code>.speech.json`: текущий GetAvailableLanguages перечисляет все корневые `*.json`, и такой файл станет ложным языком. Имена/места уточнить при реализации; правило совместимости обязательно.

### Путь переводчика

1. В существующем месте ручной локализации получить шаблон выбранного языка и экспорт речевых текстов в `.md`, сохраняя ID и связь с ключами.
2. Перевести текст, открыть его утилитой, **вручную выбрать голос** и создать записи. Если выбранная модель не поддерживает язык, показать это; разрешить присоединить/заменить запись готовым аудиофайлом. Подмена языка модели или автоматическая загрузка новой модели недопустимы.
3. Проверить комплект и подключить его к тому же коду языка. По договорённости 10.11.2026 добавить импорт ZIP: отдельного звукового комплекта из утилиты либо совмещённого пакета текстов и звуков. Ручное размещение прежнего текстового JSON продолжает работать; подробные правила — в разделе 18.
4. Выбрать язык общим переключателем — интерфейс и последующие звуковые уведомления используют соответствующий комплект. Сам голос воспроизведения задаётся подготовленными файлами, а не скрытой настройкой TTS-модели у конечного пользователя.

Voice-manifest содержит версию схемы, код языка, event ID/вариант, речевой ключ, SHA-256 исходного произносимого текста, относительный путь и SHA-256 аудио, длительность/формат и сведения о создании. Пути проверяются на принадлежность пакету, ссылки/выход за корень и исполняемые вложения не принимаются.

Частичный перевод и текстовый пакет без аудио допустимы. Для отсутствующей/устаревшей записи по умолчанию остаётся визуальное уведомление и штатное поведение звука; чужой язык не включается молча. Если позже понадобится речевой fallback, он должен быть явным выбором пользователя. Частичное покрытие показывается переводчику, не выдаётся за готовый голосовой перевод.

При изменении речевого текста его прежний файл помечается устаревшим; нельзя озвучить старый смысл под новой надписью. Изменение события/схемы обнаруживается сравнением каталога с manifest. При смене языка остановить/сбросить устаревшую очередь уведомлений; новый пакет вступает в действие без перезапуска программы. Выбор голоса для пользовательского набора в утилите при этом самовольно не менять.

## 6. Воспроизведение и детализация

Настройки в существующем разделе «Голос»: общее включение готовых голосовых уведомлений, независимые переключатели трёх групп — «Ошибки и сбои», «Статусы», «Подробные события / логи», громкость, небольшой ползунок скорости и прослушивание примера. По прямому уточнению пользователя 10.11.2026 **сама механика и все три группы по умолчанию включены**. Это заменяет прежние предложения выключенного начального состояния и пресетов «Только важное / Основные события / Подробно». Скорость по умолчанию 1×, ориентировочный диапазон 0,75–1,25×; пауза между фразами остаётся 0,5 секунды. Детальные правила — в разделе 18.

Один лёгкий проигрыватель и ограниченная очередь. Приоритеты групп: 1 перебивает 2 и 3, 2 перебивает 3; равноправные сообщения ожидают своей очереди. Повтор ожидающего события поднимает его на одну позицию внутри своей группы без добавления дубля. Устаревшие промежуточные реплики после смены состояния/завершения/отмены удаляются. Восстановление истории и перерисовка UI не повторяют старые сообщения. Выключение немедленно останавливает речь и очищает очередь. Цветная кнопка 🔊👄 в верхней панели мягко мигает при трёх и более ожидающих уведомлениях; звучащая фраза не входит в счётчик.

Не создавать одновременно речь, системный beep и второе озвучивание того же события разными слоями. Сохранить визуальные сообщения, индикаторы трея, переход к результату и аварийный STOP. Во время воспроизведения музыки или видео внутри ЛОПАТЫ звучат только уведомления, связанные с текущим материалом и сеансом работы, включая применение этого фильтра к ошибкам; посторонние сообщения не накапливаются для последующего чтения. При записи микрофона подавлять уведомления, чтобы они не попадали в диктовку. Во время озвучки читалки или ответов ИИ ошибки временно ставят текущую речь на паузу, произносятся, затем речь продолжается; статусы и подробные события ждут освобождения голосового канала с удалением устаревших. Приглушение музыки вместо согласованного фильтра не вводить. Плеер не порождает новые уведомления о собственном воспроизведении. Потеря аудиоустройства/файла не останавливает основную операцию и не создаёт цикл ошибок.

Звуковые данные проверяются по общей политике ComponentAudit при подготовке/смене ревизии, а не отдельным полным хешированием каждой реплики при каждом событии. Никаких TTS/LLM-процессов и фоновой загрузки весов ради готового уведомления. Пользовательские языковые пакеты сохраняются при обновлении; удаление поставки не уничтожает чужие записи.

## 7. Предлагаемое устройство реализации

Отдельные модули: импорт Markdown, проект/строки/дубли, оркестратор генерации поверх имеющихся narrator, экспорт набора; отдельно каталог событий, сборщик переводимых реплик, resolver языкового аудио, лёгкая очередь воспроизведения. MainWindow — только подключение и UI, без накопления всего механизма в одном файле.

Начать с существующих провайдеров и разрешённых параметров, аудита, стандартного окна подготовки компонентов и явного лицензионного согласия. Интерактивное ожидание и завершение процесса подтверждать до освобождения/возобновления; принятые файлы не генерировать и не экспортировать повторно. ## 18. Этап 2: договорённости о голосовых уведомлениях — 10.11.2026

**Статус: согласованный контракт реализован в 0.7.72-dev; результаты и границы проверки — в разделе 19.** Пользователь обозначил исходное видение как предмет обсуждения. При фиксации учитываются уточнения: все уведомления включены по умолчанию; включённый значок цветной, выключенный — чёрно-белый; при музыке/видео внутри ЛОПАТЫ действует фильтр связи с текущим материалом; очередь больше двух вызывает мягкое мигание; в глобальных настройках нужен ползунок скорости. Согласованы пауза озвучки читалки/ИИ на время ошибки и ожидание остальных групп; отдельная задержка против повторов и расширенная подсказка отклонены. Этот раздел имеет приоритет над прежними предложениями о поведении этапа 2.

### 18.1. Три группы и принадлежность событий

| Приоритет | Группа | Содержание |
|---|---|---|
| 1 — высший | Ошибки и сбои | Не удалось выполнить действие, потеря связи, сбой модели/компонента, ошибка, требующая вмешательства |
| 2 | Статусы | Начало/завершение/остановка задачи, загрузка и готовность модели, результат готов |
| 3 | Подробные события / логи | Промежуточные этапы, смена исполнителей и технические события, пригодные для голосового сообщения |

Группа определяется смыслом события, а не местом его записи: ошибка из технического журнала остаётся группой 1. Не озвучивать каждую строку stdout/stderr или каждый процент прогресса. Каталог связывает устойчивое событие с группой, задачей/сеансом, этапом и подготовленной репликой; визуальная строка может содержать подробности, голосовая — короткую общую формулировку. Перевод и изменение фонетического текста не меняют приоритет события.

### 18.2. Очередь, повторы и прерывание

- Одновременно звучит одна реплика. Группа 1 прерывает группы 2 и 3; группа 2 прерывает группу 3. Сообщение равного приоритета не обрывает текущую фразу, а ожидает в своей очереди. Более низкий приоритет не прерывает более высокий.
- Внутри группы действует порядок поступления с оговорённым продвижением дублей. Если то же событие той же задачи уже ожидает, новое не добавляется: существующее поднимается на одну позицию внутри своей группы. Повтор не переводит сообщение в более высокий класс.
- Дубли определяются по устойчивому событию и конкретной задаче/сеансу/экземпляру этапа. Совпадения текста либо одного ClipId недостаточно: одинаковая фраза может относиться к разным задачам или событиям. Повтор уже звучащего события не начинает фразу заново и не добавляет её копию в очередь.
- По уточнению пользователя дополнительную защитную задержку после окончания реплики (запрет повторной озвучки на несколько секунд) **пока не вводить**. Сохраняются оговорённые правила дублей ожидающего/звучащего события, актуальности и паузы между фразами; отдельного таймера подавления уже произнесённого нет.
- После завершения одной фразы перед следующей ожидающей выдерживается пауза **0,5 секунды**. Более приоритетное прерывание и поступившая во время паузы срочная реплика не ждут окончания этой паузы. Выключение имеет немедленный эффект.
- Устаревшие состояния удаляются: после готовности модели не читать ожидающее начало её загрузки; после завершения/отмены задачи убрать её оставшиеся промежуточные статусы. Сохранить актуальное итоговое сообщение.
- Прерванную реплику возвращать в очередь только при сохранении её актуальности. Повторное воспроизведение начинается с начала фразы, а не с середины слова или предложения.
- Один сбой не должен давать каскад нескольких одинаковых речевых сообщений из разных слоёв. Учитывать общий источник сбоя, сохраняя визуальные подробности и диагностику.
- Очередь хранит актуальные события текущей работы. Перерисовка интерфейса, повторная подписка, восстановление истории и перезапуск программы не воспроизводят старую историю уведомлений.

### 18.3. Воспроизведение музыки или видео

Во время воспроизведения музыки или видео **только внутри ЛОПАТЫ** допускаются **только уведомления, связанные с тем материалом, который пользователь сейчас слушает/смотрит, и его сеансом работы**. Привязка к целому разделу «Музыка» или «Видео» недостаточна. Состояния и ошибки текущего материала допускаются, посторонней фоновой задачи — сохраняют обычное визуальное отображение без речи. Внешние программы, сторонние проигрыватели и браузеры в область этого правила не входят; системное наблюдение за ними не требуется.

Фильтр связи применяется **до постановки в речевую очередь и сравнения приоритетов**, в том числе к группе 1. Посторонняя ошибка не обходит фильтр только из-за высокого приоритета. При начале воспроизведения или смене материала удалить ставшие посторонними ожидающие сообщения и прекратить постороннюю текущую реплику. Отфильтрованное не накапливать для чтения после окончания просмотра/прослушивания; после него принимаются новые актуальные события. Приглушение музыки вместо этого правила не вводить.

Озвучивание самого уведомления не должно ошибочно считаться началом прослушивания материала и менять собственный фильтр. Сохранить ранее заданное подавление речи при записи микрофона.

**Читалка и ответы ИИ:** по согласованному предложению ошибка группы 1 временно ставит их текущую озвучку на паузу, произносится, затем озвучка продолжается с сохранённого места. Статусы группы 2 и подробные события группы 3 ожидают освобождения голосового канала, устаревшие ожидающие удаляются по общим правилам. Возобновлять автоматически только речь, приостановленную этой механикой: ручная пауза/остановка пользователя, закрытие документа или смена ответа не должны отменяться. Прежде чем прерывать речь, проверить все общие условия допуска уведомления; фильтр музыки/видео и настройка выключения не обходятся.

### 18.4. Глобальные настройки и верхняя панель

В существующем разделе «Голос» разместить:

- общее включение голосовых уведомлений;
- три независимых переключателя групп: ошибки/сбои, статусы, подробные события/логи;
- громкость только голосовых уведомлений;
- небольшой ползунок скорости их воспроизведения: обычная скорость **1×**, ориентировочный диапазон **0,75–1,25×** (примерно ±0,25 от обычной скорости, по формулировке пользователя);
- прослушивание примера, доступ к языковым комплектам/импорту ZIP.

**В новой конфигурации по умолчанию включены и вся механика, и каждая из трёх групп.** Последующий выбор пользователя сохраняется; перезапуск/обновление не включают отключённое заново. Громкость и скорость не меняют музыку, видео, читалку, речь ядра либо исходные аудиофайлы. Изменение скорости не ускоряет паузу 0,5 секунды и не запускает повторную генерацию. Проверить разборчивость, отсутствие обрывов и корректное завершение записи на краях диапазона; точный шаг ползунка подобрать при реализации без расширения согласованного назначения.

В верхней панели нужна **одна кнопка с гибридным значком «🔊👄»**. Это не две независимые кнопки. ЛКМ включает/выключает озвучку; ПКМ открывает меню, из которого вызывается управление громкостью и доступ к настройкам. По последнему уточнению пользователя **включённый значок цветной, выключенный — чёрно-белый** в обеих темах. Расширенную подсказку со счётчиком очереди, громкостью и скоростью не добавлять: состояние показывается цветностью значка, накопление очереди — уже согласованной анимацией.

Выключение прекращает текущую фразу и очищает очередь; повторное включение принимает новые события без чтения накопленной истории. Отключение отдельной группы удаляет её ожидающие сообщения и прекращает её текущую реплику, сохраняя остальные разрешённые группы.

Если ожидает **три и более уведомления**, подсветка кнопки начинает мягко мигать/пульсировать. При двух и менее ожидающих возвращается обычное состояние. Уже звучащая фраза, объединённые дубли и отфильтрованные сообщения не увеличивают этот счётчик. При очистке очереди, выключении или смене языка анимация прекращается. Порог связан с числом ожидающих сообщений, а не с длительностью аудио или числом событий в журналах.

### 18.5. Локализация и импорт готовых ZIP

Сохранить общий выбор языка и прежний плоский JSON ручной локализации из раздела 5. Поддержать импорт отдельного звукового ZIP и совмещённого языкового ZIP с текстами и аудио. В частности, принимать существующие ZIP утилиты с подготовленными RU/EN библиотеками без повторного синтеза и обязательного ручного переименования каждого файла.

Привязка записей — по устойчивым ID, manifest и встроенным маркерам, с сохранением связи с исходным событием и aliases. Порядковый номер и имя файла сами по себе не являются идентификатором события. Сохранить различие исходного смыслового текста и произносительного текста из дубля: ручные замены «е/э» не должны разрушать связь с событием локализации.

Перед применением показать язык, покрытие, отсутствующие/устаревшие записи и замены. Проверить схему, язык, пути, хеши и согласованность маркеров; некорректный импорт не повреждает действующий комплект. Пользовательские комплекты хранятся отдельно от поставочных и переживают обновления. Пакет языка задаёт тексты и звуки, но не подменяет правила приоритета/очереди программы.

Неполный комплект и текстовый перевод без звуков допустимы. Для отсутствующего либо устаревшего аудио остаётся визуальное сообщение; автоматической подмены языка речи нет. При смене общего языка остановить текущую реплику и очистить старую очередь, последующие события используют новый комплект без перезапуска. Переводчик может добавить язык и записи без изменения кода.

### 18.6. Устройство и границы реализации

Один отдельный лёгкий сервис внутри процесса ЛОПАТЫ: каталог/привязки смысловых событий, фильтр настроек и текущего контекста, очередь, проигрыватель готовых файлов. Подключить реальные источники уведомлений и статусов, включая модельные этапы и фоновые задачи; одного tray Notify или наблюдения за надписью StatusText недостаточно. Не менять существующие визуальные сообщения и управление задачами ради добавления речи.

Не запускать TTS/LLM и не загружать веса при событии. Не делать отдельный тяжёлый фоновый job из проигрывания файла. Подготовка/проверка пакетов выполняется вне UI с общей политикой ComponentAudit; счётчик/анимация получают короткие обновления, без полного пересоздания списка или повторного полного хеширования набора на каждом событии. Ошибка файла/аудиоустройства не останавливает основную задачу и не запускает речевое уведомление об ошибке самого речевого уведомления.

## 19. Реализация этапа 2 — 0.7.72-dev, 10.11.2026

Подключены подготовленные пользователем комплекты RU/EN: по 1529 записей, без повторного синтеза. Приложение поставляет исходные ZIP вместе с компактным каталогом 5247 связей событий и 6394 текстовых шаблонов. Это число связей, а не обещание отдельной ручной проверки каждого события. Звуки связаны с устойчивыми clip ID; модель для уведомлений не загружается.

Очередь разделяет ошибки, статусы и подробные события; приоритеты 1→2→3 прерывают младшую группу. Ожидающий дубль продвигается на одну позицию своей группы, звучащий не перезапускается. Учитываются идентичность операции, актуальность статусов и завершение; нового многосекундного запрета повторов нет. Верхняя граница очереди — 512 записей: при переполнении удаляется самое старое из младшей представленной группы. Журнал и визуальные сообщения при этом сохраняются.

В заголовке размещена одна цветная кнопка 🔊👄, чёрно-белая при выключении. ЛКМ выключает/включает озвучку, ПКМ открывает меню громкости и настроек. При более двух ожидающих действует мягкая пульсация. Меню, подменю и ползунок используют текущие ресурсы темы; светлый системный фон заменён после замечания пользователя. В разделе «Голос» доступны включение, три группы, громкость, скорость 0,75–1,25× с шагом 0,05, пример, импорт ZIP и экспорт текстов для переводчика. Настройки независимы от громкости/скорости других проигрывателей.

Подключены общие фоновые операции, уведомления о завершении, известные статусы интерфейса и события загрузки/готовности моделей. Внутренние проигрыватели музыки/видео публикуют контекст материала/проекта, микрофон блокирует уведомления. Озвучка читалки/ИИ может приостанавливаться для ошибки и продолжаться с места; ручная остановка/пауза остаётся приоритетной. Внешние приложения не отслеживаются.

Отдельный сервис принимает исходные ZIP утилиты (schema 2), частичные звуковые наборы и совмещённые языковые ZIP. Общий выбор языка сохранён. Проверяются пути, ID, SHA-256 и встроенные маркеры; новая ревизия активируется после проверки с сохранением прежней при отказе. Для новых языков предусмотрен экспорт реплик с ID и исходным текстом. Нет скрытого перехода на чужой язык при отсутствии записи. Пакеты используют общую политику ComponentAudit: первый проход полный, при выключенном аудите последующие — наличие обязательных файлов, при включённом — полный контроль.
