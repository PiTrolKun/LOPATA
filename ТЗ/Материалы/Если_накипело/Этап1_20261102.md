# «Если накипело»: первый этап, 02.11.2026

Версия: **0.7.2-dev**. [Рабочее ТЗ](../../2026-11-02_Разгрузочный_разговор_Набросок.md).

## Реализовано

- Ветка «Эксперименты», группа «Чаты», карточка «Если накипело», тег и RU/EN.
- Вход через окно подготовки. Проверка ничего не скачивает; готовность требует
  отдельной кнопки «Открыть чат» и повторной проверки. Отмена возвращает к выбору.
- Существующее ядро Qwen3 8B Q4_K_M, штатный выбор llama.cpp и хранилища.
  Общие лицензии и ComponentAudit; никаких новых весов, SDK или зависимостей.
- Недостающие / неисправные веса подготавливаются общим ManagedModelAcquisitionService,
  с выбранным числом соединений и проверкой перед заменой. Движки — существующие
  установщики, без изменения выбранного набора. Скачивание запускает только человек.
- Простой чат с потоковой выдачей, историей текущего сеанса, новым разговором,
  Enter/Shift+Enter, остановкой и сохранением черновика при возврате из настроек.
  Ядро остаётся загруженным между успешными ответами.
- Общая операция `chat.let_it_out`: приватные активные контрольные точки,
  пауза / восстановление / STOP / освобождение моделей. Незавершённый ответ не
  попадает в историю модели как завершённый; пользовательские реплики не дублируются.
  Завершённая беседа не архивируется общим контроллером и не записывается в RAG.
- Восстановленный разговор на паузе показывается при входе даже при свободном общем
  вычислительном ресурсе; отправка / новый разговор ожидают разрешения этой операции.
- Ответы очищаются штатным LlamaAnswerContentFilter ещё до показа потока и записи
  checkpoint. Исправлено наблюдение пользователя: пустые `<think>…</think>` на экране.
  Старые assistant-реплики очищаются при восстановлении; пользовательский текст не меняется.
- Контекст измеряется по фактическому шаблону / токенизатору и доступной ёмкости
  сервера (`/props`, затем `/slots`). История молча не обрезается.

## Границы

Hy-Memory, даосский RAG, голос, карта ситуации, постоянная библиотека бесед и экспорт
не внедрялись. Переписка обычного завершённого сеанса не переживает закрытие приложения;
незавершённая операция имеет локальную временную контрольную точку для восстановления.
Это поясняется в интерфейсе. Скачивание новых больших файлов физически не выполнялось.
Совместимость с другими ПК не объявляется измеренной на основании одного компьютера.

Повреждённый полный final GGUF заменяется общим загрузчиком. Если внешне повреждена
уже полностью скачанная `.part`, общий загрузчик отвергает её по SHA; следующий явный
запуск скачивания начинает заново. Собственный обход этих правил не добавлялся.

Установщик не пересобирался по правилу; commit/push и файловое обновление не выполнялись.
Рабочее ТЗ остаётся активным, исходная идея остаётся в общем архиве без изменений.
