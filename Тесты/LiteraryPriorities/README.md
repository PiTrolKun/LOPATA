## Что сравнивалось

Одна Runeweaver Q4_K_M, действующие роли Писателя/Советника, настоящий LiteraryReadingSession и RAG через Giga/Qdrant на отдельной копии тестового проекта. Первая серия: четыре задачи × четыре варианта × три повтора = 48 попыток. Варианты: существующая инструкция; дополнительные словесные обязательства; те же требования с числовой шкалой; числа вместе с программным обеспечением обязательного чтения.

Задачи аналогичны последнему пользовательскому тесту: сохранение канона при прыжках во времени; три карты; вопрос о текущем наброске без продолжения; короткое продолжение с обнаружением чужого тела. Полная восьмишаговая переписка не воспроизводилась. Чтобы проверить именно управление действием, каждому варианту одинаково переданы принятые авторские условия о молнии, чужом теле и следах-артефактах. Автоматическое извлечение этих условий не проверялось.

Каждое испытание собирает контекст заново; ответы предыдущих испытаний не подмешиваются. Seed 701–703, планирование temperature=0, генерация — настройки соответствующей роли приложения; cache_prompt=false. Это три повтора, но не три независимых случайных решения планировщика. Запрос поиска задаётся стендом: правильное автоматическое определение необходимости поиска и формулировки запроса остаётся отдельной задачей.

Программный вариант при отсутствии чтения заменяет выбор модели на поиск первоисточника; перед генерацией проверяет наличие выдержек в контексте. На задачах только по редактору ограничивает действие вариантом answer. Контроль проверяет доставку материала, а не истинность всех утверждений ответа. Веса не суммируются и не меняют внутренние веса нейросети.

Поэтому доставка актуального текста и соблюдение режима ответа тоже не равны абсолютной фактической точности.

В задаче Писателя числа не обеспечили два предложения: встречались три и больше, исполнение записки вместо решения её оставить, неподтверждённые предметы и даже 2023 год. Программный контроль в этом опыте управлял чтением, не проверял литературный объём и содержание. Улучшение этих свойств ему не приписывается.

## Практический вывод

Числа в промпте сами по себе надёжности не добавили. Слово «обязательно» оказалось полезнее в проверенной задаче чтения. Программное обеспечение чтения устранило конкретный пропуск источника и помогло получить правильный основной факт во всех трёх повторах вопроса о финале. Это положительный результат для управления действиями; общая безошибочность литературного помощника не доказана.

Для приложения разумно хранить приоритеты числами, а модели выдавать небольшой словесный договор текущего этапа. Обязательные действия исполняет/проверяет программа. Промежуточный буфер содержит материалы с источником, версией и статусом, а не превращает каждую догадку модели в факт. Планирование чтения, найденные сведения и финальный ответ должны иметь разные инструкции.

## Предлагаемые элементы управления

Это проект следующего этапа, а не уже реализованные возможности.

| Элемент | Область и смысл | Как контролировать |
|---|---|---|
| Актуальный редактор, +1000 | Обоим помощникам перед каждым запросом | Снимок, номер файла и хеш; при изменении пересобрать вход |
| Авторское задание, +1000 | Последнее явное задание и принятые условия | Отдельный блок условий; предложения модели не становятся условиями без принятия |
| Источник обязателен, +1000 | Вопрос о факте книги или завершённого проекта | Программа выполняет чтение; нет результата — не выдавать непроверенный ответ как установленный факт |
| Источник запрещён, −1000 | Явно ограниченная работа только с редактором | Не предоставлять на этом этапе инструменты чтения иных источников |
| Разделение источников, +1000 | Первоисточник / завершённый проект / черновик / предположение | Маркировать каждый фрагмент; авторские изменения не объявлять оригинальным каноном |
| Граница задания, +1000 | Ответить / посоветовать / критиковать / написать | Отдельный режим шага и доступные действия; семантическое соблюдение требует проверки |
| Право записи, −1000 по умолчанию | Модель предлагает, пользователь принимает | Инструмент записи недоступен; изменение файла через явное действие пользователя |
| Обязательный бюджет, +1000 | Входные материалы и резерв ответа | Считать токены до запроса; не вытеснять обязательное молча |
| Приоритет подборки, 700–999 | Писателю ближе проект; Советнику — также канон и история | Небольшая разница в ранжировании релевантных материалов; не выдавать нерелевантное лишь из-за высокого веса |
| Дополнительный поиск, 400–699 | Только если есть конкретный незакрытый вопрос | Условие запуска и ограничение количества проходов |
| Стилевые пожелания, 1–399 | Мягкие предпочтения | Короткая инструкция, без обещания программной гарантии |
| Проверка ответа | Точность фактов, отсутствие самовольного продолжения | Ссылки на выдержки, простые проверки формы; отдельная смысловая проверка и решение пользователя |

У каждого элемента нужны тип, этап действия, источник требования, область текста и способ проверки. Противоречащие +1000/−1000 выявлять как конфликт, не усреднять. Промежуточные числа 400/700/850 пока не откалиброваны: проверялась прежде всего обязательность +1000/−1000. Автоматически повторять неудачный ответ бесконечно нельзя; ограниченное число попыток с сохранением исходного результата и причины.

## Воспроизведение

Запускать в свободное от работы приложения время, с установленными моделями и свежей папкой результата:

```powershell
dotnet run --project 'Тесты/LiteraryPriorities/Probe.csproj' -- '<новая папка стенда>' '<папка проекта>'
```

`--resume` продолжает отсутствующие файлы результатов, сохраняя уже записанные ошибки. `--staged --focused` проверяет отдельно финальные инструкции на вопросе о развязке и продолжении у трёх усиленных вариантов. Смена системных промптов приложения, скачивание весов, публикация или запись в исходный проект не выполняются. Девять файлов глав, материалов и индекса совпали по SHA256 с копией после первой серии.
