## 1. Цель и исходное состояние

Подключить рабочую «Альфу» вместо заглушки к существующему сценарию анализа одного изображения.
«Альфа», «Бета» и «Гамма» в целевом виде являются одним сценарием с разными моделями.
Готовая «Гамма» — функциональный образец. По уточнению пользователя «Бета» рабочая; её не приняли по неоправданному потреблению памяти. Существующую схему Беты (визуальный черновик → русскоязычный редактор на ядре) сохранить как резерв при подтверждённой языковой проблеме. Автоматически добавлять вторую модель в Альфу сейчас не требуется.
Не создавать отдельный пользовательский сценарий, редактор промптов, библиотеку работ, плеер или собственный загрузчик для «Альфы».

Главный критерий выбора конфигурации «Альфы» — младшие игровые ПК уровня RTX 3060–3070 / 4060–4070.
Целевая конфигурация: 16 ГБ RAM и 8 ГБ VRAM. Название серии само по себе не гарантирует достаточность памяти.
Потребление всего комплекта должно оставлять запас для Windows и обычного фона; численный запас и честные рекомендации определить по замерам.
Ровно 8 ГБ занятых моделью нельзя считать подтверждением пригодности для видеокарты с 8 ГБ.

## 3. Общий сценарий и границы адаптера

Сохранить последовательность и возможности готовой «Гаммы»:

1. Выбор одного изображения, проверка и предпросмотр выбранного файла.
2. Настройки описания, отдельное окно пожеланий, стандартные и кастомные промпты.
3. Первый запрос — анализ изображения; второй — описание на основании анализа с сохранением необходимого контекста изображения и первого обмена.
4. Краткое описание, полный предпросмотр, версии и последующая редактура, экспорт DOCX.
5. Сохранённые работы, восстановление состояния, диагностика и существующее отображение активности.
6. Озвучивание Выкл / ИИ / ПК, одноразовое автовоспроизведение, Play/Pause, экспорт ИИ-аудио и срок хранения до конца сессии/закрытия программы.

Повторно использовать общие UI, session store, парсинг результата, prompt store, редактор, менеджер и аудиомеханику.
Различия запуска runtime, формата multimodal-запроса и параметров модели вынести в небольшой адаптер/провайдер.
Не копировать большой Heavy pipeline целиком ради замены транспорта и не превращать MainWindow в новый монолит.
Расширять проверки возможностей режима вместо добавления разрозненных условий только по ID heavy.
Сохранить идентификатор «Альфы» light; старые работы «Беты»/«Гаммы» должны открываться как прежде.
Сохранять происхождение новой работы: режим, модель, квантование, ревизию, runtime и параметры; не переопределять исполнителя старой работы молча.
Для общей библиотеки промптов подтвердить совместимость действующего контракта пары; пользовательский текст не терять и не заменять скрыто стандартным.
В кастомном режиме четыре стандартные настройки остаются неактивными; пожелания, язык и служебный формат применяются по существующим правилам.
Модели SmolVLM2, Florence и отдельное ядро Qwen3 из старой заглушки не должны требоваться или прогреваться для нового двухэтапного варианта «Альфы».
Уже скачанные компоненты других сценариев не удалять автоматически.

## 4. Штатное скачивание — обязательное требование

Модель скачивает сам пользователь стандартной кнопкой программы после реализации подключения.
Codex не скачивает веса или проектор через CLI, браузер, отдельный скрипт либо автоматически при подготовке ТЗ/реализации.
Открытие карточки само по себе не начинает скачивание.

Подключить оба файла к существующим ManagedModelCatalog / ImageAnalysisBundleInstallationService / ManagedModelAcquisitionService / SegmentedModelFileDownloader.
Для всех добавляемых загрузок компонентов использовать общий механизм и его многопоточность; не создавать обходные последовательные загрузки.
Учитывать общую настройку MaximumParallelConnections: авто либо выбранные пользователем 1/2/4/8 соединений.
Для достаточно крупных файлов и сервера с Range фактически выполнять параллельную загрузку сегментов. Проверять это, а не только наличие настройки в UI.
Сохранять штатный fallback для небольших файлов, выбора одного соединения или отсутствия поддержки Range; это техническое ограничение, а не отдельный загрузчик режима.
Сохранить прогресс, скорость, отмену/приостановку, возобновление после повторного запуска, проверку целостности и понятную обработку ошибок.
Файлы размещать в выбранном хранилище моделей, учитывать лимит и временные сегменты. Статус «готово» возможен только при наличии и проверке всей обязательной пары и совместимого runtime.
Удаление через существующее подтверждение не должно затрагивать чужие/общие файлы без штатной проверки использования.

## 10. Реализация 2026-09-06

Вместо заглушки подключены Qwen2.5-Omni-3B Q4_K_M и Q8 projector из ggml-org/Qwen2.5-Omni-3B-GGUF; закреплены ревизия, размеры и SHA-256 двух файлов (суммарно 3 642 962 976 байт).
Alpha использует существующий общий двухэтапный pipeline через IOmniTextRuntime и отдельный адаптер штатного llama.cpp b9442. Гамма сохраняет BF16-runtime, Бета — прежнюю реализацию.
Сохранены общие custom-пары, точная передача первого обмена во второй запрос и редактуру, checkpoint, сырые ответы, версии, экспорт и плеер Kokoro CPU. Работы Alpha имеют собственный pipeline/model/runtime ID и профиль озвучки.
