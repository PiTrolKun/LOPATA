# Музыка U2 — проверки 0.4.9-dev / 0.4.10-dev

08.10.2026. [Принятое ТЗ](../../ТЗ/Архив/2026-10-07_Музыка_U2_Форматы_и_метаданные.md).
Реализация принята пользователем и ТЗ архивировано. По прямой команде
«Пока без публикации» commit/push, GitHub Release и файловое обновление
не выполнялись. Итоговая рабочая версия 0.4.10-dev, публичная — 0.4.8-beta.
Ниже сохранены этапы проверок и их границы; новых тестов при закрытии не запускали.

## Подтверждённое

- Opus/MP3 160, 192, 256, 320 кбит/с; MP3 CBR подтверждён ffprobe,
  Opus VBR использует целевой средний битрейт. FLAC/WAV возвращают точные
  исходные PCM16 stereo 48 kHz сэмплы. Оба файла кодируются непосредственно из PCM.
- Все теги сравниваются по ключам и значениям до публикации файла. Проверены
  кириллица, combining acute accent, CRLF/LF/CR, обратная косая черта и = ; #.
  Исполнитель/название/комментарий отделены от Style/Lyrics и имени автофайла.
  Снимок содержит фактические seed, параметры, пожелания и доступное provenance.
- Один дополнительный файл исключает основной формат, остаётся в одной карточке.
  Предпочтения формата сохраняются атомарно; недопустимые значения блокируются.
- При сбое дубля и отмене кодирования исходный PCM сохранён. Продолжение
  не вызывает модель повторно; готовые файлы принимаются по сохранённым хешам.
  Подмена готового результата обнаруживается. Старые WAV-only задания совместимы.
- Opus воспроизводится через свой CPU-декодировщик без системного codec pack.
  Проверены готовность без автозапуска, перемотка, смена источника и его сохранность.
- RU/EN, тёмная/светлая темы, узкие панели. Общий прогон обнаружил две регрессии:
  отсутствовавшие переводы тегов облака и уменьшение круга в узком окне.
  Обе исправлены, затем весь набор выполнен повторно.

## Проверка пользовательских результатов, 08.10.2026

Визуальная часть принята пользователем. Все четыре завершённых Opus одного
реального задания проверены собственной поставкой FFprobe 8.1 (только чтение).
Хеш каждого файла совпадает с ResultHash checkpoint. Слова (654 символа) полностью
совпадают с Lyrics checkpoint и lyrics фактического запроса. Style, оба seeds,
название/исполнитель/комментарий, исходная дата и запрошенная длительность совпадают.
Все записанные поля sampling, steps, cfg_scale, peak_clip и cot_mode сопоставлены
с фактическими JSON synthesis requests без расхождений. Проверка подтверждает
записанные входы; не доказывает качество или точность пения.

В существующем файле тег lyrics присутствует, но Shell.Application.ExtendedProperty
для System.Music.Lyrics возвращает пустоту на этом ПК. Title, Artist, Comment
при этом доступны. Это ограничение видимости данного обработчика Opus, не потеря
метаданных. Произвольные LOPATA_* в стандартном списке свойств не отображаются.

Microsoft определяет разные свойства [System.Music.Lyrics](https://learn.microsoft.com/en-us/windows/win32/properties/props-system-music-lyrics)
и [System.Media.SubTitle](https://learn.microsoft.com/en-us/windows/win32/properties/props-system-media-subtitle).
[ID3v2.4](https://id3.org/id3v2.4.0-frames) также отделяет TIT3 (подзаголовок / уточнение
названия) от USLT (слова без временных меток) и SYLT (синхронизированный текст).
Временные метки модель не передаёт. Наличие исходных Lyrics не означает
подтверждённую расшифровку аудио.

Приватный отчёт с извлечёнными словами и параметрами и воспроизводимый скрипт:
_tmp/music-u2/user-song-metadata-check.md, check-user-metadata.ps1,
user-song-metadata-check.json. Пользовательские входы не скопированы в этот
публичный протокол. Приложение, аудио и checkpoint не изменены; новая генерация,
перезапуск, commit/push, архивирование, сборка установщика и публикация отсутствуют.
