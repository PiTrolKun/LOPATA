# GigaAM v3 CTC — комплект синхронизации музыкального сценария

Проверено 14.10.2026. Общий комплект подготовки для всех шести подключённых музыкальных вариаций: YuE2 Q8, YuE2 BF16, YuE2 Studio Q8, ACE-Step XL Turbo, DiffRhythm 2 и HeartMuLa. Он не меняет лицензии самих музыкальных генераторов.

Используются оригинальный GigaAM и веса `v3_ctc`, MIT, GigaChat Team. Закреплённый исходный код: [salute-developers/GigaAM, 7447938d791c4f3e643386ee22c33777004293a5](https://github.com/salute-developers/GigaAM/tree/7447938d791c4f3e643386ee22c33777004293a5). Веса загружаются с официального CDN: [v3_ctc.ckpt](https://cdn.chatwm.opensmodel.sberdevices.ru/GigaAM/v3_ctc.ckpt), 441 714 678 байт, SHA-256 `a20a9b5b8ed929c4a60141753cd3dd1284138879a46fb4a1cef6430ec019a02f`.

Python, PyTorch CPU и их зависимости переиспользуются из неизменяемого штатного `runtime.python.cpu`; его отдельные лицензии и подтверждения остаются действующими. Исходный профиль не дополняется через pip. Оригинальные архивы распаковываются отдельно, подключаются только к процессу выравнивания. ANTLR устанавливается из исходного tar.gz с каталогом `src`, остальные дополнительные библиотеки — из официальных wheel-файлов для CPython 3.12 Windows x64. Перед запуском проверяются SHA-256 каждого установленного файла и весов.

Точные HTTPS-адреса, версии, размеры, SHA-256 архивов и полный перечень файлов после распаковки находятся в `Исходники/AIHub/Tools/music-lyrics-components.json`. `MusicLyricsComponentCatalog` является общим источником подготовки, зависимостей и семантических паспортов. Все варианты `MusicModelVariants.Components` включают полный набор применимых лицензий. Число карточек весов каждого генератора не меняется.

Оригинальные LICENSE/COPYING/NOTICE сохранены в `Исходники/AIHub/Licenses/texts/gigaam-*`; записи добавлены штатным `prepare-license-catalog.ps1 -AppendEntries`, без изменения Terms ранее существовавших компонентов. ANTLR LICENSE дополнен из официального тега 4.9.3, SentencePiece LICENSE и protobuf-lite LICENSE — из официального тега v0.2.1.

SoundFile использует отдельную динамическую DLL libsndfile. Оригинальные условия LGPL включены. Соответствующие исходники доступны у поставщиков: [libsndfile 1.2.2](https://github.com/libsndfile/libsndfile/tree/1.2.2), [SoundFile 0.13.1](https://github.com/bastibe/python-soundfile/tree/0.13.1). Это компонент стороннего поставщика, а не библиотека, скомпилированная ЛОПАТОЙ; оригинальные бинарные пакеты не перепакованы и код библиотек не изменён. Ограничения LGPL, включая права на изменение библиотеки, сохраняются.

По последнему решению пользователя сначала выбирается совместимый подготовленный GPU-профиль, CPU служит резервом и работает без NVIDIA. Используется штатный managed auto-выбор и полный контроль целостности профиля. Аудиобиблиотека torchaudio закреплена на 2.10.0: совместимые профили CUDA 12.6/12.8 и XPU имеют PyTorch 2.10.0; текущий ROCm-профиль 2.9.1 имеет другую ABI и пока использует CPU-резерв. Физически проверены CPU и CUDA 12.6; XPU, CUDA 12.8 и другое оборудование не объявляются испытанными. Новые согласия для GPU проходят штатные лицензии профиля, без новых ручных галочек.

Целая песня длиной 178,6 с проверена на CPU и CUDA: обе ветки нашли 34/34 строки с одинаковыми границами. Измеренное время самого исполнителя — 13,31 с на CPU и 8,14 с на GPU; пиковое выделение PyTorch на GPU — 490 584 576 байт. Полная подготовка, проверки файлов и запуск окружения не входят в эти времена. Эти измерения не доказывают слуховую точность ±0,5 с для каждой строки. Модель v3 CTC предназначена для русского текста; английская синхронизация этой версией не заявляется. ONNX, VAD, RNNT, тренировки и Flash Attention не используются и не скачиваются.

Аудио обрабатывается локально. Новые архивы и модель должны проходить обычный загрузчик и окно ознакомления с лицензиями ЛОПАТЫ; исследовательские разрешения на загрузку не подменяют сохранённое подтверждение пользователя в приложении.
