# Концепция финансового сценария ЛОПАТА

**Статус:** идея на будущее. Не ТЗ и не утверждённая реализация.

## 1. Назначение

Отдельный сценарий ЛОПАТА, близкий по назначению к планировщику личных расходов / финансовому советнику.

Это не просто учёт расходов. Пользователь сначала собирает собственную картину регулярных расходов, затем получает точный программный расчёт и только после этого — многоэтапный анализ локальной LLM.

Сценарий должен находиться рядом с Песочницей.

## 2. Выбор модели

Первым шагом пользователь выбирает модель.

- Работать можно с любой установленной поддерживаемой моделью, умеющей работать с чатом.
- По умолчанию выбирается модель, отвечающая за ядро ЛОПАТА.
- Сценарий не привязывается к одной конкретной модели.

LLM отвечает за анализ и объяснение. Критическая арифметика выполняется программой.

## 3. Профиль пользователя

Если карточка пользователя уже заполнена, данные автоматически подставляются. Пользователь их подтверждает или исправляет.

Поля:

- имя;
- возраст;
- место проживания;
- статус.

Статус выбирается из фиксированного списка:

- школьник;
- студент;
- работающий;
- безработный;
- пенсионер/инвалид;
- в декрете.

Возраст позднее используется для адаптации подачи ИИ-анализа, а не для изменения расчётов.

## 4. Сбор расходов

Расходы задаются последовательно, **по одному вопросу**.

Каждый вопрос имеет пометку класса расхода.

Для каждого значения можно выбрать период расчёта:

- день;
- неделя;
- месяц.

Программа позднее нормализует значения для общего расчёта.

### Внешние источники

У каждого расхода есть отметка **«расход из внешнего источника»**.

Примеры:

- родители;
- друзья;
- руководство / работа;
- другой внешний источник.

Внешнее покрытие не считается автоматически доходом пользователя. Программа должна отдельно видеть общий расход, покрытие извне и фактическую нагрузку на пользователя.

### Обязательные расходы

- ЖКХ:
  - вода / газ;
  - электричество;
  - дополнительные;
- проживание;
- питание.

При необходимости — другие обязательные регулярные платежи.

### Связь

- телефон;
- интернет.

### Передвижение

- автобусы / общественный транспорт;
- такси;
- бензин;
- парковка;
- мойка.

Ремонт, ТО, страховка, налоги и другие нерегулярные автомобильные расходы сюда не включаются.

### Здоровье

- лекарства;
- контрацепция;
- спорт.

Регулярные линзы и аналогичные постоянные расходы можно учитывать здесь.

Разовые врачи, лечение, стоматология и т. п. не являются обязательной частью опроса.

### Подписки

- VPN;
- стриминги;
- банки / маркетплейсы;
- ИИ;
- другое.

### Удовольствия

Только регулярные расходы:

- никотин;
- алкоголь;
- газировка;
- энергетики;
- фастфуд;
- суши;
- пицца;
- рестораны;
- сладости;
- регулярные хобби / развлечения.

Разовые крупные покупки сюда не относятся.

### Личная гигиена и уход

Отдельная постоянная категория:

- личная гигиена;
- косметика;
- парфюмерия;
- парикмахерская / барбершоп;
- другой регулярный уход.

### Животные

- корм;
- наполнитель;
- регулярный уход;
- другие постоянные расходы на животных.

Разовые ветеринарные расходы не являются обязательным регулярным вопросом.

### Образование

Регулярные расходы:

- платное обучение;
- курсы;
- репетитор;
- регулярные образовательные сервисы;
- другие регулярные платежи за обучение.

Годовые и разовые платежи не являются обязательной частью этого сценария.

### Постоянные расходы на близких

Название категории:

**«Постоянные расходы на близких»**

Примеры:

- постоянная помощь родителям;
- содержание ребёнка;
- регулярные переводы родственнику;
- постоянная оплата чего-либо за другого близкого человека.

Разовые подарки сюда не относятся.

### Дополнительные расходы

Отдельный класс для **стабильных, но очень вторичных расходов**, не попавших в основные категории.

## 5. Сознательные границы

Сценарий рассматривает прежде всего **регулярную финансовую жизнь**, а не полное годовое финансовое планирование.

Поэтому не требуется специально собирать:

- одежду и обувь;
- крупные покупки;
- ремонт техники;
- ремонт автомобиля;
- разовое лечение;
- стоматологию;
- разовые подарки;
- отпуск;
- путешествия;
- годовые страховки;
- годовые налоги;
- другие разовые или планируемые на год расходы.

Это не забытые категории, а сознательная граница сценария.

Планы на год и крупные будущие расходы относятся к другой возможной задаче.

## 6. Доход — только после расходов

После завершения сбора расходов задаются:

- стабильный доход;
- дополнительный регулярный доход.

Это принципиальная часть методики.

Если спросить доход в начале, он может стать психологическим якорем: пользователь может бессознательно подгонять под него оценки расходов, занижать траты или забывать то, что кажется «неподходящим».

Сначала пользователь отвечает:

> «Сколько я реально трачу?»

И только потом:

> «Сколько у меня денег?»

Пользователю не требуется объяснять эту психологическую механику.

## 7. Программный расчёт

После опроса открывается рабочее окно, где одновременно доступны:

- программный расчёт;
- ИИ-анализ.

Программа самостоятельно рассчитывает:

- стабильные доходы;
- дополнительные регулярные доходы;
- общие регулярные расходы;
- расходы пользователя;
- внешнее покрытие;
- остаток;
- доли категорий;
- значения за выбранный период;
- другие детерминированные показатели.

**Программный расчёт является источником истины для арифметики.**

LLM получает уже подготовленные структурированные данные и не заменяет расчётную часть.

## 8. ИИ-анализ

ИИ-анализ строится не одним огромным запросом, а последовательностью специализированных аналитических вопросов.

Базовая схема:

**исходные данные → аналитический вопрос → ответ → сохранение → очистка рабочего контекста прошлого ответа → следующий вопрос.**

Каждый вопрос смотрит на финансовую картину со своей стороны.

Модель не должна постепенно «залипать» на собственных предыдущих рассуждениях. Каждый этап получает исходные структурированные данные и необходимые результаты предыдущих этапов в компактном виде, но не длинную историю собственного рассуждения.

### Направления анализа

Точный набор вопросов ещё требует проектирования, но логика должна охватывать разные стороны расходов:

1. общая картина;
2. обязательные расходы;
3. повседневные расходы;
4. подписки и регулярные сервисы;
5. передвижение;
6. здоровье;
7. удовольствия;
8. личные расходы;
9. животные;
10. образование;
11. постоянные расходы на близких;
12. внешнее финансирование;
13. крупнейшие доли регулярных расходов;
14. возможные пропуски исходных данных;
15. потенциальные точки экономии;
16. устойчивость структуры расходов;
17. соотношение стабильного дохода и регулярных расходов;
18. другие специализированные вопросы, определённые при дальнейшем проектировании.

Это пока не утверждённый список запросов. Главный принцип — **набор независимых взглядов на одни и те же данные**.

## 9. Многоуровневая выдача

Результат идёт от простого к профессиональному.

### Уровень 1 — понятный человеку

Краткий анализ без обязательного знания финансовой терминологии.

Например:

> Ваши регулярные расходы составляют X в месяц. После них остаётся Y. Больше всего денег уходит на Z.

Стиль адаптируется под возраст пользователя.

### Уровень 2 — практический

- структура расходов;
- основные нагрузки;
- доли категорий;
- влияние внешнего финансирования;
- заметные особенности;
- потенциальные места для внимания.

### Уровень 3 — профессиональный

Можно использовать нормальную финансовую терминологию и показатели:

- доля обязательных расходов;
- доля дискреционных расходов;
- отношение стабильного дохода к регулярным расходам;
- концентрация расходов;
- запас относительно регулярных расходов;
- другие профессиональные показатели.

Термины при необходимости сопровождаются объяснением.

### Уровень 4 — бухгалтерский / финансовый финал

Полноценный профессиональный итоговый документ.

Его можно:

- сохранить в файл;
- скопировать в буфер обмена.

## 10. Адаптация под возраст

Возраст пользователя используется для первых уровней объяснения.

Принцип:

- подростку — простой язык и минимум жаргона;
- взрослому — естественный взрослый язык;
- старшему пользователю — понятная формулировка без ненужного жаргона.

При этом исходные данные, расчёты и аналитические выводы не меняются.

Меняется только форма объяснения.

Профессиональный и бухгалтерский финал остаются профессиональными независимо от возраста.

## 11. Итоговый эксперт

После завершения отдельных аналитических запросов запускается отдельный финальный запрос.

Он получает:

- исходные данные пользователя;
- структурированные расходы;
- доходы;
- программные расчёты;
- результаты всех специализированных аналитических этапов.

Его задача:

- свести результаты;
- обнаружить противоречия между аналитическими блоками;
- сформировать связный итог;
- выдать профессиональный финальный анализ.

Архитектурно:

**много специализированных аналитических вопросов → один итоговый эксперт.**

Промежуточные результаты желательно сохранять отдельно, даже если пользователю необязательно видеть всю внутреннюю историю анализа.

## 12. Устойчивость анализа

Каждый аналитический этап должен быть самостоятельным.

Если анализ остановлен на одном из вопросов, завершённые этапы не запускаются заново.

Это позволит:

- повторить только проблемный этап;
- заменить одну аналитическую модель;
- сравнить ответы разных моделей;
- позднее переработать отдельный аналитический вопрос без перестройки всего анализа.

## 13. Главный принцип

Сценарий работает в следующем порядке:

1. пользователь описывает, как он реально живёт финансово;
2. программа показывает сухую арифметику;
3. несколько независимых взглядов ИИ помогают понять картину;
4. итоговый эксперт сводит результаты.

ИИ не заменяет расчёт.

ИИ является **аналитическим и объясняющим слоем поверх детерминированного программного расчёта**.

## 14. Текущий статус

Уже определены:

- место сценария рядом с Песочницей;
- выбор установленной поддерживаемой чат-модели;
- модель ядра по умолчанию;
- использование профиля пользователя;
- основные регулярные категории расходов;
- внешние источники покрытия;
- сбор дохода после расходов;
- программный расчёт;
- последовательный ИИ-анализ;
- очистка рабочего контекста между аналитическими вопросами;
- многоуровневая выдача;
- адаптация первых уровней под возраст;
- профессиональный финальный отчёт;
- сохранение финала в файл или буфер.

Пока не определены окончательно:

- точный набор аналитических вопросов;
- их формулировки;
- полный набор профессиональных показателей;
- точный формат итогового отчёта;
- формат файла;
- детали UI аналитической части.

Эти пункты требуют отдельного проектирования.

## Ключевая идея

> **Сначала человек рассказывает программе, как он реально живёт финансово.  
> Потом программа показывает ему сухую арифметику.  
> И только после этого несколько независимых взглядов ИИ помогают понять, что всё это означает.**
