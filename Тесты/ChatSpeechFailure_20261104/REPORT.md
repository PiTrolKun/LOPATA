Общее ТЗ «Если накипело» остаётся активно; публикация/установщик не выполнялись.

## Подтверждённая цепочка

Silero 5.6, kseniya, auto → CUDA cu126. В 00:22:18 по местному времени
запущен Python PID 29584; в 00:22:32 зарегистрирован IOException, затем выход
-1073741819 (0xC0000005). Windows Application 1000 подтверждает тот же процесс
и access violation; сбойный модуль unknown. Старый worker.log содержал только
SyntaxWarning. Общий scheduler оставил speech в Waiting/RequiresDecision.
Следующая попытка ждала BlocksNewWork без конца. Предложение аудита было
реакцией на неизвестный сбой, а не обязательным условием чтения.

## Исправление

- Отказ фактического синтеза терминальный для своей операции, без автоматического
  повторения. Исходное исключение сохраняется как InnerException, общая политика
  ComponentAudit остаётся. Готовые части доступны для явной новой попытки.
- Устраняется старое Waiting только для своего валидного IO-отказа с совпадающими
  ID/диалогом. Явные паузы, прерывания без записанного отказа и чужие задания не трогаются.
- При чужой задаче, ожидающей решения, возвращается статус занятости вместо
  бесконечной подготовки. Вход в чат больше не блокируется старым отказом TTS.
- Нативная диагностика: faulthandler, PID/exit/device/profile. Отдельные события
  MediaOpened/MediaEnded/MediaFailed без содержимого сообщений.
- Завершённые приватные задания, как прежде, не остаются в постоянном реестре.
  Оригиналы в библиотеке чатов и кеш WAV сохраняются; checkpoint доступен в текущем
  сеансе, успешные части повторно определяются по WAV/receipt после перезапуска.
