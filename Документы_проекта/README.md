Ядро `Песочницы` не решает вопрос пользователя и не проводит подробное предметное интервью. Оно строит профиль возможностей и сравнивает ровно двух подтверждённых координаторов из доверенного пула программы: уже установленную runnable-модель и отдельную модель другого семейства, требующую загрузки. Ядро выбирает короткие ID и объясняет преимущества и ограничения, не переписывая статусы, семейства и характеристики моделей. Пользователь сам выбирает вариант, после чего программа разрешает его в конкретный GGUF и только с подтверждением может скачать, проверить и запустить. Исполнитель получает handoff с происхождением данных, сам сужает предметную задачу несколькими кнопочными шагами, использует разрешённые инструменты и возвращает результат в той же вкладке.

С 22 августа 2026 года `Песочница` считается условно готовой альфа-версией. Она сохраняется как рабочий интеграционный полигон и демонстрация общей архитектуры, но не считается эталоном предметной точности. Известные ограничения допускают неполные результаты, ошибки профильных моделей и несовпадение технической успешности с фактическим качеством ответа. Дальнейшая полировка сценария отложена до предрелизного состояния всего ЛОПАТА, когда появятся эталонные профильные сценарии и их контрольные наборы.

Каталог Hugging Face остаётся отдельным хранилищем и сервисом. На финальной границе сценария программа обращается к нему напрямую, формирует до шести подходящих карточек и при нехватке локальных данных сама использует живой Hugging Face fallback. Ядро не управляет модельным поиском и получает только компактный доверенный пул. Выдача учитывает metadata lineage и программную оценку совместимости с RAM/VRAM/диском. Каталог обновляется в фоне не чаще раза в 24 часа; полная база в prompt не загружается.

## Версия первого полноценного сценария

Сценарий `Анализ изображений` открывает ветку `0.1.0-dev`. Средняя цифра
версии `0.X.Y` повышается при создании каждого нового полноценного
пользовательского сценария; младшая цифра после этого используется для его
последующих исправлений и небольших улучшений. Единственным источником номера
остаётся корневой файл `VERSION`.

В `0.1.1-dev` завершён и принят пользователем первый полноценный подсценарий
`Литературное описание одного изображения`. Он последовательно использует
внутренний визуальный отчёт Kimi и ядро Qwen3, отделяет полный текст от короткой
контрольной сводки, сохраняет версии и историю, поддерживает предпросмотр,
DOCX и добровольную внутреннюю копию. Рабочий экран принят без общей
прокрутки: слева находится дерево программных событий, в центре действия,
справа — быстрая смысловая проверка. Дополнительные эталонные тесты и небольшая
полировка точности будут самостоятельными следующими задачами; активных ТЗ нет.

В `0.1.2-dev` начата отдельная диагностика точности визуального аналитика.
Kimi получил простой prompt без лимита ответа и отдельный runtime-контракт.
Тесты показали естественное завершение генерации, но грубое искажение даже
очевидного портрета; увеличение визуального бюджета не помогло. Подробный
протокол находится в `ТЕСТ_KIMI_VL_2026-08-25.md`. Следующая развилка —
сравнение с оригинальным Transformers или vLLM runtime; активного ТЗ для этой
диагностики пока нет.

В `0.1.3-dev` подтверждённый `chatllm.cpp v24` интегрирован как отдельный
визуальный backend Среднего комплекта. Kimi теперь использует GGMM Q4_1 и
CPU-профиль собственного loopback-сервера; reasoning очищается до передачи
наблюдений ядру. Прежний GGUF/mmproj-артефакт и общий `llama.cpp` сохранены для
  отката. Продуктовый API-контроль и пользовательская сквозная проверка
  интерфейса завершены успешно; ТЗ принято 25 августа 2026 года.

В `0.1.4-dev` после русского и английского A/B-контроля внедрён новый prompt
ядра. Ядро выступает опытным литературным редактором издательства и получает
ясную цель — подготовить связное описание изображения. Название программы и
происхождение черновика из инструкций удалены, а язык результата передаётся
отдельным параметром из текущего языка интерфейса. Изображения с большим
количеством текста оставлены будущему отдельному OCR-подсценарию.

Пользовательский тест `0.1.4-dev` подтвердил корректную совместную работу
нового visual runtime и издательского prompt ядра. ТЗ закрыто и перенесено в
архив; по отдельной команде пользователя текущее состояние публикуется в
GitHub без пересборки установщика.

В `0.1.5-dev` открыт небольшой этап ускорения этого подсценария. После
подтверждения комплекта Kimi и Qwen3 начинают готовиться до нажатия кнопки
анализа. При достаточной RAM они загружаются параллельно, а безопасный профиль
готовит только Kimi и оставляет запуск ядра по требованию. Kimi освобождается
после визуального отчёта, ядро остаётся готовым для ручных уточнений.
Нижняя граница параллельной подготовки Среднего комплекта — 16 ГБ RAM. Крупные
изображения передаются visual-runtime через временную копию до 2048 px, чтобы
размер Base64-запроса не обрывал локальный поток; оригинал не изменяется.
Два сквозных теста приняты пользователем 25 августа 2026 года: ускорение
подтверждено, ТЗ закрыто и перенесено в архив. По прямому указанию публикация
пока не выполняется; установщик не пересобирался.

В ветке `0.1.6-dev`–`0.1.12-dev` реализован необязательный голосовой слой всего
сценария `Анализ изображений`: локальный Kokoro, программная читалка или
выключенное состояние, отдельные настройки, прогрев и синхронное раскрытие
сводки с началом речи. Пользователь подтвердил, что Kokoro жизнеспособна и
хорошо работает. ТЗ закрыто 28 августа 2026 года; реализация сохраняется как
Legacy и временный fallback. Она не назначается обязательным голосом будущего
Среднего комплекта из-за расхода памяти.

В `0.1.14-dev` собран отдельный тестовый Heavy-контур на Qwen2.5-Omni:
полная Thinker+Talker-модель, фиксированное размещение, двухходовый скрытый чат, встроенная
речь с двумя официальными спикерами и тестовая диагностика. Веса не входят в
программу и скачиваются ЛОПАТА только после явной команды. Реальная Windows/CUDA-
среда установлена и совместима с новым классом модели. Сквозная приёмка
скачивания, прогрева, зрения, времени ответа и речи Qwen2.5 ещё не выполнена;
Legacy Среднего режима не заменён и не удалён.

В `0.1.19-dev` после первого успешного сквозного теста Heavy оптимизирован по
официальному разделению Qwen2.5-Omni. Анализ и литературный скрытый чат теперь
держат только `Qwen2_5OmniThinkerForConditionalGeneration`; полный Omni с
Talker загружается по явному запросу речи и не сосуществует с Thinker-only.
Размещение получает 90% фактически свободной VRAM с резервом не менее 1 GiB,
а журнал отдельно показывает смену профиля, preprocessing, первый токен,
генерацию, tok/s, attention backend и device map. Средний режим не изменён;
скорость нового профиля должна быть подтверждена пользовательским тестом.

В `0.1.20-dev` после неудачного 37-минутного теста частично выгруженного на CPU
7B Heavy переключён на `Qwen2.5-Omni-3B` BF16. Для него гибрид запрещён:
программа требует не менее 14 GiB рассчитанного GPU-бюджета и после загрузки
проверяет, что каждый модуль реально находится на CUDA. Средний режим не менялся.
