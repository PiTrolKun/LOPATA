# Идея: сценарий создания речевых ассетов для ЛОПАТЫ

## 1. Общая идея

После завершения литературного сценария добавить в ЛОПАТУ отдельный сценарий для создания заранее подготовленных речевых ассетов.

Главная практическая цель — использовать саму ЛОПАТУ для генерации собственных голосовых уведомлений и других коротких реплик интерфейса.

Сценарий при этом не должен быть одноразовой внутренней утилитой: его можно оформить как полноценный пользовательский модуль для генерации локальных речевых ассетов для игр, модов, роликов, презентаций, локальных ассистентов и других проектов.

Ключевая идея:

**ЛОПАТА создаёт ассеты для самой ЛОПАТЫ.**

## 2. Почему заранее подготовленные голосовые уведомления выгодны

Если уведомления генерировать заранее и хранить как обычные WAV/OGG-файлы, то у конечного пользователя:

- не требуется загружать TTS-модель для воспроизведения уведомлений;
- нет расхода VRAM и RAM в момент события;
- нет задержки генерации;
- нет зависимости от текущей загруженной LLM;
- проигрывание сводится к обычному воспроизведению аудиофайла;
- можно использовать тяжёлую и медленную модель при подготовке ассетов, не заботясь о runtime-скорости.

Это открывает возможность делать уведомления более разговорными и разнообразными, не увеличивая вычислительную нагрузку на пользователя.

Для одного события можно подготовить несколько вариантов реплики и выбирать их случайно.

Пример — сохранение проекта:

- «Проект сохранён.»
- «Готово, изменения записаны.»
- «Сохранила. Можно продолжать.»

## 3. Главный критерий качества

Для этой задачи важнее не максимальная похожесть на живого человека, а:

1. правильное русское произношение;
2. корректные ударения;
3. отсутствие случайных лишних пауз;
4. хорошая пунктуационная дисциплина;
5. ровное чтение коротких интерфейсных фраз;
6. стабильность между дублями;
7. качественная дикция;
8. управляемая, намеренно заметная искусственность голоса.

Цель — не голос уровня «Алисы» или «Алексы» и не клонирование реального человека.

Желаемый эффект:

**качественный синтетический голос, который звучит достаточно чисто и естественно для комфортного восприятия, но остаётся очевидно искусственным.**

Это полезно и для UX: пользователь может воспринимать такой голос как локальную генерацию в реальном времени, хотя фактически реплика заранее подготовлена.

## 4. Что показал текущий генератор

Текущий локальный генератор уже способен выдавать неплохой голос, но качество чтения оценивается примерно на «3»:

- иногда неправильные ударения;
- иногда появляются лишние паузы;
- фразировка не всегда удачная.

Следовательно, новая модель должна оцениваться не только по красоте тембра, но в первую очередь по надёжности русского чтения.

## 5. Основной кандидат: Qwen3-TTS VoiceDesign

На текущем этапе основной кандидат для первого теста:

**Qwen3-TTS VoiceDesign**

Почему:

- поддерживает русский язык;
- позволяет создавать голос по текстовому описанию;
- не требует клонирования реального человека;
- хорошо подходит для намеренно синтетического интерфейсного голоса;
- позволяет управлять стилем, тембром и подачей;
- Apache 2.0;
- на RTX 4090 24 GB должна запускаться без проблем;
- скорость в данном сценарии почти не важна, потому что ассеты создаются заранее.

Пример желаемого описания голоса:

> Спокойный синтетический голос. Чёткая русская дикция. Слегка цифровой тембр. Ровная подача. Минимум эмоциональных пауз. Без рекламной интонации, без излишней человечности и без дыхательных эффектов.

Qwen3-TTS VoiceDesign выбран не как окончательный победитель, а как **первый практический кандидат для проверки**.

## 6. Дополнительные модели-кандидаты

### Higgs TTS 3 4B

Интересна как тяжёлая современная модель с высоким потенциальным качеством, хорошей просодией и поддержкой русского.

Плюсы:

- крупная и современная;
- сильное качество речи;
- хорошая выразительность;
- может работать без клонирования голоса;
- RTX 4090 24 GB подходит для экспериментов.

Минус для данной задачи:

- высокая выразительность может быть даже лишней;
- необходимо отдельно следить, чтобы модель не добавляла театральные паузы и лишнюю эмоциональность.

Лицензия допускает некоммерческое использование. Для ЛОПАТЫ это приемлемо, так как сам проект останется некоммерческим.

### Fish Audio S2 Pro

Также сильный кандидат.

Плюсы:

- современная тяжёлая TTS-модель;
- сильное качество;
- поддержка русского;
- управление подачей и стилем;
- может генерировать без обязательного голосового референса.

Минусы:

- лицензия ориентирована на research/non-commercial использование;
- для ЛОПАТЫ это допустимо, но требует корректного документирования происхождения ассетов.

### VoxCPM2

Сильный свежий кандидат с хорошей лицензией.

Плюсы:

- русский язык;
- voice design;
- voice cloning при необходимости;
- Apache 2.0;
- современная модель;
- подходит для RTX 4090.

Можно использовать как альтернативу Qwen3-TTS, если она окажется лучше по русскому чтению.

### Chatterbox Multilingual V3

Ещё один кандидат для сравнения.

Плюсы:

- русский язык;
- разговорная подача;
- MIT;
- лёгкая локальная эксплуатация.

Интересен как проверка того, действительно ли тяжёлая модель нужна для данной задачи.

### CosyVoice3

Дополнительный вариант.

Плюсы:

- поддержка русского;
- управление эмоциями и скоростью;
- Apache 2.0;
- сильная мультиязычная TTS.

## 7. Лицензионная позиция

ЛОПАТА не планируется как коммерческий проект.

Допускаются сторонние ответвления и форки, но сам многоцелевой комбайн останется некоммерческим.

Следовательно, для собственных встроенных голосовых ассетов допустимо рассматривать модели с лицензиями:

- Apache 2.0;
- MIT;
- OpenRAIL;
- research/non-commercial, если условия явно допускают создание и распространение результата в некоммерческом проекте.

При этом желательно хранить информацию:

- какой моделью создан конкретный набор ассетов;
- версия модели;
- лицензия модели на момент генерации;
- дата генерации;
- используемый voice preset / описание голоса;
- при необходимости — ссылка на исходную модель.

Это позволит корректно оформить THIRD_PARTY_NOTICES и упростит будущие проверки.

## 8. Чего не делать

Не планируется:

- клонировать голос реального человека;
- имитировать известных актёров, дикторов или публичных персон;
- делать голос максимально человеческим;
- строить двухступенчатый pipeline из нескольких TTS-моделей;
- создавать сложную аудиостудию внутри ЛОПАТЫ.

Двухэтапная схема вроде «одна модель создаёт синтетический референс, другая его озвучивает» признана избыточной для задачи интерфейсных уведомлений.

Принцип:

**одна модель → один или несколько дублей → прослушивание → выбор лучшего → экспорт.**

## 9. Возможный интерфейс отдельного сценария

Минимальный сценарий создания речевых ассетов может включать:

- поле текста реплики;
- описание желаемого голоса;
- выбор сохранённого voice preset;
- параметры темпа / экспрессии, если модель их поддерживает;
- кнопку генерации;
- несколько дублей одной реплики;
- встроенное прослушивание;
- выбор лучшего дубля;
- переименование;
- экспорт WAV;
- экспорт OGG;
- пакетную генерацию списка реплик;
- сохранение набора как проекта.

Дополнительно:

- пресеты «системное уведомление»;
- «предупреждение»;
- «ошибка»;
- «завершение операции»;
- «разговорное уведомление»;
- «ироничная реплика».

## 10. Вариативные уведомления

Для одного события можно хранить несколько готовых файлов.

Пример структуры:

```text
notifications/
  project_saved/
    01.ogg
    02.ogg
    03.ogg
  calibration_done/
    01.ogg
    02.ogg
  model_error/
    01.ogg
```

Программа может случайно выбирать реплику или соблюдать простой алгоритм, чтобы одна и та же запись не повторялась подряд.

Это позволит сделать ЛОПАТУ более «болтливой» без нагрузки на оборудование пользователя.

## 11. Настройки болтливости

Идея на будущее — уровни голосовых уведомлений:

- **Выкл.**
- **Короткие** — только ключевые события.
- **Разговорные** — более длинные и разнообразные реплики.

При необходимости можно добавить отдельную регулировку громкости голосовых уведомлений.

## 12. Как тестировать TTS-модели

Для честного сравнения использовать один и тот же набор сложных русских фраз.

Проверять:

- ударения;
- пунктуацию;
- паузы;
- числа;
- сокращения;
- технические слова;
- имена;
- английские слова внутри русского текста;
- короткие фразы;
- длинные разговорные уведомления;
- стабильность между несколькими генерациями.

Для каждой модели желательно делать 5–10 дублей одной фразы.

В данном сценарии важен не средний результат модели, а возможность получить **один качественный финальный дубль**, так как генерация выполняется заранее.

## 13. Практический план

1. Завершить литературный сценарий.
2. Создать внутри ЛОПАТЫ отдельный TTS-сценарий.
3. Первой моделью проверить Qwen3-TTS VoiceDesign.
4. Создать небольшой тестовый набор русских реплик.
5. Проверить качество ударений, пауз, чтения и синтетического тембра.
6. При необходимости сравнить с Higgs TTS 3, Fish S2 Pro, VoxCPM2 и другими свежими кандидатами.
7. Выбрать один стабильный голос ЛОПАТЫ.
8. Создать набор системных уведомлений.
9. Использовать время ожидания восстановления лимитов Codex для генерации, прослушивания и отбора ассетов.
10. Позже превратить внутренний инструмент в полноценный пользовательский сценарий.

## 14. Итоговая концепция

Сценарий генерации речи имеет двойную ценность:

1. **внутренняя производственная функция** — создание собственных голосовых ассетов ЛОПАТЫ;
2. **новый пользовательский сценарий** — локальное создание речевых ассетов для сторонних задач.

Главная особенность подхода:

**максимально качественная генерация выполняется один раз на мощном ПК разработчика, а пользователь получает практически бесплатное по ресурсам воспроизведение готовых файлов.**

Для первого прототипа выбран:

**Qwen3-TTS VoiceDesign**

Основная эстетическая цель:

**узнаваемый, качественный, чисто читающий русский текст, намеренно искусственный голос ЛОПАТЫ.**
