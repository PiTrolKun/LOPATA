# Комбинированный стенд

Итоги и границы проверки — в `REPORT.md`. Данные синтетического фанфика — `fixture.json`; фрагменты первоисточника получены штатным RAG через `RagProbe` на копии проекта.

Из корня репозитория через `Runtime/Python/giga-embeddings/py312-torch210-transformers530/python.exe`:

1. `Тесты/JellyCombined/run.py Runeweaver --seconds 620 --series 3`
2. `Тесты/JellyCombined/followups.py Runeweaver`
3. `Тесты/JellyCombined/run.py VikhrNemo --seconds 450 --series 3`
4. `Тесты/JellyCombined/followups.py VikhrNemo`
5. `Тесты/JellyCombined/audit.py` — только чтение, можно повторять.

Первые четыре шага уже выполнены и отказываются перезаписывать результаты. Для повторного эксперимента использовать отдельную копию стендового кода рядом, с новой папкой runs/followups, сохранив исходную выдачу RAG. Генеративные модели запускаются последовательно. У каждой истории персонажей независимы; один сервер использует один слот. Проверка нескольких независимых слотов и сохранения KV-cache в этот опыт не входит.

Запросы и ответы сохраняются после каждого шага. Файл `002.txt` — редактор, `001.txt` — фиксированная история, `.lopata` — память стенда; чтение и исправления выполняются программой. `chats.json` сохраняет реальные диалоги серии.

Старый сбой завершения сервера первой серии Runeweaver описан в REPORT; не считать его потерей ответов. Новые запуски используют `runtime.py` с завершением через собственный процесс. Инструмент не запускает GUI приложения.
