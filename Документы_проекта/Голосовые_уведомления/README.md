# Голосовые уведомления: состояние и расширение набора

Текущая опорная точка — [неизменяемый слепок 10.11.2026, выпуск 0.7.73-beta](Слепки/2026-11-10_0.7.73/README.md). Это состав принятого набора, с которым нужно сверяться при следующем пополнении реплик. Подготовленные файлы и пользовательские настройки программа продолжает использовать своим обычным путём.

В наборе 1529 устойчивых clip ID, 5247 связей событий с репликами и 6394 шаблона сопоставления. На каждом из двух языков есть 1529 выбранных звуковых файлов. Русский голос — Silero v5.6 RU / xenia, английский — KittenTTS 2 / Iris; точные модели, ревизии, дубли и параметры находятся в манифестах. Слепок фиксирует поставку, а не личные настройки громкости/языка или все пользовательские проекты.

## Что открыть перед пополнением

В слепке есть `inventory.csv`: можно искать реплику по тексту и clip ID, видеть логический текст, исходную фразу, вариант для синтеза, звуковой файл, выбранный дубль и голос. `catalog.json` хранит все связи событий, групп и шаблонов. `origins.json` содержит относительные ссылки на исходный код и пометки первоначального отбора, в том числе резервные реплики. Номера строк относятся к исходной инвентаризации; для точного старого состояния использовать закреплённый коммит.

В `ru.manifest.json` и `en.manifest.json` сохранены точные манифесты принятых архивов, включая историю моделей, SynthesisText, TakeId и SHA-256 каждого файла. `snapshot.json` связывает всё это с выпуском и контрольными суммами. Два ZIP со звуками остаются в [Assets/VoiceNotifications](../../Исходники/AIHub/Assets/VoiceNotifications); их исходные байты доступны по закреплённому коммиту/тегу. Слепок не дублирует сами звуки.

## Произношение — отдельный слой

В русском архиве 157 записей имеют `SourceText != SynthesisText`; в английском — 0. По уточнению пользователя 10.11.2026, почти все русские правки связаны с тем, что выбранная модель не произносит латиницу и цифры так, как нужно. Например, `MP3` передано как `эМПэ три`. Сохранять эти варианты вместе с конкретным голосом и дублем.

`Texts.ru/en` — обычный смысловой текст, `SourceText` — исходная реплика проекта, `SynthesisText` — текст, который фактически отправлялся на синтез. Не переносить фонетические написания в интерфейс и локализацию, не заменять ими clip ID или event ID. Другой модели/голосу может требоваться другая подготовка: старые правки служат проверяемыми примерами, а не глобальным правилом замены букв и чисел. При новой генерации сохранить старые выбранные записи до проверки замены.

## Порядок следующего расширения

1. Прочитать этот документ и неизменяемый слепок. Сравнить текущие каталог, исходные события, RU/EN тексты и языковые пакеты с опорной точкой; выделить новые, изменённые и исчезнувшие элементы. Новый ID не должен означать уже имеющуюся реплику только из-за смены номера в списке.
2. Подготовить отдельный список добавлений/изменений: clip ID, event ID/aliases, смысловые тексты и группа 1/2/3. Сначала искать существующую подходящую реплику и её связи. Смысловые изменения требуют явного решения о совместимости; не перепривязывать старый ID к другому смыслу молча.
3. Отдельно перечислить недостающий звук по языкам, изменившиеся произносимые тексты и правки конкретной модели. Наличие строки в каталоге не означает наличие готового аудио. Отсутствующий язык или неподтверждённую запись не выдавать за завершённое покрытие.
4. Проверить прежние сопоставления, приоритеты, очередь, политику внутренних плееров, импорт локализации и ComponentAudit в затронутом объёме. Не перегенерировать весь старый набор ради добавления нескольких фраз. Не удалять прежние реплики, aliases и звуковые файлы без явного решения пользователя о замене/миграции.
5. После проверки и приёмки следующего набора создать новый датированный слепок, сохранить прежний и обновить ссылку «текущая опорная точка» в этом документе. Правила ведут на этот указатель; содержимое прежнего слепка не перезаписывать.

## Что слепок не доказывает

В каталоге есть резерв жизненного цикла моделей и автоматически выделенные кандидаты. Наличие clip ID/alias/template и готового звука не доказывает, что каждый соответствующий runtime-путь уже подключён и реально проигрывался. Слепок проверяет инвентарь, связь и байты файлов; это не сплошное прослушивание всех фраз и не тест каждого сценария. Приоритет хранится у события: 1 — ошибки/сбои, 2 — статусы, 3 — подробные события/логи. Личные настройки здесь не сохраняются.
