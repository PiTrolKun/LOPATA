# Автоматический бюджет литературного runtime — 15 сентября 2026

Версия 0.1.110-dev. Программные лимиты изменены по команде пользователя; промпты, семплирование, thinking и один абзац не менялись.

## Расчёт

При загрузке: llama.cpp b9442 `-c 0 --fit on`, один слот, GPU CUDA0, все слои (`-ngl 99`). Сам backend знает размеры весов, KV и вычислительных буферов и подбирает вместимость в пределах GGUF. Минимум подбора 1024 токена — нижняя граница работоспособного окна, не максимальный лимит модели.

До запуска сопоставляются физическая свободная VRAM из nvidia-smi и CUDA-инвентаризация того же backend. Поправка WDDM: `fit-target = max(0, cudaFree - physicalFree) + max(1 ГиБ, 10% min(cudaFree, physicalFree))`. Она не позволяет принять вытесняемую/shared память за свободную физическую VRAM. Если инвентаризация недоступна, запуск сообщает ошибку, а не выдумывает доступный объём.

Фактическое окно читается из `/slots`. Перед новой операцией проверяется свободная VRAM; при остатке менее 512 МиБ текущий процесс выгружается и выполняется новый подбор. Мелкие колебания не перезапускают модель. Если входу не хватает текущего окна, разрешён один повтор подбора между запросами. Переписка/редактор остаются в приложении, запрос пересобирается; во время генерации окно не меняется.

Перед отправкой точные сообщения проходят apply-template/tokenize с тем же режимом thinking. `max_tokens = фактическое окно − вход − 256`. Все оставшиеся токены доступны обдумыванию и финальному тексту; модель может закончить раньше. Если остаётся менее 256 токенов ответа, запрос явно отклоняется. Старые потолки 8192/16384 и 2048/3000/1024/1600/3072 больше не управляют генерацией в литературном runtime. Удалён отдельный предел рабочего текста 2500 токенов: проверяется весь пакет.

Применяется к старым чатам, F1, создателю, калибровке, служебному планированию чтения и основному архивариусу. Формат частей рукописи 7500 символов, якорей и порций индексации не менялся: это отдельные правила хранения. Индикаторы F1 и создателя показывают реальное окно загруженного runtime. Непринятый/частичный ответ не становится рукописью автоматически.

## Повтор ошибки пользователя

Сохранённый исходный запрос: 5152 токена входа, max_tokens 2048, thinking/medium. Остановился с `finish_reason=length`; видимый текст 845 символов, reasoning 7077 символов. Это не переполнение окна 16384.

Стенд `dotnet run --project Тесты/LiteraryAutoBudget/Probe.csproj` читает последнюю диагностику Советника, сохраняет копию исходного запроса и повторяет точные сообщения через код приложения в отдельном проекте. Пользовательский проект не изменяется.

Результат `runs/20260915_050049`: вход **5152**, автоматически выбранное окно **94464**, допустимый ответ **89056** токенов. Модель сама завершила ответ после **2983** токенов генерации; видимый текст **2561 символ**. Время 76.4 с включает проверку GGUF, подбор/загрузку и генерацию. Из диагностической выборки загруженного процесса: dedicated около 17.56 ГиБ, shared около 192 МиБ. Это замер RTX 4090 с текущим фоном, не гарантия такого окна на RTX 4080.

Другой запуск при иной доступности памяти выбрал **69632**, что подтверждает отсутствие фиксированного окна 16/32 тысяч. На полном окне 262144 нагрузка не проверялась. Изменение фона Windows после старта всё ещё может уменьшить запас; автоматика не резервирует видеопамять за пределами самого процесса.
