# Последовательная память пар — стенд ЛОПАТЫ

Исследование Codex, 03.11.2026. Gemma 4 26B A4B Instruct QAT UD-Q4_K_XL;
вымышленный корпус и отдельный живой разговор. Приложение не изменяется.

Порядок проверки: `prepare.py` → `replay.py` → `evaluate.py` → `live.py` →
`validate.py`. Первый prepare/replay уже создаёт состояние; повторять prepare
на существующем стенде нельзя. Replay умеет продолжать с последней сохранённой
пары; старые сводки при этом не перегенерируются. Прочие этапы запускаются один раз.
Для нового независимого опыта нужен отдельный каталог/база, не удаление этой истории.

Одна пара имеет адрес `01_work:P019`: беседа и постоянный порядковый номер пары.
Номер назначает программа. Сводка пары неизменяема и ссылается на точные исходные
ID пользователя и ассистента. Вход следующего сжатия содержит только прежние
сводки, новую пару и явно запрошенные старые оригиналы. Служебные ответы не образуют
пары. В конце беседы общая сводка заменяет список сводок в контексте ответа;
индекс отдельных пар остаётся доступным для поиска источников.

В replay старые ответы из корпуса сохранены, Gemma генерирует только сводки.
В live ответы Gemma создаются заново, без видимой несжатой истории. Эти два
результата нельзя называть одним большим живым разговором.

Уточнение пользователя учтено в живом тесте: сессия — запуск того же диалога.
Три запуска охватывают пары 1–4, 5–8 и 9–12; счётчик продолжается, процесс Gemma
между ними перезапускается. При открытии передаётся короткое оглавление прошлого
запуска и сводки новых пар; закрытие обновляет общую подробную сводку всего диалога.
Подробности и оригиналы доступны отдельно. `context-comparison.json` сравнивает
реальный вход модели с полной историей только через токенизацию, без контрольной
генерации на полном контексте. Код первого одноразового прогона — `source-snapshots`.

`protocol.json` закрепляет протокол; `adjustments.json` — изменения после ошибки.
Первые 52 пары сохранены до обнаружения пустого ответа на закрытие сессии;
ограниченное исправление пустого служебного ответа не подставляет правильные факты.

Используются установленный runtime Engine Set 002 Vulkan, существующие веса
Gemma, Giga-Embeddings на CPU и проверенные функции предыдущего стенда. Нового
модельного компонента нет. Оригинальная схема литературного «желе» не меняется.
Тяжёлые этапы запускаются последовательно; свои процессы завершаются в finally.
База/raw-журналы остаются локальными, текстовые свидетельства — в итоговом отчёте.
