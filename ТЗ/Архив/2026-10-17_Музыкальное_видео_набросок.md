## 1. Назначение

Быстро получать локальное музыкальное видео из готовой песни: звук, фон/обложка,
синхронный текст и подходящие визуальные эффекты. Основной ориентир концепции —
простая последовательность «песня → оформление → предпросмотр → готовый файл».
Подробности интерфейса, обязательные режимы и объём первого этапа ещё обсуждаются.

## 2. Подтверждённые решения пользователя

- Следующее направление работы — музыкальное видео; сначала детальное обсуждение.
- Создать набросок ТЗ и перенести исходную идею в общий архив.
- Пропуски отдельных строк существующей синхронизации допустимы: сами по себе
  они не являются проблемой, поскольку дальнейшая синхронизация не теряется.
- Не делать полное покрытие всех строк или обязательное ручное исправление
  пропусков предварительным условием этой функции.

Это уточнение не означает разрешения сдвигать следующие строки, выдумывать
времена отсутствующих строк или равномерно распределять их по длительности песни.
Точное оформление промежутков без найденной строки ещё предстоит обсудить.

### 2.1. Две точки входа — уточнение 17.10.2026

1. **Музыкальный сценарий.** Специальная кнопка открывает список песен,
   созданных в текущей музыкальной сессии, и предлагает выбрать одну для клипа.
   Место кнопки — нижняя панель блока музыкальных настроек, слева от кнопок
   со значком книги и настроек, по указанию на скриншоте пользователя.
2. **Обработка / утилиты.** Новая категория **«Работа с видео»**, в ней утилита
   **«Создание простого клипа»**. Песня выбирается через стандартный проводник
   (диалог выбора файла).

Оба входа относятся к одной механике создания клипа; различается способ выбора
исходной песни. Для входа из музыкального сценария используется текущая сессия,
для входа из утилит — файл с диска. Поддерживаемые форматы и получение недостающих
данных внешнего файла ещё нужно согласовать. Вид самого рабочего экрана/окна
создания клипа этим решением пока не определён.

### 2.5. Начало клипа — обложка, заставка и название песни

Подтверждённая пользователем последовательность:

1. **Самым первым кадром показать встроенное изображение из аудиофайла,
   если оно есть.** Назначение — подготовить первый кадр с обложкой для превью
   при публикации. При отсутствии изображения сразу начинать с заставки.
   Этот кадр не заменяет последующие заставку и титр с названием.
2. Затем **3–4 секунды** показывать заставку по приложенному образцу:
   тёмный фон, по центру небольшая надпись «A PRODUCTION BY», крупное «LOPATA»,
   тонкая линия и подпись «CREATED WITH LOCAL AI». Образец задаёт направление;
   окончательная типографика и анимация пока не выбраны.
3. **После заставки показать исполнителя и название песни.** Длительность этого
   показа и способ перехода к основной сцене пока не согласованы.
4. Далее — основная матричная сцена с обязательным старым монитором и проекцией
   текста песни, описанная выше.

[Пользовательский образец заставки](../Материалы/Музыкальное_видео/03_Вступительная_заставка_LOPATA.png)
сохранён без изменения изображения; это референс, а не готовый видеокадр.
Пользователь объяснил выбор начала тем, что у его генераторов вокал обычно
начинается примерно через 30 секунд. Это наблюдение не задаёт фиксированного
времени начала вокала для любого файла и не продлевает заставку до 30 секунд.

Музыка и времена строк остаются на исходной временной шкале. По уточнению
пользователя, ранняя речь не меняет прежнюю последовательность: обложка первым
кадром → заставка 3–4 секунды → исполнитель и название → основная сцена.
Не сокращать заставку и не переносить название в угол из-за ранней речи.
Допустимо, что начальные фразы прозвучат во время вступительных титров;
последующие строки не сдвигаются. Длительность титра с названием и подпись
для внешней песни с неизвестным происхождением ещё предстоит обсудить.

### 2.6. Финальные титры — участвовавшие модели

В конце клипа показывать модели, участвовавшие в создании, **если сведения
о них есть**. Использовать историю выбранного произведения и метаданные файла,
а не текущий выбор моделей в настройках. Указывать роль: например, музыка,
текст, обложка; техническую синхронизацию обозначать отдельно, если она показана.
Не приписывать модель неизвестному этапу и не смешивать программу/кодек с моделью.
Подтверждено пользователем: финальные титры показывать **4–5 секунд после
окончания песни**, не перекрывая музыкальную концовку. Их вид ещё обсуждается.
Отсутствие сведений о моделях не должно препятствовать созданию клипа.

## 3. Уже имеющаяся основа

К моменту обсуждения в ЛОПАТЕ имеются:

- Готовые музыкальные файлы и сведения о произведении/генерации.
- Обложки, включая выбранные пользователем изображения и сведения об их моделях.
- Синхронизация исходных строк по GigaAM v3 CTC, связанная с конкретной записью,
  сохранение разметки в метаданных и использование времён при воспроизведении.
- Видеокодирование для захвата экрана и запись происхождения выходных файлов.
- Общие механизмы фоновой работы, паузы и восстановления.

В исходной концепции синхронизация ещё названа будущей: это историческое состояние
14.10.2026, а не актуальная обязательная зависимость, которую нужно создавать заново.
Существующий видеокодер не считается готовым движком музыкального оформления.
Поддержка сложного вокала, разных языков и качество конкретных времён не
расширяются одним фактом появления видеоутилиты.

## 5. Музыка, эффекты и модели

Использовать уже известные сведения о песне и имеющиеся времена строк там,
где они подходят выбранной записи. Для визуального отклика в концепции разделены
обычный анализ аудиосигнала и необязательный анализ специализированной моделью.
Нужно отдельно решить, достаточен ли программный анализ для первого этапа.

Beat This!, All-In-One, Music2Emo и другие перечисленные в идее инструменты —
исследовательские кандидаты. Они не выбраны для поставки; их текущие возможности,
лицензии кода/весов, зависимости и работу на Windows проверить перед выбором.
Модель не должна генерировать каждый видеокадр: предполагается программное
оформление по один раз полученным данным. Дополнительные загрузки и испытания
в рамках этого наброска не выполняются.

## 13. Наследование метаданных и реализация в программе
