# RAG: параллельные страницы и умеренная нагрузка — 0.5.54-dev

По запросу пользователя распараллелена подготовка PDF. Настройка «Ориентир общей
загрузки CPU» находится в рабочем экране библиотеки; варианты 25/50/75/90%,
по умолчанию 50. Настройка сохраняется в черновике и в самом задании. Для старых
заданий без поля применяется 50%. Изменение параметра выполняется до начала
нового задания; восстановление использует сохранённое значение.

## Исполнение

- PdfPig читает страницы последовательно; его документ не разделяется между
  конкурентными OCR-исполнителями. Не более разрешённого числа страниц находятся
  в обработке, новые страницы не накапливаются без ограничения.
- Несколько независимых страниц проходят Windows-рендеринг и Tesseract параллельно.
  Каждый Tesseract ограничен одним OpenMP-потоком; вложенные команды не умножают
  незаметно число потоков. Языковые файлы подготавливаются под блокировкой и атомарно.
- GetSystemTimes измеряет общую загрузку CPU, включая сторонние программы.
  Интервал 1 секунда, сглаживание 0,35, гистерезис: рост ниже цели−5 п.п.,
  сокращение выше цели+3 п.п. При нехватке бюджета новые страницы ждут.
  Существующие страницы завершаются; память дополнительно ограничивает допуск:
  запас max(2 GiB, 10% RAM) и 384 MiB на страницу. Максимум зависит от числа
  логических процессоров и цели, с верхней границей 32. Без CPU-телеметрии —
  последовательная работа; без памяти для страницы — ожидание.
- Это мягкий ориентир нагрузки, а не системная квота: чужую нагрузку утилита
  не снижает; уже запущенная нативная операция может временно превысить цель.
- Результаты страниц собираются по исходному номеру. Сторонние ошибки/отмена
  не меняют текст и порог допуска OCR. Пауза дожидается всех дочерних исполнителей.
- Книги пока проходят по очереди. Индексация запускается после извлечения текста;
  одновременный запуск encoder и OCR не добавлялся. Ускоряются независимые страницы
  и порции индекса, без нескольких копий модели.
- Один Giga encoder использует прежнюю политику GPU-first/CPU-reserve. Порция
  начинается с двух фрагментов, растёт с учётом памяти до 16 на GPU/8 на CPU.
  При ошибке выделения памяти сначала снижается размер порции; одноэлементный
  GPU OOM передаётся существующему CPU-fallback. CPU encoder регулирует потоки
  и ожидание между порциями по общей загрузке. В SQLite остаётся один писатель.
