## 2. Планирование уже отделено, выбор ещё отсутствует

- [MusicStudioWorker.cs](../../Исходники/AIHub/Services/MusicStudioWorker.cs):
  `PlanAsync` → `v1/scores`, `SynthesizeAsync` → `v1/music/jobs`.
- [MusicGenerationRunner.cs](../../Исходники/AIHub/Services/MusicGenerationRunner.cs):
  после сохранения PlanFile/PlanHash сразу начинается синтез текущего дубля.
- [MusicGenerationJobs.cs](../../Исходники/AIHub/Services/MusicGenerationJobs.cs):
  сохранение стадий уже есть, самостоятельного набора выбираемых планов нет.
- [MusicStudioLease.cs](../../Исходники/AIHub/Services/MusicStudioLease.cs):
  собственный сервер/дерево процессов, ephemeral loopback-порты, max_batch=1,
  keep_loaded=false. Новая очередь не должна обходить общий фоновый controller.

В архиве Studio, `crates/music-server/src/lib.rs:8212–8271, 8343–8384`:
`ComposeScoreRequest` принимает full/melody и lm_batch_size 1–8;
результат содержит abc, lm_seed и plans[]. Нынешний адаптер сохраняет один abc.
Планирование использует служебный запрос duration=1, steps=1, synth_batch_size=1.
Поэтому корректное обещание — «без полного синтеза песни», а не «вообще без аудио
и загрузки моделей». Служебный рендер не является готовой песней пользователя.

LoRA-патч, `Runtime/MusicLoraStudio/v3.6.0-lopata-lora-2/lopata-paths-lora.patch`,
добавляет adapters в ComposeScoreRequest и engine body. Этот путь необходимо
сохранить: план и синтез не должны незаметно использовать разные LoRA/силы.

## 3. Keep/Words: исправление прежней трактовки

В архиве, `crates/music-server/src/score/edits.rs:1–99` и
`score/api.rs:36–51`, это привязка отредактированного плана к style/lyrics/cot:
хеш записывается комментарием `%yue2-words <16hex>`, опционально с `keep`.
`lib.rs:8708–8713` отказывает при другой привязке без keep.
Метка снимается до передачи нот движку; `score_edit` сохраняет происхождение.

Следовательно, Keep разрешает использовать сохранённый план с новым текстом
или стилем. Это **не усилитель дословного пения** и не два независимых регулятора
качества произношения. В ЛОПАТЕ нужны понятная политика и предупреждение о смене
входов, а не кнопка с обещанием «сохранить все слова». Импорт без метки тоже
требует собственной явной привязки в проекте; отсутствие метки не доказывает
совместимость нового текста с мелодией.

## 4. Секции, аккорды и timing — разные механизмы

- `lib.rs:8787–8802`: lyric_schedule строится для поданного ABC при cot≠off,
  без обычного replay semantic_tokens и при cfg_scale=1.0. При cfg=1.11 он
  пропускается. Сейчас адаптер 002 явно передаёт lyric_timing=false.
- `lib.rs:7401–7404, 8805–8823`: Studio может предварительно разложить план
  без секций по тексту, изменить ABC и автоматический предел длительности.
  Сохранить необходимо и выбранный исходный план, и фактический после обработки.
- `crates/music-server/src/harmony.rs:1–103`: harmony.follow_lyrics задаёт
  порядок секций по меткам текста; остальные поля регулируют разнообразие
  аккордов. Это не копирование аккордов первого припева во все припевы.
- README/CHANGELOG упоминают chord mirroring, однако отдельный действующий
  маршрут/поле именно для такого копирования в просмотренном закреплённом API
  не подтверждён. Обещать готовый переключатель backend нельзя. Для этой части
  нужен отдельный явный алгоритм правки ABC с просмотром результата и отменой.

## 5. Проверка ABC и предварительное прослушивание

В архиве есть `score/abc.rs:289` (parser), `score/notation.rs:108–124, 499`
(ограниченный notation reader, предел 200000 байт), `/v1/score/midi` и
`/v1/score/vocal-octave`. Отдельного универсального `/validate` среди проверенных
маршрутов нет. Экспорт MIDI не доказывает исполнение любого стандартного ABC.
Для реализации сначала оценить штатный parser через изолированный CPU helper
или небольшой endpoint в новой ревизии обёртки; не писать второй несовместимый
parser и не превращать импорт в потерю данных через MIDI round-trip.

Диалект модели имеет Vocal/Ins, секции-комментарии и ограниченные длительности;
не произвольный стандарт ABC. Голоса одноголосные, аккорды — отдельные символы,
а не произвольные стопки нот. Поддержку конструкций сверять с parser/engine;
понятная ошибка предпочтительнее молчаливого удаления неподдержанных элементов.

[MusicMelodyWave.cs](../../Исходники/AIHub/Services/MusicMidi/MusicMelodyWave.cs)
уже даёт простое CPU-прослушивание одноголосной мелодии. Для двух голосов и
аккордов потребуется ограниченное расширение preview; текущий MIDI-редактор
не является редактором полного ABC. Звук preview не изображает голос и тембр
будущей генерации.

## 6. Вывод для реализации

Первый полезный проход — A1 + базовый A2 + политика привязки плана из A3.
Следом — подтверждённые настройки секций/timing и явная правка повторов.
Не менять immutable 002/LoRA-2 на месте; если понадобится helper, выпустить
отдельную ревизию с исходниками, лицензиями, контрольными суммами и gate.
Старые задания должны выбирать прежний runtime по своей истории.

Поддержка 001 новых механизмов требует отдельной capability-сверки; существующие
генерации 001 сохраняются. Ни новый parser/helper, ни CPU-preview полного плана,
ни пауза новой очереди пока физически не испытаны. Версия программы не менялась.
