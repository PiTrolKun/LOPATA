# ЛОПАТА — исследование pi-H3 DWD для сценария «Песня → клип»

**Дата фиксации:** 25 ноября 2026 года.
**Статус:** идея для практической проверки; не утверждённое ТЗ и не решение о внедрении.

## 1. Исходная задумка

Проверить pi-H3 DWD как ускоритель создания видеоряда для уже готовой песни. Поводом послужил обзор workflow Anikin Labs pi-H3 DWD Studio v1.0 для ComfyUI.

По наблюдениям пользователя в обзоре присутствуют выраженные звуковые галлюцинации и низкое качество генерируемого звука. Поэтому на данном этапе не рассматриваем этот вариант для «Простой генерации видео»: там собственный звук видеомодели может быть важной частью результата.

В сценарии «Песня → клип» исходная звуковая дорожка уже существует. Если генерируемый моделью звук не используется в итоговом монтаже, его низкое качество само по себе не мешает применению ускорителя. Главный вопрос — насколько пригоден визуальный результат и насколько сокращается время создания клипа.

## 2. Что представляет интерес

- Специально обученные адаптеры pi-H3 DWD для MiniMax H3 с генерацией за 2 или 4 шага.
- DWD Decode — получение видеокадров без обычного финального декодирования видео-VAE.
- Возможность использовать уже подключённую в одном из вариантов «Песня → клип» базовую MiniMax H3 FL2VA INT8 ConvRot (`minimax_h3_fl2va_pruned_int8_convrot.safetensors`).
- Возможность ускорить массовую генерацию коротких фрагментов, переходов и сцен, из которых собирается клип.

Не требуется переносить весь интерфейс или весь workflow Anikin Labs в ЛОПАТУ. Присланный JSON — технический ориентир, а не обязательная архитектура интеграции.

## 3. Условия и ограничения

В приложенном workflow используются два INT8 ConvRot-адаптера:

- `pi_h3_2step_dwd_adapter_int8_convrot.safetensors`;
- `pi_h3_4step_dwd_adapter_int8_convrot.safetensors`.

Также используются планировщик pi-Flow, Euler, MiniMax H3 Sigma Shift (видео 12, аудио 3), `max_raw_t` 0.93 для двух шагов и 0.96 для четырёх, `final_step_size_scale` 0.6. Sol-Attention включён по умолчанию, но допускает компромисс по качеству. В workflow указан ComfyUI >= 0.45.0 для ComfyUI-piFlow. Эти настройки — исходные параметры для воспроизведения, не утверждённые настройки ЛОПАТЫ.

Важно:

- Официальная базовая конфигурация DWD — FL2VA. Ref2VA в описании workflow обозначена как экспериментальная совместимость, а не гарантированная поддержка.
- В режиме I2V видео-VAE по-прежнему нужен для кодирования исходного изображения. Присланная схема использует первый кадр; вход последнего кадра не подключён. Для используемых ЛОПАТОЙ переходов между двумя опорными кадрами поддержку необходимо проверить отдельно.
- AUDIO OFF в данном workflow исключает звук из итогового файла, но не отключает внутреннюю генерацию аудио. Не считать это дополнительным ускорением без отдельной проверки.
- 8 ГБ VRAM — заявленная цель автора сборки, а не подтверждённое минимальное требование.
- Совместимость обычных LoRA, альтернативных квантизаций и иных вариантов весов требует проверки; не включать их в обязательный первый проход.
- При возможной интеграции проверить лицензии и совместимость зависимостей с существующим исполнительным окружением Windows ЛОПАТЫ.

## 4. Практическая проверка для Codex

Сначала исследовать оригинальную реализацию pi-H3 и адаптеры. Сопоставить их с текущим вариантом FL2VA в «Песня → клип». Не изменять рабочие пользовательские режимы до оценки результата.

Минимальное испытание — один и тот же короткий фрагмент на действующем H3 и на pi-H3 DWD за 2 и 4 шага. По возможности сохранить одинаковые исходные изображения, промпт, seed, разрешение и длительность. Начальные параметры из workflow: около 0.23 МП, 5 секунд, 24 FPS; затем проверить на обычных для ЛОПАТЫ параметрах клипа.

Оценить:

- полное время обработки и отдельно время генерации, с учётом холодного запуска и прогрева;
- расход VRAM и RAM;
- качество видеоряда, сохранение персонажей, естественность движения, стабильность изображения;
- работу с опорными кадрами, включая начало и конец перехода, если это необходимо текущему маршруту;
- корректную сборку фрагментов под исходную песню без использования звука H3.

Первичная проверка — на основном ПК разработчика с RTX 4090 24 ГБ и 128 ГБ RAM. При необходимости отдельно сравнить Sol-Attention с обычным вниманием, а также вариант pi-H3 с обычным VAE-декодированием, если для него доступна совместимая реализация. Это дополнительные исследования, не обязательные условия первого испытания.

## 5. Решение по результатам

Если ускорение существенное, а визуальное качество и поддержка необходимых опорных кадров приемлемы, рассмотреть отдельный ускоренный вариант в «Песня → клип» с сохранением действующего движка. Проверить оба количества шагов, не предполагая заранее, что двухшаговый или четырёхшаговый режим окажется лучшим.

Если качество видеоряда недостаточно, ускорение не оправдывает компромисс или не поддерживается необходимая схема переходов, оставить идею в архиве исследований.

**Основной принцип:** оценивать технологию как ускоритель видеоряда под уже готовую песню, а не как универсальную замену видеогенератора ЛОПАТЫ. Исходная песня остаётся итоговой звуковой дорожкой.
