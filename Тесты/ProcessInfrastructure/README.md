# Процессы и Qdrant — 2026-09-10, 0.1.86-dev

## Реализация

`OwnedProcessRegistry` владеет только запущенными через него экземплярами, держит отдельный Windows Job Object с KILL_ON_JOB_CLOSE на каждый worker и закреплённый process handle для наблюдения. Учитывает завершение и убирает оставшихся потомков. Журнал ограничен двумя файлами примерно по 2 МБ; полные аргументы, промпты и переменные окружения туда не записываются. Существующие проверки готовности и блокировки runtime сохранены.

Оставшиеся прямые Process.Start в продукте — открытие браузеров, папок, внешних просмотрщиков, системного установщика компонента и установщика обновления. Они намеренно не принадлежат worker-группам. Скрипты разработки не переводились на runtime-реестр. Потомки Python/native workers наследуют назначенный Windows Job.

Ограничение: существующие .NET Process.Start присоединяются к Job сразу после запуска; между CreateProcess внутри .NET и Assign остаётся короткое окно. Авария владельца именно внутри этого окна не покрыта атомарной гарантией. Полный перевод всех запускающих API на native suspended потребовал бы отдельной переделки перенаправления потоков. Qdrant запускается нативно suspended, назначается Job до ResumeThread; отдельная скрытая консоль и явный HANDLE_LIST изолируют сигнал Ctrl+C и наследуемые дескрипторы. Ошибка назначения Job завершает запущенный процесс, а не оставляет его без контроля.

## Qdrant

- Официальный upstream: https://github.com/qdrant/qdrant/releases/tag/v1.19.1.
- Архив qdrant-x86_64-pc-windows-msvc.zip: 29 671 153 байта, SHA256 `9b6f69bd85f6abed4bc13f943099f55c6ffd55f5dd90388635320d8fbb569eb0` (сверен с GitHub release API).
- qdrant.exe: 85 063 168 байт, SHA256 `b5354e3c8f9d13d92294f38d4988d4ddedc04acaa2ce51f0a2d65b30e2d4cd69`. Проверяется перед запуском.
- Runtime: `Runtime/Backends/qdrant/1.19.1/win-x64`; в установленной копии Runtime вычисляется существующим AppDataPaths.
- Данные: `%LOCALAPPDATA%/AI_HUB/Memory/Qdrant`; путь задаётся QdrantOptions, литературные папки не используются.
- Loopback и свободный порт, случайный API key только в окружении процесса. Готовность проверяется readyz и авторизованным API. gRPC, cluster, CORS и телеметрия отключены; CPU-параллелизм поиска/оптимизации 2. Унаследованные QDRANT/RUN_MODE настройки удаляются.
- REST через штатный HttpClient: новой NuGet-библиотеки или Docker нет. Бинарный файл скачивается отдельно через общий лицензионный gate, в установщик не включается. Исходный LICENSE сохранён; аудит всех транзитивных лицензий бинарной поставки не объявляется завершённым.
- Нормальное завершение: отдельный краткоживущий helper проверяет PID + время создания, присоединяется только к выделенной консоли и отправляет Ctrl+C. После подтверждения выхода освобождается блокировка данных. При тайм-ауте — принудительная остановка с записью в журнал.
- Тестовая коллекция имеет уникальный ID; marker создаётся до HTTP. После отмены/сбоя незаконченная проверка очищается при следующем запуске только по собственным marker-файлам. Пользовательские коллекции не удаляются.
- Окно `Настройки → Внутренние процессы`: список, скачать/проверить, запустить, остановить, проверка записи/поиска/перезапуска, отмена и журнал. Qdrant не стартует при открытии окна и не подключён к сценариям.

## Воспроизведение

Из корня репозитория:

```powershell
dotnet test Исходники/AIHub.Tests/AIHub.Tests.csproj
dotnet run --project Тесты/ProcessInfrastructure/Probe.csproj -- lifecycle H:\AI_HUB\_tmp\process-lifecycle-new
dotnet run --project Тесты/ProcessInfrastructure/Probe.csproj -- qdrant H:\AI_HUB\_tmp\qdrant-new
dotnet run --project Тесты/ProcessInfrastructure/Probe.csproj -- ui H:\AI_HUB\_tmp\process-ui-new
```

Headless стенд использует существующий контракт ComponentLicenseGate без установки подтверждения UI; пользовательские receipts не меняет. Режим qdrant при отсутствии бинарного файла скачивает зафиксированный архив. Папки результатов выбирайте новые. UI-стенд использует обычную служебную базу Qdrant, без чтения или изменения литературных проектов. Для lifecycle сохраняются только PID; после проверки свои процессы завершаются.
