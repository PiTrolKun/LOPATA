# Music stems — pinned offline separation

The application uses the overlap/add inference in StemSplitio's HT-Demucs 6s
ONNX export, revision `49df9b6989cf2150840ea65b0bef77a2e471b678`.
It accumulates vocals and the float sum of the other five stems, applies one
shared gain, then writes two PCM files. No separate source-separation algorithm
or generator is trained here. Boundary windows retain edge samples and padding
is removed. The existing FFmpeg bundle resamples PCM16 WAV; it has no f32le muxer,
amix or apad. Joint playback sums aligned decoded PCM using `MusicPcm16`.

`prepare.py` prepares the committed wheel/file manifest and original notices.
Normal runs use the committed hashes; `--refresh` deliberately resolves new
metadata and requires developer review. It never pip-installs anything. Cache:
`Runtime/MusicStems/cache`, excluded from source delivery.

Application delivery uses `ComponentCatalog` / `ComponentManager` and the normal
license gate. The model is 136,428,532 bytes, SHA256
`7ce55792e2231c93fbf92de95f5fd5b3a5e6c89f7db690dfd693e8f1dce56869`.
ORT 1.23.2 CPU and common wheels are isolated component trees. The CUDA wheel is
requested only for an actually compatible prepared CUDA profile. No system
Python, ACE overlay, YuE generator weights or automatic model downloader is used.
There is no ONNX DirectML promise for this particular graph. CPU remains usable.

The complete file manifest is embedded in AIHub, including file sizes and hashes.
Unlisted executable files/links fail verification; generated bytecode corresponding
to pinned sources is quarantined before verification, never ignored or executed.

Licenses: `Licenses/music-stems-entries.json` and the three `music.stems_*` texts.
`prepare-license-catalog.ps1` includes the optional entry. Basic installer receipts
and previous component consent terms remain unchanged. The model author declares
MIT; original Demucs MIT and the wheel license/third-party notices are retained.
CUDA/cuDNN are supplied by the separately prepared hardware profile under its terms.

The worker is an owned process tagged `Music.Separation`, inside `music.generate`.
Cancellation waits for process exit; a hardware-specific GPU failure permits one
CPU retry. Data/integrity failures do not. Native PCM is retained until publication
and timing preparation settle. Resume does not synthesize completed audio again.

Developer physical fixture (no fresh music synthesis):

```powershell
dotnet run --project Тесты/MusicStemsStand/RuntimeProbe.csproj -- --prepare
dotnet run --project Тесты/MusicStemsStand/RuntimeProbe.csproj -- --source C:\path\song.mp3 --output H:\path\new-fixture --pipeline
```

Use a fresh fixture directory. `--cpu` tests CPU separation; `--pipeline` uses
supplied PCM via an explicitly labelled generator stub but real separation,
two output formats, metadata, TXT publication and joint playback. This does not
claim new Studio/ACE inference or a listening-quality evaluation.
