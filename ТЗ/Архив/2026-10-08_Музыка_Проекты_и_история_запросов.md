# Музыка — проекты и история отправленных состояний

Дата: 08.10.2026. Статус: выполнено, принято и архивировано 08.10.2026.
База: 0.4.10-dev; рабочая версия: 0.4.11-dev.
Связь: [карта музыкального конвейера](../Музыкальный_конвейер_карта.md),
[принятые форматы и метаданные](2026-10-07_Музыка_U2_Форматы_и_метаданные.md).

## 1. Проект

- При создании рабочего музыкального окна появляется временный проект:
  «Проект №{сквозной номер} — {дата и время создания}».
- Временный проект существует в памяти; на диске только общий счётчик номеров.
  Пропуски номеров допустимы, повторное использование номеров исключено.
- Первый принятый запуск генерации делает проект постоянным до выполнения
  модели, чтобы запрос сохранялся и при ошибке/отмене. Проверка железа,
  токенов, просмотр рецептов и мини-правки проект не материализуют.
- Ручная фиксация сохраняет текущие текст/настройки без запроса к модели;
  фиксированные пользователем проекты имеют отдельную таблицу.
- Значок управления внизу узкой панели быстрых действий открывает отдельное
  окно: текущее имя/статус, зафиксировать, переименовать, новый проект,
  открыть сохранённый. Переименование не переименовывает аудиофайлы.

## 2. Сохранённое состояние и шаги

- Снимок содержит текст, пожелания/профили исполнителей, модель/вариант,
  экспертные настройки/круг, исполнитель/название/комментарий, варианты,
  длительность, форматы/битрейты и папку результатов.
- Фиксировать только финальное состояние отправки. Тысячи мини-правок,
  локальный Undo и движение круга не создают записей истории и не
  перезаписывают последний сохранённый снимок проекта.
- Один запуск с несколькими вариантами — одна попытка/шаг, связанная
  с существующим заданием и его фактическими seeds/результатами.
- Повтор готового трека тоже хранит попытку с его исходным заданием,
  не приписывая ему текущий редактируемый текст.
- Возврат к старому шагу ничего не переписывает; следующая отправка
  добавляет запись. Ошибка/отмена/пауза отражены у попытки, готовые
  части и связь с треками сохраняются. Resume не создаёт новый шаг.

## 3. Навигация и окно управления

- Слева от заголовка редактора одна маленькая кнопка: «Т» → «⚙» → «○».
  Подсказки: история текста, история настроек, переходы выключены.
- Справа стрелки «‹»/«›». В режиме текста восстанавливаются только слова;
  в режиме настроек — только настройки. Полный снимок сохраняется всегда.
- «○» отключает только стрелки, не запись запросов. Границы истории,
  текущий номер шага/попытки и её состояние доступны в подсказках/окне.
- Во время активной/ожидающей продолжения генерации запрещены смена
  проекта и переходы истории, способные подменить активное задание.
- После открытия проекта восстанавливается последний сохранённый снимок
  и его готовые треки; отсутствующее аудио не объявляется существующим.
- Несохранённые мини-правки перед переключением не получают автоматическую
  историю. Ручная фиксация доступна явно. Удаление проектов/аудио не заказано.

## 4. Надёжность и совместимость

Отдельные модели/хранилище/контроллер проектов без нового монолита.
Версионированный JSON, устойчивые ID, атомарная запись, проверка схемы,
сквозной счётчик с блокировкой. Повреждение не превращать молча в пустой проект.
Существующие Jobs и общий BackgroundOperationController остаются источником
выполнения; хранение проекта не запускает модель и не создаёт второй scheduler.
Старые задания без ProjectId остаются доступными; автоматически объединять
их в выдуманные проекты не нужно. Новые теги Project/Step связывают результат
с проектом; переименование проекта не меняет старые теги задним числом.

## 5. Проверки и приёмка

Проверить временность, явную фиксацию, счётчик, перезапуск, точные снимки,
сохранение повторов, ошибку/отмену, продолжение без нового шага, возврат
без перезаписи, независимость текста/настроек, «○», обе таблицы, восстановление
треков, повреждение JSON и старые задания. STA-проверки UI/RU/EN/тем,
build/restore, релевантные и общий тестовые прогоны, scanner, штатный запуск.
Новые длительные генерации не требуются: использовать короткий fake worker
и существующие реальные результаты без изменения пользовательского аудио.
Справка «?», руководство, облако механик, реестр фоновых операций и история.
ТЗ не закрывать до приёмки пользователя. Разовое «без публикации» касалось
только U2; для будущего закрытия действуют обычные правила проекта.

## 6. Результат реализации

Хранилище Schema=1, окно управления с двумя таблицами и переключатель
Т/⚙/○ реализованы. Связь ProjectId/ProjectStep сохраняется в заданиях
и новых аудиотегах. Смена проекта/шагов заблокирована для active/pending.
Подробный [протокол проверок](../../Документы_проекта/Исследования/2026-10-08_Музыка_проекты_проверки.md).
