## Подтверждённая причина

Модель неверно выбрала текущую часть вместо истории. LiteraryReadingSession.PrepareAsync при action=read и number=Active.Number немедленно возвращает сборку финального ответа: «текущий текст уже передан». Это ошибочно превращает отсутствие необходимости перечитывать один блок в завершение всей задачи чтения. В результате в финальном контексте остались только каталог и рабочий хвост; модель стала гадать по названиям и просить доступ, который программно уже был предоставлен.

Первый ошибочный ответ также вошёл в беседу Советника и присутствует во втором запросе. Это может подкреплять неверное объяснение, но повторная ошибочная ветка управления подтверждена независимо от влияния беседы. Причина не в автосохранении, исчезнувшем якоре или нехватке памяти.

## Следующее исправление (ещё не выполнено)

Не завершать обход истории только потому, что выбранный блок уже есть в контексте. Нужен контролируемый учёт требуемых/прочитанных частей и их покрытия; для общего обхода — продолжение по бюджету с честным сообщением о реально прочитанном объёме. Добавить регрессию с обычными словами «первая глава»/«все файлы» и несколькими продолжениями: прошлые успешные короткие тесты с явным номером 001 не покрывали этот пользовательский путь.

ТЗ остаётся активным, пользовательская проверка выявила невыполненную часть. Публикаций нет. Backup документации: _backups/literary_reading_user_diagnosis_20260909/files.txt.

Тем не менее Писатель объявил 002.4 неполным, сославшись на nextOffset=7200 третьего блока, хотя четвёртый с 294 символами уже передан. Также придумал значение history как одобрение другими участниками. В ответе о 002.2 он ошибочно отнёс исторический текст к workingDraft и назвал отсутствующим предложение «Барышня взяла книгу и прочла несколько строк», которое присутствует в последнем переданном фрагменте. Это подтверждённая ошибка интерпретации полученных материалов. Причинность конкретной разметки ещё требует сравнительного теста; передача каждого фрагмента отдельным объектом с транспортными смещениями — обоснованный кандидат на упрощение.

Запрос 22:13:41 (20260909_151341_585_0478e5ff3f604575b17fc72d84d557c8.jsonl), «Прочти все файлы Начиная с 002.1», снова выбрал активный 002.5 и завершился без source_read. Номера 002.1 в каталоге нет: первая часть называется 002. При этом модель ошибочно отрицала и существование 002, который в каталоге есть.

Дополнительный фактор последнего ответа: Писатель получает только последнюю команду. В запросе «Тогда начиная с файла 002.2» уже нет предыдущего поручения «Прочти все файлы». Это действующая договорённая политика контекста Писателя, не вытеснение памяти. Изменять её молча нельзя; при необходимости отдельно согласовать сохранение краткого текущего задания.

Предложение для следующего исправления: собрать прочитанные фрагменты одного файла в единый текст с ясными границами и программно рассчитанным покрытием; отделить текущий набросок от предыдущих частей рукописи простыми названиями. Смещения чтения оставить внутреннему механизму, не заставлять финальную модель выводить полноту по нескольким nextOffset. Исправить преждевременное завершение обхода независимо от этого. Пока только диагностика: модельных запусков и изменений кода нет.
