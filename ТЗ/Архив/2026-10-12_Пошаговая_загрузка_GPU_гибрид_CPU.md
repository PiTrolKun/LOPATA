# ТЗ — пошаговая загрузка GPU → гибрид → CPU с запоминанием

Дата: 12.10.2026. Статус: принято пользователем 12.10.2026 («Все тз выполнены»). Основание: прямое поручение пользователя после анализа CPU-запуска Gemma Poetry; дополнительное требование сохранять последний удачный выбор.

## Поведение

- Первый запуск песенной GGUF-модели пытается использовать полную VRAM выбранного совместимого GPU, без прежнего запрета на основании завышенной верхней оценки. Устройства/runtime получают штатные проверки версии, целостности и лицензии.
- Во время загрузки периодически измеряется общая занятость dedicated VRAM именно выбранного устройства: DXGI определяет адаптер/LUID/объём, PDH GPU Adapter Memory — занятые байты. Отдельный --list-devices используется для обнаружения устройства, но не как общий счётчик: Vulkan heapUsage относится к процессу опроса. Занятость >=97% или ошибка GPU-загрузки завершает этот процесс и переводит в гибрид. Опрос не гарантирует перехват мгновенного скачка; ошибка выделения также приводит в гибрид. Если достоверный счётчик выбранного адаптера недоступен/неоднозначен, ошибка явно журналируется, неизвестную память не считать нулевой.
- Гибрид использует официальный --n-gpu-layers: часть слоёв на GPU, остальные в RAM. Число слоёв рассчитывается по распределению GGUF-тензоров, рабочему кэшу и текущей памяти с резервом ниже порога. Гибрид — реальная смешанная загрузка, не shared-VRAM драйвера.
- CPU используется после отказа гибрида. Если совместимого GPU нет, разрешён CPU напрямую. Отмена/выход никогда не вызывают следующую попытку; неизвестные/повреждённые данные не обходятся. RAM/контекст проверяются и при необходимости уменьшается контекст CPU до прежнего минимального 1024.
- Удачно загрузившийся режим, число GPU-слоёв и контекст запоминаются отдельно от пользовательского содержания. Следующий запуск использует его без самовольного повышения режима. Отказ ведёт только вниз по цепочке и сохраняет новый удачный выбор.
- Ключ предпочтения включает модель (путь/размер/mtime), выбранный runtime/устройство и запрошенный контекст; смена этих условий начинает новую цепочку. Предпочтение не заменяет валидацию/лицензии/проверки ресурсов. Ошибка записи не ломает готовый runtime, но логируется.

## Реализация и границы

Самостоятельные компоненты для политики/переходов, хранения предпочтения, журнала и чтения размещения тензоров. Подключение сначала к песенному чату (LlamaServerRuntimeService.PreparePoetryAsync); прочие сценарии не переводить молча на новый режим. Обычный путь core/financial сохраняет нынешний контракт. Gemma получает корректный SWA-профиль по закреплённому b9442: pattern, window+ubatch, padding256, разные размеры голов, shared-KV учитывается консервативно.

Сохранять стадии, устройство, контекст, бюджет, PID/команду, замеры VRAM, причины переходов и stdout/stderr. Совместимость с общей отменой и owned-process retirement обязательна. Новых весов/runtime не скачивать. Рассуждения вне задачи.

## Проверки

Фикстуры переходов GPU-success, GPU97→hybrid, GPU-error→hybrid, hybrid-error→CPU; отмена без retry; cache reuse без GPU-upgrade, fingerprint invalidation, запись только ready. Проверки tensor placement/памяти, Gemma per-layer SWA и плохих метаданных. Один минимальный живой запуск установленной Gemma с журналом загрузки/ответом и освобождением процесса; дополнительные тяжёлые прогоны только при конкретной оставшейся ошибке. Safe-start, UTF-8, RU/EN, diff-check. Установщик не пересобирать, публикации/архивирования без приёмки всего ТЗ нет.

## 12.10.2026 — пошаговый запуск и память удачного режима, 0.5.25-dev

По поручению пользователя песенный GGUF-чат получил GPU → гибрид → CPU. Первый запуск проверенного совместимого runtime пытается загрузить все слои на GPU. Порог 97% учитывает общую dedicated VRAM выбранного DXGI/LUID-адаптера через PDH и намерение выделения GPU-буферов из pinned native журнала: Windows может вытеснять страницы в RAM до насыщения resident-счётчика. --list-devices остаётся для обнаружения, не для измерения глобальной занятой VRAM (Vulkan heapUsage относится к процессу опроса). --fit off предотвращает незаметную смену слоя/контекста самим движком. Установлены ubatch512/F16 KV; INFO-native stdout/stderr записываются без DEBUG-промптов.

После порога/ошибки GPU прежний owned worker полностью завершается, затем планируется гибрид через штатный --n-gpu-layers. Доли определяются по реальным GGUF tensor offsets/spans, с резервом кэша/вычислений/VRAM. Для Gemma корректно учитывается SWA window+ubatch/padding и per-layer головы; native подтвердил KV 2560+1200 MiB на 32768. CPU — после отказа гибрида, либо при отсутствии совместимого GPU. Неоднозначные/недоступные счётчики не считаются нулевой занятостью. Проверка RAM и прежнее безопасное уменьшение CPU-контекста сохранены; при отмене нет нового режима. Частичный видимый ответ не переигрывается.

Последний ready-режим, GPU-слои и контекст атомарно сохраняются в Runtime/LlamaPlacement. Ключ: модель path/size/mtime, runtime/device и requested context, ревизия алгоритма. Следующий запуск использует сохранённый режим без повышения из-за изменившейся свободной памяти; отказ ведёт вниз, новый ready сохраняется. Предпочтение не заменяет лицензию/проверки bundle/model/resources. Ошибка сохранения логируется отдельно и не превращает готовую модель в ошибку.
