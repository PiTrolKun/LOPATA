# Музыкальные LoRA

Каталог поставляется в `Исходники/AIHub/Tools/music-loras.json`. Весов в поставке
нет: их получает обычный managed downloader по закреплённым ревизиям/SHA256,
с отдельными лицензионными записями. Удаление ограничено файлами карточки.
ID и ревизию опубликованного рецепта не переписывать: новую ревизию добавлять
отдельным ID, сохраняя прежнюю запись для повторов старых заданий.

Первые проверенные рецепты:

- Studio, набор 002: Atomtan Dream pop и Old-school hip-hop; AR + NAR;
- ACE-Step 1.5 XL Turbo: str8bored JAY_2; PEFT DiT.

Сила 0–1, шаг 0,05. Это множитель штатного коэффициента адаптера. Значение 0
не отправляет адаптер исполнителю; индивидуальный выбор и общий bypass сохраняются
в проекте. JAY_2 автор рекомендует использовать на 1; ниже возможны артефакты.
Для других вариантов каталог пуст, пока не подтверждена совместимость.
Particle/LoKr и произвольный импорт не подменяются обычной PEFT LoRA.

В 0.5.97-dev Studio/002 расширен до 32 карточек: Industrial, GRVL ×6,
MLTNT ×6, NTC distill v2 ×16, Instrumental V3 и прежние две Atomtan.
У NTC только AR; у двух быстрых MLTNT AR/NAR = ½/1. Это коэффициенты рецепта,
на которые умножается пользовательское влияние. Условия новых весов — CC BY-NC.
Полный список и ограничения: `Документы_проекта/Музыкальные_LoRA_каталог.md`.
Не путать обычные NTC distill с исходным специальным Particle-форматом.

## Обвязка Studio

Существующие наборы движков 001/002 и их manifests не переписаны.
Только запрос с дополнительными LoRA использует изолированную обвязку
`Runtime/MusicLoraStudio/v3.6.0-lopata-lora-2`. Сам yue-server и библиотеки
по-прежнему берутся из закреплённого набора 002. Обвязка добавляет лишь передачу
проверенной временной папки через `LOPATA_YUE_ADAPTERS` → `YueModelFiles.adapters`.
В ревизии 2 маршрут `/v1/scores` также передаёт список адаптеров и силы через
штатный `adapter_fields`: upstream 3.6.0 отбрасывал их при отдельном создании плана.
Неизвестная папка адаптера отклоняется до отправки задания. Штатная API Studio
продолжает управлять генерацией и жизненным циклом движка.
Без дополнительных LoRA используется прежняя обвязка. Сопровождающий
`nar_lora_joint_v9` остаётся обязательным и не удаляется из этого окна.

Для пересборки: распаковать `Studio-source.zip` из этого каталога, применить
`lopata-paths-lora.patch`, в MSVC x64 developer shell с CMake запустить
`cargo build --locked --release -p music-server --jobs 4` с
`CMAKE_GENERATOR=Visual Studio 17 2022`. Cargo.lock закреплён; исходники
и лицензии зависимостей той же ревизии поставляются в наборе 002.
Новый бинарник паковать отдельной ревизией и закреплять ожидаемый SHA256 в
`MusicLoraStudioRuntime`; не переписывать уже выпущенную immutable ревизию.
csproj включает обвязку, source/patch/license в обычные build/publish outputs;
отдельного скачивания обвязки пользователь не выполняет.

## ACE

`music_lora_runtime.py` использует официальный handler.add_lora и set_lora_scale.
Для нескольких адаптеров список выбирается в `decoder.base_model.set_adapter`:
внешний PeftModel.set_adapter данной версии принимает только строку. До и после
генерации проверяются активный список, слои и реальные коэффициенты scaling.
Хеши проверяются до загрузки. Путь к папке не попадает в публичный LoRA receipt.

## Стенд

`MusicLoraNativeTests` включается только при явных переменных
`LOPATA_LORA_STAND` и `LOPATA_LORA_MODELS`. Стенд содержит заранее проверенные
downloaded safetensors. Тест не скачивает модель скрытно.

Доказательства первого прогона: `Тесты/MusicLoraStand_20261020_190509`.
Studio: native-195707; ACE: ace-201039. При фиксированных seed отключение
в обоих случаях вернуло побайтно исходный WAV. Это подтверждает механику,
но не гарантирует улучшение художественного качества.

Прогноз VRAM — ориентир с запасом. Studio использует штатный preflight;
ACE — недавний снимок свободной памяти из его штатной проверки и грубый рецепт
BF16 XL + резерв. Устаревший/отсутствующий снимок честно обозначается неизвестным.
Память игры не считается памятью ЛОПАТЫ, но уменьшает доступный остаток.
Режим вычислений окно не переключает; исполнитель повторяет проверку при запуске.
