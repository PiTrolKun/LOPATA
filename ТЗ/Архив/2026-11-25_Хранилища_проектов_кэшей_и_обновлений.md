# ТЗ — хранилища проектов, временных файлов и обновлений ЛОПАТЫ

25 ноября 2026 года. Аудит исходного кода и требования к реализации. Версия на момент проверки установленной копии — 0.9.23-beta. Ключевые пути сверены с коммитом выпуска `0d0f4bf844af9d882e6a1c9d9433e6768f830691`. Реализация опубликована в 0.9.25-beta. [Протокол проверки](../../Документы_проекта/Релизы/0.9.25-beta_проверки.md)

## 1. Что должно измениться для пользователя

- **Обычная работа.** ЛОПАТА использует папки и лимиты, заданные при первой настройке. Проект, его материалы, сохраняемые попытки и результаты попадают в выбранное рабочее хранилище. Модели и установленные компоненты учитываются по своим правилам.
- **Отдельная папка для конкретной работы.** Проект, созданные для него материалы, нужные контрольные точки и итог хранятся в этой папке. На внешние исходники проект ссылается по их текущим путям. Копия исходника допустима только при технической необходимости. Отдельная команда «Экспорт копии» или «Сохранить проект как…» остаётся осознанным действием.
- **Временные файлы.** Для всех работ используются управляемые подпапки исходного выбранного рабочего хранилища, включая работы с отдельной папкой сохранения. Нужную для завершения записи кратковременную копию на томе назначения удалять после проверки. Доступные настройки действуют и для существующих пользователей, повторно проходить первый запуск не нужно.
- **Обновления.** При превышении **10 ГБ** ЛОПАТА предлагает удалить старейшую половину наборов, доступных для очистки. Ориентир — освободить **5 ГБ** за одну очистку. Текущая установка и **три последние предыдущие версии для отката** защищены. Пользователь видит, сколько места освободится фактически. Очистка начинается после подтверждения.
- **Уже установленные копии.** При первом успешном запуске после обновления ЛОПАТА предлагает перенести распознанные файлы из прежних папок туда, где они должны храниться по новым правилам. Это относится к тестировщикам и другим пользователям существующих установок. Предложение показывает план, перенос начинается после согласия.
- **Dev-сборка.** Порог хранения обновлений, предложение очистки, резерв версий для отката и предложение переноса старых данных относятся к установленным выпускам. В dev действуют общие правила записи проектов, результатов и временных файлов.

## 2. Что показал аудит

В первой настройке сохраняются две категории — `Models` и `Results`. У каждой есть общий лимит, лимиты папок и разрешённое временное превышение. Единого механизма выбора папки, резервирования места и завершения работы для всех сценариев нет. Часть кода берёт первую папку `Results` как начальный адрес, часть пишет прямо в `AppDataPaths.BaseDirectory`, другие используют системный `TEMP`. В установленной версии `AppDataPaths.BaseDirectory` — `%LOCALAPPDATA%\AI_HUB`. В исходниках принудительное применение общих лимитов результатов обнаружено у литературного импорта. Оно действует только внутри настроенных папок, а предварительная проверка не резервирует место между параллельными записями. Лимиты моделей временно отключены по принятому ТЗ о переносе моделей, физическое место проверяется отдельно.

### Подтверждение на установленной копии

Замер выполнен после частичной ручной очистки. Пользователь сообщил, что уже освободил **более 200 ГБ**. Состав удалённых файлов не восстанавливался, результат замера отражает остаток. Настроенная папка результатов была доступна на H:, лимит — 100 ГБ с разрешённым временным превышением 50 ГБ. Размеры ниже — сумма логических размеров файлов без перехода по ссылкам. Это объём хранения, а не прогноз освобождения места. Профиль может содержать данные и других запусков ЛОПАТЫ.

- В `Programs/LOPATA/.lopata-update` оставалось **10,80 ГиБ** резервных файлов в 80 каталогах транзакций. Текущий журнал указывал успешную транзакцию `Healthy`.
- В `AI_HUB/Updates` оставалось **38,85 ГиБ**, в том числе 25,91 ГиБ пакетного кэша, 6,62 ГиБ распаковок шести выпусков, 3,70 ГиБ копий рабочих обновляторов по 77 ревизиям. Здесь же лежат прежние установщики и данные мини-установщика. Вместе два хранилища обновлений занимали **49,65 ГиБ**.
- Из крупных путей, связанных со сценариями, в профиле отмечены `SongClip/Projects` (~9,7 ГиБ), `Music/Jobs` (~8,0 ГиБ), `SpeechAssets/Sessions` (~4,3 ГиБ) и `VideoPreparation/H3Jobs` (~3,6 ГиБ). Эти каталоги могут содержать единственные копии работ или данные возобновления. Объёмы не считать объёмом мусора или доказательством совпадения содержимого.

## 3. Требования к размещению и лимитам

1. Сделать общий способ расчёта путей и учёта жизненного цикла файлов для программы, агентского и фонового запуска, Python/native-процессов, загрузчиков и обновлятора. На старте работы закреплять разрешённые адреса и идентификатор задания. Повтор после сбоя использует сохранённый адрес. Новые настройки действуют на новые работы. Хранилище с уже сохранёнными проектами остаётся доступно для чтения, пока они не перенесены.
2. Приоритет для сохраняемых данных — папка конкретной работы, затем подходящая папка из первой настройки. Хранить в ней проект, созданные для него материалы, нужные контрольные точки и по одной основной копии результата. Для внешнего исходника сохранять его путь. Копия допустима, только когда без неё операция технически невозможна или пользователь явно создал автономный пакет, которому нужен этот файл. Для каждого технического исключения указать причину и срок хранения. Промежуточную копию или преобразованный вход хранить в рабочей временной папке и убирать по завершении, если он больше не нужен для восстановления.
   - При перемещении или удалении внешнего исходника показать, какого файла не хватает и где он ожидался. Открыть проект с остальными доступными данными. Если операция зависит от отсутствующего файла, остановить её и предложить указать новый путь. ЛОПАТА не делает запасных копий на случай, если пользователь переместит или удалит файл после добавления в проект.
3. Временные задания, части скачивания, промежуточные кадры и технические кэши маршрутизировать в управляемые подпапки выбранного при настройке хранилища. По умолчанию использовать выбранную папку результатов. Выбор отдельной папки проекта не меняет место временной работы. ЛОПАТА передаёт дочерним процессам управляемые пути и переменные `TEMP`, `TMP` и профильные пути кэша на уровне запуска. Настройки Windows целиком не менять.
4. Штатный профиль остаётся адресом для небольших файлов начальной настройки и указателей, нужных до открытия рабочего диска. Профиль для входа в сервис и живые базы с правилами блокировки переносятся только с подтверждённой совместимостью. Обязательные данные, которые по техническим причинам должны быть рядом с приложением или на томе назначения, перечислить явно и учитывать в предварительной оценке места. Большие временные данные не перенаправлять на C: при отсутствии или переполнении выбранного диска. Показать путь, причину, нужное и свободное место и предложить выбрать доступную рабочую папку либо возобновить позже.
5. Проверять общий лимит, лимит папки, разрешённый временный запас и фактическое место на каждом задействованном томе до старта. Учитывать ожидаемые временные пик и итог, вложенные пути и параллельные задания как общую нагрузку. Если размер заранее неизвестен, следить за ростом на контрольных точках и безопасно приостанавливать работу до исчерпания резерва. Временное превышение предназначено для промежуточных файлов. Для явно выбранного внешнего каталога действует физический лимит его диска, для каталога внутри управляемого хранилища — также его лимиты. Лимиты моделей остаются по принятому ТЗ.
6. При завершении проверять результат и его метаданные, затем записывать индекс или ссылку на основной файл. Для одного тома завершать запись безопасной атомарной заменой, для двух томов — через короткоживущий файл на томе назначения с проверкой до переключения ссылки. Убирать техническую копию только после подтверждения записи. Данные, нужные для редактирования, просмотра сохранённых попыток или возобновления, получают явную роль. Совпадение имени, формата или размера само по себе не основание удалять файл.
7. Привязать уборку временных файлов к состоянию работы. Безопасная автоматическая уборка разрешена только для управляемых воспроизводимых частей завершённых работ. Для поставленной на паузу, восстановимой или записываемой работы сохранять нужные файлы. По незнакомым версиям, заблокированным файлам и нераспознанным каталогам показывать причину. Сведения о работе в интерфейсе и диагностике должны указывать фактические корни, а пользователю — показывать категорию, занятое место, доступный лимит и остаток по диску.

## 4. Порог локальных обновлений

Сейчас `UpdateTransaction` сохраняет одну текущую запись в `transaction.json`. При следующей транзакции она заменяется. Старые резервные папки сами по себе не дают трёх доступных точек отката. Для новой политики нужен сохраняемый журнал проверенных точек и их зависимостей. [Транзакция обновления](../../Исходники/LOPATA.Updates/UpdateTransaction.cs)

Подключать политику только для проверенной установки. Проверка режима должна предшествовать учёту, подготовке предложений и записи состояния. Dev-сборка пропускает этот раздел целиком, в том числе при общем профиле с установленной бета-версией. [Проверка установки при запуске](../../Исходники/AIHub/Services/ApplicationUpdateStartup.cs)

- Порог по умолчанию **10 ГБ**, меняется в настройках. Подсчёт охватывает архивы и недокачанные части, старые установщики, распаковки, временные копии рабочих обновляторов, кэш мини-установщика и резервные копии обновления во всех распознанных корнях установки и профиля. Подписанные рабочие манифесты, живой загрузчик, установленная программа, действующие наборы движков и сама «Коллекция» защищены. Правило относится к локальным данным пользователя.
- Новые большие загрузки и распаковки обновлений направлять в выбранное рабочее хранилище. Файлы, требуемые для атомарной замены на томах установки и отката, учитывать отдельно и резервировать заранее. Совместимость с уже открытым агентским соединением и проверкой блокировки обновления обязательна. Перемещение резерва отката на другой диск допускается после проверки автономного восстановления и поведения при его отключении.
- При превышении порога упорядочить пригодные к удалению наборы от старых к новым и предложить **старейшую половину по числу наборов**. При нечётном числе округлить вверх. Ориентир — освободить **5 ГБ** за один проход, чтобы накопление не вызывало предложение после каждого обновления. Размеры наборов различаются. Если старейшая половина освобождает меньше 5 ГБ или остаток выше порога, показать фактический результат и причину. Набор — завершённая транзакция или логическая группа артефактов одной загрузки/ревизии. Общий пакет учитывать один раз и защищать, пока есть активный потребитель.
- Помимо текущей установки, защищать **не менее трёх последних предыдущих версий**, к которым возможен проверенный откат. Если история пока короче, сохранять все имеющиеся точки и накапливать их при успешных обновлениях. Для каждой сохранять достаточные подписанные данные, файлы, сведения о настройках и цепочку замен, если без промежуточной версии откат невозможен. Наличие ZIP или папки старой версии не подтверждает готовность отката. Если защищённые точки занимают больше ожидаемого резерва, сохранять их и показывать фактический объём.
- Защитить текущее применение обновления, отложенное обновление, докачку, ожидающий или незавершённый откат, исполняемый рабочий обновлятор и нужные подписанные сведения. Проверять принадлежность старого набора и отсутствие зависимостей по журналам или манифестам. Для новых обновлений сохранять запись о завершении и составе набора. Исторические каталоги без надёжного подтверждения выделять в отчёте отдельно. Одного совпадения шаблона папки недостаточно для удаления.
- В интерфейсе показать общий объём, **«Удалить N самых старых наборов»**, разбивку по дискам, объём защищённого резерва и ожидаемый результат. Действие «Позже» сохраняет файлы. При подтверждении повторно проверить состояние и блокировки. Пропущенные файлы сообщить в результате операции. Повторять предложение при существенном изменении объёма или состава кандидатов. Очистка пакетов не меняет установленную версию и не запускает обновление.

## 5. Старые работы и порядок внедрения

1. **Пути и отчёт.** Реализовать общий расчёт путей и учёт объёма, подключить окно хранилища к действующим настройкам. Для старого профиля построить предварительный список по подтверждённым корням, с группами «Проекты и результаты», «Данные восстановления», «Кэш», «Обновления» и «Установленные компоненты». Отдельно показывать нераспознанные и неполные данные. Уже вручную удалённые файлы считать отсутствующими, сообщать о потерянных ссылках конкретного проекта.
2. **Обновлятор и готовое видео.** Подключить новый каталог загрузок, сводку и предложение очистки. Затем мигрировать «Песня → клип», оба режима шортсов, H3 и VACE, апскейл, видеоредактор и захват. Покрыть Deno RTX, pi‑H3 DWD и стандартные варианты через штатные входы.
3. **Остальные способы хранения.** Подключить музыку, речь, изображения и анимацию, книги и офис, литературу/RAG, нейроконструктор, игровые сценарии, чаты и почту, Песочницу, профили, кэши компонентов и фоновые работы из карты. До приёмки сверить также новые точки записи исходников, скрипты, профили внешних программ и дочерние процессы. Для каждого исключения указать причину, адрес, предельный размер либо политику хранения и тест.
4. **Перенос уже существующих данных.** Подключить его к первому успешному запуску после обновления. Выпустить предложение вместе с первой сборкой, которая умеет переносить заявленные категории. По мере добавления способов хранения показывать новые распознанные группы, пока они не обработаны. Выпуск с новой механикой поставляется с предложением переноса, доступным из настроек и после установки.

### Предложение после обновления

Предложение и его фоновая предварительная проверка запускаются для установленной версии. Запуск dev не меняет состояние предложения в общем профиле и не помечает перенос завершённым.

- Как только обновление подтверждено успешным, начать фоновую проверку известных старых папок. Показать **«Навести порядок в файлах ЛОПАТЫ»**, если есть что перенести или есть старые записи, требующие внимания. На чистой установке пустое предложение пропустить. Сам запуск программы работает в обычном режиме.
- Предварительный план показывает сколько места займёт и освободит перенос по дискам, какие проекты и категории обнаружены, их старый и целевой адрес, а также группы, которые сейчас нельзя перенести. Для отдельной папки работы использовать её сохранённый путь; для остальных — прежний выбор рабочего хранилища. Уже удалённые вручную файлы не восстанавливать и не считать переносимыми. Если путь неизвестен или диск недоступен, показать что требуется для продолжения.
- Действие **«Перенести»** запускает перенос подтверждённых групп. Записать журнал, заблокировать изменения затронутых объектов, сверить копию, переключить ссылки и только затем освободить старую копию. Отложить занятую группу до завершения её работы. При остановке и аварии сохранить исходник либо проверенную цель со связанными данными и дать возобновить работу. Проверить открытие старых проектов, хранилище «Коллекции», историю, фоновое восстановление и совместимость при откате версии.
- **«Позже»** сохраняет старые адреса и оставляет действие в настройках. Повторный запуск не показывает это же предложение поверх работы. Показать итог переноса с числом завершённых и отложенных групп, причиной пропуска и фактически освобождённым местом. Неизвестные файлы, пользовательские экспорты, сохранённые варианты и архивы сохраняются. Для удаления старых наборов обновлений используется отдельное подтверждение из раздела 4, даже если обе рекомендации показаны в одном окне.

## 6. Приёмка

| Проверка | Ожидаемый результат |
| --- | --- |
| Изолированная установленная сборка на C:, рабочие папки на другом томе | Задания из карты пишут проект и итог в выбранный корень. Установка и профиль не растут из-за больших генерируемых файлов. Любой технический рост подтверждён перечнем исключений и журналом записи. Проверить в том числе работу после первого запуска без смены настроек. |
| Для конкретной работы задан третий диск | Проект, нужные для него материалы и итог находятся там. Временные файлы — в исходной рабочей папке. После завершения основной результат один, проект открывается через историю, сохраняемые варианты доступны. Явный экспорт копии и переносимый проект работают как отдельные действия. |
| Внешние исходники | Добавление больших аудио, видео и изображений по ссылке не создаёт постоянных дублей. Для подтверждённого исключения тест показывает, почему исходник нельзя использовать напрямую, где лежит копия и когда она убирается. При переносе или удалении внешнего файла проект открывается и показывает недостающий источник. Проверить замену ссылки и продолжение задания. |
| Смена папки, параллельные работы, лимиты и пропавший диск | Папка старой работы закреплена. Новая работа использует новые настройки. Общий и индивидуальный лимиты и физический запас соблюдаются с учётом параллельных задач, вложенных папок, временного превышения и частично завершённой записи. При отсутствии диска сообщение объясняет, где и почему невозможно продолжить. Не возникает запасных гигабайт на C:. |
| Пауза, остановка, авария и два тома | Восстанавливаемые задания, предпросмотр и редактирование сохраняются. После успеха кэш задания уходит по политике. При обрыве посередине переноса или записи результата после перезапуска доступно восстановление либо целый исходный экземпляр. Перезапуск не дублирует результат. |
| Несколько последовательных обновлений и превышение 10 ГБ | Ниже порога предложения нет. При превышении показана старейшая половина допустимых наборов, оценка освобождаемого места с ориентиром 5 ГБ и фактический резерв. Проверить чётное и нечётное число наборов, недостаточный объём, совместно используемые файлы и отказ пользователя. После согласия, на независимых копиях одной установки, выполнить проверенный откат к каждой из трёх последних предыдущих версий. Отдельно проверить короткую историю, большой защищённый резерв, отложенное обновление, докачку и переключение открытого агента. |
| Профиль после ручной очистки и переход со старой версии | Программа открывает оставшиеся проекты и не удаляет незнакомые каталоги, файлы пользователя, защищённые копии и живые базы. Перенос с кириллицей, длинными путями, несколькими дисками, конфликтом имени, недоступным каталогом или ссылкой не подменяет и не стирает чужие данные. Проверить отмену, откат и повтор той же операции. |
| Первое предложение действующему тестировщику | Установить файловое обновление на стенд со старой структурой. После первого успешного запуска появляется план переноса с использованием сохранённых настроек. До согласия старые работы остаются на местах. После «Позже» проект открывается по старому пути, а перенос доступен из настроек. После «Перенести» проект и материалы открываются с новых адресов, ссылки в истории обновлены, а потерянные при прежней ручной очистке файлы отмечены. Чистая установка проходит без такого предложения. |
| Dev и установленная бета-версия с общим профилем | Создать в профиле повод предложить очистку и перенос. Dev не сканирует старые папки в рамках этих механизмов, не показывает предложения и не меняет их состояние и файлы обновлятора. После запуска установленной версии оба предложения доступны. Проверить обычное сохранение проекта и временных файлов в настроенных папках в обеих сборках. |
| Итоговые доказательства | Для каждого способа хранения из карты — сценарий, сохранённый путь, вид данных, владелец, срок хранения, показания до и после и необходимая причина исключения. Для тяжёлых сценариев — реальная короткая генерация из установленной тестовой сборки с наблюдением путей программы и дочерних процессов. Для обновлятора — полный набор проверок подписи и автономный стенд. |
