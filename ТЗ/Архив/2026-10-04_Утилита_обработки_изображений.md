## Назначение и границы текущего обсуждения

### Дополнение: две быстрые команды Проводника

Отдельно от полноценной утилиты в контекстном меню изображений:
«ЛОПАТА → В WebP» и «ЛОПАТА → Увеличить ×2». Других команд здесь нет.
×2 использует встроенный качественный фильтр без докачки ИИ и заменяет
выбранный файл. Конвертация создаёт WebP и только после успешной проверки
удаляет исходник; существующие посторонние WebP не перезаписываются.
Повреждённый, занятый или изменившийся во время работы исходник не удаляется.
Обе операции сначала создают и проверяют отдельный временный результат.
Исходный WebP для команды «В WebP» оставляется как есть.

Команда передаётся существующему экземпляру через single-instance/Named Pipe
без показа окна. Если приложение не запущено, оно запускается тихо, выполняет
команду и остаётся в трее. Несколько запросов образуют очередь; не прерывать
уже выполняемую тяжёлую операцию. Без необходимости загружать модели.
Общий фоновый механизм, пауза, восстановление и журнал сохраняются.

Настройки → Общие → Интеграция с Windows:
«Добавить команды ЛОПАТЫ в контекстное меню изображений», включено по умолчанию.
Регистрация на текущего пользователя без прав администратора; отключение
убирает только собственные ключи. Для тестов — изолированные ключи и файлы.
Это отдельная политика файлов: утилита по-прежнему никогда не изменяет исходники.

#### Зафиксированная реализация быстрых команд

- «В WebP»: размеры исходника сохраняются, используется WebP без потерь.
  Исходный WebP остаётся без повторной конвертации. Имя результата образуется
  от имени исходника в той же папке; при занятом имени выбирается свободное.
- «Увеличить ×2»: ширина и высота умножаются на два; встроенный Lanczos3,
  исходный формат и путь. Для форматов с параметром качества применяется 100;
  режим без потерь используется там, где его поддерживает этот формат.
- Сохранённые настройки полной утилиты и её избранный инструмент на быстрые
  команды не влияют. Докачка и применение ИИ здесь не требуются.
- Перед заменой проверяются декодируемость, размеры и число кадров результата.
  Исходник и результат удерживаются файловыми дескрипторами; их идентичность
  и SHA-256 сверяются с журналом. До подтверждения публикации исходник
  сохраняется в резерве транзакции. Чужой файл при совпадении имени
  не перезаписывается. При сбое журнал позволяет завершить публикацию
  или сохранить исходник для восстановления, не повторяя готовое увеличение.
- Запрос сначала сохраняется в `app-data/image-shell`, и лишь затем IPC
  подтверждает его приём. RequestId защищает от повторной доставки одного
  запроса. Очередь `image-shell` ждёт свободного общего фонового механизма;
  три повтора после ошибки, пауза и продолжение относятся к незавершённому
  файлу. Уведомление результата открывает соответствующий файл в Проводнике.
- Тихий shell-запуск не показывает главное окно и не меняет пользовательскую
  настройку обычного запуска в трее. После выполнения приложение остаётся
  в трее. Уже открытый экземпляр принимает запрос, не переключая страницу.

#### Регистрация и ограничения Windows

Единственная ветка регистрации:
`HKCU\Software\Classes\SystemFileAssociations\image\shell\LOPATA`.
Она содержит только две команды, путь текущего `Environment.ProcessPath`
и маркер владения `AIHub.ImageShellIntegration.v1`. Командная строка:
`"<exe>" --shell-image webp|upscale2 -- "%1"`. Пути заключаются в кавычки;
IPC передаёт тип операции и буквальные пути, а не произвольную shell-команду.
Регистрация актуализируется при обычном запуске, смене настройки и языка.
Отключение и удаление установки очищают только её собственную ветку с тем же
маркером и исполняемым файлом; регистрация другой копии ЛОПАТЫ сохраняется.
Тестовые хосты не регистрируются, тесты сервиса ограничены отдельным
`HKCU\Software\AIHub.Tests\<GUID>`. Установщик с `StandDataRoot` не очищает
production-ветку. Пересборка установщика в этот этап не входит.

Это классические команды Проводника. В Windows 11 они могут находиться
в «Показать дополнительные параметры»; отдельное расширение компактного
меню `IExplorerCommand` не реализовано. Для каждой команды задан
`MultiSelectModel=Document`: Windows вызывает её для отдельных выбранных
файлов, которые попадают в очередь ЛОПАТЫ. У этого системного механизма
по умолчанию лимит 15 выбранных файлов; глобальный лимит Проводника
приложение не меняет. Массовые партии добавляются через полноценную утилиту.

Технические основания: [каскадное меню Microsoft](https://learn.microsoft.com/en-us/windows/win32/shell/how-to-create-cascading-menus-with-the-extendedsubcommandskey-registry-entry),
[модель выбора файлов Microsoft](https://learn.microsoft.com/en-us/windows/win32/shell/context-menu-handlers#employing-the-verb-selection-model).
Фактические прогоны и их границы ведутся в
[протоколе проверок](../../Документы_проекта/Исследования/2026-10-04_Утилита_изображений_проверки.md).

Самостоятельная утилита в категории утилит ЛОПАТЫ: пользователь добавляет
исходные изображения и получает новые файлы после выбранной обработки.
Это инструмент обработки файлов без большого встроенного предпросмотра
или сравнения исходника с результатом. Маленькие миниатюры в списке
нужны для узнавания файлов и не являются зоной предпросмотра.

Связанный готовый механизм: [программное масштабирование генераций](Архив/2026-10-04_Программное_масштабирование_генераций.md).
Его общий CPU-сервис предусмотрен для повторного использования.
Список методов и выходные размеры до 8K утверждены ниже. Ранее отдельный
экспериментальный ИИ-апскейл 8K был исключён из этапа генерации. Здесь 8K —
выходной размер утилиты; свободная творческая перерисовка не входит в объём.
Реализованный путь: Утилиты → Изображения → Обработка изображений.

## Компоновка окна

1. Сверху остаётся стандартная общая шапка ЛОПАТЫ. Синяя полоса
   пользовательского эскиза обозначает именно её.
2. Под шапкой слева — вертикальная карта источников: специальные кнопки
   наверху, ниже дерево дисков, папок и доступных в них файлов.
3. Справа от карты, над основной рабочей областью — зона управления.
   Слева в ней основные параметры, справа настройки выбранного способа
   обработки с постоянно видимыми пояснениями.
4. Под зоной управления в центре — вертикальный список добавленных
   в обработку файлов. Ориентир — строки Проводника: маленькая миниатюра,
   имя файла и расположение под ним. Для сетевого источника — его адрес.
5. Справа от списка — информационная зона и статусы процессов.
   Сверху анимация процесса, ниже состояние ИИ при его использовании,
   внизу журнал событий в стиле терминала.

Эскиз задаёт расположение областей, а не их точные размеры, цвета или
копирование всего Проводника. Разделы «Недавние», «Избранное», облачные
службы, дополнительные колонки и другие элементы фонового скриншота
автоматически в требования не входят. Отдельный большой предпросмотр
внутри утилиты не нужен. Оформление — в общей теме ЛОПАТЫ.

## Верхняя зона управления

Левый блок содержит:

- желаемое разрешение результата;
- выбор инструмента через отдельное окно;
- галочку «Только сменить формат»;
- формат экспорта;
- место экспорта;
- необязательный выбор желаемого названия результатов.

Справа расположен блок настроек выбранного способа апскейла.
Его содержимое зависит от способа обработки. Правила настроек, размеров
и экспорта описаны ниже; точные диапазоны зависят от выбранной реализации.

## Утверждённый список методов обработки

Сохраняем все десять вариантов: семь обычных и три ИИ. Пользователь
осознанно принял избыточность выбора. Близость некоторых фильтров сама
по себе не является разрешением удалить их из списка.
В выборе две группы: «Обычная обработка» и «ИИ-обработка».

| Метод | Название в интерфейсе | Назначение и ограничения |
| --- | --- | --- |
| Nearest Neighbor | Без сглаживания | Чёткие пиксельные блоки, схемы и пиксельная графика; ступенчатые контуры на фото. |
| Bilinear | Быстрый мягкий | Простое мягкое масштабирование; увеличение смягчает детали. |
| Mitchell | Сбалансированный | Компромисс резкости и плавности; повторное использование механизма генератора. |
| Catmull–Rom | Чёткий | Более резкие контуры; возможны обводки контрастных границ. |
| Lanczos3 | Детальный | Фото, мелкие детали и качественное уменьшение; возможны обводки. |
| Area / усреднение площади | Уменьшение | Усреднение пикселей при уменьшении; не предлагать как восстановление деталей при увеличении. |
| HQx (в первой реализации HQ2x) | Пиксельная графика | Специализированное увеличение спрайтов и ретрографики; не для фото. В проверенной реализации ImageMagick есть HQ2x, не обещать полноценные HQ3x/HQ4x. |
| Real-ESRGAN | ИИ · Фото и восстановление | Увеличение и восстановление фото, включая дефекты сжатия; может менять фактуры и мелкие детали. |
| Real-CUGAN | ИИ · Рисунки и аниме | Рисованная графика, контуры и шумоподавление; может упрощать тонкие линии и удалять мелкие элементы вместе с шумом. |
| SwinIR — классическое увеличение | ИИ · Бережное увеличение | Относительно чистые исходники и сохранение структуры. Выбирать классический SR-вариант, не подменять его GAN-моделью real_sr. |

Mitchell, Catmull–Rom и Lanczos3 различаются характером резкости, но не
составляют три принципиально разных класса обработки. «Бережное» у SwinIR
обозначает предполагаемое назначение, а не доказанное превосходство:
сравнительные тесты выбранных сборок ещё не проведены.

### Дорисовка в ИИ-режимах

Все три ИИ-метода могут неверно восстанавливать отсутствующие детали.
Ожидаются главным образом локальные изменения фактуры, волос, линий
и узоров; точное сохранение содержания не гарантируется. При одинаковом
файле, модели и настройках результат обычно повторяем: повторный запуск
не является способом получить случайный новый вариант.

В описании ИИ-режимов: «Может изменять мелкие детали изображения».
По умолчанию — умеренная обработка без отдельного улучшателя лиц.
Шумоподавление показывать только при реальной поддержке выбранной моделью;
не представлять его универсальной настройкой силы дорисовки.
Обычное масштабирование не пытается восстановить отсутствующие детали.
Свободная творческая перерисовка не утверждается. Выходной размер 8K
входит в обычные пресеты утилиты, а не в отдельный творческий режим.

### Техническая основа и проверка перед внедрением

Общие ввод, обработка файлов и экспорт; внутри переключается метод.
Для обычных операций использовать существующие SkiaSharp и ImageMagick,
проверив поддержку конкретных алгоритмов выбранной сборкой. ИИ-компоненты
докачиваются по выбору пользователя штатным механизмом, с многопоточной
загрузкой и возобновлением там, где источник это поддерживает.
Конкретные версии runtime, веса, множители, параметры, лицензии кода
и весов проверяются перед внедрением через общий каталог компонентов.
Точные требования к памяти и скорость пока не зафиксированы и не измерены.

Источники технического обсуждения (04.10.2026):

- [ImageMagick — параметры и методы](https://imagemagick.org/command-line-options/).
- [ImageMagick — фильтры масштабирования](https://usage.imagemagick.org/filter/).
- [Real-ESRGAN](https://github.com/xinntao/Real-ESRGAN).
- [Real-CUGAN](https://github.com/bilibili/ailab/blob/main/Real-CUGAN/README_EN.md).

## Выбор инструмента, порядок и избранное

Выбор открывается в отдельном окне. Для каждого инструмента показываются
человеческое название, техническое имя модели/алгоритма, краткое назначение,
ограничения и состояние «Готов к работе» или «Нужно скачать».
Там же видны недостающие компоненты, объём загрузки и действие скачивания.
Уже установленные совместимые компоненты используются повторно.

Порядок списка — от восстановления деталей к простому масштабированию:

1. Real-ESRGAN — восстановление деталей фотографий.
2. Real-CUGAN — восстановление деталей рисунков и аниме.
3. SwinIR — бережное ИИ-увеличение.
4. Lanczos3 — детальное масштабирование.
5. Catmull–Rom — чёткие контуры.
6. Mitchell — сбалансированное масштабирование.
7. HQ2x — увеличение пиксельной графики.
8. Bilinear — мягкое масштабирование.
9. Nearest Neighbor — сохранение пиксельных блоков.
10. Area — уменьшение изображения.

Это порядок по назначению, не обещание универсального рейтинга качества.
ИИ-группа сверху. Специализированные методы сохраняют пояснение назначения.
Звёздочка «Использовать по умолчанию» назначает один избранный инструмент;
выбор сохраняется между запусками. Временный выбор другого инструмента
не меняет избранный. Скачиваемый инструмент назначается после установки.
Начальный избранный — Lanczos3. Это заменяет раннее предложение Mitchell.

## Настройки и их объяснения

Показывать все поддерживаемые настройки обработки выбранного инструмента,
включая экспертные и способные дать неожиданный результат. Не скрывать их
только из-за сложности. Не добавлять параметры чужих моделей или обучения.
Все названия настроек — человеческие аналоги технических терминов.
Возле каждой настройки постоянно видны назначение и влияние на результат:
обычным текстом рядом или под ней, без раскрывающихся пояснений и без
обязательного наведения. Технический термин при необходимости вторичен.
Экспериментальные параметры помечаются с конкретным последствием:
обводки, потеря мелких деталей, повышенный расход памяти и т. п.
Для каждого инструмента — «Вернуть рекомендуемые настройки».

Общие параметры: размер, формат и применимое качество сжатия, прозрачность
или цвет фона для форматов без неё, папка и имя результата. Дополнительная
резкость после масштабирования — отдельная общая обработка, по умолчанию
выключена; не выдавать её за собственную настройку каждой модели.
Интерфейса выбора/изменения метаданных нет.

| Метод | Настройки и ограничения |
| --- | --- |
| Nearest Neighbor | Размер; режим целого увеличения ×2, ×3, ×4 и т. д. для одинаковых пиксельных блоков. |
| Bilinear | Общие настройки и реально доступные параметры выбранной реализации; не придумывать «качество алгоритма». |
| Mitchell | Рекомендуемые коэффициенты по умолчанию; доступные экспертные коэффициенты можно менять с понятными подписями и предупреждением об изменении характера фильтра. |
| Catmull–Rom | Аналогично: рекомендованный профиль и поддерживаемые экспертные коэффициенты с пояснениями. |
| Lanczos3 | Стандартный профиль — три лепестка. Если реализация позволяет менять их число/охват, показать человеческое объяснение и отметить, что это изменяет стандартный профиль Lanczos3. |
| Area | Размер/процент уменьшения; увеличение недоступно. |
| HQ2x | Родное увеличение ×2. Повторный проход допустимо обозначать как два прохода HQ2x, но не как HQ4x. |
| Real-ESRGAN | Множитель и варианты модели по фактическим весам, устройство, обработка частями и поддерживаемые настройки памяти/точности. Шумоподавление 0–1 есть у realesr-general-x4v3 в Python; не обещать этот ползунок у x4plus или стандартного Vulkan-инструмента. |
| Real-CUGAN | Множитель ×2/×3/×4 и уровни шумоподавления только для поддерживающих их весов; устройство, части, память, объединение повёрнутых/отражённых проходов при поддержке. Прочие параметры зависят от Python/Vulkan-реализации. |
| SwinIR classical SR | Множитель по загруженным весам (существуют ×2/×3/×4/×8); размер частей и их перекрытие, устройство. Подавление шума/JPEG-дефектов — отдельные модели, не ползунки классического увеличения. |

Параметры расхода памяти имеют автоматические рекомендуемые значения,
но поддерживаемая ручная настройка остаётся доступной с видимым описанием.
Точный набор и диапазоны сверяются с зафиксированными версиями движков;
ожидаемые характеристики не выдаются за результат наших замеров.

## Размер результата

Основной выбор — обобщённые пресеты. Программа учитывает ориентацию
и соотношение сторон, сохраняет пропорции без растягивания и обрезки.
Пресет задаёт длинную сторону; вторая округляется до целого пикселя.

| Пресет | Длинная сторона, пикселей |
| --- | ---: |
| 360 | 640 |
| 720 | 1280 |
| 1080 | 1920 |
| 4K | 3840 |
| 8K | 7680 |

Пример 1080: 16:9 → 1920×1080, 9:16 → 1080×1920,
квадрат → 1920×1920. В списке до начала обработки показывать
«исходные размеры → итоговые размеры» после определения размеров источника.
Для сетевого файла размеры могут стать известны только после загрузки.
После метода с фиксированным множителем доводить точный размер обычным
масштабированием. Нельзя скрыто подменять Area увеличивающим алгоритмом.
Проценты и ручные размеры упоминались как возможные дополнительные режимы;
их обязательность после выбора пользователем обобщённых пресетов не уточнена.

## Только смена формата и экспорт

Галочка «Только сменить формат» сохраняет исходные размеры и отключает
масштабирование, ИИ, резкость и прочую обработку изображения. Остаются
формат, сжатие, применимый фон, папка и имя результата. После выключения
возвращаются ранее выбранные параметры обработки.

Форматы охватить максимально широко: включать в экспорт все применимые
форматы изображений, запись которых реально поддерживается поставляемой
сборкой и зависимостями. Не ограничивать заранее четырьмя названиями,
но не путать декодирование с кодированием и не показывать внутренние
псевдоформаты как пользовательские форматы изображений.

Исходники только читаются: не перезаписывать, не переименовывать и не
менять их метаданные. Результаты всегда отдельные. При совпадении имён
добавлять номер, ничего автоматически не перезаписывать.
Если обрабатывается более одного файла, в выбранном месте экспорта
создавать папку процесса «Дата_Апскейл_ОбщийНомер», например
«2026-10-04_Апскейл_000123». Общий номер сохраняется между запусками.
При обходе подпапок сохранять их структуру внутри папки результатов.
Точный шаблон пользовательского переименования отдельных файлов ещё не задан.

### Метаданные — внутренняя автоматическая механика

Сохранять исходные метаданные, включая авторство, где это поддерживается.
Обновлять технические сведения об изменившихся размерах и добавлять отметку
ЛОПАТЫ: технология, исходные/итоговые размеры, дата и время обработки.
При одной конвертации указывать конвертацию, а не апскейл.
Прямое уточнение пользователя: выполнять это молча там, где возможно.
Не добавлять настройки, предупреждения, уведомления, рекламные обещания
или пояснения ограничений метаданных в интерфейс. Не обещать полного
переноса между любыми форматами; отсутствие поддержки не является ошибкой
обработки изображения. Отдельные файлы метаданных не согласованы.

## Очередь, дубликаты и анимированные файлы

Управление: «Начать», «Пауза», «Остановить». При ошибке файла — до трёх
повторных попыток после первоначальной (до четырёх попыток суммарно).
После исчерпания попыток отметить ошибку и продолжить остальные файлы.
Завершённые результаты при повторах не обрабатывать заново. Неудачные
файлы можно повторить отдельно. Сохранять общий контракт фоновых операций.

Повтор того же пути или той же прямой ссылки показывается в списке красным
с пояснением «Дубликат — уже добавлен», но повторно не обрабатывается.
Не путать повтор источника с разными файлами, имеющими одинаковое имя.

Анимированные GIF/WebP: включить обычное масштабирование кадров при
подтверждённом сохранении таймингов, прозрачности и повторения. Проверить
полные кадры и способ их наложения, а не обрабатывать только первый кадр.
ИИ-анимации на первом этапе пропускать с пояснением: отдельная задача
с высокой стоимостью и возможной нестабильностью деталей между кадрами.
Если выходной формат не поддерживает анимацию, не превращать её молча
в один кадр. Пользователь разрешил пропуск проблематичных вариантов.
После обработки в списке доступно открытие результата, без зоны предпросмотра.

## Правая информационная зона

### Анимация процесса

В верхней части — палочный человечек, который идёт от одного края
выделенной области к другому, разворачиваясь у границ.
При паузе человечек останавливается; после завершения работы — тоже.
Движение обозначает активную работу и не выдаётся за процент выполнения.
Фактический числовой прогресс показывается отдельно от анимации.
Анимация должна быть лёгкой и не мешать обработке изображений.
Предпросмотр исходного или обработанного изображения здесь не появляется.

### Состояние ИИ

Под анимацией размещается состояние ИИ, когда он задействован:
например, загрузка модели или обработка. Список трёх ИИ-методов утверждён
выше; точный состав статусов предстоит уточнить.

### Журнал событий

Ниже — журнал с оформлением в стиле терминала:

- тёмный фон и моноширинный шрифт;
- время перед каждой строкой;
- разные цвета обычных событий, успешного завершения и ошибок;
- новые события добавляются снизу;
- текст можно выделять и копировать.

Строки сообщают понятными словами, какой файл начат, какой результат
сохранён, что пропущено и где возникла ошибка. Это журнал процесса;
ввод и выполнение команд терминала в текущие требования не входят.

## Левая карта: навигация и перетаскивание

Карта предназначена для пользователей, которые знают, где искать файлы.
Переходы по дискам и папкам раскрывают содержимое только в карте.
Обычный выбор файла или папки в ней ничего не добавляет в обработку
и не подменяет содержимое центрального списка.

Из карты файлы и папки добавляются в центральный список только
перетаскиванием. Для папки в обработку берутся изображения.
Галочка «Включая вложенные папки» изначально выключена; при включении
результаты сохраняют структуру вложенных папок.

Контекстное меню карты:

- «Открыть в Проводнике»: открыть нужную папку; для файла — его папку
  с выделением этого файла.
- «Просмотреть» для файла: открыть сам файл в существующем просмотрщике
  ЛОПАТЫ. Просмотр не добавляет файл в обработку.

## Специальные кнопки над картой

| Кнопка | Действие |
| --- | --- |
| Добавить ссылки | Открыть отдельное окно для многострочного ввода прямых ссылок на изображения. |
| Добавить файлы | Открыть стандартный диалог Windows с выбором одного или нескольких изображений. |
| Добавить папку | Открыть стандартный диалог Windows для выбора папки. |
| Сгенерированные изображения | Открыть стандартный диалог выбора файлов сразу в папке, указанной в настройках сохранения генераций. |

После подтверждения диалога выбранное пополняет общий список обработки.
Отмена ничего не добавляет. Кнопка генераций не переключает левую карту
и не добавляет автоматически всю папку генераций.

Системные диалоги нужны тем, кому удобны миниатюры, поиск и выбор
из большой библиотеки. Это стандартная механика выбора Windows,
а не отдельное самостоятельно написанное окно библиотеки ЛОПАТЫ.
Все способы добавления работают с одним общим списком обработки.

## Добавление из сети

В отдельном окне «Добавить ссылки» одна строка соответствует одной ссылке.
Пользователь может вставить сразу список произвольного количества ссылок;
не вводить искусственный лимит числа строк. После подтверждения ссылки
добавляются как источники изображений для обработки.

Пример прямой ссылки из обсуждения:
`https://s0.rbk.ru/v6_top_pics/media/img/1/76/347691541130761.webp`.
Это иллюстрация типа источника, не обязательный адрес для реализации
или тестовой загрузки. Разбор обычных веб-страниц и автоматический сбор
всех картинок с сайта пока не согласованы.

## Другие способы добавления

Общее требование пользователя — добавлять изображения всеми привычными
способами. Помимо кнопок и карты предусматриваются:

- перетаскивание файлов и папок из внешнего Проводника;
- вставка изображения из буфера обмена;
- вставка скопированных файлов;
- добавление прямой ссылки или списка ссылок через отдельное окно.

Точное расположение действий буфера обмена и клавиатурные сочетания
ещё предстоит уточнить. Пункт буфера обмена предлагался, но его место
и вид пока не закреплены так же подробно, как четыре кнопки выше.
