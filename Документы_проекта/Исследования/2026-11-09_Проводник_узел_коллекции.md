# Раздел «ЛОПАТА» в левой панели Проводника Windows 11

09.11.2026. Исследование документации Microsoft для [рабочего ТЗ коллекции](../../ТЗ/2026-11-09_Коллекция_произведений_в_Проводнике_Windows.md). Рассматривается самостоятельный раздел, как в примере пользователя с Яндекс Диском. При выборе «ЛОПАТА» правая панель сразу показывает все найденные произведения всех типов и сценариев. Уточнение пользователя: категории показаны сворачиваемыми группами справа, пока слева выбран один узел «ЛОПАТА». Поиск уже выбран гибридный: локальные сведения о местах сохранения дополняются системным поиском по встроенным признакам происхождения.

## Два способа получить собственную строку слева

| Механизм | Что увидит пользователь | Пригодность для коллекции |
|---|---|---|
| Именованный узел, которому Windows делегирует показ обычной папки | Свои имя и значок слева, справа — содержимое каталога TargetFolderPath. В дереве раскрываются реальные подпапки | Подходит для короткой проверки размещения узла. Если положить в каталог ярлыки или описания поиска, они сами станут элементами папки. Такой опыт проверит внешний вид входа, но ещё не выполнит требование об оригиналах в правой панели |
| Собственный источник данных Shell с виртуальными папками | Корень получает собственный идентификатор. Расширение перечисляет оригиналы и предоставляет данные для их группировки. Отрисовку можно поручить штатному представлению | Основной кандидат. Он позволяет подать в одно представление оригиналы с разных томов, найденные обоими способами. Понадобятся реализация объектов Shell, проверка файловых команд и обслуживание компонента при обновлении |

Первый путь Microsoft показывает в инструкции для поставщика облачного хранилища. Указанные там шаги регистрации навигации и шаги регистрации синхронизации имеют разные назначения. Пример навигации опирается на обычную папку. Для произвольного виртуального дерева Microsoft описывает расширение пространства имён и поставляет образец Explorer Data Provider. Образец открывается под «Этот компьютер» и служит примером устройства папок. Место размещения корня ЛОПАТЫ выбирается отдельно. [Навигационная часть примера](https://learn.microsoft.com/en-us/windows/win32/shell/integrate-cloud-storage#instructions) · [Виртуальные папки Shell](https://learn.microsoft.com/en-us/windows/win32/shell/nse-works) · [Образец Explorer Data Provider](https://learn.microsoft.com/en-us/windows/win32/shell/samples-explorerdataprovider)

## Регистрация и положение в дереве

Для собственного корня Windows предусматривает точку подключения под системной виртуальной папкой Desktop. У текущего пользователя это ветка `HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\Desktop\NameSpace\{CLSID}`. CLSID — постоянный идентификатор класса ЛОПАТЫ. Ветка MyComputer соответствует другой иерархии, где корень станет дочерним для «Этот компьютер». Положение в дереве, класс папки и значок — отдельные составляющие регистрации. [Расположение расширения в иерархии Shell](https://learn.microsoft.com/en-us/windows/win32/shell/nse-junction)

Свойство `System.IsPinnedToNameSpaceTree` обозначает закрепление в панели навигации. В примере Microsoft имя, значок, закрепление и подключение под Desktop задаются раздельно. Там же отдельно скрывают лишнюю иконку с видимого рабочего стола. Для ЛОПАТЫ проверить это в обычном режиме и с включённым «Показать все папки», а также во втором профиле пользователя. Точное соседство с другими расширениями и конкретный порядковый номер не брать за критерий. [Свойство закрепления](https://learn.microsoft.com/en-us/windows/win32/properties/props-system-ispinnedtonamespacetree) · [Регистрация навигационного узла](https://learn.microsoft.com/en-us/windows/win32/shell/integrate-cloud-storage)

## Что происходит при выборе «ЛОПАТЫ» и сворачивании группы

Корень сообщает Проводнику состав коллекции. Штатное представление DefView выводит оригиналы справа. У каждого заголовка группы своя стрелка. Раскрытие меняет видимость файлов внутри той же области просмотра, сохраняя адрес и выделенный узел. [Контракт перечисления](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-ishellfolder-enumobjects) · [Штатное представление папки](https://learn.microsoft.com/en-us/windows/win32/api/shlobj_core/nf-shlobj_core-shcreateshellfolderview)

Пример пользователя показывает конкретные названия типов файлов. Для такого вида проверить группировку по свойству `System.ItemTypeText`; для более крупных системных групп ранее проверено `System.Kind`. Метод `SetGroupBy` принимает ключ свойства и порядок. Для собственных групп внутри виртуальной папки Microsoft предоставляет `ICategoryProvider` и `ICategorizer`. Метод `GetCategory` связывает элементы с идентификаторами групп, а `GetCategoryInfo` задаёт отображаемый текст. Например, два PNG можно разместить под заголовками «Генерация изображений» и «Захват экрана» по сохранённому сценарию. Образец SDK подтверждает механизм. Его поведение в нашей коллекции Windows 11 нужно проверить на стенде. [Тип элемента](https://learn.microsoft.com/en-us/windows/win32/properties/props-system-itemtypetext) · [SetGroupBy](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-ifolderview2-setgroupby) · [GetCategoryInfo](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-icategorizer-getcategoryinfo) · [Пример Microsoft](https://learn.microsoft.com/en-us/samples/microsoft/windows-classic-samples/explorerdataprovider/)

## Как справа сохранить настоящие файлы

Список результатов сводит две записи об одном доступном файле к одному элементу, сохраняя разные физические копии. По исходному адресу следует получать объект файловой системы Shell. Виртуальная коллекция и действительный родитель файла имеют разные идентичности. Для команды «Открыть расположение файла» Microsoft описывает `IIdentityName`, через который Shell узнаёт настоящий объект. Отдельно проверить открытие, свойства, миниатюры, копирование, перемещение, переименование и удаление. Интерфейс `ITransferMediumItem` участвует в привязке к объекту для переноса. Передавать операции оригиналу с его действующими правами. Успешная отрисовка значка этих возможностей не подтверждает. [Определение истинного расположения](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nn-shobjidl_core-iidentityname) · [Файловые операции для представляемого объекта](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nn-shobjidl_core-itransfermediumitem)

При множественном выделении оригиналы могут иметь разные физические родительские папки. Некоторые операции Shell над массивом требуют общего родителя. Для операций над всем выбором исследовать массив Shell-объектов, построенный из абсолютных идентификаторов оригиналов. В стенде выделить два одноимённых файла на разных дисках и проверить копирование обоих. При обновлении открытой коллекции использовать адресное уведомление Shell об изменении её содержимого. [Ограничения привязки массива](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-ishellitemarray-bindtohandler) · [Создание массива из PIDL](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-shcreateshellitemarrayfromidlists) · [SHChangeNotify](https://learn.microsoft.com/en-us/windows/win32/api/shlobj_core/nf-shlobj_core-shchangenotify)

Для объединения уже найденных объектов заслуживает проверки IResultsFolder::AddItem. Пример Microsoft наполняет встроенный в приложение ExplorerBrowser. Он демонстрирует работу списка, но его применимость внутри собственного узла штатного Проводника требует отдельной проверки. Базовый путь для стенда — собрать подтверждённые оригиналы обоих источников и перечислить их как содержимое корня коллекции. [Добавление Shell-объекта](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl/nf-shobjidl-iresultsfolder-additem) · [Образец ExplorerBrowser Custom Contents](https://learn.microsoft.com/en-us/windows/win32/shell/samples-explorerbrowsercustomcontents)

## Поставка в составе ЛОПАТЫ

Для прототипа предпочтителен небольшой нативный COM-компонент соответствующей Проводнику архитектуры. В нём нужны папки Shell и связь с данными коллекции. Разбор тяжёлых форматов, ожидание недоступной сети, обход папок и запуск моделей на потоке интерфейса Проводника исключить. Опубликованный образец Microsoft демонстрирует работу самого расширения после регистрации обычным пользователем, при этом регистрация собственной схемы свойств — отдельная привилегированная операция. Коллекции для первого стенда достаточно штатных свойств. [Образец и условия регистрации](https://learn.microsoft.com/en-us/windows/win32/shell/samples-explorerdataprovider) · [Рекомендации Microsoft по расширениям внутри процесса](https://learn.microsoft.com/en-us/previous-versions/windows/desktop/legacy/dd758089(v=vs.85))

Оба установщика ЛОПАТЫ рассчитаны на пользовательские права. Обновлятор ожидает завершения приложения, а DLL расширения может оставаться загруженной в работающем Explorer. Возможная схема для проверки — каталог DLL по версии, переключение собственной регистрации только после проверки нового файла, отложенная уборка прежнего после его освобождения. Проверить согласованность активной версии и регистрации при откате. Не останавливать открытый Проводник пользователя ради замены файла. Отдельно проверить отключение интеграции, удаление с открытой папкой коллекции, два профиля и ограничения корпоративной политики. [Полный установщик](../../Инструменты/Installer/LOPATA.iss) · [Миниустановщик](../../Инструменты/Installer/LOPATA.Mini.iss) · [Запуск обновления](../../Исходники/LOPATA.Updater/UpdateHost.cs) · [Замена файлов и откат](../../Исходники/LOPATA.Updates/UpdateTransaction.cs)

В проекте есть общий кандидат для уборки при удалении, включая установки, обновлённые файловым патчем. Полный и миниустановщик вызывают UpdateHost с ключом --unregister. Проверить снятие принадлежащих именно этой установке узла и класса до удаления обслуживающих файлов. Если DLL всё ещё используется оболочкой, проверить завершение уборки после её освобождения. Сначала испытать x64 на целевой Windows 11. При заявлении поддержки других архитектур проверять загрузку DLL именно в соответствующий процесс оболочки. [Существующая процедура удаления](../../Инструменты/Installer/UpdateFlow.iss) · [Обновление занятых DLL](https://learn.microsoft.com/en-us/windows/win32/dlls/dynamic-link-library-updates) · [Совместимость процессов разной разрядности](https://learn.microsoft.com/en-us/windows/win32/winprog64/process-interoperability)

## Изоляция в отдельном процессе

Предлагаемая архитектура для проверки — небольшой нативный адаптер внутри Explorer и независимый пользовательский обработчик коллекции. Долгие запросы Windows Search, чтение журналов и метаданных относятся к обработчику. Адаптер обслуживает стандартные интерфейсы Shell, выдаёт подготовленный набор и принимает уведомления об обновлении. В IPC нужны границы времени и размеров, отмена, обработка отключения и проверка пользователя. Начальный вариант жизненного цикла — по требованию с завершением после простоя.

Такое разделение — инженерная рекомендация на основе модели COM. Оно ещё не испытано нашим прототипом. Загрузка обработчика в отдельный процесс не изолирует собственные ошибки оставшейся DLL. Microsoft отдельно предупреждает, что код in-process расширения выполняется в процессе оболочки. Возможность общей COM DLL работать через surrogate сама по себе не доказывает, что Explorer активирует конкретное расширение пространства имён этим способом. [Расширения Shell](https://learn.microsoft.com/en-us/windows/win32/shell/shell-exts) · [Модель namespace extension](https://learn.microsoft.com/en-us/windows/win32/shell/nse-implement) · [COM DLL surrogates](https://learn.microsoft.com/en-us/windows/win32/com/dll-surrogates)

Добавить в стенд закрытие главного окна ЛОПАТЫ при открытой коллекции, аварийное завершение обработчика, зависший ответ, повреждённое сообщение и два одновременных окна. Проверять доступность обычных папок, сохранение видимых результатов и успешное восстановление обработчика.

### Кто восстанавливает отдельный обработчик

Для первого прототипа роль инициатора запуска и восстановления выполняет асинхронная часть адаптера. Она обнаруживает разрыв связи, координирует один запуск для текущего пользователя, дожидается ответа готовности в ограниченное время и обновляет открытый список после восстановления. COM EXE можно активировать по требованию средствами COM; при собственном IPC потребуются явные запуск и повторное подключение. Сама запись LocalServer32 не задаёт нашу политику повторов и восстановления выдачи. [Активация локального COM-сервера](https://learn.microsoft.com/en-us/windows/win32/com/localserver32)

При отсутствии открытых клиентов обработчик может штатно завершиться после простоя. При новом обращении его снова запускают. Для продолжающегося просмотра аварийное завершение должно приводить к автоматической ограниченной попытке восстановления. После повторяющихся сбоев увеличить паузы, прекратить автоматические запуски и дать ручной повтор. Отключение и удаление интеграции останавливают восстановление. Отдельный постоянно работающий наблюдатель для проверки этой схемы не требуется.

В адаптере сохранять последний целый снимок и направлять команды открытия к настоящим локальным оригиналам. IPC не должен ждать на потоке интерфейса Explorer. При выборе именованных каналов Microsoft документирует асинхронный ввод-вывод, позволяющий освободить вызывающий поток на время операции. Тест зависания обязателен отдельно от теста завершения процесса. [Асинхронный обмен по каналу](https://learn.microsoft.com/en-us/windows/win32/ipc/synchronous-and-overlapped-input-and-output)

## Следующая практическая проверка

1. На тестовом профиле показать один постоянный узел «ЛОПАТА» с иконкой и без дубля при повторном включении. Сверить положение относительно Desktop и «Этот компьютер». Открыть при закрытом основном приложении.
2. Подать три контрольных оригинала: один доступен только по подтверждённому локальному сохранению, второй найден только индексом, третий найден обоими способами. В корне ожидаются три оригинала. В одном списке проверить две сворачиваемые группы. Свернуть и раскрыть одну группу: соседняя сохраняет состояние, в дереве и адресной строке остаётся «ЛОПАТА», после раскрытия видны те же три оригинала. Повторить с двумя открытыми вкладками.
3. Проверить операции на расходных копиях, включая файлы с двух томов. После удаления или переноса в сторонней программе обновить выдачу, для недоступного тома проверить отсутствие зависания интерфейса.
4. Пока узел открыт, выполнить тестовое обновление и откат, потом отключение и удаление. Проверить оставшиеся регистрацию, иконки, загруженные версии и состояние соседних узлов.

Решение по итогам чтения — начать с собственного виртуального корня, штатного представления и двух заголовков групп справа. Системный делегат для обычной папки пригодится как контроль, если потребуется отделить ошибку размещения от ошибки перечисления. Физический прототип узла Windows 11 в этом исследовании не выполнялся.
