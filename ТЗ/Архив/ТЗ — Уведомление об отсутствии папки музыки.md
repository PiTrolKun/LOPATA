# ТЗ для Codex: понятное уведомление об отсутствии папки сохранения музыки

**Проект:** ЛОПАТА  
**Дата:** 23.10.2026  
**Направление:** «Создание → Музыка» — общий музыкальный рабочий экран  
**Основание:** пользовательский сбой при запуске генерации; локальная DEV-сборка пользователя является актуальным состоянием интерфейса.  
**Статус:** выполнено и закрыто по прямой команде пользователя 23.10.2026; 0.6.8-dev. Публикация разрешена отдельной текущей командой пользователя.

## 1. Наблюдаемая проблема

При попытке создать музыку в журнале появляется общее сообщение «Не удалось завершить генерацию», дополненное необработанным английским текстом:

```text
Choose an audio output folder.
```

На присланном скриншоте ошибка повторяется при попытках запуска в 14:54:12 и 14:54:19, без заметной работы генератора. Пользователь не получает понятного объяснения, **где именно выбрать папку**, и может принять отказ подготовки за ошибку музыкальной модели.

**Подтверждённый источник по опубликованному коду:** `Исходники/AIHub/Services/MusicGenerationJobs.cs`, метод `Create(...)`:

```csharp
if (string.IsNullOrWhiteSpace(output))
    throw new ArgumentException("Choose an audio output folder.");
```

`MusicGenerationSession.StartPauseAsync` передаёт сюда `_view.Tracks.OutputFolder`. То же поле используется в `RepeatAsync`. Значение может быть пустым из исходной настройки `AppSettings.MusicOutputFolder` либо после применения сохранённого `MusicProjectSnapshot.OutputFolder` в `MusicProjectController.Apply`. Последнее — **возможный путь возникновения**, а не доказанная причина конкретного пользовательского случая.

Полезные ориентиры исходников:

- `Исходники/AIHub/Controls/MusicGenerationSession.cs` — `StartPauseAsync`, `RepeatAsync`, обработка ошибок.
- `Исходники/AIHub/Controls/MusicTracksControl.cs` — текущий `OutputFolder`, существующая кнопка выбора и `OpenFolderDialog`, уведомление об изменении папки.
- `Исходники/AIHub/Controls/MusicWorkspaceControl.cs` — `ConfigureOutput`, связь списка треков с плеером.
- `Исходники/AIHub/Controls/MusicProjectController.cs` — `Apply`, `New`, `Open`, `Capture`.
- `Исходники/AIHub/MainWindow.Music.cs` — сохранение общего параметра `MusicOutputFolder`.
- `Исходники/AIHub/Localization/ru.json`, `en.json` — локализация.

Текущую локальную DEV-реализацию сверять самостоятельно; GitHub содержит опубликованную базу и не заменяет её.

## 2. Цель

Если пользователь запускает **новую музыкальную генерацию или повтор результата**, а папка сохранения не указана, ЛОПАТА должна **сразу и по-русски (либо на выбранном языке интерфейса)** объяснить причину, позволить открыть штатный выбор папки и безопасно вернуться к работе.

Это **не задача** по изменению генераторов, аудиоформатов, хранилища моделей или автоматическому назначению папок.

## 3. Требуемое поведение

1. **До создания задания и до длительной подготовки** проверить, что текущий `_view.Tracks.OutputFolder` не пустой и не состоит из пробельных символов. Проверку применить как минимум к обычному запуску и к команде повтора существующего трека.
2. Проверку выполнять **только при намерении создать новое задание**. Нельзя мешать штатной паузе, продолжению и восстановлению уже существующей операции.
3. При пустом пути **не создавать** `MusicGenerationJob`, не запускать генератор и не записывать несуществующее неудачное задание в историю проекта.
4. Показать **понятное уведомление с действием**. Рекомендуемый текст:

   **Заголовок:** `Не выбрана папка для музыки`  
   **Описание:** `Чтобы создать песню, выберите папку, в которую ЛОПАТА будет сохранять готовые аудиофайлы.`  
   **Действия:** `Выбрать папку…` и `Отмена`.

   Форму уведомления выбрать согласованную с существующим WPF-интерфейсом; пользователь должен видеть причину и путь исправления без поиска по настройкам. Дублирующую английскую строку в пользовательском статусе не показывать как основное объяснение.
5. По действию `Выбрать папку…` открыть **штатный** выбор папки. Использовать имеющуюся логику музыкального сценария (сохранение общей настройки, обновление `Tracks.OutputFolder`, синхронизация с плеером); не заводить независимый путь, существующий только внутри диалога.
6. Если выбор отменён, окно закрыто или пользователь не выбрал папку — вернуться к экрану **без потери** текста песни, пожеланий, выбранной модели, настроек и текущего проекта. Не включать генерацию автоматически.
7. После успешного выбора обновить показ папки в музыкальном экране. **Саму генерацию запускать только по следующей явной команде пользователя**, чтобы избежать случайных повторов и дублирования работ.
8. Если путь **непустой, но недоступен** (нет прав, диск отключён, недопустимый адрес и т. п.), не подменять эту причину сообщением «папка не выбрана». Существующую техническую обработку таких исключений сохранить; по возможности перевести её в понятный локализованный текст в рамках этого узкого изменения.
9. Дважды нажать запуск при пустой папке — не значит создать два задания или два параллельных окна выбора. Сохранять обычную защиту от повторного старта.

## 4. Восстановление проекта и настройки

Отдельно проверить важный воспроизводимый сценарий:

- пользователь ранее указал общую папку для музыки;
- затем открыл старый проект или новый проект, где `snapshot.OutputFolder == ""`;
- `MusicProjectController.Apply` восстановил это пустое значение;
- при следующем запуске пользователь получил описанную ошибку.

**Обязательный результат этой задачи:** даже в таком случае понятное уведомление работает и выбор папки позволяет продолжить использование сценария. Не менять молча политику наследования папки проектами и не подставлять автоматически путь из глобальных настроек: такое поведение требует отдельного решения.

## 5. Локализация и границы

- Добавить необходимые строки в RU/EN, проверить одинаковый набор ключей.
- Сообщение должно одинаково работать в тёмной/светлой темах, на обычных размерах окна и при увеличенном масштабе Windows.
- Не изменять `MusicGenerationJobs.Create` так, чтобы он молча принимал пустые пути. Его проверка остаётся защитным инвариантом. Новая пользовательская проверка должна перехватывать штатный случай **до** исключения.
- Не пересоздавать и не удалять ранее выбранные аудиофайлы, треки, проекты, настройки и результаты.
- Не затрагивать длительную музыкальную обработку, выбор моделей, экспорт и фоновые механизмы, кроме необходимых точек входа.
- Не запускать установку моделей, новые скачивания или полноценную генерацию для проверки простой ошибки выбора папки, если достаточно изолированного теста.

## 6. Проверки и критерии приёмки

1. **Пустая папка:** запуск показывает локализованное уведомление с действиями, не создаёт задания, не показывает вводящую в заблуждение ошибку генератора.
2. **Выбор папки:** штатный `OpenFolderDialog`, путь отображается в треках, сохраняется штатным способом; следующий ручной запуск использует выбранный путь.
3. **Отмена выбора:** ни задания, ни записи об ошибочном запуске; ввод, настройки и текущая история остаются без изменений.
4. **Повтор трека:** при пустом пути действует та же защита, исходный трек не изменяется.
5. **Восстановление проекта с пустым `OutputFolder`:** ошибка объясняется пользователю и устраняется выбором папки.
6. **Валидная папка:** прежний маршрут подготовки и генерации не меняется; сообщение не появляется.
7. **Недоступная непустая папка:** не выдавать ложное «папка не выбрана»; корректно показать отдельную причину.
8. **Пауза / продолжение:** новая проверка не блокирует операции, уже имеющие сохранённое задание.
9. **RU/EN и обе темы:** интерфейс, надписи, кнопки, клавиатура, отсутствие обрезания текста и зависших диалогов.
10. **Регрессии:** профильные тесты, сборка, проверка локализации, штатная проверка запуска по проектным правилам; не изменять прочие сценарии.

**Приёмка пользователем:** при отсутствии папки он должен без знания внутреннего устройства программы понять, почему генерация не началась и что сделать дальше.
