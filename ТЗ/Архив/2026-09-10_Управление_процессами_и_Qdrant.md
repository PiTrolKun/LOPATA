# Управление внутренними процессами и Qdrant

Дата: 2026-09-10. Статус: закрыто по решению пользователя как частично выполненное. Версия реализации: 0.1.86-dev; закрытие на 0.1.87-dev.

Приняты управление запуском/жизненным циклом внутренних workers, техническая панель и работоспособный локальный Qdrant. Визуальная группировка как у Teams не достигнута: пользователь отказался от неё ради сохранения стабильности. Это снятое требование, не исправленная функция. Ограничение короткого окна между Process.Start и назначением Job у прежних workers сохраняется; Qdrant назначается до ResumeThread. Исходники публикуются по правилу закрытия; установщик не выпускается. Прежние статусы «на доработке/без публикации» ниже — история этапа.

## Цель

ЛОПАТА управляет жизненным циклом собственных вспомогательных процессов. Qdrant доступен как локальный компонент программы, пока без подключения сценариев и индексации пользовательских данных.

## Согласованные границы

- Провести инвентаризацию всех запусков процессов в приложении. Серверы моделей, речевые workers, внутренние инструменты и диагностические команды проходят через общий механизм владения.
- Запуск без лишних окон; учёт компонента, PID, времени запуска, завершения и ошибки. Не записывать полные промпты/секреты в общий журнал процессов.
- Нормальный выход сначала использует штатную остановку компонентов. Windows Job Objects обеспечивают аварийную уборку принадлежащих приложению процессов и потомков.
- Нельзя завершать процессы по одному имени EXE или старому PID. Внешние браузеры, просмотрщики пользовательских файлов и установщик обновления не относятся к внутренним workers.
- Существующие блокировки повторных запусков и проверки готовности runtime сохранить. Для Qdrant добавить сериализацию запуска/остановки и защиту от дубликатов.
- Группировку в диспетчере задач проверить отдельно; Job Object не равнозначен визуальной группе Teams. Не обещать неподтверждённое отображение.
- Qdrant: официальная Windows x64 сборка, фиксированная версия и SHA256; существующие соглашения о лицензиях, Runtime и AppData. Только loopback, без внешнего доступа и телеметрии.
- Запуск Qdrant только по явной технической команде, не на старте приложения. Отладочная панель позволяет проверить компонент, состояние процессов и открыть журнал.
- Проверка Qdrant создаёт только собственную временную коллекцию: запись, поиск, перезапуск, повторное чтение, удаление тестовой коллекции. Данные сохраняются на диске между остановками.

## Не входит

RAG сценариев, embedding-модель, разбиение произведений, «желе», миграция литературных файлов, изменение промптов и качества генерации. Установщик и публикация не выполняются без отдельной команды. ТЗ остаётся активным до приёмки пользователя.

## Модули

Новый общий модуль владения процессами и Windows Job Objects; существующие Services с Process.Start; App exit; отдельные Qdrant options/install/runtime/probe; отладочный UI; локализация RU/EN; каталог лицензий, реестр, история и версия. Полный список точек подключения и исключений фиксируется в отчёте проверки.

## Проверки и критерии приёмки

1. Restore/build/test не ухудшают baseline 491 тест, 0 предупреждений/ошибок.
2. Реальные процессы: запуск, естественное завершение, штатная/аварийная остановка владельца и потомков; посторонний процесс остаётся жив. Ошибка запуска и отмена не оставляют бесхозных процессов.
3. Qdrant: готовность, конкурентный повторный старт, запись/поиск/перезапуск/чтение, остановка, восстановление после сбоя; отсутствие автостарта и подключения к сценариям.
4. WPF/safe-start, RU/EN, UTF-8 scanner и git diff --check. Группировка Windows отмечается только по наблюдению.
5. Поставщик, версия, SHA256, лицензия, способ загрузки и сохранения данных описаны. Тестовый отчёт отделяет выполненное от ограничений.

- Реализация и направленные проверки завершены. Полный отчёт: [ProcessInfrastructure](../../Тесты/ProcessInfrastructure/README.md). 496/496 .NET, build без warnings/errors, реальный Qdrant и lifecycle, WPF RU/EN в обеих темах. Пользовательские сценарии не подключены, установщик/публикация не выполнялись.

Полный запуск всех тяжёлых моделей не повторялся. Эти ограничения не скрыты и не считаются результатом пользовательской приёмки.
