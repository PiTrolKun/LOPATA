# Подключение внешних ИИ-агентов к установленной ЛОПАТЕ

Рабочее ТЗ от 24.11.2026. Статус — открыто, идёт проверка реализации. [Исходная идея](Архив/ЛОПАТА_идея_подключение_внешних_агентов.md)

## Пользовательский результат

Пользователь обсуждает задумку в своём настольном ИИ-клиенте для Windows. Агент получает от установленной ЛОПАТЫ инструкции выбранного сценария и передаёт ей подготовленные материалы. ЛОПАТА проверяет данные и сохраняет новый проект в штатном виде — отдельным файлом или в библиотеке сценария. При открытии пользователь сразу попадает на последний шаг, проверяет результат и сам решает, что править, когда обратиться к помощнику или запустить выполнение. Подключение агента добровольно.

## Доступ в dev-версии и в пользовательской сборке

**Dev-версия.** Codex получает прямой доступ к механикам ЛОПАТЫ для разработки и испытаний без функциональных ограничений пользовательской сборки. Через это подключение можно вызывать и проверять отдельные операции и новые механики, в том числе у сценариев без проектов. Новую механику можно испытывать через тот же вход по мере разработки.

**Пользовательская версия.** Внешний агент может подготовить и создать новый проект **в любом сценарии, у которого есть собственная механика проектов**. Это относится и к файлам, и к проектам из библиотеки сценария. Агент получает инструкции, передаёт данные для проверки и сохранения, а при необходимости запускает штатное скачивание моделей для порученной работы. Состав операций определяет сама сборка. Команды разработки отсутствуют в пользовательском интерфейсе подключения и недоступны при прямом вызове.

ЛОПАТА в первую очередь предназначена для локальной работы. В обеих сборках пользователь может по желанию попросить уже подключённого агента объяснить сбой по сохранённым журналам. Для этого достаточно сообщения в чате, даже если ЛОПАТА полностью закрыта или не запускается.

## Как пользователь подключает своего агента

На экране «Начало работы» кнопка «Подключить агента» стоит под карточками направлений, сразу справа от смайлика Мастерской анимированных ассетов. Порядок слева направо — геймпад, смайлик, эмблема подключения. Размер кнопки, выравнивание и отступ соответствуют соседним кнопкам. Для эмблемы используются исходные цвета SVG в обеих темах. При наведении показывается подсказка «Подключить агента». [Эмблема кнопки](Материалы/Подключение_внешних_ИИ-агентов/lopata_ai_unity_emblem.svg)

По нажатию ЛОПАТА предлагает два варианта — «Подключить к Codex» и «Другой агент».

До выбора агента пользователь видит, зачем подключаться, пример запроса в чате и результат в ЛОПАТЕ. На примере видеоролика объясняем, где открыть проект, что можно подправить и кто запускает генерацию. Здесь же коротко описаны штатное скачивание моделей, разбор сохранённых журналов, особенности двух способов подключения и возможная обработка переданных материалов облачным поставщиком агента.

Окно подключения показывает весь список проектных сценариев по направлениям ЛОПАТЫ. Список изначально раскрыт, его можно свернуть. Состав берётся из того же каталога, которым отвечает инструмент агента, а названия — из навигации текущего языка.

### Как ЛОПАТА отличает агентский проект

Проект, созданный внешним агентом, получает явную отметку происхождения в самом файле или записи библиотеки. Она сохраняется при повторном открытии, редактировании и сохранении. Перенос файла и переименование сохраняют происхождение. При открытии такого проекта ЛОПАТА переходит к проверке результата. Прогрев и обращение к местному помощнику выполняются по запросу пользователя. Ручные и прежние проекты без отметки проходят штатную подготовку своего сценария.

### Подключить к Codex

1. **Первое подключение.** ЛОПАТА регистрирует свой локальный каталог плагинов и открывает в настольном Codex для Windows карточку плагина «ЛОПАТА». Пользователь подтверждает установку в Codex. Вводить команды, редактировать настройки или копировать пути вручную не требуется.
2. **Начало работы.** После подключения кнопка «Начать в Codex» открывает чат с выбранным плагином и редактируемым черновиком запроса. Пользователь дописывает задачу и сам отправляет сообщение. Если он уже работает в чате, где доступен плагин, можно попросить «Подготовь видеопроект в ЛОПАТЕ» или явно выбрать плагин через `@`.
3. **Следующий проект.** Пользователь сразу формулирует задачу в Codex. Одно подключение действует для следующих проектов и для всех доступных этому агенту сценариев. По завершении агент показывает путь к созданному файлу либо название проекта в библиотеке и поясняет, как его открыть.

В поставку ЛОПАТЫ входит один плагин Codex с короткой инструкцией для агента (навыком) и подключением к общим локальным инструментам ЛОПАТЫ через MCP. Публичный каталог плагинов для такой поставки не требуется. Навык объясняет, когда обратиться к ЛОПАТЕ, как запросить правила сценария и как сообщить пользователю результат. Перечень сценариев, требования к проектам и доступные операции агент получает у той копии ЛОПАТЫ, которая ответила на запрос. Штатную подготовку моделей и создание проектов выполняет эта копия по правилам своей сборки.

### Другой агент

1. Пользователь выбирает «Другой агент».
2. ЛОПАТА создаёт по своему шаблону файл инструкций `AGENTS.md` в выделенной папке. В файл попадают актуальные для этой установки пути и сведения о подключении. Пользовательские файлы с таким же именем сохраняются. ЛОПАТА копирует в буфер короткое сообщение с абсолютным путём к подготовленной инструкции.
3. Пользователь вставляет сообщение в чат агента. Агент читает инструкцию, подключается средствами своего клиента и запрашивает доступные сценарии. Если клиент запрашивает разрешение, пользователь видит его штатный запрос.

Для этого маршрута пользователю достаточно кнопки и вставки сообщения. Если конкретному клиенту нужны дополнительные действия, их фиксируем при проверке этого клиента.

## Что предоставляет пользовательская версия

| Действие агента | Что возвращает или делает установленная программа |
| --- | --- |
| Узнать доступные сценарии | Сообщает, для каких сценариев эта установка принимает данные от агента. |
| Получить инструкции сценария | Возвращает правила, обязательные поля, допустимые значения и порядок подготовки проекта. Агенту хватает этих сведений для работы без исходников ЛОПАТЫ. |
| Проверить и подготовить среду | Для порученной операции ЛОПАТА определяет нужные модели и компоненты. Агент может запустить штатное скачивание недостающих файлов, узнать его ход и получить итог проверки. |
| Передать данные нового проекта | Проверяет их по штатным правилам. При успехе возвращает файл проекта либо создаёт запись в библиотеке сценария и сообщает, как её открыть. При ошибке указывает, какое поле или вложение нужно исправить. |
| Прочитать журнал для разбора проблемы | Находит события по времени, сеансу, сценарию или операции. По выбранному случаю возвращает техническую выдержку с ошибкой и связанными событиями. |

В пользовательской версии доступны подготовка проекта, штатная подготовка нужных компонентов и чтение журналов по запросу пользователя. За разрешения отвечают клиент и локальный компонент ЛОПАТЫ. Файл инструкций и текст в буфере могут содержать пути, но не ключи доступа. До передачи личных материалов пользователь должен понимать, что его агент может обрабатывать их у своего облачного поставщика. Управление моделями, настройками, очередями и запуском генерации остаётся в ЛОПАТЕ.

### Как агент объясняет сбой

Пользователь может написать «Почему вчера прервалось скачивание модели?» или «ЛОПАТА закрылась во время работы. Что произошло?». Искать файл журнала вручную и связываться с разработчиком для этого не требуется. Инструкция для Codex и общая инструкция для других агентов описывают один и тот же способ разбора.

Локальный компонент подключения читает сохранённые журналы независимо от процесса основного приложения. Открывать проект, запускать ЛОПАТУ или загружать локальную модель для такого запроса не требуется. Пользователь обращается за объяснением из чата, без дополнительных кнопок в окнах ЛОПАТЫ и сообщениях об ошибках.

1. ЛОПАТА ищет в собственных журналах последние ошибки и события, подходящие под описание пользователя. Если подходят несколько попыток, агент различает их по времени и операции и при необходимости уточняет, какую разобрать.
2. Для выбранного случая агент получает источник и время записи, доступные сведения о сценарии, этапе и компоненте, текст или код ошибки, а также связанные события до и после неё. Так видно, например, завершилась ли повторная попытка успешно. Связь событий из разных журналов указывается, когда её можно установить по имеющимся записям.
3. Агент простыми словами объясняет, что произошло, на какую запись он опирается и что пользователь может сделать дальше. Если причина остаётся предположением, агент обозначает это и предлагает конкретную проверку. Например, событие аварийного завершения с кодом выхода подтверждает, что программа неожиданно закрылась. Самого кода может быть недостаточно, чтобы установить причину. Если журнал недоступен или в нём нет нужного события, агент сообщает об этом и подсказывает, какие сведения помогут.

Инструмент принимает выбор события и параметры поиска. Источники определяет сама ЛОПАТА. Она передаёт технические поля и очищенные сообщения, исключая ключи доступа, личные пути, содержимое документов и тексты запросов к моделям. Это важно и для свободного текста ошибок. Разбор выполняется в режиме чтения. Пользователь получает совет и сам решает, применять ли его.

Для реализации уже есть журналы сеансов с отметками времени, события установки компонентов и журнал неожиданного завершения приложения. Подробные журналы отдельных сценариев могут содержать тело запроса к модели. ### Если среда ещё не готова

В обеих сборках агент может сам запустить штатное скачивание в рамках исходного поручения. Отдельная просьба «скачай модель» не требуется. ЛОПАТА определяет нужные файлы по выбранной операции и варианту сценария, использует настроенное хранилище, общую политику аудита компонентов и обычный порядок принятия лицензий. Если требуется согласие с условиями, его запрашивает сама программа.

Агент видит ход загрузки, ожидание согласия, готовность, отмену или ошибку. Повторный запрос возвращает состояние уже начатой загрузки. После подтверждения готовности агент продолжает исходное поручение. При отмене или ошибке подготовленные данные сохраняются. Если среда готова или задача обходится без моделей, скачивание пропускается. Например, для сохранения текстового замысла не нужны веса будущего видеогенератора. Скачивание само по себе не запускает генерацию или локального помощника.

## На какой шаг попадает пользователь

При штатном открытии файла или выборе созданного агентом проекта из библиотеки сценарий сразу показывает последний шаг подготовки, где видны подготовленные данные и доступное пользователю действие. В редакторе без пошагового мастера этому соответствует открытый рабочий документ с заполненным содержимым. Пользователь может вернуться к любому редактируемому шагу и внести правки.

Сохранение, открытие и переход на последний шаг сами по себе не вызывают локальных моделей-помощников. Текст, промпты и решения агента показываются в переданном виде. Локальный помощник подключается только по явной просьбе пользователя.

Последний экран отражает фактическую готовность проекта. Если, например, агент подготовил описание кадра, но изображение ещё предстоит нарисовать, пользователь видит это на последнем шаге. Оттуда он может перейти к нужному материалу. ЛОПАТА не помечает отсутствующее изображение готовым и не начинает его генерацию при открытии.

## Как проверяем подключение

Codex самостоятельно проверяет подключение из текущего чата. По решению пользователя от 24.11.2026 испытания проходят в следующем порядке.

1. **Проверить dev-версию.** Напрямую обратиться к ней через точку подключения для внешних агентов. Получить список сценариев и инструкции по видео, сохранить черновик `.lopataAIVid` с уникальной контрольной фразой и сверить её при штатном открытии файла. При сбое исправить причину и повторить проверку на dev-версии.
2. **После успешной проверки сделать push и выпустить подписанное файловое обновление.** Опубликовать проверенные изменения. На этом этапе ТЗ остаётся открытым.
3. **Обновить установленную ЛОПАТУ** через её штатный обновлятор. Сверить версию обновлённой программы.
4. **Повторить прямую проверку на установленной копии.** Из того же чата обратиться к компоненту из каталога установки и пройти действия первого шага с новой контрольной фразой. Зафиксировать фактическую версию, путь компонента и результат открытия второго проекта. Успешный проход подтверждает подключение вне среды разработки.

| Проверка | Наблюдаемый результат |
| --- | --- |
| Определить, какая копия ответила | Для каждого прогона записаны версия и фактический путь вызванного компонента. В первом прогоне это dev-сборка, во втором — копия, обновлённая штатным обновлятором. |
| Подтвердить работу штатного механизма | Из текущего чата передать уникальную контрольную фразу и запросить сохранение черновика. Открыть полученный файл штатным механизмом ЛОПАТЫ и сверить фразу. Для этого достаточно одного небольшого проекта. |
| Сверить возможности сборок | В dev напрямую вызвать тестируемую механику вне создания проектов. В пользовательской сборке проверить список доступных операций и прямой вызов той же dev-команды. Создание проектов доступно, dev-команда не исполняется. |
| Проверить подготовку среды в обеих сборках | На готовой среде передача файлов не начинается. На неполной агент запускает штатное скачивание, получает прогресс и после проверки продолжает ту же задачу. Повторный запрос не дублирует загрузку. При отказе от условий, отмене или ошибке агент получает соответствующий результат. Число вызовов локальных помощников при скачивании равно нулю. |
| Проверить охват проектных сценариев | Сверить список, выдаваемый агенту, со всеми сценариями, где пользователь может создать и повторно открыть проект. Для каждого проверить штатный способ создания и открытия, включая проекты из библиотеки. |
| Проверить последний шаг и помощников | Открыть агентский проект обычным пользовательским способом. Сразу виден итоговый экран или заполненный редактор, контрольная фраза сохранена, число вызовов локального помощника при создании и открытии равно нулю. Для незавершённого материала видна причина и доступен переход к правке. |
| Разобрать известный сбой по журналу в dev и установленной копии | Из текущего чата спросить о контрольной ошибке установки компонента. Сверить время, компонент и сообщение в ответе с записью нужного запуска. Агент объясняет сбой и предлагает выполнимый следующий шаг. При наличии записи об удачном повторе сообщает о результате. |
| Прочитать журнал при закрытой ЛОПАТЕ и после неудачного запуска | В dev и установленной копии проверить два случая. После полного выхода из ЛОПАТЫ запросить из чата известную запись предыдущего сеанса. После неудачного запуска запросить сведения об этой попытке до следующего запуска приложения. Сверить ответ с тем, что записано на диске. Во время чтения основное приложение и локальные модели не запускаются. |
| Разобрать неполный журнал | Если записан только факт неожиданного выхода, агент сообщает, что известно. Если новая попытка не оставила записи, агент сообщает об этом. Дату и время более раннего события указывает явно. |
| Проверить состав выдачи | Поместить в тестовую запись вымышленные личный путь, ключ и фрагмент запроса. Проверить сам ответ инструмента до передачи в чат. Техническая причина доступна, контрольные личные данные исключены. Запрос на объяснение сохраняет состояние приложения и журналов. |
| Проверить повторное подключение | После перезапуска и при проверке установки в другой папке инструкция ведёт к фактическому компоненту. Пути к репозиторию и к сборке разработчика не требуются. |
| Проверить понятную ошибку | При недоступности самого компонента подключения клиент сообщает о проблеме связи. При некорректных данных проекта ЛОПАТА объясняет, что исправить. |

Критерий успеха каждого прогона — прямой ответ нужной копии и чтение контрольной фразы из созданного ею проекта. Результаты двух прогонов записываются отдельно.

### Проверка плагина в настольном Codex для Windows

| Действие | Наблюдаемый результат |
| --- | --- |
| Первое подключение через ЛОПАТУ | Открывается карточка нужного плагина. После подтверждения в Codex доступны и навык, и инструменты. В протоколе отдельно отметить, подхватил ли их уже открытый чат или понадобился новый. Прямую проверку самой ЛОПАТЫ проводим из текущего чата. |
| Нажать «Начать в Codex» | Открывается редактируемый черновик с выбранным плагином. До отправки пользователем работа над проектом не начинается. |
| Поручить плагину создать проект | Через инструмент плагина Codex получает версию и расположение нужной копии ЛОПАТЫ, запрашивает правила сценария и создаёт проект с контрольной фразой. По ответу в чате пользователь находит проект и видит эту фразу на последнем шаге при штатном открытии. |
| Попросить второй проект после обновления ЛОПАТЫ | Повторная установка плагина и ввод пути не требуются. Инструмент отвечает от имени обновлённой установленной копии и возвращает новый проект. |

В протоколе отдельно фиксируем прямой вызов ЛОПАТЫ и работу через установленный плагин. Для последней проверки нужен фактический вызов инструмента из Codex с результатом от нужной сборки.

Режиссуру, переводы и качество промптов на первом этапе разбираем преимущественно на примерах. Для технической проверки охвата достаточно небольших проектов с различимыми данными. Полноценный творческий прогон каждого сценария для этой проверки не требуется.

## Что решить в дальнейшем обсуждении

- Для других настольных клиентов Windows определить поддерживаемый способ локального подключения, в том числе совместимость с MCP. Для каждого клиента и тарифа отдельно указать, что подтверждено реальным вызовом, а что известно только из документации.
- Для каждого проектного сценария описать обязательные данные, штатный способ сохранения и конкретный последний экран или рабочий редактор. Первым предметным примером служит видеопроект.
- Можно ли после первоначального подключения готовить проекты при закрытом главном окне и без установки генеративных моделей.
