# Публикатор — исправления 0.5.5-dev

Пользователь сообщил о неверном отклонении URL /releases, долгой проверке
и белых строках таблицы при тёмной теме. Долгая проверка завершилась сама;
без сетевой трассы её причину установить нельзя.

ParseRepository теперь принимает корень репозитория и точную /releases
страницу с завершающим slash, нормализует в owner/repo. Прочие пути,
чужие host, credentials, query/fragment остаются недопустимыми.
В «?» ссылка проекта открывает Releases; действия направления позволяют
открыть такую же страницу его источника. Хранилище не мигрировалось:
PiTrolKun/LOPATA уже читает GitHub Releases. Пустой список старых выпусков
при выключенном «Показать все» — штатное поведение.

Установлен отдельный дефект: HttpClient.Timeout с ResponseHeadersRead
ограничивал только получение заголовков. Microsoft подтверждает этот
контракт: https://learn.microsoft.com/en-us/dotnet/api/system.net.http.httpcompletionoption?view=net-10.0
Теперь linked CancellationTokenSource ограничивает каждый запрос,
включая загрузку тела. Рабочий timeout 35 секунд, отмена пользователя
сохраняется. При timeout мастер показывает сетевую ошибку ожидания,
сохраняя введённые данные, вместо ложного сообщения об отмене.

PublisherResources.xaml задаёт тематические строки/ячейки/выделение,
PasswordBox, меню и подсказки. Checkbox колонки сохраняет общую тему,
включая режим редактирования. Подтверждения — собственные тематические
окна, безопасный выбор «Нет» по умолчанию и Escape. Общие ресурсы списков,
кнопок, полей и прокрутки сохранены. Заголовки используют существующий
WindowTitleBarThemeService, реагируют на изменение цвета фона.
