# «Текст в книгу»: технологии первого этапа

Дата проверки: 19.10.2026.
Основание: [набросок ТЗ](../../ТЗ/Архив/2026-10-19_Текст_в_книгу.md).
Статус: изучены официальные руководства и смежный исходный код ЛОПАТЫ.
Это техническое предложение для обсуждения, не готовая интеграция и не протокол
физических испытаний конвертеров. Программы/модели не устанавливались и не запускались.

## 1. Предлагаемый набор

| Технология | Роль | Решение по результатам изучения |
|---|---|---|
| C#/.NET 10, WPF | Интерфейс, очередь, маршрутизация, объединение, файловые операции | Существующая основа приложения |
| calibre CLI | Широкая конвертация книжных форматов и обратные направления | Основной новый кандидат для стенда |
| LibreOffice CLI | Старый DOC, ODT/RTF и прямой экспорт офисных документов в PDF | Переиспользовать существующий каталог компонентов и discovery |
| Open XML SDK | DOCX, структура частей и встроенные сведения происхождения | Уже подключён, нужен новый книжный адаптер |
| PdfPig | Извлечение текста/геометрии из цифровых PDF, независимое чтение | Уже подключён; не заменяет OCR и рендерер |
| Windows.Data.Pdf | Постраничный рендер PDF в изображения | В проекте есть готовый способ вызова |
| WPF/WIC и SkiaSharp | Чтение страниц/обложек, TIFF, WebP, создание графического PDF | Использовать имеющиеся возможности с проверкой каждого кодека |
| AngleSharp и Markdig | Структурный разбор HTML и Markdown | Уже подключены; не уплощать книгу в одну строку текста |
| System.Xml и System.IO.Compression | FB2, EPUB, CBZ, проверки контейнеров | Штатные средства .NET, без отдельного тяжёлого runtime |
| SharpCompress | Чтение дополнительных архивов, включая CBR/RAR | Уже подключён; запись CBR этим не обеспечивается |
| EPUBCheck | Независимая проверка EPUB | Кандидат для стенда, затем решить доставку/обязательность |
| OutputProvenance / OutputOfficeMetadata | Общие факты происхождения и запись в DOCX | Переиспользовать модель фактов, добавить форматные адаптеры |
| ExifTool | Чтение/проверка и доступные операции с PDF-метаданными | Уже существует отдельный проверяемый комплект; не универсальный писатель книг |
| Pandoc | Дополнительные документные/Markdown-маршруты, структурная модель | Изучен как резерв, не делать второй обязательной зависимостью без сравнения |
| ImageMagick | Дополнительные графические форматы/особые TIFF | Изучен как необязательный резерв; не тянуть Ghostscript ради основного PDF-маршрута |

Выбор calibre главным кандидатом — инженерный вывод этого исследования, а не
ранее утверждённое пользователем требование. Широту форматов не ограничивать
двумя-тремя расширениями, но каждую реально поставляемую пару подтвердить на стенде.

## 2. Что уже есть в текущем коде

Проверены текущие файлы, а не архивные копии. Atlas Scout вернул свежий индекс;
для C# покрытие частичное, поэтому выводы сверены чтением исходников.

- `Исходники/AIHub/AIHub.csproj`: `net10.0-windows`, OpenXml 3.5.1,
  PdfPig 0.1.15, AngleSharp 1.5.2, Markdig 1.3.2, SharpCompress 1.0.0,
  SkiaSharp 3.119.4. Это версии проекта; документация ветвей upstream может
  описывать другой API. Задача не является обновлением этих пакетов.
- `Services/ComponentCatalog.cs`: WPF BitmapDecoder, LibreOffice 26.2.4,
  ImageMagick и отдельные OCR-компоненты. Наличие записи в каталоге не доказывает
  установку конкретного компонента на компьютере пользователя.
- `Services/SystemCliDiscoveryService.cs`: уже ищет `soffice`; готового книжного
  маршрута это не даёт. Поиск по исходникам не обнаружил существующего вызова
  `--convert-to`/`UserInstallation`, который можно просто включить для новой утилиты.
- `Services/LiterarySourceReader.cs`: TXT/EPUB/PDF читаются для текстового
  литературного сценария. EPUB превращается в обычный текст, не сохраняются все
  связи/иллюстрации/стили. Это не ядро конвертера без потерь. Его пределы
  100 MiB исходника / 20 млн знаков / 150 MiB распакованного EPUB не переносить
  автоматически в новый сценарий как универсальные ограничения книг.
- `Services/LiteraryDocxExporter.cs`: создаёт DOCX из глав/текста, а не переносит
  произвольную исходную книгу со всеми объектами. Он публикует файл с заменой;
  этот способ нельзя напрямую использовать для нового требования «всегда новый файл».
- `Services/OutputProvenance.cs` и `OutputOfficeMetadata.cs`: фактические участники,
  время, версия, собственное DOCX-свойство `LOPATA.Provenance`.
- `Services/AudioShellIntegration.cs`, `ImageShellIntegration.cs`: меню текущего
  пользователя, маркировка своих ключей, неизменность чужих ассоциаций, `MultiSelectModel=Document`.
- `Services/ImageShellProtocol.cs`: ограниченное сообщение и подтверждение после
  сохранения в очередь. Подход пригоден, но операции изображений с заменой
  исходника из `ImageShellProcessor.Transaction.cs` для книг не копировать.
- `Services/RagBookOcr.cs`, `Tools/rag_pdf_render.ps1`: отделённый Windows-рендер
  страниц. Весь OCR-процесс с лицензиями/распознаванием не включать скрытно в простой режим.

## 3. calibre: основной книжный исполнитель

Официальная [матрица форматов](https://manual.calibre-ebook.com/faq.html#what-formats-does-calibre-support-conversion-to-from)
различает входы и выходы. В ней есть DOCX, FB2, EPUB, AZW3, MOBI, RTF, TXT,
PDF и другие направления. Старого DOC среди входов нет. ODT читается, но
в этой матрице отсутствует среди выходов; CBZ/CBR перечислены как входы.
Поэтому «calibre читает формат» не означает возможность записать его.

[ebook-convert](https://manual.calibre-ebook.com/generated/en/ebook-convert.html)
принимает входной и выходной файлы; параметры и их значения по умолчанию зависят
от обоих форматов. До реализации профилей снять справку `input.ext output.ext -h`
именно с закреплённого исполнителя. Сохранять типизированный список разрешённых
настроек. Эвристическая обработка способна менять текст и структуру, по умолчанию
выключена; в тихом профиле её не включать. Не выдавать пользователю произвольную
командную строку. Конвертация каждой пары — отдельная операция очереди.

[Руководство по конвертации](https://manual.calibre-ebook.com/conversion.html)
описывает существенные ограничения PDF: сложная многоколоночная и графическая
вёрстка, векторные изображения, таблицы и навигация не переносятся универсально.
Следствие для ЛОПАТЫ: цифровой PDF → адаптивная книга является маршрутом с
ограничениями; скан без текста обрабатывается как страницы, а не как готовые абзацы.
Уточнение пользователя после исследования: восстановление сложных PDF оставляем
умному этапу. Пользователь сам решает повторить исходник в умном режиме, если
качество обычной конвертации его не устроит; автоматического запуска ИИ нет.
Первый этап не обязан программно восстанавливать всю сложную PDF-вёрстку.

[ebook-meta](https://manual.calibre-ebook.com/generated/en/ebook-meta.html)
умеет читать и записывать книжные сведения, причём списки форматов различаются.
Неподдерживаемое поле может быть молча проигнорировано. Значит, успешный exit code
не заменяет чтения обязательной отметки ЛОПАТЫ после записи. Не записывать программу
в автора/издателя ради видимости отметки.

[ebook-polish](https://manual.calibre-ebook.com/generated/en/ebook-polish.html)
может выполнять ограниченные изменения EPUB/AZW3/KEPUB с меньшим вмешательством,
чем полная переконвертация. Он не является общим конвертером и не нужен каждому
маршруту. Автоскачивание ресурсов, изменение пунктуации и добавление страниц со
сведениями не включать просто ради записи метаданных.

Официальный [Windows-комплект](https://calibre-ebook.com/download_windows64)
требует совместимую Windows; есть [portable-вариант](https://calibre-ebook.com/download_portable).
Для поставки выбрать официальный полный комплект, закрепить версию/хеши/уведомления,
не выдёргивать один EXE из среды с зависимостями.
[Лицензия calibre — GPLv3](https://github.com/kovidgoyal/calibre/blob/master/LICENSE).
У ЛОПАТЫ в корневом LICENSE также GPLv3; всё равно сохранить условия и сведения
о конкретном распространяемом комплекте и его исходниках/зависимостях.

Онлайн-руководство при проверке обозначено 9.16.0. Это версия документации,
не утверждённая версия будущей поставки и не подтверждение её локального запуска.

## 4. LibreOffice: офисный мост и прямые маршруты

Изучены [параметры запуска](https://help.libreoffice.org/latest/en-US/text/shared/guide/start_parameters.html),
[фильтры](https://help.libreoffice.org/latest/en-US/text/shared/guide/convertfilters.html)
и [параметры PDF](https://help.libreoffice.org/latest/en-US/text/shared/guide/pdf_params.html).

Для фоновой работы предусмотрены `--headless`, `--convert-to`, `--outdir` и
изолированный профиль через `-env:UserInstallation=file:///...`.
В Windows для получения консольного вывода предназначен `soffice.com`.
Нужен собственный профиль задания/исполнителя, чтобы не занять открытый офис пользователя.
Фильтры выбирать по типу документа; таблица включает DOC/DOCX, ODT, RTF, PDF и EPUB.
Наличие EPUB-фильтра не означает произвольное чтение EPUB обратно в Writer.

Предлагаемые маршруты: DOC → DOCX → книжный выход; DOCX → ODT/RTF/DOC при запросе
обратного офисного формата; DOC/DOCX/ODT → PDF напрямую, если важно оформление.
Промежуточный документ всегда в рабочей папке задания. Проверять не только код
завершения, но наличие, структуру и непустое ожидаемое содержимое результата.
Не включать снятие проверки блокировок пользовательского профиля.

[Условия LibreOffice](https://www.libreoffice.org/licenses/): MPL 2.0 и условия
отдельных компонентов. Существующий каталог использует системный MSI, а не
готовую переносимую книжную среду. Установку/лицензии проводить штатно до тихой
операции; ПКМ без необходимых компонентов не открывает установщик сам.
Latest-help не считать точным списком фильтров установленной 26.2.4 без стенда.

## 5. Прямые библиотечные пути

### DOCX — Open XML SDK

[SDK Microsoft](https://learn.microsoft.com/en-us/office/open-xml/about-the-open-xml-sdk)
предоставляет доступ к частям/отношениям/WordprocessingML, а не готовый рендер Word.
[OpenXmlValidator](https://learn.microsoft.com/en-us/office/open-xml/word/how-to-validate-a-word-processing-document)
проверяет разметку, но не визуальную тождественность.
[Custom properties](https://learn.microsoft.com/en-us/office/open-xml/word/how-to-set-a-custom-property-in-a-word-processing-document)
подходят для структурированных сведений ЛОПАТЫ без замены автора.
[Официальный репозиторий](https://github.com/dotnet/Open-XML-SDK) отмечает риск
роста памяти при работе с ZIP-пакетами. Большие книги проверять отдельно.

Наш адаптер должен сохранять отношения к изображениям, стили, нумерацию, таблицы,
гиперссылки, сноски/концевые сноски и пробелы. Сбор всех `Text` в строку этого не делает.

### PDF — PdfPig, Windows.Data.Pdf и SkiaSharp

[PdfPig](https://github.com/UglyToad/PdfPig) даёт текст, символы, координаты и
инструменты анализа расположения. Порядок операторов PDF не равен гарантированному
порядку чтения. Извлечённый текст не доказывает правильность колонок и таблиц.
Уплощённые страницы нужно отличать от исходных иллюстраций.

[PdfPage.RenderToStreamAsync](https://learn.microsoft.com/en-us/uwp/api/windows.data.pdf.pdfpage.rendertostreamasync)
предназначен для рендера страницы. Используем последовательную/ограниченную обработку
со своевременным освобождением потоков и страниц. Это рендер, не OCR.

[SKDocument.CreatePdf](https://learn.microsoft.com/en-us/dotnet/api/skiasharp.skdocument.createpdf)
создаёт PDF и принимает сведения документа. Это подходит для сборки изображений
страниц в графический PDF; вёрстку произвольного Word через рисование Skia заново
не реализовывать. [SkiaSharp](https://github.com/mono/SkiaSharp) уже поставляется
с native-частью в проекте. Кириллицу, поворот, размер страницы и качество проверять.

### HTML и Markdown

[AngleSharp](https://github.com/AngleSharp/AngleSharp) — DOM-разбор HTML;
[Markdig](https://github.com/xoofx/markdig) — разбор Markdown с расширениями.
Предложение: переносить дерево заголовков/абзацев/ссылок/таблиц в книжную модель,
а не использовать `.TextContent` как весь результат. Не подключать выполнение
скриптов и произвольный сетевой загрузчик. HTML для предпросмотра очищать отдельно:
парсер не является полной политикой безопасности просмотра.

### Графические страницы

[WPF Imaging](https://learn.microsoft.com/en-us/dotnet/desktop/wpf/graphics-multimedia/imaging-overview)
поддерживает кодеки и многокадровые изображения, включая TIFF.
[TiffBitmapDecoder](https://learn.microsoft.com/en-us/dotnet/api/system.windows.media.imaging.tiffbitmapdecoder)
позволяет читать кадры. Обрабатывать все страницы TIFF, а не только `Frames[0]`.
Для WebP использовать доступный кодек существующего графического стека после
проверки; наличие TIFF у WIC не доказывает его наличие у Skia и наоборот.

## 6. Книжные контейнеры и сведения происхождения

### EPUB

Основа — [EPUB 3.3](https://www.w3.org/TR/epub-33/): контейнер OCF, package/manifest,
порядок `spine`, навигация и ресурсы. `mimetype` должен быть первым ZIP-элементом
без сжатия; package содержит идентификатор, название, язык и `dcterms:modified`
в UTC. В EPUB 3 дата модификации пакета имеет единственное основное значение.
Собственные свойства требуют корректного словаря/префикса. Не записывать ЛОПАТУ
в `dc:creator` вместо автора.

Инженерное предложение: собственные метасвойства происхождения в OPF с
объявленным пространством имён; при пересборке сохранить ресурсы, навигацию,
ссылки и допустимую структуру. EPUB 2 и 3 имеют разные правила, адаптер их различает.
При объединении переназначать коллизии ID, пути картинок и ссылки.

[EPUB 3.4](https://www.w3.org/TR/epub-34/) на дату проверки — Candidate Recommendation
Draft от 02.10.2026. Не переводить выходы на черновой профиль только потому, что
новая версия валидатора его уже проверяет.

### FB2

Изучена авторская [FictionBook.xsd](https://github.com/gribuser/fb2/blob/master/FictionBook.xsd):
описание, разделы, дополнительные тела для примечаний, изображения/binary и
внутренние ссылки. Для отметки предусмотрены `document-info/program-used`,
дата/история и `custom-info` с `info-type`. Происхождение не помещать в автора
из `title-info`. Валидировать по закреплённым локальным XSD с их зависимостями,
а не скачивать схемы при открытии каждой книги. Сохранить уведомления лицензии
из исходных схем. Сложную таблицу/формулу не объявлять тождественно перенесённой.

### FB3

Найден [авторский репозиторий FB3](https://github.com/gribuser/FB3),
изучены [схема тела](https://github.com/gribuser/FB3/blob/master/fb3_body.xsd),
[описания](https://github.com/gribuser/FB3/blob/master/fb3_descr.xsd) и
[лицензия](https://github.com/gribuser/FB3/blob/master/license.txt).
FB3 нельзя считать FB2 с новым расширением: предусмотрены отдельные части,
отношения и схемы. В опубликованных изученных списках calibre FB3 нет.
Нужен отдельный программный адаптер/проверка официальных инструментов на Windows.
Пока это исследованный, но незакрытый маршрут; отсутствие готовой интеграции
не переносит его автоматически в ИИ-этап.

### CBZ и CBR

[SharpCompress: матрица](https://github.com/adamhathcock/sharpcompress/blob/master/docs/FORMATS.md)
указывает чтение RAR, но не его запись. Значит, чтение CBR реально рассматривать,
а создание CBR без отдельного исполнителя обещать нельзя. Для графического выхода
предлагается CBZ через ZIP, изображения с устойчивым естественным порядком.

[ComicInfo](https://anansi-project.github.io/docs/comicinfo/documentation) содержит
`Notes` для информации о программе и сведения о страницах. Предлагаемый контракт:
читаемая отметка в `Notes` и структурированная запись внутри того же контейнера,
без произвольных полей, нарушающих XSD. Это не соседний JSON снаружи книги.
[Схемы ComicInfo](https://github.com/Anansi-Project/comicinfo) имеют опубликованные
версии и отдельные drafts: закрепить проверенную версию, не брать draft молча.

### Остальные форматы

- DOCX: уже существующее `LOPATA.Provenance` + application/modified-by; сохранить автора.
- ODT: [OpenDocument metadata](https://docs.oasis-open.org/office/OpenDocument/v1.3/OpenDocument-v1.3-part3-schema.html)
  предусматривает `meta:generator` и `meta:user-defined`. Использовать их в `meta.xml`.
- PDF: [документация ExifTool](https://exiftool.org/TagNames/PDF.html) различает Creator,
  Producer и другие поля; изменения записываются инкрементально, это не удаление
  прежней истории. [XMP](https://exiftool.org/TagNames/XMP.html) позволяет отдельные
  сведения; точный писатель/читаемый контракт проверить на стенде. Не вызывать
  существующий редактор с путём исходника: работать только с новым результатом.
- AZW3/MOBI: стандартные поддерживаемые поля — через calibre; произвольный JSON
  нельзя считать сохранённым без чтения результата. Если полного контракта в
  доступных полях нет, до приёмки выбрать проверяемое встроенное представление.
- HTML/MD/TXT: meta/машинно читаемый блок/преамбула по формату. Для TXT такая
  преамбула видна как текст; независимая проверка должна отделять её от произведения.
- RTF и старый DOC: проверить сохранность custom properties через офисный маршрут;
  пока полноценная запись нашего контракта здесь не подтверждена.

## 7. Проверка EPUB и общие проверки

[EPUBCheck](https://github.com/w3c/epubcheck) — независимый проверяющий инструмент
W3C/DAISY, лицензия BSD-3-Clause. При проверке latest production указан 5.4.0;
он ориентирован также на EPUB 3.4, что нужно учесть при выборе профиля.
[Установка](https://w3c.github.io/epubcheck/docs/installation/) требует Java и
полного комплекта JAR + lib. В каталоге ЛОПАТЫ есть JRE для других задач, но
его фактическую доступность/совместимость предстоит проверить.
[CLI](https://w3c.github.io/epubcheck/docs/cli/) позволяет сохранять JSON-отчёт.
Код 0 по умолчанию допускает предупреждения; для строгой проверки есть
`--failonwarnings`. Повторяющиеся сообщения в JSON/XML по умолчанию ограничены
25 экземплярами на код/текст; на стенде сохранять полный отчёт через
`--maxOfEachMessage unlimited`, если закреплённая версия поддерживает параметр.
Сначала использовать в стенде; вопрос обязательной
доставки пользователю пока открыт. Собственная проверка ZIP/XML не равна EPUBCheck.

Проверка схемы или контейнера не доказывает сохранность текста. Отдельно:
сопоставление текста/порядка блоков, числа страниц, картинок и примечаний,
проверка ссылок и независимое чтение отметки происхождения. Для графического
маршрута — порядок/размеры/ориентация/сопоставление страниц, а не сравнение текста.

## 8. Проводник, очередь и неизменность источника

По [Microsoft Verb Selection Model](https://learn.microsoft.com/en-us/windows/win32/shell/how-to-employ-the-verb-selection-model)
legacy-команда `Document` имеет стандартный предел 15 выбранных объектов,
`Player` — 100, у COM Player модель иная. Существующий код использует Document.
Это историческая находка исследования, **не задача расширять пакетный ПКМ**:
пользователь уточнил, что Проводник работает только с одним файлом.
Для нового меню использовать одиночную модель выбора (`Single`) и проверять
один вход в протоколе. При множественном выделении книжной команды нет; не
создавать скрытую серию одиночных задач. Проверить один файл, отсутствие команды
при двух/нескольких выбранных файлах и отклонение некорректного запроса.
Много → много и много → один остаются внутри подробной утилиты.
Появление в основном меню Windows 11 без «Показать дополнительные параметры»
не обещается без отдельной интеграции и проверки.

Предлагаемая последовательность: проверка запроса → устойчивое сохранение в
очередь → обработка в отдельной рабочей папке → метаданные → проверка → публикация
под новым свободным именем. Не изменять ассоциации по умолчанию и чужие ключи.
Не показывать основной UI, вопросы или лицензии в тихом запуске.

[ProcessStartInfo.ArgumentList](https://learn.microsoft.com/en-us/dotnet/api/system.diagnostics.processstartinfo.argumentlist?view=net-10.0)
передаёт аргументы без ручной сборки shell-команд. Запускать конкретный разрешённый
EXE с `UseShellExecute=false`/`CreateNoWindow=true`, собирать stdout/stderr,
отменять только собственный процесс и его дочерние процессы.
Профиль/этапы/версия конвертера должны фиксироваться в журнале для повторяемости.

Гарантия нового файла — ответственность нашего кода: `CreateNew`/публикация без
overwrite с повторным выбором свободного имени при гонке. Нельзя полагаться
только на предварительный `File.Exists`. Метаданные пишутся до окончательной
публикации; хеш/идентичность источника проверяется независимо. Отмена оставляет
источник целым, а временный результат не выглядит завершённой книгой.

## 9. ZIP/XML и ресурсы

[ZipArchive](https://learn.microsoft.com/en-us/dotnet/api/system.io.compression.ziparchive?view=net-10.0)
достаточен для обычных EPUB/CBZ, но защита путей и бюджета распаковки остаётся
нашей обязанностью. Проверять выход за рабочий каталог, коллизии имён, количество
элементов/распакованный объём, ссылки на ресурсы и отмену. Не распаковывать книгу
рядом с произвольными пользовательскими файлами.

[XmlReaderSettings.DtdProcessing](https://learn.microsoft.com/en-us/dotnet/api/system.xml.xmlreadersettings.dtdprocessing?view=net-10.0)
позволяет запретить DTD. Для наших адаптеров — `XmlResolver=null`, ограниченные
документы и локальный набор доверенных схем. Совместимость старых EPUB с DOCTYPE
потребует отдельного безопасного профиля, а не разрешения сетевых DTD без проверки.
Ссылки HTML/CSS/изображений разрешать относительно выделенного набора ресурсов.

## 10. Изученные резервные решения

**Pandoc.** [Руководство](https://pandoc.org/MANUAL.html) описывает чтение/запись
DOCX, EPUB, FB2, ODT и разметки через AST; некоторые детали исходного оформления
теряются. Есть списки поддерживаемых форматов, JSON-журнал и объединение с
`--file-scope`/переназначением идентификаторов. PDF не является обычным входом,
его создание требует отдельного PDF-движка. `--sandbox` не покрывает фильтры и
внешний PDF-движок; доступ к ресурсам также требует контроля. Предложение:
сравнить на сложных сносках/таблицах, если calibre или наш Markdown-путь не хватает;
не включать заранее TeX/wkhtmltopdf. [Windows-поставка](https://pandoc.org/installing.html),
[лицензия GPL v2+](https://github.com/jgm/pandoc/blob/main/COPYRIGHT) изучены.

**ImageMagick.** [Форматы](https://imagemagick.org/formats/) зависят от реального
комплекта и delegates; PDF-маршрут требует Ghostscript. Для нашего базового
PDF-рендера он поэтому не нужен. При использовании сложных графических входов
проверять `identify -list format`, кадры и ориентацию.
[Security policy](https://imagemagick.org/security-policy/) позволяет ограничивать
память, диск, время и кодеры; подготовить ограниченный профиль для книжных страниц.
[Лицензия](https://imagemagick.org/license/) и лицензии delegates рассматриваются
отдельно. Каталог ЛОПАТЫ уже содержит компонент, но фактическая установка не проверялась.

**Tesseract.** Изучена [официальная CLI-документация](https://github.com/tesseract-ocr/tessdoc/blob/main/Command-Line-Usage.md):
языковые данные, TSV/hOCR/PDF и режимы сегментации. Это распознавание с обученными
данными, а не точное извлечение существующего текста. Сейчас не объявляем его
частью обязательного простого профиля; пользователь разделил кодовую и модельную
обработку. Даже без LLM нужны отдельная оценка ошибок/разметки и история распознавания.

## 11. Предварительная матрица для стенда

Это маршруты-кандидаты, а не перечень уже поддержанных функций ЛОПАТЫ.

| Формат | Чтение | Создание | Основное ограничение |
|---|---|---|---|
| DOCX | calibre / OpenXml | calibre / OpenXml / LO | Стили, сноски, таблицы и ресурсы проверять отдельно |
| DOC | LibreOffice → DOCX | LibreOffice, если включим выход DOC | Встроенное происхождение и совместимость требуют проверки |
| ODT | calibre / LO | LibreOffice | Нет прямого ODT-выхода в изученном списке calibre |
| RTF | calibre / LO | calibre / LO | Проверить перенос метаданных/изображений |
| TXT | .NET / calibre | .NET / calibre | Кодировка, структура абзацев, видимая преамбула |
| Markdown | Markdig → HTML / возможный Pandoc | Структурный адаптер / возможный Pandoc | Диалект, таблицы, ресурсы и сноски |
| HTML/XHTML | AngleSharp / calibre | Собственный адаптер / calibre HTMLZ | Вложения для обычного HTML, сетевые ссылки, очистка |
| FB2 / FB2 в ZIP | calibre / XML + ZIP | calibre / XML | XSD, binary, примечания, program-used/custom-info |
| EPUB 2/3 | calibre / ZIP + XML/DOM | calibre / пакетный адаптер | Навигация, spine, ресурсы, версия, EPUBCheck |
| AZW3/MOBI/KEPUB | calibre для поддержанных разновидностей | calibre | DRM не обходится, полнота встроенных сведений |
| PDF с текстом | PdfPig / calibre | LO / calibre | Обычная конвертация может иметь потери; интеллектуальное восстановление сложного PDF — этап 2 по выбору пользователя |
| Скан PDF | Windows-рендер страниц | Графический PDF/CBZ | Без OCR не получается достоверный текст |
| PNG/JPEG/TIFF/WebP | WIC/Skia, резерв ImageMagick | Страницы PDF/CBZ, ресурсы EPUB | Все кадры TIFF, ориентация, размер, кодек |
| CBZ | ZIP / calibre | Собственная упаковка | Порядок страниц и ComicInfo |
| CBR | SharpCompress / calibre | Не подтверждено выбранными средствами | RAR — только чтение у SharpCompress |
| FB3 | Отдельный адаптер | Отдельный адаптер | Схемы изучены, готовый Windows-маршрут не подтверждён |
| CHM/LIT/LRF/DJVU/PDB и прочие | По точному списку calibre | Только поддержанные выходы | Для DJVU calibre ожидает имеющийся текстовый слой |

Объединение много → один — отдельная программная операция с управляемым порядком,
переназначением идентификаторов и разрешением метаданных. Нельзя просто склеить
байты ZIP/XML или считать обычный одиночный ebook-convert командой объединения.

## 12. Что проверяем до переноса в живой код

1. Закрепить реальные стабильные дистрибутивы/хеши и их справку, сохранить лицензии.
   Ничего не обновлять в текущих работающих сценариях ради этого исследования.
2. Сравнить DOC/DOCX → FB2 и обратный FB2 → DOCX, EPUB ↔ FB2, EPUB → AZW3,
   офисные → PDF, TIFF/скан → CBZ/PDF, CBR → CBZ и направления разметки.
3. Контрольный корпус: кириллица, редкие символы, стихотворения, таблицы, примечания,
   несколько иллюстраций, простой PDF и контрольный сложный PDF для проверки
   ограничений (без обязательного восстановления), многостраничный TIFF, коллизии имён/ID.
4. Много → много и много → один на смешанных источниках, больших книгах,
   отмене/ошибке и продолжении. Измерять время/память, не назначать лимиты по одному ПК.
5. Хеши исходников, отсутствие замены готовых файлов, независимое чтение выходов,
   схемы/EPUBCheck, ссылки/картинки/сноски, обязательное происхождение.
6. ПКМ: один файл при закрытом/открытом основном окне, отсутствие команды при
   множественном выделении, защита от многофайлового запроса, отсутствие компонента
   и ранее не принятая лицензия. Тихий режим не превращается в мастер установки.
7. После стенда уточнить список поставляемых форматов, профили популярных команд
   и настройки. Доступность исходного кода решения не равна готовой поддержке формата.

Исследование завершено на уровне документации. Физические конвертации, качество
русских книг, реальные пики памяти, бинарная совместимость комплектов и правильная
работа нового ПКМ пока не проверены. Реализация остаётся отдельным следующим шагом.
