# Концепция универсального голосового ввода LOPATA

Статус: идея на будущее. Не текущее ТЗ.

## 1. Назначение

Общесистемный локальный голосовой ввод для всей LOPATA, а не отдельная функция Советника, Писателя или другого сценария.

Один механизм должен работать в:
- запросах ИИ;
- ручном редактировании книги;
- описаниях изображений;
- будущей музыке;
- Песочнице;
- настройках и описаниях проектов;
- будущих утилитах;
- любых подходящих текстовых полях.

Новый сценарий не должен самостоятельно реализовывать диктовку.

## 2. Базовый принцип

Микрофон → локальный CPU ASR → нормализованный текст → выбранная текстовая цель.

Главная цель — практичная офлайн-диктовка, а не голосовой ассистент.

Желательны:
- русский и английский;
- пунктуация;
- заглавные буквы;
- нормальная структура предложений;
- числа, сокращения и технические термины;
- низкая задержка;
- небольшое потребление RAM;
- отсутствие нагрузки на GPU.

Первый кандидат для стенда: **Parakeet TDT 0.6B v3 INT8**.

VibeVoice-ASR-BitNet остаётся альтернативным CPU-кандидатом, но русский для BitNet требует отдельной проверки.

## 3. Управление

Управление вынесено в отдельное небольшое плавающее окно поверх других окон.

Кнопка микрофона работает как в звонке:

- первое нажатие — начать текущую диктовку;
- второе — завершить текущий фрагмент;
- желательно также поддержать нажатие с удержанием и завершение при отпускании.

Модель может быть постоянно загружена в RAM, но микрофон не должен постоянно слушать пользователя.

Архитектуру постоянной загрузки определить после стенда:
- холодный старт;
- задержка первого результата;
- повторный запуск;
- RAM;
- CPU;
- качество RU/EN.

## 4. Временный файл

Текущая диктовка хранится во временном файле.

Он является:
- промежуточным результатом;
- защитой от потери текста;
- страховкой при неудачной передаче;
- независимым от системного clipboard хранилищем.

После успешной передачи временный результат очищается. При ошибке передачи текст остаётся.

## 5. Выбор цели

В правом нижнем углу виджета находится маленькая кнопка выбора цели, условный «прицел».

Пользователь:
1. нажимает прицел;
2. указывает на нужную область ввода;
3. LOPATA запоминает выбранную цель;
4. последующая диктовка направляется туда.

Стрелка на концептуальном рисунке — только иллюстрация принципа, постоянная линия между окнами не нужна.

## 6. Визуальное подтверждение

Без лишних сообщений.

Успешная привязка:
- маленькая синяя галочка коротко проходит от кнопки прицела к выбранному полю.

Неудачная:
- красный крестик выполняет аналогичную короткую анимацию.

## 7. Собственные окна LOPATA

Для собственных сценариев и утилит использовать прямую внутреннюю передачу текста.

Не требуется имитация клавиатуры или clipboard там, где LOPATA сама контролирует поле.

## 8. Внешние программы

Основной порядок интереса:
1. LOPATA;
2. утилиты LOPATA;
3. браузеры;
4. Telegram;
5. другие распространённые программы.

Внешняя привязка — дополнительная фича, а не основная цель.

Не создавать пользователю таблицу совместимости. Пользователь просто пробует указать поле:
- синяя галочка — получилось;
- красный крестик — не получилось.

Если программа уже имеет собственную удобную диктовку, LOPATA не обязана её заменять.

## 9. Что не требуется

Не нужны:
- голосовой ассистент;
- голосовые команды;
- постоянное прослушивание без включения пользователем;
- облачная обработка;
- обязательная LLM;
- сложная семантическая редактура;
- отдельная диктовка в каждом сценарии;
- обещание работы со всеми программами Windows.

## 10. Будущий интеллектуальный уровень

Отдельно можно рассматривать:

ASR → небольшая LLM → нормализованный текст.

Например, превращать разговорную, сбивчивую речь в аккуратно сформулированный запрос.

Это отдельная будущая функция. Базовая диктовка должна быть полезна и без неё.

## 11. Главный критерий

Нужен не самый большой или самый современный ASR, а **самая дешёвая по ресурсам приемлемая локальная диктовка**.

Если небольшой CPU-движок достаточно хорошо понимает RU/EN, ставит пунктуацию и почти не мешает 27B-моделям на GPU, он предпочтительнее более тяжёлого решения.

## 12. Итог

LOPATA получает универсальный плавающий голосовой виджет:

запуск LOPATA → локальный CPU ASR → выбор цели → включение микрофона → диктовка → выключение микрофона → передача текста → очистка временного файла.

Внутри LOPATA используется прямая интеграция. Внешние приложения могут подключаться через механизм выбора цели.

Главная идея:

> **один локальный голосовой ввод для всей LOPATA, а не отдельная диктовка для каждого сценария.**
