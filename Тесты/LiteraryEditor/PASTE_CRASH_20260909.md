# Сбой длинной вставки — 0.1.83-dev

Пользовательский сбой 2026-09-09 21:10:39: Windows Application/.NET Runtime подтвердил необработанный InvalidOperationException в LiteraryEditorDialogs.Choose при установке DialogResult. Сообщение: DialogResult можно задавать только у окна, открытого модально. Тексты моделей и нагрузка не участвовали.

Причина воспроизведена до правки в WPF-стенде: вызов InsertTextAsync с 8000 символов внутри Dispatcher.DisableProcessing приводит к исключению в ShowDialog/PushFrame («работа диспетчера приостановлена»). Task переходил в Faulted, а окно уже было видимо. Нажатие его кнопки воспроизводило точное исключение из журнала пользователя. В обработчике Pasting задача запускалась без ожидания; первая ошибка оставалась ненаблюдаемой. Нативная команда вставки выполняется внутри блока изменения текста, поэтому открывать модальный цикл прямо из этого обработчика нельзя.

Исправление: общий InsertTextAsync сначала уступает диспетчеру, чтобы исходная команда завершилась; затем обрабатывает вставку. Последовательная очередь предотвращает перекрывающиеся диалоги нескольких вставок. При сбое запуска модального окна helper закрывает частично открытое окно и повторно выбрасывает ошибку, не оставляя доступных кнопок у немодального окна.

Предыдущий стенд проверял прямой InsertTextAsync и синтетическое событие Pasting без ограничения диспетчера. Это было недостаточное покрытие: большие вставки проходили в стенде, но реальная команда имела другой жизненный цикл. Теперь проверка включает Dispatcher.DisableProcessing и ожидает отложенную задачу без открытого окна до окончания блока. После возобновления диспетчера проверяются отмена, редактирование, продолжение и деление 14001 символа на части. Общий обработчик Pasting также вызывается внутри этого блока. Полный прежний WPF-набор сохранён и проходит.

На диске пользовательского проекта найдены читаемые главы [001] Книга тестов.txt (14 символов, 21:07:59) и [002] Без названия.txt (23 символа, 21:09:52); индекс содержит обе главы, активна [002].
