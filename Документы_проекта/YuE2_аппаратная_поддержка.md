## Решение

Один GPU-комплект, содержащий CUDA для SM86/89/120, Vulkan и CPU через `GGML_BACKEND_DL`; отдельный маленький CPU AVX2 комплект остаётся независимым аварийным вариантом. Исторические имена `win-cuda128-x64`/`win-x64` сохранены для совместимости заданий. Раздельные пакеты для каждой марки GPU не создаются: это дублировало бы большие cuBLAS библиотеки.

Системный драйвер предоставляет `nvcuda.dll`/`vulkan-1.dll`. В приложение не входит SDK, nvcc, glslc или изменение драйверов. CUDA выбирается по capability и версии API драйвера (>=12080), не названию карты. Vulkan рассматривается независимо от марки; AMD — основной дополнительный путь, Intel допустим при совместимом Vulkan, но без обещания физической проверки.

Закреплённый GGML заменяет CMake `120-real` на `120a-real` для архитектурных FP4 инструкций Blackwell. Проверка cuobjdump 12.8.90 реальной DLL обнаружила 432 cubin: SM86, SM89, SM120a. Это support capability 12.0, не обещание совместимости со следующим GPU поколением. cuobjdump — дополнительный developer архив 5484288 байт, SHA-256 `af6c4b7678cd9f3f3b8eeff7cc44f9d732bfacf70b1bdd03abccc25fec6c1ac1`, из официального NVIDIA redistrib_12.8.1.json; не поставляется пользователю.

`GGML_BACKEND` позволяет назначить точное устройство (`CUDA0`, `Vulkan0`, `CPU`). Пробник запускается как собственный короткоживущий процесс отдельно для каждой GPU-библиотеки: сбой драйвера не должен завершить WPF. Измеряется свободная память через `ggml_backend_dev_memory`; переменные, меняющие видимость устройств, очищаются одинаково у пробника и исполнителя.

## Память и запуск сценария

При входе проверяются runtime, лицензии, GGUF metadata и свободная память для текущих пожеланий. Перед каждым незавершённым этапом измерение повторяется. Начальная оценка при ещё неизвестном ABC использует его максимальный бюджет. Она не резервирует память: другой процесс может занять её позже.

Размеры весов читаются из tensor metadata GGUF. AR и NAR разделяются по реально используемым именам; общий norm учитывается в обоих. Norm/bias расширяются до F32. Для планирования берётся AR; для синтеза — максимум AR и NAR+VAE. KV сохраняется между группами и добавляется отдельно. В универсальном preset cot=full/batch=1/guidance=1 одна KV-копия: `layers * kvHeads * headDim * 2 * sizeof(F16) * context`.

Контекст этапа округляется вверх до 256: prefix+budget ABC для планирования; prefix+ABC+2*semantic budget для синтеза с сохранением полного chunk, когда он помещается. Потолок upstream 24576 сохраняется. Это снижает лишнюю KV память коротких запросов. Смешанного размещения слоёв/частичного offload в CLI нет — оно не выдумывается.

Compute/allocator reserve оценивается консервативно: 1 GiB + зависимость от длины prefix и semantic budget + 512 MiB запаса. Это оценка, а не измеренный максимум для всех драйверов. При CPU дополнительно учитывается место под отображение обоих файлов модели и проверяется AVX2. При нехватке GPU и RAM выполнение запрещается.

Только распознанная ошибка инициализации, устройства или выделения GPU памяти допускает один CPU повтор того же незавершённого этапа. Отмена, лицензия, испорченные веса/ABC/WAV и произвольные ошибки не запускают fallback. Два seed, запрос и сохранённый ABC не меняются. Численные результаты разных backend могут отличаться даже при одинаковых seed. Готовые файлы публикуются штатно после проверки; частичный WAV не становится результатом.

UI: «Видеокарта»/«Процессор», для CPU человеческая причина. Точные backend, устройство, capability/driver при диагностике, free/required estimate, KV/context/weights — журнал.

## Границы проверки

Виртуальная матрица и физическая генерация различаются. На этом ПК доступна только RTX4090. Проверка CUDA/Vulkan на ней не подтверждает фактический запуск на RTX30, RTX50, AMD или Intel. Их сборочная/логическая поддержка проверяется отдельно; физическая проверка остаётся неизвестной до соответствующего железа.

Физический opt-in стенд прошёл 2/2: CPU AVX2 и автоматический CUDA0 через MusicYueWorker; дополнительно принудительный Vulkan0 напрямую CLI. Каждый путь создал валидный WAV 47936 stereo frames @ 48000 Hz, 191788 байт; журналы подтвердили LM/NAR/VAE backend. Отмена при Score 0/128 остановила owned process и не опубликовала план. Vulkan — на RTX4090, не AMD. Native CLI сборка 509 шагов прошла; предупреждения upstream CUDA floating overflow и yyjson /W0 сохранены, предупреждений кода собственного probe нет; MSVC /W3→/W4 обусловлено флагами upstream.

Общая проверка: 1165 успешных, 0 ошибок, 2 opt-in native случая отдельно. Точность токенизатора проверена по реальному GGUF: прежний повреждённый JSON-пример whitespace восстановлен из неизменённых reference token IDs и словаря модели; ожидаемые IDs не менялись. CUDA capability сопоставляется по PCI bus ID, а не по совпадению порядковых номеров GGML и драйвера.
