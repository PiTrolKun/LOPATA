# Аудит компонентов — внедрение и проверки

Дата: 22.10.2026. Реализовано в 0.5.117-dev, принято пользователем после проверки
всех сценариев, повторных входов и перезапусков. Закрытие — 0.6.0-dev/0.6.0-beta;
[протокол выпуска](../Релизы/0.6.0-beta_проверки.md). Ниже — доказательства реализации.

## Общий контракт

`ComponentAudit` выбирает режим для конкретной установки, ревизии и известного
состава файлов. Режим фиксируется на операцию. Квитанции первого полного
прохода и поколения установок хранятся в локальной служебной папке
`AI_HUB/ComponentAudit`; настройки переключателя — в обычных настройках программы.

Первый проход, смена ревизии и переустановка требуют полного аудита даже при
зелёной кнопке. Проверка во время скачивания/установки не заменяет первый запуск.
Неудача, отмена и ошибка записи не создают успешную квитанцию. Повреждённые
служебные квитанции вызывают повторный полный аудит; повреждённый реестр
поколений восстанавливается с общей новой эпохой и отзывом прежних подтверждений.

После успеха OFF посещает обязательные пути и проверяет существование файлов,
без чтения содержимого, сравнения размеров/дат, рекурсивного поиска лишних файлов
или карантина. Маленькие манифесты и центральный каталог ZIP читаются для списка
необходимых путей; это не чтение/хеширование payload. ON сохраняет штатный полный
контроль. Одинаковые вложенные запросы одной операции согласованы.

## Карта подключённых путей

| Область | Точки входа и назначение |
|---|---|
| Общие библиотеки и native | `PinnedFileTreeVerifier`, `PythonRuntimeBundleVerifier`, `HardwareRuntimeBundleVerifier`, `NativeEngineBundleVerifier`, `PinnedZipExpansionVerifier`; выбор Llama/SD, отдельные диагностические `--version` |
| Установка | `ComponentManager`, Python staging, managed model acquisition, загрузчики ядра/executor/reranker, литературных файлов и Qdrant: полная проверка и сброс поколения после замены |
| Модели | `ManagedModelAcquisitionService`, `CoreModelManager`, `ExecutorModelInstaller`, `ManagedModelRuntimeAudit`: одинаковая идентичность подготовки и фактического использования |
| Музыка | Studio/YuE, ACE, BF16, DiffRhythm, HeartMuLa; собственные Source/Runtime и диагностические import-probe; ASR/GigaAM, LoRA, stems, нотный парсер и аудио/видео helpers |
| Книги | Управляемые Calibre/Office, Smart OCR и его wheel/runtime inventory; подготовка и повторное использование сессии |
| Литература и базы | `LiteraryFileVerification`, Giga/Jelly/Qdrant, личная база текстов и её embedding; общие Llama/Python; immutable RAG-источники отдельно |
| Изображения | Подготовка и фактическая загрузка image/vision, старый SD runtime, runtime compatibility smoke-check, SwinIR и native utilities |
| Прочие помощники | ExifTool, LyricVideo/FFmpeg, общий audio runtime; первый вызов записи тоже готовит ExifTool |
| UI и ошибки | Один глобальный переключатель; RU/EN, обе темы, popup/трей, сохранение первого отключения; общая фоновая работа и terminal handlers литературы/изображений/музыки |

Явный контракт C# → Python передаёт подготовленность LoRA/GigaAM только после
проверки host. Вложенные scripts всё равно проверяют наличие и допустимые пути.
Самостоятельный запуск без prepared-контракта сохраняет полное хеширование.
Нет глобальной подмены `hashlib`, переменной окружения для отключения всех проверок
или изменений закреплённых сторонних архивов/весов.

## Сохранённые проверки другого назначения

- Лицензии, подписи обновлений, распаковка и безопасная публикация новой установки.
- Пользовательские аудио/документы, защита перезаписи, immutable RAG import,
  snapshots, восстановление и идентичность исходника/результата.
- Provenance и встроенные метаданные, конвертация LoRA/тензоров,
  совместимость ACE retake/noise и узкие upstream compatibility patches.
- Реальная загрузка моделей, рабочие импорты, текущая память, список устройств,
  выбор совместимого backend. Это выполнение и аппаратный выбор, а не аудит.
- Внешний системный LibreOffice исторически не имеет нашего закреплённого
  манифеста. Для него сохранён внешний инструментальный путь; собственный bundle
  Office охвачен. Новый полный аудит внешнего ПО не изобретался.

Старые достоверно не связанные с установкой квитанции не объявлены новым
подтверждением: первая подготовка существующего компонента может один раз занять
обычное время полной проверки. Массового чтения всех весов при старте нет.
