## 2. Системная телеметрия Windows

На рабочем ПК указана Windows 11 25H2, сборка 26200.9974. В коротком пробном чтении PowerShell с двумя срезами через секунду доступны `GPU Adapter Memory`, `GPU Process Memory` и `GPU Engine`. Во втором срезе валидны 2 записи счётчика адаптера, 45 записей памяти процессов и 687 записей GPU-движков для экземпляров счётчика. Последнее число описывает записи, включая сочетания процесса и движка. Полученный срез подтверждает доступность на этой машине в текущем сеансе. Проверки на iGPU, нескольких адаптерах, при ограниченных правах и повторном подключении ещё предстоят. [Информация о выпусках Windows 11](https://learn.microsoft.com/en-us/windows/release-health/windows11-release-information)

Базовая частота для опыта — раз в секунду во время задачи, в простое проверить более редкий сбор. Значения со статусом ошибки или без нужного экземпляра помечать как недоступные. ## 3. Правила, статистика и модели

**Простые правила нужны как контрольный вариант.** До запуска сравнить фактический запас памяти с оценкой для этой модели, движка и размера. Краткий провал показателя можно уточнить повторным замером. После старта использовать этап и время последнего подтверждённого продвижения. Один и тот же сигнал показывать один раз на запуск. Для похожих запусков хранить условие прогрева, параметры и backend, считать медиану, квантили и разброс длительности. Малую выборку и недоступность данных передавать как уровень уверенности. [Робастная оценка разброса NIST](https://www.itl.nist.gov/div898/handbook/eda/section3/eda356.htm)

**Isolation Forest** исследует необычные сочетания признаков, например низкий запас памяти, длительность давления и время без продвижения. Для него признаки вычислять по истории, доступной в момент оценки. Модель возвращает оценку аномальности. Порог надо калибровать на проверочных запусках, интерпретация как вероятность нехватки памяти требует дополнительных данных. Актуальный проверенный scikit-learn 1.9.1 опубликован 10 сентября 2026 года, лицензия BSD-3-Clause, для Windows x64 есть колёса. У IBM своя граница scikit-learn ниже 1.8. Для сравнения разумны отдельные среды. [IsolationForest](https://scikit-learn.org/stable/modules/generated/sklearn.ensemble.IsolationForest.html) · [scikit-learn 1.9.1](https://pypi.org/project/scikit-learn/1.9.1/)

## 5. Как проверить выводы при реализации

1. **Зафиксировать основу сравнения.** Для каждого прогона записать версию Windows и драйвера, ревизии движка и компонентов, backend, фактический адаптер, параметры Krea, режим разового/прогретого процесса. Менять по одному условию. Для начала сравнить повторные серии с одинаковыми запросом, seed и разрешением, затем отдельно проверить другой размер.
2. **Проверить наблюдение до оценки алгоритмов.** Сопоставить замеры по адаптеру, приложению и задаче с независимыми источниками. Среди контролей из ТЗ для оценки сигналов особенно важны обычный ход, длительная штатная стадия, подтверждённый сбой и неполные данные. Для Krea дополнительно отличить первую попытку GPU, CPU-повтор, сохранение результата и штатный прогрев.
3. **Разделять наблюдение и вмешательство.** Сценарии с Black Desert проверять при фактической доступности игры и замере её вклада на том же адаптере. При отсутствии игры измерить общий механизм на контролируемой нагрузке. Отсутствие подтверждения по BDO записать в результат. Во время сравнительных прогонов учитывать внешний софт, который может сам менять приоритеты.
4. **Сравнить на новых целых запусках.** Правила, затем статистика, Isolation Forest и TSPulse получают один и тот же отложенный набор. Сравнивать ложные уведомления на штатный запуск и час фона, долю пропущенных подтверждённых случаев, время сигнала до запуска и задержку расчёта. Для полного анализа истории и имитации работы в реальном времени вести отдельные результаты.
5. **Измерить цену каждого слоя.** Простой и генерация с наблюдением и без него. Записать CPU, RAM, рост журнала, длительность генерации, задержку измерения и объём выборки. Для Python-модели отдельно замерить холодный старт, полную память процесса, повторный вызов и длительный простой. Codex ведёт прогоны и сохраняет повторяемые команды, версии, результаты и ограничения по устройствам.

**Вывод для внедрения.** Начинать со счётчиков Windows, событий ЛОПАТЫ и правил на закреплённом Krea 2 Turbo. Сначала проверить, какие данные действительно доступны до запуска и какие события надёжно отделяют сбой GPU от успешного повтора на CPU. По результатам этих серий можно оценить, окупаются ли TSPulse, дополнительные API драйверов и более глубокие трассы.
