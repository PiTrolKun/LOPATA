# Обновления программы и публикация установщика

Первый выпуск с обновлениями: **0.1.53-beta**. Внутренняя версия: **0.1.53-dev**.

В настройках кнопка «Обновления программы» открывает проверку, выбор тестового
канала и автоматической проверки. Проверка запускается после открытия главного
окна при каждом запуске (исправлено в 0.1.55-dev: пауза в 6 часов удалена). Найденное обновление
показывается кнопкой в шапке. Без интернета работа программы продолжается.

Скачивание начинается только по кнопке. Используется существующий
`SegmentedModelFileDownloader` и общая настройка соединений (авто/1/2/4/8).
Сервер без Range обслуживается последовательным путём того же загрузчика.
Скачанное хранится в `%LOCALAPPDATA%\AI_HUB\Updates\<версия>\<хеш>`.
При паузе/закрытии части остаются для докачки. Размер и SHA-256 проверяются
до признания файла готовым; перед запуском проверка повторяется. Контрольная
сумма подтверждает целостность файла, не заменяет цифровую подпись издателя.

Установка — отдельное подтверждение. Программа штатно завершает сессии и
runtime, установщик ждёт завершения процесса. Лицензионный экран сохраняется.
Установленная копия обновляется по своему пути; dev-копия не перезаписывает
исходники и предлагает обычную установку. Постоянные результаты и модели
не удаляются; временные изображения очищаются по ранее выбранной политике.

## Сборка не публикует

Обычная команда `Собрать_установщик_LOPATA.cmd` остаётся внутренней dev-сборкой.
Подготовить отдельную публичную beta-сборку:

```powershell
pwsh -NoProfile -File .\Инструменты\build-installer.ps1 -PublicBeta
```

VERSION не меняется на beta. Публичная сборка получает beta через параметр
сборки; программа и установщик имеют одинаковую версию. Рядом с EXE создаётся
`.build.json` с хешем, версией payload и исходным коммитом. Для публикации
нужны предварительно закоммиченные исходники; сборки с грязными исходниками
отклоняются. `-PublicBeta -SkipPublish` запрещён, чтобы не выдать старый payload.

## Публикация только отдельной командой пользователя

Сначала проверить выбранный установщик. Скрипт требует GitHub CLI (`gh`) с
авторизацией владельца репозитория. Ключи не входят в программу или установщик.
Сначала просмотр:

```powershell
pwsh -NoProfile -File .\Инструменты\publish-installer.ps1 -InstallerPath '.\Тесты\Установщики\LOPATA_Setup_0.1.53-beta.exe' -NotesPath '.\Документы_проекта\Релизы\0.1.53-beta.md'
```

Добавить `-Publish` только для действительной публикации. Исходный коммит
должен уже находиться в GitHub. Скрипт создаёт черновик, загружает EXE и
`lopata-update.json`, сверяет серверные SHA-256 обоих файлов и публикует.
После ошибки черновик остаётся закрытым для пользователей; автоматического
перезаписывания опубликованных выпусков нет. Для продолжения использовать
тот же EXE и заметки с `-Publish -ResumeDraft`: исходный коммит и хеши
уже загруженных файлов должны совпасть. Загружаются только недостающие файлы;
при несовпадении скрипт останавливается без перезаписи.

`-PruneInstallers` дополнительно разрешает очистку старых EXE. Сохраняются
первый установщик текущей линии X.Y и два последних. Удаляются только EXE,
не теги, исходники и заметки выпусков. Без флага выводится план без удаления.
Скрипт не запускается из сборщика и не вызывается приложением.

Проверка каналов использует список Releases, поскольку GitHub latest
исключает предварительные выпуски. Beta/dev-копии по умолчанию видят Beta;
стабильные — только стабильные. Пользователь может изменить это в окне
обновлений. Версии dev не публикуются.
