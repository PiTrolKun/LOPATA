# Надёжная подготовка файловых выпусков

10.11.2026. Пользователь поручил устранить повторяемые проблемы, обнаруженные при выпуске речевых ассетов, чтобы подготовка следующих обновлений не требовала ручного восстановления. Само принятое ТЗ ассетов остаётся в архиве. Исправление включается в текущий разрешённый выпуск 0.7.73-beta; 0.7.72-beta не опубликована.

## Причины и обязательные изменения

| Сбой | Действие, которое его вызвало | Отсутствующее ограничение |
|---|---|---|
| Ссылочный каталог прежнего движка отклонён после долгой упаковки | В сборочной копии runtime подключён через junction | Нет обязательной ранней материализации подписанного legacy-набора в обычный каталог сборочных входов |
| Два прежних файла модуля Проводника отсутствуют в новой поставке | Новый publish содержит только текущую версию модуля | Новый комплект собирается без обязательного переноса недостающих прежних файлов из проверенных пакетов |
| У неизменённых текстов изменились SHA-256 | Git применил общие правила перевода строк к поставочным файлам | Не все поставочные тексты объявлены побайтными контрактами; перед упаковкой нет канонизации эквивалентных текстов по предыдущему подписанному выпуску |
| После сбоя агента потерялся активный шаг | Долгая команда полагалась на временный идентификатор tool-session | Штатный сборочный скрипт пишет итоговый отчёт только в конце, без устойчивых фаз и проверенного продолжения |

1. В общем пути подготовки подписанного выпуска проверять предыдущий манифест, восстанавливать отсутствующие обычные файлы и исходные байты эквивалентных текстов только из аутентифицированных прежних пакетов. Содержательные изменения сохранять. Не ослаблять правила извлечения ZIP или защиты установочных путей.
2. Раннюю подготовку legacy-набора выполнять до упаковки: допустимый ссылочный источник разработчика копируется в обычный временный каталог с проверкой каждого файла по подписанному набору. Не доверять ссылкам внутри скачанного пакета, не менять installed updater.
3. Уточнить Git-атрибуты поставочных текстов, восстановить их канонические байты и проверить сохранность после чистого checkout.
4. Добавить устойчивое состояние в общий сборочный скрипт: версия, исходный коммит, подтверждённые этапы и реальные каталоги. Продолжение проверяет идентичность входов; параллельный запуск в тот же каталог запрещён блокировкой. Не объявлять выпуск опубликованным по одному запущенному процессу.
5. Покрыть тестами исходные ошибки и нормальный путь: отсутствующий старый файл, CRLF/LF/BOM, содержательная правка, повреждённый прежний ZIP, junction сборочного источника, отказ для повреждённого legacy-файла и сохранность запрета ссылок для установки.

Охват: два штатных входа `build-release-packages.ps1` и `build-file-update.ps1`, общий CLI упаковки, Git-контракты данных и повторный прогон настоящего выпуска. Модели не скачиваются и не генерируют записи; пользовательские проекты, звуки, настройки и ключ подписи сохраняются. Проверки подписей/хешей не зависят от UI-переключателя аудита компонентов: это контракт безопасности выпуска.

## Готовность

Ошибочные входы должны воспроизводимо останавливаться до долгой упаковки, обычный путь — формировать проверенные fresh/transition. Пакет должен сохранять прежние пути и байты неизменённых компонентов. Подписи, sourceDirty=false, standBuild=false и серверные SHA-256 проверяются штатно. Полный установщик не требуется. Статус реализации и фактические результаты будут записаны после проверки.
