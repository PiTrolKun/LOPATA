# Песня → клип: первый рабочий путь Glitchframe

## Закрытие плеера — исправление 0.6.88-dev

Два Application/.NET Runtime события 1026 (31.10, 03:02 и 03:40) показали
точную причину пользовательского падения: NotSupportedException при Stop
из Closed отдельного плеера с LoadedBehavior=Play. Это ошибка контракта WPF,
не результат SDXL и не подтверждение сбоя видеодрайвера.

Ручное управление, mute перед освобождением, Close/Source=null, единственное
учитываемое внешнее окно и cleanup при смене ролика/проекта и hide/unload.
Освобождение выполняется в Closing с идемпотентным резервом в Closed.
Повторный вход сам звук не включает; Play/Pause сохраняет ожидаемую позицию.

Содержательные STA-проверки используют настоящие окна и собственный silent
PCM WAV, а не поддельный MediaElement. Воспроизведение подтверждается ростом
Position, Pause — стабильными часами; после Close проверяются mute, Source=null,
отсутствие движения позиции спустя 1,25 с и эксклюзивный доступ к файлу.
11 новых случаев: обычное/немедленное закрытие, владелец, двойной клик,
смена ролика/проекта/пустой выбор, hide/unload/return и pause/resume до/после fullscreen.
46 PASS / 0 FAIL / 1 opt-in SKIP в scope SongClip/Glitchframe.

Safe-start .88: 0 ошибок / 0 предупреждений; окно открыто. Пакет тестов имеет
прежние 6 предупреждений baseline, новых нет. Готовые пользовательские MP4
не изменялись, длительная генерация не повторялась. Факт короткого повторного
звука сообщён пользователем; физическая запись аудиовыхода не выполнялась,
технически проверено отключение/освобождение обоих потоков.

## Что подключено

- Соседний вход с Видеомастерской, рабочая страница по макету, RU/EN и темы.
- Отдельные проекты, закрепление, импорт собственных копий файлов, история готовых
  клипов, неизменяемые снимки запусков, экспорт MP4 и передача в видеоредактор.
- Glitchframe: анализ музыки → фоны SDXL → Ken Burns → реактивные эффекты и LRC →
  исходная песня → проверка дорожек/длительности и встроенная отметка LOPATA.
- Общий многопоточный загрузчик, отдельное окно с файлами/скоростью, продолжение,
  автоматическое закрытие после проверки, общий аудит и лицензионный каталог.
- Изолированные библиотеки: общие среды H3/музыки не обновлялись. Повреждённая
  распакованная копия ремонтируется из закреплённых архивов с карантином старой копии.
- Общие фоновые операции, сохранение незавершённого запуска, повторное использование
  готовых фонов и суммарный таймер попыток. Кнопки не управляют чужими операциями.

Варианты H3 Music Context / Geekatplay / Any Song / InfiniteTalk / LongCat остаются
в объёме ТЗ, но их исполнители ещё не подключены. В интерфейсе это отмечено явно;
неизвестный полный размер не выдан за измеренный и следует после подготовленного набора.

## 0.6.86-dev — проверка макета и чтения текста песни

Первый интерфейс существенно отклонился от пользовательского наброска и
проверялся без ограничений основного окна. Исправлены оба уровня: контейнер
страницы использует доступную ширину, а области соответствуют трём рядам
макета. Список клипов отделён от экспорта/журнала; прогресс находится под
журналом. На маленьком окне доступна прокрутка ко всем действиям.

- Геометрия: 8 сочетаний RU/EN × 100/140% × 1900×980/860×560 DIP.
  Проверены конечные границы кнопок/надписей, clip/scroll viewport и достижимость
  нижнего правого края. Отдельно проверены обе темы и отключённый список.
- Миниатюра референса: файл после декодирования можно эксклюзивно открыть;
  повреждённый PNG оставляет placeholder и не ломает открытие проекта.
- Реальное окно ЛОПАТЫ: штатный вход через «Создание → Песня → клип», широкая
  страница и все основные действия видимы. После пользовательского повторного
  импорта полный текст и тайминги отображаются в своих полях.
- Причина пустого текста: ffprobe отдаёт собственный ID3 USLT как `lyrics-xxx`.
  Импорт принимает `lyrics-*`, прежние aliases и теги аудиопотока, использует
  существующий сборщик `AudioConversionMetadata.ProbeTags`. Резервный источник —
  валидный `LOPATA_TIMED_LYRICS`, без ASR и выдумывания таймингов.
- Проверка текущей MP3: 2213 символов текста / 2292 LRC; оба значения точно
  совпали с тегами. UI-текст совпал с сохранённым проектом, SHA256 аудио совпал
  с именем его устойчивой копии. Подтверждение пользователя: «Теперь ок».
- Регрессия: **64 PASS / 0 FAIL / 1 opt-in SKIP**, всего 65. Пропущен только
  физический повтор инференса Glitchframe, не требующийся для правки интерфейса.
  Сборка тестов сохраняет известные шесть baseline warnings; новые не добавлены.
  Production safe-start: **0 ошибок / 0 предупреждений**.
