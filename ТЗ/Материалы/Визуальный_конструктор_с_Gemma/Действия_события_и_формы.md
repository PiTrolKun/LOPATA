## Из чего пользователь собирает поведение

**Событие** определяет, когда начать работу. **Действие** выполняет один понятный шаг и при необходимости возвращает значение. Кнопку «Показать справку» можно настроить одним действием «Открыть форму». Для просмотра текста достаточно цепочки «Выбрать файл → Прочитать текст → Показать текст». Составные сценарии собираются из таких шагов и могут быть длиннее.

Пользователь добавляет действие, выбирает откуда взять данные и указывает, куда передать результат. Для простого действия достаточно одного или нескольких полей. Для повторяющегося сценария можно сохранить последовательность под своим именем и вызвать её одной строкой. Быстрый шаблон вставляет от одного до трёх обычных редактируемых действий. Это ориентир для размера готового блока, а длина сценария определяется задачей.

В каждом поле доступны совместимые источники. Это заданное значение, свойство элемента, переменная или результат предыдущего шага. Например, поле «Число» предложит прочитанное из формы число, а поле «Форма» — созданные в проекте формы. Стандартные типы включают текст, число, выбор «да/нет», дату, время, список, запись, таблицу, путь к файлу и выбор формы. Пустое значение, отмена и ошибка обрабатываются явно. Выбор «Папка» возвращает выбранный путь или статус отмены, который может остановить цепочку.

Искать действия можно по понятным названиям, например «записать файл», «показать текст», «перейти к форме». В списке сначала видны подходящие команды для текущего элемента. Все команды доступны через каталог. Быстрые действия и полный редактор используют один порядок выполнения.

## Формы и окна создаваемой программы

Форма — сохранённый экран со своими элементами и событиями. Её можно показать внутри текущего окна программы или поместить в собственное отдельное окно. Один проект может содержать много форм. У всех форм постоянные идентификаторы, поэтому в настройках и на вкладках можно использовать понятные названия, а связи сохраняются после переименования. В проекте выбирается стартовая форма.

### Вкладки над полотном

```text
[ Конвертер ] [ Справка ] [ Настройки ] [ ⋯ Формы ]     [ + ] [ − ]   [ 100 % ]
┌────────────────── полотно активной формы ───────────────────────────────────┐
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

- Вкладка меняет форму, которую сейчас редактирует пользователь. Список элементов, свойства и события следуют за выбором. При возврате на вкладку удобно восстановить последнее выделение и позицию полотна. В готовой программе поведение задают действия кнопок и других элементов.
- «+» добавляет форму и открывает её на полотне. «−» предлагает удалить активную форму и показывает, какие кнопки, события и стартовые настройки на неё ссылаются. Перед удалением можно выбрать замену цели или вернуться к редактированию. Для названий, дублирования и выбора стартовой формы подходит меню вкладки.
- «⋯ Формы» показывает все формы, когда вкладки перестают помещаться. Список с поиском доступен и при узком окне. Поле «100 %» управляет масштабом полотна.

### Один выбор в настройках кнопки

```text
Кнопка «Справка» → При нажатии → Открыть форму

Форма     [ Справка              ▾ ]
Как открыть  [ В этом окне       ▾ ]
               В этом окне
               Отдельным окном
```

| Способ | Что произойдёт при запуске программы |
| --- | --- |
| **В этом окне** | Содержимое текущего окна сменится на выбранную форму. Действие «Назад» возвращает предыдущую форму с её данными и фокусом. У каждого окна своя история. |
| **Отдельным окном** | Выбранная форма откроется в новом окне той же программы. Исходная форма остаётся доступной. Закрытие отдельного окна возвращает фокус вызывавшему окну, если оно открыто. |
| **Диалог с ответом** | Расширение для случая, когда программа ждёт «Применить» или «Отмена». В действие возвращается выбор и, при наличии, результат формы. |

Для повторного открытия того же отдельного окна предложено значение по умолчанию «Показать открытое». Оно сохраняет уже введённые там данные. Редактор сможет предложить вариант «Открыть ещё одно» для форм, где нужны несколько независимых экземпляров. У каждого экземпляра свои значения и история. Начальные параметры передаются явно, например «открыть Результат с вычисленным числом». Для общих настроек доступны специально выбранные переменные приложения и хранилища.

При удалении стартовой формы выбирается новая. При дублировании у копии появляются собственные идентификаторы элементов и связей. Переходы на другие формы видны в свойствах действий. Несуществующая цель сохраняется как видимая проблема проекта до исправления. Предпросмотр по умолчанию начинает работу со стартовой формы, как и экспортируемый EXE. Для быстрой проверки удобна команда предпросмотра активной формы.

Техническая основа на WPF позволяет собрать одну форму как содержимое и разместить её в области переходов или в отдельном окне. У WPF есть внутренняя навигация и обычные и модальные окна. Правила сохранения данных при возврате и повторного открытия определяет конструктор. [Навигация в WPF](https://learn.microsoft.com/en-us/dotnet/desktop/wpf/app-development/navigation-overview) · [Окна и диалоги в WPF](https://learn.microsoft.com/en-us/dotnet/desktop/wpf/windows/how-to-open-window-dialog-box)

Отдельному окну назначаются заголовок, начальный размер и режим изменения размера. Внутренняя форма располагает элементы под доступные размеры текущего окна. Адаптивность в обоих режимах проверяется и в редакторе, и в готовом EXE. [Размеры и компоновка](Окна_Windows_и_компоновка.md)

## Каталог готовых действий без Gemma

Одинаковые операции с разными параметрами показываются одной командой. «Рассчитать» может сложить числа, вычислить процент или выполнить выражение по выбранным правилам. «Изменить элемент» предлагает только свойства, подходящие его типу. Это даёт широкое покрытие и сохраняет короткие списки команд.

### Интерфейс и логика

| Группа | Что предусмотреть |
| --- | --- |
| **Формы и навигация** | Открыть форму внутри текущего окна или отдельным окном, назад, на стартовую форму, передать параметры, закрыть текущее окно, активировать уже открытое, завершить приложение. Для расширения подходят диалог с ответом, изменение заголовка и состояния окна. |
| **Элементы формы** | Прочитать и задать значение, текст, подпись, выбранный пункт, состояние флажка, значение ползунка. Очистить поле или группу. Показать, скрыть, включить, выключить, изменить цвет или доступное свойство, передать фокус. |
| **Сообщения и диалоги** | Показать сообщение и подсказку возле поля, спросить «Да/Нет», попросить короткий ввод, показать ход задачи. Выбрать файл, несколько файлов, папку, имя для сохранения или принтер штатным окном Windows. |

| **Отмена и сбои** | Обработать отмену выбора, ошибку и превышение времени. Выбрать поведение «Остановить», «Пропустить этот элемент» или «Выполнить действия при ошибке». Показать причину и записать выбранный результат в журнал. |
| **Время и задачи** | Подождать, запустить и остановить таймер, измерить время, запустить длительный шаг с прогрессом и отменой. Продолжить цепочку после завершения. Для простой отложенной реакции можно указать задержку или число повторов. |

Штатный выбор файлов и принтера опирается на диалоги Windows. Выбранный путь или принтер подставляется из окна выбора в следующие шаги. [Общие диалоги WPF](https://learn.microsoft.com/en-us/dotnet/desktop/wpf/windows/how-to-open-common-system-dialog-box)

## Каталог событий

Показывать события, доступные выбранной форме, окну или элементу. Для события важны его человеческое название, момент запуска и данные, которые оно отдаёт цепочке.

| Источник | Какие события предусмотреть |
| --- | --- |
| **Программа** | При запуске, при штатном завершении с возможностью отмены, после возврата к работе при наличии такого режима. У запуска могут быть входные параметры. |
| **Форма** | При первом открытии экземпляра, при показе, перед уходом с формы. «При показе» работает и при возврате через «Назад». «При открытии» подходит для начальной загрузки значений. |
| **Окно** | При активации, при смене размера, перед закрытием с возможностью отмены, после закрытия. |
| **Кнопка и команда меню** | При нажатии мышью или клавиатурой, вызов контекстного меню. Двойное нажатие доступно для подходящих элементов. |
| **Поле ввода** | При изменении текста, при подтверждении ввода, при входе и выходе фокуса. Доступны текущее значение и при необходимости предыдущее. |
| **Список, флажок, переключатель и ползунок** | При смене выбора, флажка или значения, при завершении перемещения ползунка. |
| **Таблица** | При выборе и открытии строки, после редактирования ячейки, при добавлении или удалении записи. Событие знает строку и столбец. |
| **Клавиатура, указатель и перетаскивание** | Выбранное сочетание клавиш в программе, вход или выход указателя, начало и завершение перетаскивания, приём файлов. Подходящие события получают точку, кнопку или список файлов. |
| **Таймер и длительная операция** | По таймеру, при изменении прогресса, при успехе, отмене или сбое. Последние три дают исход операции. |
| **Файл, медиа и устройство** | При изменении в выбранной папке, при готовности или окончании воспроизведения, при появлении настроенного устройства или новых данных. Доступность зависит от выбранного исполнителя. |
| **Сигнал внутри программы** | При явной отправке выбранного сигнала или изменении общей переменной. В цепочку передаются данные выбранного типа. |

Для первого стенда достаточно событий запуска, открытия и показа формы, перехода, закрытия окна, нажатия, подтверждения ввода и смены выбора. Отдельные события открытия и показа дают понятный способ один раз подготовить форму и обновлять её при возврате. Программное заполнение поля по умолчанию меняет значение без повторного запуска пользовательской реакции. Для намеренной реакции используется явный вызов действия или сигнала. Операция в процессе получает выбранное правило на повторное нажатие и отмену. Предпросмотр и EXE передают одинаковые события и данные. ## Когда использовать Gemma

| Задача | Предпочтительный способ |
| --- | --- |
| Показать форму, прочитать файл, записать значение, отфильтровать список или посчитать обычный процент | Готовые команды и формула. У пользователя видны входы, порядок и результат. |
| Повторно использовать порядок из нескольких понятных операций | Сохранить цепочку под своим именем. Gemma при необходимости может предложить вариант из уже известных действий выбранного события. Такой вариант редактируется и проверяется в том же списке. |
| Выполнить пользовательское правило, которое неудобно выразить формулой и короткой цепочкой | Попросить Gemma написать одну функцию на C#. Пример — пересчёт измерений по заданной таблице калибровки с особым правилом для пропущенных точек. Выбрать входные значения и ожидаемые результаты. |
| Нужен новый доступ к Windows, устройству, библиотеке или формату | Предусмотреть явное подключение исполнителя с понятными параметрами и тестом. Пользовательская функция получает уже прочитанные данные и возвращает обработанный результат. |

Для первого стенда перевод температуры можно собрать из выражения и условия выбора направления. Gemma может предложить короткую цепочку готовых карточек для события или C# для одного действия. Редактор показывает черновик и результат проверки. Применённый вариант записывается в общие исходники, а предыдущую версию можно восстановить.

## Что включить в первый стенд и как расширять

**Шаг 0** — папка обычного WPF-проекта, из которой уже запускается и собирается пустое окно. Для пробы после этого подходит конвертер со справкой и настройками или другой небольшой проект с нужными действиями. Чтение текста и сценарий «Начало работы за ПК» можно взять как дополнительные примеры. [Проверки в рабочем ТЗ](../../2026-11-27_Визуальный_конструктор_с_Gemma.md#план-проверки-и-критерии-приёмки)

**Основа каталога** включает чтение и изменение элемента, переменные, условие, числовое выражение, форматирование, показ сообщения, выбор файла, чтение текста, действия открытия формы, «Назад» и закрытие окна. Полный каталог выше задаёт направления расширения. Команды для других форматов, устройств, сети и продвинутой обработки можно добавлять группами через тот же механизм. Сборка и интерфейс показывают фактически подключённые действия.

Описывать каждую команду её постоянным идентификатором и версией параметров. Описание содержит русское и английское имя, совместимые входы, результат, доступность в предпросмотре и экспорте, зависимости и правила ошибки или отмены. Новые команды сохраняют параметры и связи в исходниках проекта. При повторном открытии сохраняются состав, порядок и связи уже записанных шагов.

Примеры ниже помогают выбрать проверку по ситуации.

| Проверка | Что увидеть |
| --- | --- |
| Создать формы, выбрать стартовую, переименовать, закрыть проект и открыть снова | Состав форм и пути кнопок сохраняются. На узком экране доступен список всех форм. |
| Открыть справку внутри, затем нажать «Назад» | Видна та же системная рамка окна. Восстановлены введённое число и выбранное направление. |
| Открыть настройки и справку как отдельные окна | Оба окна и конвертер видны одновременно. Изменение в одном окне сохраняет данные остальных. Закрытие возвращает фокус к вызывавшему окну. Повторное нажатие следует выбранному правилу повторного открытия. |
| Попробовать удалить форму, на которую ведёт кнопка | Редактор показывает источник ссылки и позволяет указать новую цель или отменить удаление. |
| Выключить Gemma и сеть | Вычисление, внутренняя навигация, отдельное окно и пробное чтение файла выполняются штатными действиями. Отмена выбора файла завершает цепочку с понятным статусом. |
| Применить предложение Gemma | Для выбранного события появляются готовые шаги либо для выбранного действия меняется C#. Принятый вариант сохраняется в исходниках и работает в сборке. |
| Открыть код действия через ПКМ | Переход ведёт к выполняемому коду проекта. Ручная правка видна при следующем запуске. |
| Запустить экспорт на чистой поддерживаемой Windows | Оба способа перехода, возврат назад, закрытие отдельного окна и расчёт работают как в предпросмотре. |
