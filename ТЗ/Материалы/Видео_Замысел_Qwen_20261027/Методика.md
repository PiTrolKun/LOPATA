# Проверка Qwen на авторском замысле

Дата: 27.10.2026, версия ЛОПАТЫ 0.6.38-dev. Пользователь поручил проверить
шесть ранее перечисленных кандидатов на своём примере. Это диагностический
проход, не реализация ИИ-механики в интерфейсе мастера.

Один исходный запрос (`input-ru.txt`), согласованный русский промт
(`prompt-ru.txt`), сюжетная форма, три уровня свободы — 18 независимых ответов.
Перевод и видеосинтез в этот проход не входят. Модели ниже ядра не запускаются.
Один проход на сочетание, без отбора лучшего дубля. Это предварительная
редакторская оценка на одном примере, не универсальный рейтинг моделей.

Параметры одинаковы: seed 42, temperature 0.7, top_p 0.9, top_k 40,
min_p 0, repeat_penalty 1.05, max_tokens 1536, контекст запрошен 8192,
thinking отключён, истории предыдущих ответов нет, cache_prompt=false.
Уровень меняет только поле выбора свободы в тексте промта. Полный заполненный
промт передан как одно сообщение user; дополнительные инструкции музыкального
сценария и личности ядра не добавляются. Фактическая вместимость контекста,
runtime, устройство, stop/length, usage и время сохраняются в result.json.

Использован действующий LlamaServerRuntimeService с размещением из
PreparePoetryAsync и переданным без изменений payload через
GeneratePrivateJsonAsync. Диагностическая обвязка обращается к внутренним
методам через reflection, без правок программы. Лицензии проверяются по
существующим подтверждениям, новые согласия автоматически не создаются.
ManagedModelAcquisitionService проверяет копии карточек в изолированном
каталоге; ComponentAudit сохраняет действующий режим. Ядро и исполнитель
также проходят свои штатные проверки запуска. Предпочтения размещения
стенда изолированы, после каждой модели процесс штатно освобождается.

Первый запуск обвязки выявил ошибку пути к служебным JSON и особый формат ID
исполнителя; инференс тогда не начинался. Ошибки сохранены в
`diagnostics/harness-initialization`, обвязка исправлена. Эти ошибки не
приписываются качеству моделей. Дальнейшие полные ответы сохраняются без
редактирования; журналы и payload позволяют восстановить цепочку запуска.

## Шкала 0–10

Каждый ответ оценивается отдельно:

| Критерий | Максимум |
| --- | ---: |
| Явные условия: мрачная, умеренно тревожная атмосфера без монстров и хоррора | 2.5 |
| Соблюдение выбранной свободы и честное описание изменений | 2.5 |
| Смысловая связность и цельность замысла | 2.0 |
| Ясность, естественность русского языка, отсутствие лишнего объёма | 1.5 |
| Польза для следующего творческого этапа, соблюдение формы ответа | 1.5 |

На уровне 1 неизвестный объект поиска и необъяснённый свет должны остаться
неопределёнными; нельзя добавлять прошлое героя, погоду/время суток,
предметы/действия и причину света без основания в исходнике. На уровне 2
допустимы детали, но центральная идея не подменяется. На уровне 3 допустима
новая интерпретация, которую нельзя штрафовать только за отличие от исходника.
При этом запреты действуют на всех уровнях. Сама по себе тревога или
необъяснённость не считается монстром/хоррором. Наличие технических кадровых
указаний, выдуманных обязательных условий и ненужных блокирующих вопросов
снижает соответствующие оценки.

Итог модели — среднее трёх уровней. Скорость указывается отдельно и не
добавляет баллы художественному качеству. Незавершённый ответ не выдаётся
за полный, техническая ошибка отделяется от оценки текста.

Примечание публикации 27.10.2026: текстовые копии ответов оформлены без хвостовых пробелов; исходные request/result JSON и runtime-журналы остаются локальными и не публикуются. Это редакционное оформление, а не новая оценка моделей.
