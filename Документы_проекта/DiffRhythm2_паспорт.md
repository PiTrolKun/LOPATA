## Текст и русский адаптер

Штатный обработчик заявляет EN/ZH и отклоняет кириллицу до модели (`other`).
Пользователь прямо разрешил экспериментальный русский через eSpeak.
`experimental_ru=1` включён по умолчанию, переключается в экспертном окне.
При `0` русский отклоняется с пояснением.

Текст остаётся кириллицей в проекте и аудиотегах. eSpeak RU выдаёт IPA-фонемы;
составные фонемы разбиваются на существующие обученные токены. Приближения
`ɭ→l`, `ɵ→o` и удаление конечной служебной кавычки eSpeak явно записываются
в receipt; неизвестная фонема вызывает ошибку. Это не доказательство обучения
модели русскому и не гарантия правильного произношения. «ЛАПАТА» сохраняется.

В Windows не открываем неиспользуемый японский/MBROLA голос при импорте G2P:
инициализация EspeakBackend отложена до вызова. Используемые голоса и EN/ZH
токенизатор выполняют исходный код. Китайский ONNX работает на CPU; upstream
сообщает предупреждение о недоступном CUDA provider. Старые SyntaxWarning
в исходниках upstream сохранены; исходники не переписаны ради их подавления.

Текст отдельно от стиля. `[Verse 1: MALE]` передаётся как штатный `[verse]`,
с предупреждением и сохранением оригинала. Неизвестные секционные маркеры
не удаляются молча: запрос отклоняется. Роли вокала, запреты хора/подпевки и
остальные пожелания передаются описанием стиля; отдельного жёсткого управления
ролями у данного API нет. Нормализация и эффективные фонемы сохранены в
`LOPATA_DIFFRHYTHM_REQUEST`.

## Настройки и границы первого подключения

Seed −1 (новый случайный для каждого варианта), 16 шагов, CFG 1,3,
ODE euler. Доступны midpoint/rk4/implicit_adams. `fake_stereo=1` — штатное
псевдостерео, не независимые вокальные каналы. Длительность — до 240 с;
«Автоматически» задаёт штатный предел 240 с. Модель может закончить раньше.
Точный объём готового аудио берётся из результата. Круги YuE/ACE скрыты.
Экспертные пресеты имеют собственную схему 7 и не переносятся между семействами.

Аудиореференс поддерживается авторами, но отдельный ввод референса в нынешнем
сценарии ЛОПАТЫ ещё не подключён. Instrumental отмечен TODO upstream: запрос
«Без вокала» отклоняется явно. Штатный генератор не заменён экспериментальным
streaming API; поток ЛОПАТЫ — очередь полных вариантов общей операции.

## Устройства и жизненный цикл

Общая политика выбирает совместимый управляемый PyTorch CUDA/XPU или CPU,
без жёсткого закрепления за CUDA0. CPU использует float32, GPU — float16.
ROCm pack 2.9.1 не подменяет ABI 2.10; при отсутствии совместимого GPU доступен CPU.
Это реализованные маршруты, не физическое испытание всех перечисленных GPU.
Подготовка API ограничена 90 с после запуска Python, без загрузки весов песни.

Операция `music.generate`, очередь, проекты, история и трэй общие. Настройки
привязаны к модели. Пауза/отмена прекращают принадлежащий ЛОПАТЕ процесс,
ожидают его выхода и удаляют собственную промежуточную копию исходников.
Незавершённый audio stage запускается заново; подтверждённые результаты не
повторяются. Физическая пауза генерации с весами/замер VRAM ещё не проверены.

## Исправление первого испытания — 0.4.33-dev, 09.10.2026

Пользователь загрузил компоненты. Сбой китайского запуска воспроизведён отдельно:
локальная ветка Hugging Face Hub ищет `model.safetensors`, а MuQ/MuLan этого
закреплённого комплекта поставляют `pytorch_model.bin`. Адаптер теперь вызывает
штатный `_load_as_pickle` (`torch.load(weights_only=True)`), сохраняя конструкторы,
strict/map_location и исходные веса. Safetensors продолжает штатный путь;
неподготовленные/незакреплённые пути не допускаются, загрузки из сети не добавлены.

Все реальные веса загружены на RTX 4090. Короткая проверка двух китайских строк
с потолком 30 с и штатными 16 шагами создала валидный WAV и receipt через тот же
изолированный launcher. Это проверка конвейера, не оценка полной песни/произношения.
27 тестов прошли, 1 прежний opt-in пропущен. Отдельная Python-регрессия проверяет
BIN/Safetensors, weights_only, отказ незакреплённому пути и отсутствующему файлу.

stderr теперь отделён от буферизованного stdout и сохраняется при сбое в локальном
processes.jsonl, до 32 Ки символов. Поздние обычные сообщения не вытесняют исключение.
В редакторе DiffRhythm показана собственная RU/EN подсказка вместо лимитов ACE.

Первый TypeError `attribute name must be string, not UnaryOp` внутри typeguard
наблюдался один раз при подготовке; повтор в программе прошёл. Прямой probe
установленных библиотек и 32 отдельных холодных импорта inflect также прошли.
Причина не доказана; Typeguard, проверки типов и зависимости не отключались.
При повторении сверять сохранённый полный хвост stderr, не объявлять сбой исправленным.

## 09.10.2026 — падение после проверки музыки, 0.4.34-dev

Windows .NET Runtime 1026 подтвердил три падения 0.4.33-dev на SwitchModel
из MusicPreparationControl.Render в finally. DiffRhythm probe завершался
с кодом 0. Причина: сохранённое китайское задание оставалось Waiting после
прежней ошибки загрузки; новый выбор модели нарушал защиту pending operation.
Выбор модели и применение примера вынесены из Render в обработанный переход.
При входе с pending music job открывается его проект без запуска модели,
с исходным JobId, текстом, настройками, продолжением и отменой. Контрольная
точка не очищается. Отдельный runtime probe не запускается при просмотре
pending job: исполнитель повторно проверит компоненты при продолжении.
Подписи этапов DiffRhythm больше не используют имя ACE.
Проверено 31 профильным тестом, 2 прежних аппаратных opt-in пропущены;
старые предупреждения Image-тестов сохранены, новых нет.
Backup: _backups/20261009_music-preparation-crash/files.json (12 файлов SHA256).
ТЗ остаётся активным; публикация и полный установщик не выполнялись.

строкой карточки и в лицензионном шлюзе.

аппаратуры выполняются в операции генерации после нажатия Start.
