## [BUG:VIKHR-GROUNDED-PREFILL] Вместо второго ответа возвращается прежний JSON

11.09.2026. [TAG:llama.cpp] [TAG:RAG] [TAG:chat-template] Проверено только на внешнем стенде, продукт не изменён.

- Симптом: первый grounded шаг Vikhr возвращает правильные relevant_doc_ids, второй возвращает тот же JSON, usage.completion_tokens=1.
- Причина: последнее сообщение имеет роль assistant. llama-server b9442 по умолчанию включает его продолжение (prefill), модель выдаёт EOS; API возвращает прежний текст как префикс. Это не цикл длинной генерации.
- [FIX:VIKHR-DISABLE-PREFILL] Для двух отдельных ответов использовать --no-prefill-assistant. Не применять вслепую ко всем backend/моделям: другие протоколы могут нуждаться в настоящем продолжении префикса.
- Проверка: в no-prefill-01 повторены 15 точно одинаковых JSON-тел второго шага; вместо JSON получены ответы с правильными основными фактами/признанием отсутствия сведений. Родной шаблон совпадает с исходной карточкой. Новые инструкции/ответы в эти 15 запросов не добавлялись.
- Доказательства: Тесты/VikhrNemo/REPORT.md, runs/first-01/native и runs/no-prefill-01/protocol; код backend d4c8e2c29/tools/server/server-common.cpp, строки 976–986. Не переносить вывод на прежние циклы Runeweaver/Qwen.

## [BUG:LITERARY-PASTE-MODAL] Падение длинной вставки в DialogResult

2026-09-09, исправлено в 0.1.83-dev. [TAG:WPF] [TAG:clipboard] [TAG:dispatcher]

- Симптом: после длинной вставки виден диалог переполнения, нажатие кнопки закрывает приложение. Windows .NET Runtime: InvalidOperationException, DialogResult можно задать только для модального окна.

- [FIX:DEFER-PASTE-DIALOG] Сначала Dispatcher.Yield, затем обработка текста и диалоги; очередь вставок последовательна. Частично открытое окно закрывается, если ShowDialog выбросил исключение. Не лечить только условием IsVisible перед DialogResult: видимость не означает успешный модальный запуск.
- Проверка: длинная вставка внутри Dispatcher.DisableProcessing; до окончания блока задача ожидает и окно не открыто, после — рабочие кнопки отмены/редактирования/продолжения/разделения. Одного вызова RaiseEvent(Pasting) без блока диспетчера недостаточно.
- Доказательства: ../Тесты/LiteraryEditor/PASTE_CRASH_20260909.md; Windows-событие сохранено в _backups/literary_paste_crash_20260909/windows-crash.json. Это интерфейсный сбой, не цикл модели.

Этот файл нужен, чтобы при повторных ошибках не гадать и не лечить по памяти.
