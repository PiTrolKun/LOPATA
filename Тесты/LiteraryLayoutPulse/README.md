# Регрессия пульсации литературного окна

Стенд WPF без загрузки модели и без запросов. Создаёт отдельный проект, длинную беседу и окно с увеличением текста 125%. Использует действующий масштаб Windows, UseLayoutRounding, шрифт и компоненты рабочего литературного окна. Проверяет обычное окно, разворачивание, прокрутку, рост ввода вверх до шести строк, очистку ввода, повторное разворачивание и соседние высоты рабочей области.

Запуск из корня репозитория:

```powershell
dotnet run --project 'Тесты\LiteraryLayoutPulse\Probe.csproj'
```

Журнал `runs/<дата>/layout.txt` содержит размеры строк, состояние Measure/Arrange, положение прокрутки и CPU-время. Ошибка возвращает ненулевой код. Отдельный watchdog завершает зависший стенд через 45 секунд. Считать только события LayoutUpdated недостаточно: при бесконечном внутреннем пересчёте это событие может вообще не доходить до обработчика.

Для контрольного воспроизведения прежней ошибки перед запуском задать `$env:PULSE_UNROUNDED_CONTROL='1'`. Этот режим только в стенде возвращает прежний расчёт дробной высоты; продукт не меняется. Для обычного прогона удалить эту переменную из окружения процесса.

Необязательный `PULSE_REPLAY_DIRECTORY` указывает на проект для чтения. В отдельную копию переносятся параметры, текущая беседа и текст первой главы; ID копии согласуются. Исходный проект не меняется, модели и индексы не запускаются. Такой прогон сохраняется только в игнорируемом `_backups/layout_replay_*`, поскольку содержит пользовательский текст.

## Результат 19 сентября 2026, 0.1.118-dev

При Windows DPI 200%, тексте 125% и высоте рабочей области 862,5 DIP прежняя формула задавала нижней строке 431,25 DIP — половину физического пикселя. Рядом с Auto/Star-строками WPF чередовал округление, Measure оставался невалидным, а прокрутка и разворачивание задерживались. В маленьком окне ошибка исчезала; увеличение ввода также временно разрывало цикл.

- Контроль со старой формулой: **FAIL**, `runs/20260919_225714`. На развёрнутом окне строки колебались между 431 и 431,5 DIP; на обычном окне стабилизировались.
- Та же синтетическая беседа с исправлением: **PASS**, `runs/20260919_225823`. Прокрутка достигает заданного смещения, ввод растёт вверх, размеры стабилизируются.
- Отдельная локальная копия пользовательской беседы: воспроизведение до исправления и PASS после него. Тексты не входят в этот отчёт.
- Общий литературный стенд: **137 проверок**, `../LiteraryStudio/runs/20260919_225848`; автотесты: **608/608**.

Исправление округляет нижнюю строку по DpiScaleY до физического пикселя до назначения Height. Размеры и поведение остальных частей интерфейса сохранены. Подтверждён дефект компоновки; это не проверка качества генерации модели. Окончательная пользовательская проверка открытого приложения остаётся отдельной.

Пользовательская проверка 19 сентября 2026: пользователь подтвердил, что проблема решена. Дефект пульсации и торможения прокрутки закрыт.
