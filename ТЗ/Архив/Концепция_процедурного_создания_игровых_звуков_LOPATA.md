# Концепция сценария процедурного создания игровых звуков LOPATA

Статус: идея на будущее. Концепция признана полезной и технологически реализуемой. Не текущее ТЗ.

## 1. Общая идея

Создать в LOPATA отдельный сценарий для создания коротких игровых звуков процедурным синтезом.

Проблема: готовых ретро-SFX много, но лицензия конкретного файла часто неизвестна; даже хороший готовый звук почти всегда немного не тот по длительности, высоте, атаке, хвосту или характеру. Поэтому предпочтительнее создавать собственный звук из параметров.

Главная цель: дать человеку без навыков программирования и без музыкального образования понятный интерфейс процедурного синтезатора, а LLM использовать как помощника, который умеет выставлять параметры по человеческому описанию.

## 2. Основной принцип

LLM не генерирует аудиофайл и не пишет произвольный DSP-код. Сам синтезатор уже готов.

LLM — скорее **«водитель такси»**: машина уже есть, руль и педали уже есть; пользователь говорит, куда ехать, а LLM крутит готовые органы управления.

**Человеческое описание → LLM → параметры синтезатора → процедурный звук.**

Пользователь после этого сам может поправить параметры ползунками.

## 3. Пример взаимодействия

Пользователь: «Сделай звук получения монетки, как в старой RPG, короткий, яркий, сначала ниже, потом быстро вверх, без длинного хвоста».

LLM не создаёт WAV. Она выставляет существующие параметры: длительность, начальную и конечную высоту, скорость изменения высоты, атаку, затухание, хвост, форму волны, шум, модуляцию, арпеджио и другие доступные параметры.

Пользователь видит параметры и может сказать «Хвост слишком длинный» или просто двинуть соответствующий ползунок.

**Основной инструмент — один редактируемый звук с параметрами.** Не три готовых варианта.

## 4. Почему LLM здесь подходит

Современные coding/chat-модели хорошо знают контекст старых игр: NES, SNES, Game Boy, Mega Drive, C64, аркады, 8-bit/16-bit SFX и типичные события вроде coin pickup, jump, hit, explosion, menu click, item pickup, level up и power-up.

Модели не требуется учиться генерировать аудио. Ей достаточно знать доступные параметры, их смысл, диапазоны и характерные комбинации.

## 5. Интерфейс

### Простой режим
- Длительность
- Высота
- Яркость
- Резкость
- Шум
- Хвост
- Скорость изменения тона

### Расширенный режим
- Attack
- Decay
- Sustain
- Release
- pitch envelope
- duty cycle
- FM depth
- noise amount
- bit crush
- vibrato
- arpeggio
- фильтры
- другие параметры конкретного backend.

## 6. Схема работы

1. Пользователь описывает звук простыми словами.
2. LLM выставляет параметры.
3. Процедурный backend генерирует звук.
4. Пользователь прослушивает результат.
5. Пользователь меняет параметры ползунками или описывает небольшую правку.
6. LLM меняет только нужные параметры.
7. Backend повторно рендерит звук.
8. Пользователь экспортирует результат.

Результат должен оставаться полностью редактируемым.

## 7. Найденные готовые технологии

### JFXR
Процедурный генератор игровых SFX на базе подхода sfxr. Интересен как backend с параметрами pitch, duration, oscillators, envelopes, filters, bit crunch, vibrato, arpeggio и другими элементами.

Репозиторий: https://github.com/ttencate/jfxr
Лицензия кода: BSD-3-Clause. Автор также разрешает использование созданных звуков без ограничений, включая коммерческие проекты.

### Bfxr
Развитие sfxr с дополнительными waveform, compression, harmonics, bitcrusher, pitch-jumping, mixer, reverse и сохранением параметров.

Проект: https://www.bfxr.net/
Использование конкретной версии исходного компонента требует отдельной проверки актуальной лицензии.

### ChipTone
Более развитый генератор ретро-звуков с генератором, sampler и sequencer. Для созданных пользователем звуков заявлен CC0.

Рассматривать прежде всего как референс возможностей и интерфейса, а не автоматически как компонент для встраивания.

### retro-sfx-gen
Небольшой процедурный генератор ретро-SFX на Python: чистый Python, без сторонних библиотек, математическая генерация, WAV 44.1 кГц/16 bit, осцилляторы, pitch glide, arpeggio, detune, ring modulation, шум, огибающие, 16 категорий, детерминированная генерация, MIT.

Репозиторий: https://github.com/PrayerT/retro-sfx-gen

## 8. Найденные проекты, подтверждающие саму UX-концепцию

### SoundSculptor / sfx-generator
Практически прямое подтверждение архитектуры: естественное описание → AI → параметры синтеза → ручное управление параметрами → процедурный звук. Есть seed, сохранение параметризованных звуков и экспорт WAV.

Репозиторий: https://github.com/neurofuzzy/sfx-generator
Лицензия репозитория: MIT.
Ограничение для LOPATA: AI-часть использует Gemini 2.5 Flash через Google AI, поэтому это не готовый локальный компонент.

### Chiptune SFX Maestro
Практически совпадающий с нашей концепцией исследовательский проект: текстовое описание → локальная небольшая модель → параметры sfxr → процедурный синтезатор → WAV. В проекте используется локальная модель примерно на 11M параметров, которая генерирует параметры, а не аудиоволну.

Источник: https://saf1.me/blog/chiptune-sfx-maestro/
Публично подтверждённую лицензию для повторного использования самого проекта надёжно установить не удалось; рассматривать как готовый компонент пока нельзя. Как доказательство концепции — очень полезен.

## 9. Furnace

Furnace Tracker интересен для максимально аутентичной эмуляции конкретного старого железа. Поддерживает большое количество реальных звуковых чипов, включая NES, Game Boy, Sega Genesis/YM2612, C64 SID, SN76489, PC Speaker, Atari, PC Engine, аркадные системы и другие FM/PSG/Wavetable-системы.

Умеет экспортировать WAV/VGM. Главное для LOPATA — имеет командную строку, поэтому его потенциально можно использовать как отдельный backend без необходимости заставлять пользователя работать с tracker-интерфейсом.

Сайт: https://tildearrow.org/furnace/
CLI: https://github.com/tildearrow/furnace/blob/master/doc/8-advanced/command-line.md
Лицензия: GPLv2+. Поэтому встраивание исходников в LOPATA требует отдельного лицензионного анализа; предпочтительнее рассматривать Furnace как отдельный backend.

## 10. Два класса backend

### Backend A — свободный процедурный SFX
Для UI, кнопок, монет, предметов, оружия, попаданий, шагов, меню, уведомлений, взрывов и других коротких эффектов.

Кандидаты: JFXR, собственный небольшой процедурный backend, retro-sfx-gen и другие sfxr-подобные движки.

### Backend B — эмуляция конкретного железа
Для NES, Game Boy, Mega Drive, C64, аркадных систем и других конкретных ретро-платформ. Основной найденный кандидат — Furnace.

## 11. Специальная AI-модель сначала не требуется

Наиболее интересный вариант для LOPATA:

**человеческое описание → существующая локальная LLM LOPATA → строгий набор параметров → синтезатор.**

LLM получает описание доступных параметров и допустимых диапазонов и возвращает только разрешённые значения, например:

```json
{
  "duration": 0.18,
  "waveform": "square",
  "pitch_start": 880,
  "pitch_end": 1320,
  "pitch_sweep": 0.12,
  "attack": 0.01,
  "decay": 0.14,
  "noise": 0.03
}
```

Это пример структуры, а не фиксированный набор параметров.

LLM не должна получать возможность произвольно выполнять код. Она должна работать как ограниченный контроллер существующего синтезатора.

## 12. Воспроизводимость

Хранить желательно не только WAV, но и рецепт:

```text
coin/
    parameters.json
    coin.wav
    README.md
```

Для chip backend дополнительно можно хранить проект/исходные параметры и VGM.

Главный объект — параметры/рецепт. WAV является производным результатом.

## 13. Лицензионная ценность

Процедурный подход позволяет не брать случайные готовые ассеты с неизвестным происхождением. Собственный звук создаётся из параметров.

Для проекта желательно фиксировать backend, версию, лицензию, параметры, дату создания, AI-модель, версию модели и её лицензию. Это упрощает THIRD_PARTY_NOTICES и проверку происхождения результата.

## 14. Пользовательская ценность

Сценарий полезен для разработчиков игр, моддеров, авторов небольших игр, разработчиков утилит, презентаций, роликов и всех, кому нужны уникальные UI-звуки без поиска готовых ассетов.

Главное преимущество: пользователь описывает нужный звук простыми словами, а не изучает профессиональный синтезатор.

## 15. Принцип интерфейса

Не делать интерфейс генератора нескольких готовых вариантов.

Основой должны быть **ползунки + числовые значения + прослушивание результата**.

LLM используется для первоначальной настройки и точечных изменений. Пользователь всегда может самостоятельно перехватить управление.

**LLM → выставила ручки → человек поправил ручки → готово.**

## 16. Главный архитектурный принцип

Это не AI-аудиогенератор.

Это понятный человеку интерфейс над процедурным звуковым инструментом, где локальная LLM умеет управлять уже существующими органами управления.

ИИ не обязан уметь синтезировать звук. Он должен уметь понимать, что хочет человек, и приблизительно выставить, какие ручки для этого надо повернуть.

## 17. Итог исследования

Основные технологические кирпичики найдены практически полностью:

- процедурные SFX-движки;
- параметры и ручное редактирование;
- свободные backend;
- WAV;
- VGM;
- эмуляция старых чипов;
- командное управление Furnace;
- проекты natural language → параметры SFX;
- локальные маленькие модели, генерирующие параметры.

Проблема не в отсутствии технологии. Потенциальная ниша LOPATA — собрать существующие инструменты в один понятный локальный сценарий для человека, который не хочет становиться программистом или музыкантом.

Первый технический стенд разумно строить на простом параметрическом backend вроде JFXR или retro-sfx-gen. После проверки UX можно добавить Furnace для аутентичной эмуляции конкретных игровых чипов.

Специальную AI-модель сначала создавать не требуется: для первого прототипа можно использовать существующую локальную LLM LOPATA и заставить её выдавать строго ограниченный JSON параметров.
