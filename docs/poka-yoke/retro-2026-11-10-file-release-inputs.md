# Retro · проверяемые входы файлового выпуска · 2026-11-10

**Дефект:** подготовка 0.7.72-beta не дошла до публикации. Первый запуск остановился поздно на ссылочном legacy runtime; независимая проверка следующего комплекта выявила отсутствие двух прежних файлов Collection и 139 изменений только в переводах строк/BOM. Ошибочный комплект не был опубликован.

**Действие:** сборочная копия подключила runtime через junction, свежий publish использовали без прежних модулей, а чистый Git checkout нормализовал поставочные тексты. Долгий запуск полагался на временную tool-session.

**Уязвимость процесса:** не было обязательной аутентифицированной подготовки входов и устойчивых подтверждённых этапов. Правильная защита установочных путей обнаруживала ошибку слишком поздно; исходное дерево и свежий publish сами по себе не доказывали полноту обновления.

## Почему это было возможно

Свежая версия модуля Проводника использует собственный каталог; старые два файла не попадают в новый publish автоматически. Поставочные лицензионные тексты и Python-файлы наследовали text/eol Git-правила, хотя их SHA-256 является контрактом. Низкоуровневый упаковщик корректно отклоняет ссылки, но раньше весь обычный комплект сжимался до проверки legacy-источника. Скрипт записывал итог только в конце.

## Почему проверка пропустила причину

Тесты установщика/извлечения охватывали строгие пути и ZIP, но не подготовку реальных входов разработчика. Независимая сверка старого и нового комплектов сработала и остановила публикацию; раньше неё не было автоматического восстановления безопасно определяемых пропусков.

## Проверка класса ошибок

Проверены два основных входа (`build-release-packages.ps1`, `build-file-update.ps1`), дополнительный вызывающий offline-скрипт `build-installer.ps1` и общий CLI `pack`. Во всех трёх production-скриптах отсутствие предыдущего манифеста теперь отклоняется до сборки/упаковки. Установочный тестовый fixture уже передаёт предыдущий манифест. Изолированный StandBuild остаётся явным исключением. Низкоуровневые UpdatePackageBuilder/Extractor и EngineSetTransition сохраняют строгие прежние правила.

## Оставшиеся ограничения

Сбой ОС, диска или агента остаётся возможным. Новый механизм позволяет увидеть незавершённую фазу и проверить продолжение, а не объявлять незавершённую работу готовой. Повреждённые/лишние файлы этапа вызывают сборку в новом каталоге; прежний каталог сохраняется как доказательство. Изменение исходного коммита требует нового output. При остановке внутри упаковки она повторяется, готовые app/updater этапы используются после SHA-сверки. Публичная публикация отдельно проверяет GitHub и SHA-256; один PID не является доказательством выпуска. Удаление старых компонентов и миграция версионных движков остаются отдельными явными механизмами. Никакие пользовательские проекты, модели и ключи подписи эти исправления не меняют.
