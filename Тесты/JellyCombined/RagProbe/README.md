# Получение реального RAG для комбинированного стенда

Команда из корня репозитория (последний путь должен быть новым):

```powershell
dotnet run --project 'Тесты/JellyCombined/RagProbe/RagProbe.csproj' -- 'Тесты/1/Фанфик_По_Пиковой_даме' 'Тесты/JellyCombined/rag-live'
```

Стенд копирует исходные файлы проекта, повторно импортирует готовые векторы книги в отдельный Qdrant и выполняет три настоящих семантических запроса штатным `LiteraryRagReader`. Векторы запросов вычисляет установленная Giga на CPU. Генеративная модель не запускается. Исходная книга заново не индексируется.

Результаты прогона 2026-09-12:

- 31 точка импортирована и проверена штатным поиском, три запроса завершились за 18,47 секунды вместе с импортом.
- `rag_results.json`: первые три фрагмента на каждый запрос.
- `query-N-raw.json`: полная выдача, параметры и длительность.
- `verification.json`: исходные файлы не изменились по всем десяти SHA256; завершённых частей проекта нет.
- `source_hashes_before.json`: исходные хеши до копирования.

Выдача — найденные фрагменты, а не автоматически подтверждённые факты. Score не означает истинность. Штатный Reader проверяет совпадение текста с источником и его смещением, но обрезает длинные фрагменты до 900 символов, иногда посреди слова. На запрос о лестнице нужный эпизод обнаружен в выдаче другого запроса: `id=1`, третий фрагмент. Финал оригинала полностью присутствует в `id=2`, второй фрагмент (`ref:7`).

Запуск завершился штатно, свои процессы Giga/Qdrant остановлены. Приложение и пользовательский проект не редактировались. При запуске под изолированным пользователем sandbox .NET не смог прочитать пользовательский NuGet.Config; выполнен разрешённый повтор вне sandbox. Сам стенд не скачивает компоненты.
