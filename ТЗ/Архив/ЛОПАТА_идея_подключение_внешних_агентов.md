# ЛОПАТА — подключение внешних ИИ-агентов для подготовки проектов

**Дата фиксации:** 24.11.2026  
**Статус:** концепция для будущего обсуждения и исследования; не ТЗ и не утверждённая реализация.

## 1. Исходная идея

Предоставить пользователям ЛОПАТЫ возможность привлекать собственных ИИ-агентов (Codex, Claude и других) к интеллектуальной и творческой подготовке проектов, не заставляя агентов изучать исходный код программы, воспроизводить её механики на отдельном стенде или управлять графическим интерфейсом через Computer Use.

Рассматриваются только агенты, имеющие устанавливаемый клиент для Windows и способные взаимодействовать с локальными инструментами. Поддержка браузерных и исключительно облачных клиентов в эту концепцию не входит.

Главная задача — не автоматизация полного цикла генерации, а создание готового проекта ЛОПАТЫ средствами внешнего агента. После этого пользователь самостоятельно открывает проект в ЛОПАТЕ, проверяет, при необходимости редактирует и запускает штатную локальную генерацию.

## 2. Зачем это нужно

В сложных сценариях ЛОПАТЫ значительная часть работы выполняется ещё до запуска генеративных моделей. Локальная чат-модель помогает развивать замысел, структурировать материал, составлять промпты и принимать творческие решения.

Пользователь, у которого уже есть доступ к сильному внешнему агенту, мог бы поручить ему эту подготовительную работу. Однако без штатного подключения приходится расходовать лимиты агента на изучение ЛОПАТЫ, объяснение форматов и последовательности действий, чтение кода и повторные уточнения.

Прямое подключение должно уменьшить эти накладные расходы: агент получает необходимые правила и инструменты сразу, а его лимиты расходуются преимущественно на содержательную работу. Это может быть полезно как владельцам дорогих тарифов, так и пользователям бесплатных тарифов, если соответствующий Windows-клиент поддерживает подключение. Фактическая экономия зависит от объёма проекта и особенностей тарифа.

## 3. Основной принцип

**Внешний агент создаёт проект. ЛОПАТА исполняет проект.**

1. Пользователь обсуждает будущий результат со своим агентом.
2. Агент подключается к локальному компоненту ЛОПАТЫ и получает описание поддерживаемого сценария, необходимые инструкции, форматы и ограничения.
3. Агент выполняет творческую и интеллектуальную подготовку, формирует данные и передаёт их штатному механизму создания проекта.
4. Компонент ЛОПАТЫ проверяет данные и сохраняет обычный совместимый файл проекта.
5. Пользователь открывает этот файл в основной программе, проверяет результат, вносит необходимые изменения и самостоятельно запускает генерацию.

Агенту не нужно ждать окончания локальных вычислений, следить за видеокартой, управлять моделями или контролировать сборку готового материала. Для подготовки проекта запуск основного графического интерфейса в идеале не требуется.

## 4. Возможный технический подход

В качестве общего стандарта подключения рассмотреть MCP (Model Context Protocol — протокол взаимодействия ИИ с внешними инструментами). Предпочтительный вариант — небольшой локальный компонент, предоставляющий только функции, необходимые для подготовки и сохранения проектов.

Минимальный набор возможностей:

- получение перечня поддерживаемых сценариев;
- получение актуальных инструкций, структуры проекта и требований к входным данным выбранного сценария;
- создание и сохранение нового проекта через штатные механизмы ЛОПАТЫ с проверкой совместимости данных.

Следует по возможности повторно использовать существующие форматы проектов, сериализацию, правила валидации и инструкции для локальных моделей. Агент не должен самостоятельно воспроизводить внутреннее устройство архивов или угадывать форматы файлов.

Локальное подключение не предполагает VPS, публикацию сервера в интернете или предоставление произвольного доступа к компьютеру. Доступ ограничивается предназначенными для этого операциями создания проектов и разрешёнными пользователем материалами. Поддержку конкретных Windows-клиентов и способ их подключения необходимо проверить перед реализацией.

MCP — кандидат на общий интерфейс, а не обязательство реализовать конкретный транспорт или архитектуру на данном этапе.

## 5. Основной пример — подготовка видеороликов

Видеосценарий представляет наибольший первоначальный интерес из-за значительного объёма режиссёрской работы до генерации.

В опубликованной архитектуре ЛОПАТЫ уже существуют структурированные протоколы взаимодействия с локальной моделью (`VideoConceptProtocol`, `VideoReferencePromptProtocol`, `VideoShotsProtocol` и другие), а также механизмы создания, сохранения и проверки проектов. Для ряда этапов имеются инструкции, входные данные и схемы JSON-ответов.

Внешний агент потенциально может подготовить:

- первоначальный замысел и его творческое развитие;
- рабочие переводы;
- визуальный мир, стиль, карточки персонажей, мест и предметов;
- перечень необходимых референсов и промпты для их последующей отрисовки;
- разбивку на сцены и планы, начальные и конечные состояния кадров;
- композицию, движение камеры, свет, связность сцен, длительность и ограничения.

Результат — обычный проект видеосценария, который пользователь продолжает в ЛОПАТЕ. Материалы, для создания которых необходима локальная генерация (например, сами изображения-референсы), могут оставаться незавершёнными до открытия проекта. Не следует выдавать запланированные материалы за уже сгенерированные.

Преимущество сильного агента здесь заключается в понимании замысла, удержании большого контекста и режиссуре, а не в непосредственном управлении локальной генерацией.

- [VideoConceptProtocol.cs](https://github.com/PiTrolKun/LOPATA/blob/main/Исходники/AIHub/Services/VideoPreparation/VideoConceptProtocol.cs)
- [VideoReferencePromptProtocol.cs](https://github.com/PiTrolKun/LOPATA/blob/main/Исходники/AIHub/Services/VideoPreparation/VideoReferencePromptProtocol.cs)

## 6. Расширение на другие сценарии

Механика потенциально универсальна, поскольку во многих сценариях ЛОПАТЫ уже существует собственный формат проекта. Подключать следует только те сценарии, где внешняя интеллектуальная подготовка действительно полезна.

| Сценарий | Возможная работа агента |
| --- | --- |
| Видеоролики | Замысел, режиссура, визуальный мир, сцены, раскадровка и промпты |
| Музыкальные клипы | Концепция клипа, планирование сцен и их согласование с музыкальным материалом |
| Музыка | Текст песни, музыкальное описание, структура композиции |
| Мастерская анимированных ассетов | Описание персонажа, набор реакций, последовательности ключевых действий |
| Изображения | Подготовка описаний и параметров, если соответствующий формат проекта это поддерживает |

Это примеры возможного применения, а не обязательный перечень интеграций. Объём подготовки определяется возможностями каждого существующего сценария.

## 7. Отдельная адаптация для Codex

Помимо универсального подключения можно рассмотреть специализированную адаптацию для устанавливаемого Windows-клиента Codex: навык (Skill) или иной штатный механизм, описывающий назначение инструментов ЛОПАТЫ и порядок подготовки проектов.

Цель — сократить объём объяснений и повторного изучения механик, используя при этом те же штатные функции создания проектов, что и другие агенты. Codex может стать первым испытательным клиентом. Конкретный способ адаптации пока не выбран.

## 8. Подключение в одно действие — автоматически формируемый AGENTS.md

Дополнение к концепции от 24.11.2026: максимально упростить первоначальное подключение внешнего агента, используя привычный для агентных инструментов файл инструкций `AGENTS.md`.

ЛОПАТА поставляется с заранее подготовленным шаблоном этого файла. В шаблоне содержатся общие правила работы с программой, порядок обращения к её штатным механизмам создания проектов, ограничения и инструкции по подключению. При формировании файла ЛОПАТА автоматически дописывает фактические локальные пути к необходимым компонентам, документации и другим требуемым файлам, учитывая конкретную установку программы. При необходимости указываются параметры подключения и доступные сценарии.

Пользовательский маршрут:

1. Пользователь нажимает в ЛОПАТЕ одну кнопку подключения внешнего агента.
2. ЛОПАТА формирует актуальный `AGENTS.md` в выделенном для этого месте, не перезаписывая чужие файлы инструкций, и копирует в буфер обмена готовую короткую команду для агента с абсолютным путём к этому файлу.
3. Пользователь вставляет скопированный текст в чат своего агента.
4. Агент читает `AGENTS.md`, получает необходимые сведения, при необходимости регистрирует локальный MCP-компонент средствами своего клиента и проверяет доступность инструментов. Если клиент требует подтверждения, пользователь выдаёт его штатным способом.
5. Агент может приступить к подготовке обычного проекта ЛОПАТЫ без предварительного изучения её исходников и без ручного объяснения пользователем устройства программы.

`AGENTS.md` служит единым паспортом подключения. Не следует считать, что все агенты автоматически обнаруживают этот файл или умеют самостоятельно менять свою конфигурацию. Поэтому явное указание пути в сообщении пользователя является частью общего маршрута; особенности конкретных Windows-клиентов проверяются при реализации.

Сам файл инструкций не является средством авторизации и не выдаёт технических прав. Разрешения должны проверяться локальным компонентом ЛОПАТЫ и средствами клиента агента. В файл и буфер обмена не нужно помещать секретные ключи или предоставлять произвольный доступ к файловой системе. При обновлении программы достаточно актуализировать шаблон и формировать его с текущими путями и правилами.

Главная цель пользовательского интерфейса: **одна кнопка в ЛОПАТЕ, затем вставка текста в чат агента**. Пользователю не требуется вручную редактировать конфигурацию, разбираться в MCP или искать файлы установки. Возможные обязательные подтверждения со стороны клиента агента сохраняются.

## 9. Применение для разработки и тестирования самой ЛОПАТЫ

Этот же механизм полезен разработчику: Codex получает возможность создавать штатные тестовые проекты, проверять различные комбинации параметров, воспроизводить ошибки пользователей и сохранять проблемные проекты для повторных испытаний после исправлений.

Предпочтительно использовать общие механизмы подготовки и проверки проектов, а не создавать их копии на временных стендах. Это позволяет сократить число отдельных стендов и обращений к Computer Use при проверке проектной логики. Проверки графического интерфейса, внутренних механизмов и полноценного исполнения проектов при этом остаются самостоятельными задачами.

Отдельная адаптация для Codex может содержать дополнительные инструкции по тестированию, не требуя отдельного сервера или иной реализации форматов проектов. Одна и та же механика приносит пользу обычным пользователям и разработчику.

## 10. Границы концепции

- ЛОПАТА остаётся самостоятельной локальной программой; внешний агент необязателен.
- Существующие локальные чат-модели и обычные маршруты подготовки сохраняются.
- Не требуется полноценное внешнее управление интерфейсом, настройками, моделями, очередями и генерацией.
- Не требуется предоставлять исходники ЛОПАТЫ агенту для штатной пользовательской работы.
- Пользователь сам выбирает, использовать ли внешнего агента, и самостоятельно запускает готовый проект.
- Локальный транспорт не означает, что материалы остаются на компьютере: подключённый агент может отправлять переданный ему контекст своему облачному поставщику. Это следует учитывать при работе с личными материалами.
- Не нужно заранее открывать все функции и сценарии программы. Расширение определяется практической необходимостью.

## 11. Что предстоит проверить при возвращении к идее

- Поддержку локального MCP и других подходящих способов подключения в конкретных устанавливаемых Windows-клиентах, включая ограничения тарифов.
- Возможность формирования штатных проектов без запуска графического интерфейса и без установки локальных генеративных моделей для одной лишь подготовки.
- Совместимость подготовленных агентом проектов с существующими правилами валидации, версиями форматов и этапами видеосценария.
- Какие инструкции и данные достаточно передавать агенту, чтобы он не тратил лимиты на изучение реализации ЛОПАТЫ.
- Возможность подключения через автоматически сформированный `AGENTS.md` и вставку одной команды из буфера обмена, включая ограничения самостоятельной настройки в конкретных клиентах.
- Пригодность общего механизма создания проектов для повторяемых испытаний Codex без дублирования проектной логики на отдельных стендах.

## Итог

Не отдельная агентная версия ЛОПАТЫ и не сервер удалённого управления всей программой, а **локальный интерфейс создания совместимых проектов для внешних ИИ-агентов**.

Внешний интеллект занимается подготовкой сложного замысла. ЛОПАТА сохраняет проект и затем самостоятельно выполняет вычислительную работу на оборудовании пользователя.

Подключение в идеале сводится к автоматически сформированному `AGENTS.md` с актуальными путями и одной команде, которую пользователь вставляет в чат агента. Та же точка входа используется для подготовки тестовых проектов при разработке ЛОПАТЫ.
