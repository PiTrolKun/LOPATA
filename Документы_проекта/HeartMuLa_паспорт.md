## Текст и экспертные настройки

Текст песни и теги идут раздельно. Сохраняются оригинал, эффективный запрос,
выбранные устройства/точности, предупреждения и фактический сид в
`LOPATA_HEARTMULA_REQUEST`. Авторский preprocessing переводит текст/теги
в нижний регистр; оригинал проекта остаётся неизменным. Кириллица не
транслитерируется и не заменяется экспериментальным G2P.

Жанры, инструменты, настроение, развитие звучания, голос и ограничения идут
тегами. Между тегами нет лишних пробелов; пробелы внутри названий сохраняются.
API не имеет отдельного отрицательного запроса и жёсткого разделения ролей.
«Без вокала» очищает только эффективный текст и добавляет instrumental/no vocals,
с явным предупреждением: это пожелание, не жёсткий авторский режим.
Аудиореференс upstream помечен NotImplemented; отдельный ввод не подключён.

Экспертные группы: seed, top-k, temperature, CFG, предел автоматической
длительности, последовательная загрузка, точности генератора/декодера,
перенос декодера на CPU. Defaults: новый seed, top-k 50, temperature 1,
CFG 3 из официального CLI-примера, автоматический предел 240 секунд,
lazy-load включён, генератор Auto, codec FP32 на том же устройстве.
Длительность из главных настроек заменяет автоматический предел; модель
может завершить раньше. Пресеты имеют собственную схему 8; перенос параметров
YuE/ACE/Diff не выполняется. Круг скрыт до отдельных испытаний.

До загрузки весов проверяется общий контекст: prompt tokens + предел
аудиокадров + 1 ≤ 8192. Переполнение выдаёт ошибку без обрезания строк.
Диапазон top-k ограничен реальным audio_vocab_size=8197.

## Windows и устройства

Узкие адаптации, записанные в receipt:

- Eager вместо безусловного torch.compile: в Windows не нужен недоступный Triton.
- Освобождение предыдущего этапа учитывает CPU/CUDA/XPU, вместо CUDA-only вызовов.
- WAV PCM16 записывается soundfile; не требуется отдельный TorchCodec.

Управляемый аппаратный выбор допускает совместимые Torch 2.10 CUDA128/CUDA126,
XPU или CPU; выбирает проверенный доступный комплект и устройство.
Auto генератора: BF16 на совместимой GPU, FP16 на CUDA без BF16, FP32 на CPU.
Auto codec — FP32. CPU-путь допускает FP32; неподдерживаемая ручная точность
отклоняется до весов. Нынешний ROCm 2.9.1 не смешивается с ABI 2.10;
при отсутствии подходящего GPU доступен CPU, если стандартный CPU runtime готов.
Физическая генерация на CPU/XPU/AMD не проверена.

Последовательная загрузка на одной GPU освобождает генератор перед decoder.
Это не CPU offload. Codec-on-CPU использует штатное разделение устройств;
авторский API в этом случае отключает lazy-load. Реальная потребность памяти
ещё не измерена; аппаратный минимум по размерам весов не выводится.

Проверка импортов не загружает веса; лимит 90 с начинается после запуска Python.
Проверка файлов и библиотек имеет отдельный прогресс и отмену. Start после
правки текста не запускает дорогое повторное приготовление: оно относится
к самой операции запуска с журналом.

## Жизненный цикл и лицензии

Общий `music.generate`, проекты, история, очередь, трей и уведомления.
Настройки хранятся по модели. Python принадлежит OwnedProcessRegistry;
отмена/пауза ждут выхода только своего процесса. Незавершённая генерация
повторяется с тем же сидом, подтверждённый WAV/трек не дублируется.
Receipt сверяется с фактическим запросом и ревизией перед принятием результата.
Физическая пауза с полными весами и освобождение VRAM ещё не испытаны.

Авторы модели, codec и heartlib заявляют Apache-2.0. Три собственные записи
ComponentLicenseGate, 114 оригинальных уведомлений/списков библиотек;
прежние лицензионные согласия других моделей сохранены.

Подтверждены реальные импорты и preprocessing на CPU и RTX 4090/CUDA126,
путь codec-on-CPU и пустой эффективный instrumental-текст. Проверены 22 138
архивных записей библиотек: хеши, размеры, отсутствие конфликтов путей.
Автотесты покрывают запросы, пресеты, общий проект, восстановление задания,
неповторение готового результата, изменение исходников/receipt, экспертное окно
и мгновенную готовность Start после правки текста. Это технические проверки,
не подтверждение музыкального качества полной модели.

Музыкальный/навигационный/локализационный набор: 180 успешно, 4 специальных
пропущены, 0 сбоев. Общий: 1389 успешно, 80 пропущены, один воспроизведённый
timeout старого LiteraryJellyHardwareNativeTests при проверке общего CPU Python
до запуска fixture; этот тест и runtime-код не менялись. Сборка приложения
0.4.37-dev без ошибок/предупреждений; safe-start — окно отвечает. Scanner не
нашёл новых проблем; сохранён прежний дефект оригинального лицензирования
pyreadline3/DiffRhythm. Полные веса ещё не запускались.

## Пользовательский пример и физический замер — 10.10.2026

В пользовательском испытании полные веса отработали на RTX 4090/CUDA126.
Один полный цикл потока: 125,04 с аудио; 285 отсчётов, загрузка/генератор/
HeartCodec/сохранение. Процесс занимал до 13,3167 ГиБ выделенной VRAM и
5,9370 ГиБ резидентной ОЗУ. Частная резидентная ОЗУ — до 1,7334 ГиБ;
PrivateBytes 16,0735 ГиБ — виртуальные обязательства, не физическая ОЗУ.
В карточке: 13,3/5,9 ГиБ, расход модели без игры и прочих приложений.
blues rock/jazz, температура 0,75, top-k 50, CFG 3, auto/max 240 с,
BF16/FP32, последовательная загрузка. Другие условия могут менять расход;
минимальные требования из этого замера не выводятся.
Частное подтверждение: Тесты/MusicHeartMuLaMemory_20261010/measurement.md.

По оценке пользователя модель даёт хороший русский вокал и подходит для
поиска необычной интерпретации, особенно при понижении температуры.
Описание карточки приведено по его формулировке; это результат пользовательской
оценки, не подтверждение официальной поддержки русского или универсального
качества. Круг и рецепты остаются вне текущего этапа.

Единственный пример — исходный Opus без перекодирования и изменения тегов:
heartmula-blues-jazz.opus, 3 782 448 байт, 92,8865 с, температура 0,75.
SHA256 1DAB6E864F4F52CF2290F21BF2F134EC3A1ED0E41F9999A38972882A887507DA.
Облачное сравнение отсутствует. Плеер читает параметры из audio stream
comments Opus, сохраняет формат Opus и восстанавливает реальные настройки.
