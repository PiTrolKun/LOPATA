# Автоматические программные лимиты литературного runtime

Статус: реализовано в 0.1.110-dev, ожидает приёмки пользователя. [Отчёт](../Тесты/LiteraryAutoBudget/REPORT.md). 596 .NET / 172 WPF, scanner пройден; точный оборвавшийся запрос завершён с новым расчётом, живые ветки runtime проверены.

Цель: убрать фиксированные потолки контекста и генерации прежней модели. Промпты, роли и правило одного абзаца не меняются. Размер частей рукописи и порции индексации — отдельный формат хранения, не бюджет LLM; в этой задаче не меняются.

При загрузке тот же llama.cpp рассчитывает максимально помещающееся окно из метаданных GGUF и памяти GPU. Использовать штатный --fit, но скорректировать запас с учётом физической свободной VRAM NVIDIA: на WDDM оценка CUDA может включать вытесняемую память. Все слои остаются на GPU, скрытого перехода на CPU нет. Если сведения о памяти недоступны, не придумывать вместимость: сообщать ошибку диагностики.

После загрузки прочитать фактическую вместимость слота. Перед каждым запросом токенизировать точные сообщения с применённым шаблоном и режимом thinking. Доступный бюджет ответа = вместимость слота минус вход минус небольшой технический запас. Это общий бюджет thinking и финального текста. Одинаковый принцип для старых чатов, F1, создателя, калибровки, служебного чтения и основного архивариуса. Убрать отдельный токеновый предел рабочего текста, сохранив контроль всего пакета.

Проверять свободную VRAM перед новой операцией. При нехватке запаса либо необходимости большего окна допускается один пересчёт/перезапуск между запросами под общим gate. Не менять окно во время генерации. Переписка/редактор/выбранные источники остаются в приложении; не считать сохранённый KV единственным состоянием. Не удалять сообщения автоматически ради вмещения. Показывать реальную вместимость в существующих индикаторах.

Проверки: границы арифметики, WDDM-поправка, отказ при неизвестной памяти, реальный подбор окна, повтор оборвавшегося запроса 5152/2048 с прежним промптом, структурированные операции, regression tests и scanner. Исходный проект не менять. Установщик/публикация не входят в задачу.
