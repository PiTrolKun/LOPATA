# Периодическая проверка патчей в быстром направлении обновлений

Дата: 27.09.2026. Исходная версия: **0.2.43-dev**.

Статус: **ЗАКРЫТО ПО ПОДТВЕРЖДЕНИЮ ПОЛЬЗОВАТЕЛЯ 27.09.2026.** Реализация 0.2.44-dev принята. Это отдельное дополнение к уже работающему механизму обновлений. [ТЗ доставки](2026-09-27_Лёгкая_установка_и_файловые_обновления.md) закрыто; его исходные условия не пересматриваются.

Реализация: при включённой автопроверке и выборе Беты приложение проверяет выпуск на старте и затем раз в 30 минут. Открытое окно обновлений и уже подготовленный выпуск не допускают параллельной проверки; если окно открыто во время фоновой операции, оно ждёт и показывает её результат. Найденный выпуск предлагается один раз за сеанс, сеть не приводит к скачиванию или установке без действия пользователя. Настройка «Стабильная» сохраняет прежнюю проверку только при запуске. Dev-сборка запущена без ошибок и предупреждений. Пользователь принял реализацию; полный 30-минутный интервал на установленной Бете инженерным прогоном не подтверждён. Публикация исходников и файлового патча выполняется при закрытии.

## 1. Требование пользователя

Если выбрано быстрое направление обновлений (**«Бета»**, файловые патчи), искать новые патчи не только при запуске программы, но и каждые **30 минут**, пока программа открыта.

Уточнение пользователя: **автоматическая проверка включена по умолчанию**. Следовательно, при обычной установке с выбранной «Бетой» оба вида проверки работают без дополнительного включения настройки. Если пользователь сам выключил автопроверку, его выбор сохраняется.

Выбор направления определяет способ доставки, а не отдельный ряд версий. «Стабильная» продолжает искать полные установщики в прежнем порядке; периодическая проверка по этому ТЗ к ней не относится.

## 2. Согласование с текущим поведением

- Существующий `ApplicationUpdateSettings.CheckOnStartup` уже имеет значение `true` по умолчанию. При запуске проверка выполняется, если пользователь не отключил её, выбрано направление обновлений и нет подготовленного к установке выпуска. Новая проверка через 30 минут использует тот же переключатель; название `CheckOnStartup` не должно ограничивать действие настройки только запуском. Выключенная автоматическая проверка означает отсутствие фоновых запросов; ручная кнопка «Проверить» остаётся доступной.
- При включённом переключателе и выбранной «Бете» после проверки на старте следующая попытка начинается через 30 минут. Следующие интервалы отсчитываются от завершения предыдущей попытки; после сетевой ошибки интервал сохраняется, без частого повторения. При выборе «Беты» в уже открытой программе проверить актуальность один раз, затем перейти к обычному интервалу.
- Периодическая проверка получает только сведения о выпуске по действующему доверенному каталогу и сравнивает их с установленной версией. Она **не скачивает патч и не устанавливает его автоматически**. Перед скачиванием остаётся показ описания каждого накопившегося выпуска; после загрузки остаётся выбор установки сейчас или при следующем запуске.
- Если выпуск уже подготовлен, идёт проверка/загрузка/установка или уже выполняется ручная/автоматическая проверка, новый запуск проверки не создаётся. Переключение на «Стабильную», выключение автопроверки и закрытие приложения останавливают запланированные бета-проверки. При возврате к «Бете» не создавать несколько таймеров.
- При обнаружении новой версии показать существующее ненавязчивое уведомление о доступном обновлении. Один и тот же выпуск не должен многократно открывать окно или повторно тревожить пользователя каждые 30 минут после закрытия уведомления. Следующий действительно новый выпуск может снова показаться. Открытое окно обновлений обновляется согласованно, без второго параллельного окна.
- В отсутствие сети программа продолжает работать; ошибка фоновой проверки не блокирует интерфейс и не закрывает уже полученное предложение. Ручная проверка по-прежнему сообщает о причине ошибки. Не применять по сети более старую версию и не подменять уже подготовленный выпуск новым.

## 3. Что найдено в текущем коде

- `Исходники/AIHub/MainWindow.Updates.cs`: проверка из `ContentRendered` однократная; учитывает `CheckOnStartup`, выбранное направление и подготовленное обновление. Сохраняет найденное предложение и показывает `ApplicationUpdateNotice`.
- `Исходники/AIHub/Models/ApplicationUpdate.cs`: `CheckOnStartup` инициализирован как `true`; это уже действующее значение по умолчанию. Код для изменения умолчания не требуется.
- `Исходники/AIHub/ApplicationUpdateWindow.cs`: окно содержит переключатель автоматической проверки, выбор направления и ручную проверку. При смене направления сбрасывает дату последней проверки.
- `Исходники/AIHub/Services/ApplicationUpdateCoordinator.cs`: уже есть `CheckAsync` для обоих направлений. Повторно использовать действующую проверку и проверку подписи, не создавать второй сетевой путь.
- `Документы_проекта/ОБНОВЛЕНИЯ.md`: «Бета» означает файловый патч, «Стабильная» — полный установщик; скачивание и установка требуют отдельных действий пользователя.

## 4. Порядок реализации после завершения обсуждения

1. Разделить однократный запуск и повторяемую проверку так, чтобы оба использовали одну защищённую операцию проверки и один источник состояния предложения. Не превращать `MainWindow` в новый центр отдельной логики таймеров, если её можно компактно вынести.
2. Подписать периодическую проверку на жизненный цикл окна и изменения направления/автопроверки. Исключить наложение с ручной проверкой и загрузкой.
3. Обновить уведомление только при изменении найденной версии, сохранив доступ к полному описанию выпуска перед скачиванием.
4. Проверить поведение и обновить документацию. При кодовой правке поднять последнюю цифру внутренней версии по правилам проекта; пока меняется только ТЗ.

## 5. Проверки и приёмка

- При «Бета» с настройкой по умолчанию: одна проверка на старте и следующая после 30 минут работы; затем тот же интервал. Проверка не запускается по одному разу на каждое окно и не размножается после повторного открытия настроек. Если пользователь отключил автопроверку, его сохранённый выбор не сбрасывается обновлением программы.
- При «Стабильная» либо выключенной автопроверке: периодических бета-запросов нет. Ручная проверка работает. Переключение туда-обратно не оставляет старых таймеров.
- Медленная проверка, сетевой сбой, открытое окно обновлений, текущая загрузка и подготовленный выпуск не вызывают параллельных проверок, повторных предложений или автоматической замены подготовленного выпуска.
- Один выпуск показывается без повторного навязывания через 30 минут; более новый выпуск снова заметен. Список изменений открывается до загрузки; загрузка и установка остаются решениями пользователя.
- Закрытие программы отменяет ожидание и выполняющуюся проверку. Нет блокировки интерфейса и новых предупреждений после отмены. Проверены установленная «Бета» и доступная ветка ручной проверки; dev-ограничения поставки патчей сохраняются.
- После реализации: релевантные тесты, сборка, штатный safe-start, локализация RU/EN, UTF-8 и `git diff --check`. Пользователь проверяет поведение на следующем доступном патче. Это ТЗ не закрывать и не публиковать только из-за создания документа.
