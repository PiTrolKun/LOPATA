# HeartMuLa: подготовка закреплённой поставки

Используется официальный heartlib `5858ca8f1ffe58d62be7c007ea55f1033c5ca456`.
Веса здесь **не скачиваются**. Они загружаются пользователем через ЛОПАТУ.
Модельные ревизии и SHA256 находятся в `Tools/heartmula-models.json`.

`prepare.py --runtime <управляемый Python 3.12/Torch 2.10> --stage <отдельная staging-папка>`
получает авторские исходники с проверкой Git blob SHA1, закреплённую модельную
метаинформацию и Windows wheels. Pip применяется только для разрешения плана
зависимостей; установка в глобальную среду не выполняется. Затем wheels
проверяются по SHA256 и извлекаются в отдельную папку. Транзитивные версии
фиксируются в pip-report и итоговом manifest; новый план требует повторных
проверок и новой версии библиотек. Не заменять опубликованный lock автоматически.

`finalize.py --stage <staging>` копирует проверенные manifests, создаёт
детерминированный `Runtime/MusicHeartMuLa/source.zip` и сохраняет оригинальные
уведомления wheels в Licenses/texts. Каталог пополняется только отдельной командой
`prepare-license-catalog.ps1 -AppendEntries <staging>/license-entries.json`;
повторное добавление уже существующих ID запрещено. Для восстановления готового
overlay использовать точные URL/размеры/SHA256 из committed модели-manifest,
без нового разрешения pip. Источник ZIP должен совпадать с константами
`MusicHeartMuLaSource`; исполняемые авторские файлы не редактируются.

Windows-адаптер в `music_heartmula_worker.py` отключает torch.compile,
освобождает память по устройству и записывает WAV через soundfile.
Авторские preprocessing, generate_frame, sampler и detokenize сохраняются.
Probe импортирует официальный API и токенизатор без весов.
