# GIF — стенд этапа 2

Рабочая папка `H:\AI_HUB`, .NET 10 Windows/WPF, обычный профиль сборки.
Тестовые файлы пишутся в `runs/yyyyMMdd_HHmmss`; результаты в `checks.txt`
или `failure.txt`. Нативные окна/ввод не запускать одновременно с другим UI-стендом.

```powershell
dotnet run --project 'Тесты/GifCapture/Probe.csproj'
dotnet run --project 'Тесты/GifCapture/Probe.csproj' -- --minute
```

26 проверок (`20261002_223418`): WIC-декодирование/палитра/LZW, интервалы,
merge, масштабы, bounded collection, slow adapter, остановка, отмена сборки,
восстановление. Отдельный собственный worker завершается принудительно после
flush кадров и незавершённого journal.tmp; проверяется восстановление.
Нативные WARP окно, GDI монитор/область, PNG индикатора и capture exclusion.
`--minute` проверяет реальный 60-секундный лимит, не ускоренные часы.

Отдельная проверка с установленной литературной моделью:

```powershell
dotnet run --project 'Тесты/GifCapture/Probe.csproj' -- --import
```

Это настоящий штатный ImportPipeline, шесть вымышленных фрагментов, прогрев,
baseline, CPU100 GIF и WGC25 GIF; ресурсы/тайминги в `import-load.json`.
Загружает существующую модель и запускает собственный runtime backend,
не скачивает модели и не принимает новые лицензии. Нужны ранее подтверждённые
лицензии в обычном профиле; не запускать рядом с чужим активным runtime,
чтобы не конкурировать за VRAM. Не является тестом полного длительного импорта.
