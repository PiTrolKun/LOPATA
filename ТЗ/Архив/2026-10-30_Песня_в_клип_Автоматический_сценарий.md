## 1. Подтверждённые решения и границы

1. Новый сценарий располагается в «Создание → Видео» непосредственно рядом с Видеомастерской. Рабочее название — «Песня → клип».
2. Интерфейс строится по пользовательскому [макету](../%D0%9C%D0%B0%D1%82%D0%B5%D1%80%D0%B8%D0%B0%D0%BB%D1%8B/2026-10-30_%D0%9F%D0%B5%D1%81%D0%BD%D1%8F_%D0%B2_%D0%BA%D0%BB%D0%B8%D0%BF/%D0%9C%D0%B0%D0%BA%D0%B5%D1%82.png). Макет задаёт состав и взаимное расположение областей, а не жёсткие пиксельные размеры.
3. Подключаются все обсуждённые варианты, а не только первый H3. Общая реализация развивается в этом ТЗ; отдельное ТЗ на каждый конвейер не создавать без самостоятельной необходимости.
4. Варианты располагаются от лёгкого полного набора к тяжёлому. Размер на диске и потребление RAM/VRAM показываются раздельно.
5. Обычная работа: добавить песню → при желании добавить исполнителя → выбрать вариант → «Старт генерации» → получить полный клип.
6. Планирование, подготовка запросов, необходимые изображения, видеосинтез и сборка выполняются автоматически. Обязательных утверждений каждого запроса, референса или сцены нет.
7. Предусмотрены проекты по образцу музыкального сценария: текущий проект, автоматическое сохранение запусков, закрепление, название, список проектов и история.
8. Скачивание вызывается отдельным внешним окном общей системы ЛОПАТЫ. После успешной загрузки и проверки окно закрывается автоматически. Уточнение пользователя 01.11.2026, к реализации после текущего теста: при обнаружении недостающих компонентов показывать их список и автоматически начинать скачивание; дополнительное нажатие «Скачать» не требуется. Если подготовка вызвана уже запрошенной генерацией, после успешной подготовки продолжается та же попытка; отдельное открытие окна компонентов само по себе генерацию не запускает. Подробности — в дополнении «Автоматическое скачивание недостающих компонентов».
9. Это отдельный сценарий, а не переименование Видеомастерской, существующего Lyric Video или музыкального генератора. Их проекты и поведение сохраняются.
10. Размещение кнопки передачи из музыкального сценария не входит в обязательный первый объём: пользователь сейчас согласовал самостоятельный соседний вход.

Создание этого ТЗ не означает разрешение автоматически скачивать все веса, запускать длительные испытания или публиковать новую версию. Следующее внедрение выполняется по отдельной команде. Карта направления остаётся активной.

## 2. Обязательный результат и виды клипа

Готовый результат покрывает выбранную песню целиком: вступление, вокальные части, инструментальные промежутки и окончание. Исходное аудио остаётся главным источником звука; генератор не переписывает песню своим голосом или музыкой.

Варианты дают разные художественные результаты:

| Вид | Ожидаемый результат |
| --- | --- |
| Сюжетный/образный | Сцены по содержанию, настроению, структуре и энергии песни |
| Исполнительский | Персонаж исполняет песню; движения и артикуляция управляются аудио |
| Музыкальная визуализация | Фоны, графика, текст и эффекты реагируют на музыку |

В списке явно указывать вид результата каждого варианта. Автоматизация должна доводить его до целого клипа, но не обещать одинаковую артикуляцию, танец или сюжет у всех исполнителей.

Для нейросетевых продолжений использовать реальный поддержанный перенос контекста. Монтаж независимых сцен обозначать монтажом, а не бесшовным продолжением. Для реактивной визуализации длительность задаёт монтажный конвейер, а не несуществующая способность видеомодели Extend.

## 3. Интерфейс по макету

Оболочка использует общий заголовок приложения, темы и стандартную навигацию. Внутри — одна основная рабочая страница, без обязательного мастера ручной раскадровки.

```text
[Новый проект] [Проекты…] [Закрепить проект]  Название проекта

┌ Текст песни ┐ ┌ Референс исполнителя ┐ ┌ Параметры выбранного варианта ┐
│            │ │                     │ │                              │
└────────────┘ └─────────────────────┘ └──────────────────────────────┘
[Добавить песню] [Добавить референс] [Выбор модели ▾] [Старт] [Ⅱ] [⛔]

┌ Тайминги ──┐ ┌ Предпросмотр выбранного клипа ┐ ┌ Готовые клипы ┐ │ Выходной файл
│            │ │                             │ │ этой песни   │ │ и сохранение
│            │ │                      [⛶]    │ │              │ │ Журнал стадий
└────────────┘ └─────────────────────────────┘ └──────────────┘ │ Прогресс / время
```

- Слева сверху — редактируемый текст песни; под ним импорт песни, ниже — её тайминги.
- Рядом сверху — изображение исполнителя и кнопка добавления. Если конкретный вариант не использует такой референс, это видно в интерфейсе; выбранный файл сохраняется в проекте и не удаляется.
- Большая верхняя область — компактные параметры текущего варианта. Понятные фиксированные варианты задаются выбором, а не произвольным вводом. Подробные настройки сворачиваются.
- Под параметрами — выбор модели/конвейера и управление генерацией.
- Снизу по центру — просмотр выбранного готового результата, воспроизведение/пауза, перемотка и раскрытие на всё окно с возвратом.
- Рядом с просмотром — список полных клипов текущей песни. Смена выделения меняет предпросмотр и сведения о результате.
- Справа — параметры нового выходного файла, сохранение/экспорт, журнал генерации и индикатор прогресса.
- Проектная панель добавляется над макетом. Список проектов — отдельное окно, по образцу музыкального сценария.
- Рабочая страница занимает доступную ширину оболочки. При нехватке места сохраняется взаимное расположение областей с доступной прокруткой; кнопки не обрезаются. Длинные пояснения референса не вытесняют само изображение и управление.
- Светлая/тёмная тема, обычные и отключённые состояния, масштаб Windows и минимальный размер окна проверяются отдельно. Полосы прокрутки не перекрывают кнопки; отсутствуют белые панели при старте задачи в тёмной теме.
- Для ручных текстовых полей — приглушённый пример до ввода, штатная проверка опечаток по языку. Пример не является содержимым проекта и не уходит модели.
- «Старт генерации» — зелёная кнопка, пауза — серая, остановка — красная; понятные подсказки и имена доступности обязательны.

## 4. Импорт песни, текст и тайминги

1. Поддержать готовые аудиофайлы через существующий проверенный аудиотракт ЛОПАТЫ. Точный список форматов наследовать от реально используемого декодера и проверить.
2. Сначала извлекать имеющиеся текст, тайминги, название и исполнителя из поддерживаемых метаданных/данных песни. При импорте из внутреннего результата музыкального сценария использовать его сохранённые сведения, если они доступны через существующие контракты.
3. Авторский текст и подтверждённые тайминги имеют приоритет. Не распознавать заново готовый текст без причины и не заменять слова модельной догадкой.
4. Оставить ручную вставку и правку текста и таймингов. Показать понятный пример допустимого формата; ошибки времени привязать к конкретной строке.
5. Если данных нет, предусмотреть автоматическое получение: распознавание текста при его отсутствии и выравнивание известного текста с аудио при отсутствии таймингов. Эти источники обозначать различно.
6. Сохранять происхождение: встроено в песню, введено пользователем, распознано или вычислено. Не выдавать оценочные времена за исходные точные тайминги.
7. Анализировать ритм, акценты, структуру и энергию для монтажа. Предусмотреть песню без вокала, паузы и инструментальные части; не требовать непустой текст для инструментала.
8. Проверять границы и последовательность времён, отрицательные значения и выход за длительность; не растягивать слова равномерно по всей песне как скрытую замену реального выравнивания.
9. Любое извлечение/перекодирование производится в собственных материалах проекта. Исходный аудиофайл не переписывать.

## 5. Проекты и история по образцу музыкального сценария

Использовать знакомую пользователю модель `MusicProjects` / `MusicProjectController` / `MusicProjectsWindow` как образец поведения. Не помещать видеозадания в музыкальное хранилище и не менять схему старых музыкальных проектов ради нового сценария.

- Новый проект создаёт чистый черновик. Материалы предыдущей песни не становятся его шаблоном.
- Перед первым запуском проект автоматически сохраняется в настроенное хранилище. Поле обязательного выбора пути на каждом запуске не вводится.
- «Закрепить проект» сохраняет именованный проект до генерации; окно проектов показывает закреплённые и автоматически созданные проекты и историю их запусков.
- Одна песня — один проект с несколькими вариантами клипа. Повторный запуск создаёт новую попытку с собственным снимком входов и параметров.
- Смена генератора сохраняет песню, референсы, настройки других вариантов и все готовые клипы. Результаты разных моделей можно сравнивать в одном списке.
- Замена основной песни не переименовывает старые результаты в результаты новой песни: предложить новый проект либо хранить явную отдельную ревизию источника с корректной привязкой попыток.
- Состояние включает исходную песню/вложения, текст/тайминги и их происхождение, референсы, автоматический план, запросы, параметры и фактические ревизии моделей, результаты, затраченное время и контрольные точки.
- При продолжении незавершённой попытки не добавлять дубликат нового запуска и не пересчитывать уже принятые этапы без изменения их входов.
- Изменения после запуска не подменяют снимок активной попытки. Открытие старого результата восстанавливает именно его сведения, а не текущие настройки списка моделей.
- Хранить собственные устойчивые копии необходимых вложений; перенос/удаление исходника пользователем не должен ломать сохранённый проект.
- Сохранение атомарное, с проверкой чтения и сохранением предыдущей рабочей версии при ошибке. История не растёт в один неограниченный JSON с многократными копиями бинарных вложений.
- Версию схемы, миграции и ограничения размера оформить и испытать до подключения генерации. Импорт проекта из Проводника при появлении переносимого формата маршрутизируется в правильный сценарий.

Новый файловый суффикс в обсуждении не утверждён. Не назначать произвольно расширение и не объявлять музыкальные проекты или `.lopataAIVid` совместимыми с новым форматом. Внутренний проект и экспорт готового видео входят в объём; переносимый контейнер требует отдельного зафиксированного решения о формате в этом ТЗ.

## 7. Порядок списка, размеры и доступность

- Основной ключ сортировки — точный суммарный размер обязательных модельных весов полного выбранного набора, по возрастанию. Общие файлы внутри набора учитывать один раз. При равенстве — устойчивый порядок по названию/ID.
- Текущая установленность не меняет порядок: размер дополнительного скачивания показывается отдельно. Малый размер загрузки из-за общего кеша не делает тяжёлую модель первой.
- До составления точных манифестов не придумывать числовые размеры или доказанный порядок. Неизвестный размер отмечать явно и располагать после измеряемых вариантов.
- Рядом с названием показывать вид клипа, полный размер весов, объём недостающей загрузки, оценку совместимости и статус компонентов.
- Отдельно показывать RAM/VRAM: измерено с условиями, оценено либо неизвестно. Размер весов не равен занимаемой памяти. Конфигурация тестового ПК не является минимальным требованием.
- Название модели, квантизация и конвейер должны быть различимы. История использует устойчивые ID/ревизии, а не индекс сортировки.
- Совместимость рассчитывается по возможностям конкретного backend и доступному железу. Поддерживаемые upstream другие GPU не исключаются только из-за отсутствия нашего тестового устройства.
- Прежняя цель 16 ГБ VRAM / 32 ГБ RAM остаётся ориентиром доступности, а не уже подтверждённой характеристикой всех музыкальных вариантов.

## 8. Внешнее окно скачивания и проверки

Использовать общий управляемый загрузчик ЛОПАТЫ, общий лицензионный путь и `ComponentAudit`. Отдельную самодельную систему скачивания и согласий для нового сценария не создавать.

1. Выбор модели обновляет её параметры и локальный статус. Для отсутствующих компонентов доступна явная кнопка подготовки/скачивания, открывающая отдельное внешнее окно.
2. До загрузки показывать точный состав, полный/оставшийся объём и необходимые условия. Скачивание начинается по пользовательскому действию, а не от простого раскрытия списка.
3. Несколько соединений, безопасная докачка, скорость, общий прогресс и объём. Для каждого файла — ожидает / скачивается / частично скачан / проверяется / готов / ошибка.
4. Поддержка Range определяется фактически. Если источник не допускает безопасную докачку, корректно перезапустить только соответствующую собственную загрузку, сохранив остальные файлы и исходники.
5. Общие веса, кодировщики, VAE и другие компоненты повторно используются по подтверждённой идентичности/хешам; одинаковое имя само по себе не доказывает совпадение.
6. Полученные файлы проверяются по манифесту. Уровень аудита наследуется из приложения и фиксируется на операцию. Первая установка/новая ревизия и переустановка требуют полного аудита; скачивание не заменяет первый аудит установки/runtime.
7. «Успешно» означает готовность и проверку обязательного состава выбранного набора. После этого окно само закрывается, основная страница показывает готовность.
8. Ошибка оставляет окно открытым с понятной причиной и повтором. Отмена сохраняет проект и пригодные скачанные части; не удаляет пользовательские модели.
9. Закрытие окна загрузки не запускает видеогенерацию. Для запуска остаётся основная кнопка «Старт генерации».
10. Не требовать от пользователя установки Python/Git/ComfyUI, копирования узлов, поиска весов или вставки терминальных команд. Первоначальная управляемая установка и штатное согласие с лицензиями остаются явными действиями.
11. Обязательная регистрация, посещение внешнего сайта, принятие gated-доступа вне ЛОПАТЫ или ввод стороннего ключа не считаются выполнением согласованного встроенного пути. Такой блокер обсуждается; зеркала и обход доступа не подставлять.

Вспомогательное окно имеет простой локальный жизненный цикл. Длительная генерация нового сценария подключается к общей фоновой операции отдельно; исключение для окна скачивания не отменяет проверок компонентов и сохранности файлов.

## 9. Автоматическая подготовка и исполнение

```text
Снимок проекта и проверка входов
  → извлечение/получение текста и таймингов при необходимости
  → музыкальный анализ
  → визуальный замысел и план по всей песне
  → необходимые запросы и референсы
  → генерация сцен/выступления/реактивных визуальных частей
  → сборка и исходная звуковая дорожка
  → проверка полноты, метаданных и сохранение полного результата
```

- Автоматически использовать подходящие заранее проверенные помощники, сохраняя возможность выбрать их пользователю. Во время испытаний доступны все подходящие варианты из проверяемого списка, а не произвольные установленные модели.
- Переиспользовать существующие в ЛОПАТЕ анализаторы, Qwen, рисующие модели, аудиотракт и экспорт там, где их контракты подходят. Подключение конкретных помощников и их ревизий записать в паспорт исполнения.
- Готовые корректные данные не вычисляются повторно. Инвалидация этапов зависит от содержимого входов, параметров и фактических ревизий, а не просто от открытия страницы.
- Автоматическое планирование охватывает всю песню и допускает реальную структуру: вступление, куплеты/припевы, бриджи, повторы и инструментальные места. Смысл, персонажи, визуальный стиль и ритм учитываются совместно.
- Для исполнительского варианта при необходимости выделять вокальную дорожку только как модельный управляющий вход. В финале используется исходный микс, а не выделенный вокал или повторно сгенерированное аудио.
- Запросы помощникам задают конкретные схемы результата; структурная и смысловая проверка предшествует видеосинтезу. Не превращать произвольный ответ модели в бесконтрольное исполнение команд.
- Служебные запросы при необходимости переводятся на поддерживаемый генератором язык. Оригинальный текст песни, имена, намеренные надписи и вокал не переводятся автоматически вместо авторского содержания.
- Референс исполнителя закрепляет согласованную внешность; вставки и инструментальные места не обязаны показывать поющее лицо. Для дуэтов возможность нескольких референсов/потоков определяется реальными способностями варианта, а не общим обещанием.
- В обычном режиме не выводить цепочку обязательных экранов подтверждения плана. Ручные правки доступны по желанию; технические/смысловые ошибки отмечаются и безопасно исправляются в ограниченном числе попыток.
- Тяжёлые модели выполняются последовательно внутри одной логической задачи. Выгружать ненужную Qwen/рисующую модель перед видеосинтезом, переиспользовать прогретый компонент, пока он нужен и помещается.
- Сначала предпочитать полностью GPU-вычисления там, где это поддерживается и помещается. При временной занятости памяти предложить освободить её; GPU/гибрид выбирать честно по реальному backend. Чужие игры/процессы самостоятельно не закрывать.
- Поддержанный сторонний конвейер использовать штатно, добавляя адаптер проекта и фоновой работы. Любой собственный исполнитель или отклонение от штатной схемы требует конкретного технического объяснения в этом ТЗ.

## 10. Длительность, звук и связность

1. Основной источник длительности — фактически декодируемая песня, а не число строк текста или приблизительный запрос.
2. Полный результат покрывает её от начала до конца; нет жёсткого лимита, обрезающего финальную музыкальную фразу. Проверяются короткий хвост, затухание, тишина в начале и конце, длинное инструментальное вступление.
3. Ограничения кадровой сетки, длины одного прохода и перекрытия учитываются адаптером автоматически. Пользователь не высчитывает их вручную.
4. Контекст предыдущих кадров/латентов переносится только поддерживаемым способом. В паспорте каждого участка сохраняются родитель, выбранные референсы, временной интервал песни и параметры продолжения.
5. При сборке исключить повтор музыкальных тактов, накопительный аудиосдвиг, разрывы и дублированные участки. Автоматический монтаж по битам не должен рвать фразу только ради равных фрагментов.
6. Не выдавать аудиореференс тембра за гарантированное исполнение точных слов. Для липсинка испытать действительное управление от заданной песни, включая русский язык.
7. Итоговое кодирование может изменить аудиокодек согласно формату, но не заменяет содержание/скорость/высоту песни. При допустимом копировании потока сохранять его; отдельно проверять синхронизацию и отсутствие отсечения.
8. Временные участки и отдельные проходы — внутренние результаты незавершённой попытки. Основной список макета содержит цельные клипы; незавершённый результат нельзя обозначать успешным полным клипом.

## 11. Прогресс, пауза, остановка и восстановление

- Подключить основной сценарий к общей фоновой операции, трею, уведомлениям, контрольным точкам и реестру `ФОНОВЫЕ_ОПЕРАЦИИ.md`.
- Показывать реальную стадию: анализ, планирование, изображения, участок N/M, шаг N/M, декодирование, сборка, проверка. Новый проход не должен выглядеть как необъяснимый перезапуск всей задачи.
- Общий процент учитывает все стадии и участки; не достигает 100% до проверки готового файла. Для неопределённого этапа — анимация и название без выдуманного процента.
- Счётчик прошедшего времени опирается на монотонные часы; обновление прогноза не ускоряет и не сбрасывает его. Отдельно сохранять общее время и время активных вычислений/пауз, не смешивая эти значения.
- Прогноз уточнять по завершённым сопоставимым шагам/участкам; холодную загрузку, нейросинтез, декодирование и сборку учитывать раздельно. До накопления данных показывать «Оцениваем время».
- Журнал содержит понятные события, предупреждения, переходы и причины ошибок; подробности раскрываются по желанию. Не выдавать журнал за внутренние мысли модели, не публиковать секреты/служебные токены.
- При долгом этапе различать живой backend, ожидание, паузу и подтверждённый сбой. Само отсутствие новых кадров или низкая загрузка GPU не доказывает зависание.
- Пауза сохраняет входы и принятые результаты, останавливает собственные вычисления и освобождает модели согласно общему контракту. «На паузе» показывается после подтверждения этих действий.
- Продолжение повторяет только незавершённый этап. Восстановление после закрытия приложения/перезагрузки не зависит от сохранения кеша ComfyUI в RAM.
- Остановка прекращает дальнейшую работу, оставляя проект и подтверждённые файлы. Явная остановка не превращается в автоматический повтор.
- Повторы временных ошибок ограничены, видны в статусе и не образуют бесконечный цикл. Для компонентного/непонятного сбоя сохраняется общий путь диагностики без скрытого автоматического повторного запуска.
- Сворачивание в трей не останавливает задачу. Возврат восстанавливает страницу и проект. Просмотр уже готового результата остаётся доступен там, где не конфликтует с записью активной попытки.

- В публичные метаданные/экспорт не включать абсолютные личные пути, ключи и сырые диагностические журналы.
