# Подготовка списков уведомлений для озвучки

Инструменты разработки, не runtime-зависимость ЛОПАТЫ. Используется Roslyn из установленного .NET SDK без нового NuGet-пакета. Программа, голоса и настройки уведомлений не изменяются.

Из корня проекта:

```powershell
New-Item -ItemType Directory -Path '_tmp/notification-catalog' -Force
dotnet run --project 'Инструменты/SpeechAssets/CatalogScan/CatalogScan.csproj' -- 'Исходники' 'Исходники/AIHub/Localization/ru.json' '_tmp/notification-catalog/csharp.json'
python 'Инструменты/SpeechAssets/build_notification_lists.py' --scan '_tmp/notification-catalog/csharp.json' --output 'Данные_для_внедрения/Речевые_ассеты/Уведомления_и_статусы_2026-11-09'
```

Сканер C# использует синтаксическое дерево: словарные ключи, локальные префиксы переводов, присваивания статуса, сообщения/прогресс, исключения, enum-состояния и диагностические события моделей. Python-файлы исполнителей разбираются стандартным AST. Дополнительно проверяются XAML и оба словаря локализации. notification_filter.py оставляет уведомления и состояния выполнения; названия, подписи, подсказки, описания, инструкции, параметры и пустые фрагменты исключаются. Название модели или слово «загрузка» само по себе не является основанием для включения. Короткие просьбы о действии при ошибке сохраняются. Длинные сообщения сокращаются, исходные формулировки принятых событий остаются в реестре.

Одинаковые пары RU/EN объединены в один clip ID с явными aliases исходных событий. Динамические поля не заполняются вымышленными числами/путями: сохраняется исходный шаблон и предлагается общая произносимая формулировка с пометкой проверки. Есть отдельный резерв жизненного цикла моделей; это не заявление о подключённых runtime-уведомлениях. Все такие решения доступны в реестре, `review_required` сохраняется.

Каждый пункт списка — одна реплика, заголовок содержит номер и устойчивый clip ID. Комментарии со связями не произносятся. Markdown-пунктуация экранируется, чтобы нумерация вроде `2.` не создавала вложенный список. Перед перезаписью трёх выходных файлов инструмент автоматически делает backup.

Проверка настоящим импортёром из уже собранного приложения:

```powershell
dotnet run --project 'Инструменты/SpeechAssets/CatalogScan/CatalogScan.csproj' -- --verify 'Исходники/AIHub/bin/Debug/net10.0-windows/AIHub.dll' 'Данные_для_внедрения/Речевые_ассеты/Уведомления_и_статусы_2026-11-09/LOPATA_реестр_уведомлений_и_статусов.json' 'Данные_для_внедрения/Речевые_ассеты/Уведомления_и_статусы_2026-11-09/LOPATA_уведомления_и_статусы_ru.md' 'Данные_для_внедрения/Речевые_ассеты/Уведомления_и_статусы_2026-11-09/LOPATA_уведомления_и_статусы_en.md'
```

Проверка вызывает только `SpeechAssetMarkdown.Parse`, не запускает модель и не сохраняет пользовательский сеанс. Сверяются число реплик, каждый произносимый текст и clip ID с реестром. Перегенерация набора может изменить порядковые номера; для будущей связи уведомлений использовать clip ID/aliases, а не один номер WAV.

Проверка фильтра:

```powershell
python -m unittest discover -s 'Инструменты/SpeechAssets' -p 'test_notification_filter.py' -v
```

Нормализация никогда не принимает одну точку за текст. Обычная пунктуация не экранируется; экранируются активная Markdown-разметка и начальная нумерация. Исходные списки в проектах утилиты являются снимками: после обновления файла импортировать его заново.
