# ЛОПАТА — идея системного инструмента скриншотов и GIF-записи

**Статус:** идея для будущей реализации.  
**Дата фиксации:** 28.09.2026.  
**Зависимость:** реализовывать после полноценного режима жизни ЛОПАТЫ в системном трее.

## 1. Общая идея

Добавить в ЛОПАТУ собственный системный инструмент захвата экрана, ориентированный не на профессиональный редактор скриншотов, а на быстрый бытовой сценарий:

- сделать снимок;
- сразу положить его в буфер обмена;
- при необходимости одновременно сохранить в файл;
- быстро захватить отдельную область;
- повысить читаемость очень маленьких UI-фрагментов;
- записать короткий GIF с действиями для мини-инструкций и обучения;
- работать даже тогда, когда основное окно ЛОПАТЫ скрыто в трей.

Инструмент не должен превращаться в полноценный профессиональный аналог ShareX, графического редактора или видеорекордера.

## 2. Режимы захвата

Четыре основных режима:

1. **Скриншот ЛОПАТЫ** — окно самой программы.
2. **Скриншот активного монитора** — полный снимок текущего активного монитора.
3. **Скриншот всех мониторов** — единое изображение всего виртуального рабочего стола с сохранением реального расположения экранов.
4. **Скриншот выделенной области** — пользователь выделяет произвольную область мышью; доступен дополнительный режим повышения читаемости маленьких фрагментов.

## 3. Два независимых действия для каждого режима

Для каждого вида захвата отдельно две независимые галочки:

- **В буфер обмена**
- **Сохранять в файл**

Допустимы все варианты:

- только буфер;
- только файл;
- буфер + файл.

Обычный путь должен быть быстрым и не требовать дополнительных подтверждений, если нет риска потерять данные из буфера.

## 4. Форматы сохранения

Обязательные:

- **PNG**
- **JPEG**
- **WebP**

WebP нужен как удобный формат для публикации в интернете.

Дополнительно можно поддержать BMP и TIFF.

Для WebP желательно иметь:
- lossless-режим для интерфейсов, текста и схем;
- обычный режим с настраиваемым качеством для уменьшения размера файла.

Формат по умолчанию выбирается в настройках.

## 5. Исходное разрешение

Обычные скриншоты сохраняются в **исходном разрешении**.

Автоматическое изменение размера не требуется для полного монитора, всех мониторов или окна ЛОПАТЫ.

Исключение — специальный режим повышения читаемости выделенной области.

## 6. Повышение читаемости маленькой области

Это не AI-upscale и не попытка дорисовать новые детали. Задача — сделать маленькие фрагменты интерфейса, иконки и текст удобными для просмотра.

Правило:

- базовое увеличение: **×2**;
- если после ×2 итоговая область всё ещё слишком маленькая, увеличить сильнее автоматически;
- итоговый результат не должен оставаться меньше примерно **100×100 px**;
- пропорции сохраняются;
- используется качественное масштабирование и лёгкое повышение резкости;
- нейросетевое сверхразрешение не требуется.

## 7. Сохранение оригинала и увеличенной версии

Если для выделенной области включён режим повышения читаемости:

### На диск
Сохраняются две версии:
1. **оригинал** без обработки;
2. **увеличенная версия**.

### В буфер
Автоматически помещается **только увеличенная версия**.

## 8. Защита текста в буфере

Проверка нужна только перед тем, как ЛОПАТА сама собирается заменить содержимое буфера скриншотом.

Если в буфере уже находится текст, показать предупреждение:

**«В буфере обмена находится текст. Заменить его скриншотом?»**

Сам текст:
- не сохранять автоматически;
- не архивировать;
- не отправлять;
- не анализировать.

Если сохранение в файл включено, скрин уже сохраняется штатно.

Если сохранение в файл выключено, ЛОПАТА всё равно должна **принудительно сохранить скриншот в страховочный файл**, чтобы снимок не потерялся, если пользователь откажется заменять текст в буфере.

Если это увеличенная выделенная область, страхуется комплект:
- оригинал;
- увеличенная версия.

Если текста в буфере нет, никаких предупреждений: скрин сразу помещается в буфер.

## 9. GIF-запись действий

Добавить отдельный режим короткой GIF-записи.

Назначение:
- мини-учебники;
- короткие инструкции;
- демонстрация действий в интерфейсе;
- показ багов или последовательности шагов.

Это не полноценный видеорекордер.

Основная логика:
- выбрать источник: ЛОПАТА / монитор / все мониторы / область;
- начать запись;
- выполнять действия;
- остановить запись горячей клавишей;
- сохранить готовый GIF.

Желательные параметры:
- исходное разрешение;
- 5 FPS — инструкция;
- 10 FPS — стандарт;
- 15 FPS — плавно;
- зацикливание.

Позже можно добавить:
- подсветку курсора;
- визуальный эффект клика;
- отображение нажатых клавиш;
- автоматическую паузу после клика;
- простую обрезку начала и конца.

Для учебных GIF полезно не хранить одинаковые кадры постоянно: если изображение не меняется, продлевать длительность существующего кадра вместо записи множества одинаковых кадров.

## 10. Горячие клавиши

Нужны **настраиваемые глобальные горячие клавиши** минимум для:

- скриншота ЛОПАТЫ;
- активного монитора;
- всех мониторов;
- выделенной области;
- начала / остановки GIF-записи.

В настройках:
- назначить собственную комбинацию;
- отключить комбинацию;
- увидеть конфликт;
- сбросить к умолчаниям.

Горячие клавиши работают, даже когда окно ЛОПАТЫ:
- не в фокусе;
- свёрнуто;
- скрыто в системный трей.

## 11. Зависимость от режима трея

Инструмент скриншотов реализуется после полноценного tray-режима ЛОПАТЫ.

Смысл:
- ЛОПАТА может жить в фоне;
- основное окно скрыто в трей;
- скриншоты и GIF продолжают работать по глобальным горячим клавишам;
- для использования инструмента не нужно открывать главное окно.

Это системная функция ЛОПАТЫ, а не функция отдельного сценария.

## 12. Меню системного трея

При ПКМ по значку ЛОПАТЫ в трее должна быть команда:

**«Открыть скриншоты»**

Она открывает текущую папку хранения снимков в Проводнике Windows.

Путь хранения:
- настраиваемый;
- пункт в трее всегда открывает актуальную выбранную папку.

## 13. Поведение при свёрнутой ЛОПАТЕ

Когда ЛОПАТА скрыта в трей:
- горячие клавиши продолжают работать;
- захват выполняется без открытия главного окна;
- сохранение и запись в буфер выполняются в фоне;
- GIF может стартовать и останавливаться глобальной горячей клавишей;
- предупреждение о замене текста в буфере показывается отдельным небольшим окном/уведомлением.

## 14. Папка хранения и имена файлов

Для снимков и GIF должна быть отдельная настраиваемая папка.

Желательно:
- дата и время в имени;
- тип захвата в имени или метаданных;
- для увеличенной области — отличимые суффиксы оригинала и увеличенной версии.

Пример:
- `2026-09-28_013500_area_original.png`
- `2026-09-28_013500_area_scaled.png`

Точная схема имён определяется при реализации.

## 15. Настройки

Минимум:

### Общие
- папка хранения;
- формат по умолчанию;
- качество JPEG/WebP;
- WebP lossless;
- параметры GIF.

### Для каждого режима
- [ ] В буфер обмена
- [ ] Сохранять в файл

### Для выделенной области
- режим повышения читаемости;
- базовое увеличение ×2;
- автоматическое дополнительное увеличение для слишком маленькой области.

### Горячие клавиши
- отдельные комбинации для каждого действия.

## 16. Чего пока не требуется

Не превращать первую реализацию в профессиональный редактор.

Пока не нужны:
- сложное рисование;
- стрелки и аннотации;
- размытие областей;
- OCR;
- длинные scrolling screenshots;
- запись полноценного видео;
- монтаж;
- AI-super-resolution;
- облачная загрузка;
- социальные функции.

## 17. Польза для ЛОПАТЫ

Инструмент полезен не только сам по себе. Он может стать общим входом для:

- анализа изображений;
- баг-репортов;
- документации;
- будущих учебников;
- демонстрации действий;
- передачи визуального контекста модели;
- быстрых мини-инструкций через GIF.

## 18. Текущий технический фундамент

По состоянию репозитория на момент обсуждения:

- .NET 10 / WPF / Windows Forms;
- уже есть работа с изображениями из Clipboard / drag&drop;
- используется `System.Drawing.Bitmap`;
- есть собственная инфраструктура уведомлений;
- готового глобального `RegisterHotKey`-сервиса пока нет;
- отдельного screenshot/capture-модуля пока нет.

Потребуются новые системные части:
- захват экрана;
- multi-monitor/DPI;
- глобальные hotkeys;
- WebP-кодирование;
- GIF-запись;
- интеграция с tray-режимом.

# Главный принцип

> **Обычный путь должен быть максимально быстрым. Защита и дополнительные вопросы появляются только в потенциально разрушительных местах.**

Если пользователь просто делает скрин:

**горячая клавиша → снимок → буфер и/или файл.**

Если в буфере лежит текст и ЛОПАТА собирается его уничтожить:

**сначала страховка снимка → затем понятный вопрос пользователю.**

Если выделена слишком маленькая область:

**оригинал сохраняется как есть, а читаемая увеличенная версия создаётся автоматически.**

# Короткий итог

Будущий инструмент должен быть:

**быстрым, системным, живущим в трее, удобным для буфера, безопасным от случайной потери текста, пригодным для публикации в интернете и способным создавать простые GIF-инструкции.**

Его задача — закрыть большинство повседневных потребностей без запуска отдельной программы.
