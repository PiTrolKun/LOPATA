# Расширение сценария 1С

Код: Исходники/AIHub/{Models,Services,Controls}/OneC. Тесты: Исходники/AIHub.Tests/OneC*.cs. Локальные документы: Tools/OneC. В опубликованной репе эти каталоги находятся по тем же путям. Общий репозиторий: https://github.com/PiTrolKun/LOPATA .

## Карта

- OneCProject: схема 1, задачи, привязки диапазонов, предложения, снимки ошибки пользователя, история и Pending.
- OneCProjectStore + Files + Validation: единственная точка сохранения и проверки принадлежности. Реестр .ownership хранится отдельно от изменяемого manifest проекта. Ревизии создаются с новым именем и никогда не перезаписывают предыдущие байты.
- OneCProtocol: неизменяемый запрос, строгий ответ, fingerprint задачи и источника. Не включайте секреты, произвольные пути или разрешения в ответ модели.
- OneCWork: этапы model → durable proposal → checker → durable diagnostics → ограниченные исправления. Общий BackgroundOperationController сохраняет паузу и продолжение. Конец этапа не означает применение файла.
- OneCLocalModelSession: общий ReaderTranslationRuntime, штатные модели, лицензии, аппаратный выбор и ComponentAudit. Для GGUF передаётся JSON schema; для chatllm обязательна проверка полученного JSON.
- OneCBslRuntime / OneCBslChecker: отдельный owned-процесс, закреплённая версия, лимиты, проверяемая связь отчёта с фактическим исходником. Нет исполнения пользовательского кода.
- OneCControl partials: UI и только его связи. Один компонент редактора OneCCodeEditor используется для файлов, предложения, справочного кода и диагностики.
- OneCAdapters: регистрация источников и проверяющих инструментов. OneCLanguageReference: небольшой версионируемый источник синтаксических примеров без метаданных чужих конфигураций.

## Добавить источник за четыре шага

1. Реализуйте IOneCProjectAdapter: Id, Supports(path), ListAsync(path, token). Возвращайте проверяемые реальные пути и относительные подписи. Не выдавайте выдуманные сведения о конфигурации. Действующий образец — OneCTextProjectAdapter.
2. Сохраняйте режим чтения: общий Store.Import создаёт снимок материала, а не право записи. XML: DTD запрещены, XmlResolver=null, объём до двух миллионов символов, глубина до шестидесяти четырёх. Каталоги ограничены глубиной, числом файлов и посещённых папок. Ссылки и junction запрещены.
3. Добавьте экземпляр в OneCAdapters.Sources. UI и OneCWork менять не требуется. Более специфические Supports располагайте раньше общего адаптера папки.
4. Повторите контрактные тесты OneCAdapterTests: реальные модули читаются, исходник не изменяется, небезопасный XML отклоняется, неизвестные возможности/версии дают явный отказ. Добавьте тесты своего формата и кодировок.

## Добавить проверяющий инструмент

Реализуйте IOneCCodeChecker (Id, Version, CheckAsync) и зарегистрируйте factory в OneCAdapters.Checkers. Выбираемый инструмент должен быть явно разрешён manifest. Возвращайте диагностики со строками и столбцами от единицы, CodeHash точного входа и честным State. Исключение процесса, отсутствие отчёта и несовпадающий путь не являются успехом. Пример настоящей реализации — OneCBslChecker; статическая и платформенная проверки различаются по Id и возможности.

Обязательны общие лицензии и ComponentAudit: первый запуск новой ревизии/переустановка всегда полные, повтор OFF проверяет наличие. Модель/инструмент работают в owned-процессе с отменой и лимитами. Общие фоновые операции и завершение программы не обходятся собственным вечным процессом. Право записи остаётся только у Store, расширение не получает полномочий менять чужие файлы.

## Контракты

Файлы contracts содержат manifest, запрос/ответ примера и JSON schema. ProtocolVersion=1; capability run отсутствует. Неизвестная версия возвращает unsupported-version, неизвестная возможность — unsupported. Внутрипроцессные адаптеры используют типизированные контракты. Внешний stdio/MCP транспорт пока не подключён: перед реализацией требуются отдельный процесс, requestId, ограничение размера кадра/ответа, отмена, таймаут и проверка версии. Содержимое модели, BSL и XML — данные, не команды.

## Проверки

Из корня репозитория:

```powershell
dotnet build .\Исходники\AIHub.Tests\AIHub.Tests.csproj -p:BookOfficeArchive=true
.\Исходники\AIHub.Tests\bin\Debug\net10.0-windows\AIHub.Tests.exe --filter 'FullyQualifiedName~AIHub.Tests.OneC'
```

Реальные испытания требуют LOPATA_ONEC_MODEL (ID установленной модели), LOPATA_ONEC_BSL_EXE (официальный launcher BSL LS). WPF: LOPATA_ONEC_UI=1; снимки — LOPATA_ONEC_UI_OUTPUT. Тесты с фикстурами проверяют сохранение/состояния и не доказывают генерацию. Для worktree со ссылкой Runtime запускайте native-host из настоящего корня или используйте обычный checkout; защиту от junction не отключайте ради теста.

## Статусы развития

Реализовано: copy/paste, локальные проекты и права файлов, редактор/diff, реальные локальные модели и BSL LS, папка текстовых материалов, учебные примеры, связь ошибки с версией, возобновление.

Заготовлено контрактами: другие источники/проверяющие инструменты/локальные справочники.

Требует отдельной реализации и стенда: точная модель метаданных выгрузки Конфигуратора/EDT, изолированный OneScript, настоящий запуск в тестовой базе, сборщики CF/CFE/EPF/ERF, внешние stdio/MCP коннекторы, портативный пакет проекта. Проверка на одной конфигурации не означает совместимость со всеми базами.
