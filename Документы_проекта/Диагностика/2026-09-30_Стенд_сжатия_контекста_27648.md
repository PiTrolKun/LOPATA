# Стенд сжатия литературной беседы — окно 27 648 токенов

30.09.2026. Выполнены девять основных тестов: три возраста одной синтетической авторской беседы для каждого из трёх вариантов. Изменения приложения не выполнялись, версия остаётся 0.2.55-dev. По последнему уточнению пользователя достаточно уменьшить исходный объём хотя бы вдвое; качество проверяется отдельно. Малого фиксированного итогового лимита нет.

## Оборудование и условия

ПК разработчика: i9-13900KF, около 128 ГиБ RAM, RTX 4090 24 ГБ, Windows 11; CPU-варианты ограничены 8 потоками. От друга взято измеренное ранее окно 27 648 из внешнего теста RTX 4080 SUPER / i7-13700KF. Это не повтор скорости на его ПК и не журнал его последнего переполнения. [Исходный внешний отчёт](2026-09-22_внешний_тест_литературы_0.2.5-beta.md).

Источники: 21 / 45 / 79 реплик, 6 365 / 15 370 / 29 349 литературных токенов. Полный третий вход с минимальной инструкцией занимает 29 592 токена и не помещается в окно 27 648. Обработка порциями выполнена без потери хвоста входа. Это три связанных возраста одной беседы, а не три повторных запуска одного текста: статистика разброса времени не измерялась. Первые два возраста заканчиваются благоприятной авторской сверкой, третий содержит распределённые поздние исправления без готового финального списка.

Одна модель загружалась и обслуживала три случая последовательно. Общая реально измеренная подготовка: литературный сервер 4.30 с; CPU Qwen 7.10 с; mT5 импорты 1.31 с + загрузка 2.48 с. Эти времена не включены в таблицу. Файловый кеш ОС не очищался; это не три холодных запуска.

У Qwen это максимум секундных замеров Working Set и GPU Process Memory, у mT5 — штатный накопительный PeakWorkingSetSize; методы измерения пиков различаются. Private commit отдельно достигал примерно 15,09 / 2,21 / 5,46 ГиБ: это не физически занятая RAM. Перед GPU-запуском другие процессы занимали около 2,9 ГиБ видеопамяти, поэтому общая занятость карты не приписана модели. Фоновая нагрузка не была фиксирована.

Shared GPU Memory относится к системной RAM, доступной GPU, и не прибавлена к физической VRAM. Пояснение счётчиков: [Microsoft, GPU memory in Task Manager](https://devblogs.microsoft.com/directx/gpus-in-the-task-manager/).

Qwen: существующие GGUF Ridge 3.7bpw и Distill Q5_K_M, llama.cpp b9442-d4c8e2c29. Одинаковые инструкции, seed 20260930, temperature 0.4, thinking=false, cache_prompt=false. Исходные части до 12 000 токенов, целые реплики; затем объединение в хронологическом порядке. max_tokens равен свободному остатку окна после инструкции/входа и страховки 256; искусственного итогового лимита 1500 нет. Все основные Qwen ответы имеют stop и пустой reasoning. Словари двух Qwen дали идентичные token IDs для каждого исходного случая.

mT5: закреплённый checkpoint 2437a524effdbadc327ced84595508f1e32025b3, CPU FP32, 582 401 280 параметров. Это новостной суммаризатор; использован [профиль автора](https://huggingface.co/csebuetnlp/mT5_multilingual_XLSum/tree/2437a524effdbadc327ced84595508f1e32025b3): 511 исходных токенов + EOS, beam4, no_repeat_ngram_size2, локальный max_length84. Пробелы нормализованы, каждый исходный token ID обработан; порции сохраняют реплики/абзацы/предложения, где возможно. Локальный лимит84 отличается от свободного бюджета Qwen и прямо ограничивает применимость сравнения: тестируется весь выбранный метод, а не только архитектура модели. Повторный уровень нужен лишь при превышении половины исходного литературного объёма. Gold модели не получали.

Количество проходов mT5 с обрывом по max_length: 0 из 154. Семантическую пригодность завершение по EOS не доказывает.

## Что сохраняется и что теряется

Литературный Qwen лучше сохраняет ограничения и исправления на этом корпусе, но тоже ошибается. Например, предложенную последовательность с щепкой/мокрым рукавом выдаёт за принятое событие; в третьем случае переворачивает явную авторскую замену Увель → Савр. Это проверено непосредственно по M013–M015/M021 и M063–M064. Полный архив и просмотр пересказа перед принятием нужны даже при хорошем среднем балле.

CPU Qwen сохраняет часть основного сюжета, но теряет детали и возвращает отменённые варианты. Во втором случае снова объявляет ответ Тавена невыбранным после выбора автора; в третьем смешивает возраст 23/24 и прежний выход с тетрадью с новым решением оставить оригинал в сушильне. На этом стенде CPU не ускорил пересказ.

mT5 в этом профиле породил посторонние новостные формулы о рецензиях BBC/публикациях, которых в исходнике нет. Такой результат нельзя использовать как рабочую память литературной беседы. Вывод относится к данному checkpoint, корпусу и профилю, а не ко всем небольшим моделям или суммаризаторам.

Проверка mT5 проведена дополнительно из-за конкретного сомнения в исправности стенда. SHA-256 весов совпадает с официальным LFS ETag; непрерывные диапазоны входа, EOS/PAD, декодирование и параметры генерации проверены. Отдельная оригинальная английская новостная статья из скачанной README дала тематически корректный ответ: YouTube удаляет видео с дезинформацией о вакцинах. Один проход, 4,19 с полного времени после загрузки, без обрыва. Это согласуется с неподходящей задачей новостного checkpoint; английская статья не позволяет изолировать язык и жанр как отдельные причины. Контроль не включён в девять основных результатов.

## Границы для будущего внедрения

Основной кандидат для следующего обсуждения — литературная модель порциями. CPU Qwen технически может работать без дополнительных GPU-буферов, однако здесь ожидание дольше и смысловых потерь больше. mT5 в проверенном виде выбирать для рабочего пересказа не стоит. Более маленький instruct Qwen не тестировался и не скачивался; его результат нельзя переносить с Qwen4 или mT5.

Предложение для умного режима, пока без реализации и без стендового доказательства качества: сохранять последние реплики/текущую задачу дословно, более старую часть пересказывать с явным отделением решений автора от вариантов Советника и сверкой поздних поправок. Не стремиться к предельно короткому тексту, если уже достигнуто сокращение вдвое. Показывать результат до принятия, сохранять оригиналы и дать отмену. Это не обещание сжатия без потерь.

Сжатие беседы не гарантирует вместимость всего запроса: отдельно остаются редактор, выбранные источники, правила, цитаты и резерв ответа. Снижение количества токенов также не равно освобождению всей VRAM. Совместное нахождение литературной GPU-модели и CPU-помощника в RAM здесь не проверялось, как и настоящий запуск при CUDA OOM. Скорость на более слабом ПК требует отдельного измерения.

При реализации нельзя использовать обычный StudioAsync, который снова добавляет проектные материалы, либо принимать пересказ через Clear(), сбрасывающий восстановленный вопрос/цитаты. Нужны отдельный запрос без лишнего контекста, актуальный снимок с устойчивыми IDs, атомарное принятие и отдельная сводка беседы, не факт Желе. Подробные привязки к текущему коду сохранены в локальном integration-review.md.

## Доказательства и состояние проекта

Локальная папка: `H:\AI_HUB\_backups\20260930_context_compression_bench`. В ней frozen fixtures/READY+SHA, source-counts, все запросы/ответы/проходы, coverage, launch/stop, тайминги, ресурсы, blind finals, semantic quality JSON, aggregate.json, методический и интеграционный аудит. Предварительные попытки с малыми целями сохранены отдельно и в основные девять результатов не входят. Новый mT5 и его происхождение/лицензионное неизвестное зарегистрированы в REESTR; веса тестовые и не распространяются.

Все основные процессы стенда и дополнительного контроля завершены, временные серверы остановлены. Код выхода 1 у явно остановленных Windows llama-server относится к принудительному завершению после успешных тестов; Python runners завершились с кодом 0. Приложение пользователя не закрывалось. Перед итоговыми изменениями документов проверены копии с SHA-256 в doc_before_final/files.json; первоначальные копии находятся в doc_backup/files.json.

Изменены только исследовательские документы и локальный стенд. Пользовательские проекты/настройки, исходники приложения и VERSION не изменялись. Сборка приложения, установщик, commit/push, patch-feed и публикация не выполнялись. Рабочий интерфейс ручного сжатия ещё не реализован.
