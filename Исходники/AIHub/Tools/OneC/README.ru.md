# 1С в ЛОПАТЕ

Сценарий находится в «Создание → Vibe Coding → 1С». Он помогает составить небольшой код или разобраться с исходником. Установка 1С для начала работы не нужна.

1. Создайте проект или откройте прежний в панели «Проекты». Панель можно свернуть кнопкой ☰.
2. Вставьте исходник, добавьте BSL/OS-файл или папку текстовых материалов BSL/XML. Добавленный материал доступен только для чтения; оригинал остаётся в своей папке.
3. Во вкладке файла выделите фрагмент и нажмите «Использовать в задаче». Без выделения используется весь файл. Можно начать и с пустого запроса без исходника.
4. Выберите «Сделать задачу» или «Разобраться», опишите цель. Заготовки помогают начать запрос. В режиме обучения доступны небольшие упражнения, подсказки и отдельные образцы решений.
5. Выберите текстовую модель кнопкой AI. Используется общая библиотека моделей ЛОПАТЫ; настройка этого сценария не меняет выбор модели читалки. Кнопка подготовки позволяет проверить или загрузить модель штатным способом.
6. Подготовьте статический анализатор через «Подготовить проверку». Отдельный компонент BSL Language Server включает Java runtime и не устанавливает Java в Windows.
7. Нажмите «Подготовить предложение». Ответ модели сохраняется, затем проверяется реальным анализатором. При синтаксических ошибках возможны ещё две попытки исправления, каждая остаётся в истории.
8. Сравните исходный фрагмент с предложением. Код результата можно редактировать вручную, копировать без нумерации, экспортировать новой копией или превратить в свой файл проекта.

«Применить к моему файлу» доступно только для файла, созданного этим сценарием в текущем проекте. Изменённая задача или исходник требуют нового предложения. Импорт, имя файла и поле origin сами по себе не дают права записи. Экспорт не перезаписывает имеющийся файл и не разрешает впоследствии автоматически изменять внешнюю копию.

Если после переноса кода в 1С возникла ошибка, нажмите действие возле соответствующего предложения и вставьте сообщение. При необходимости добавьте фактически опробованный код. Ошибка сохранится вместе с версией предложения. Затем явно запросите новую правку. Предыдущие варианты останутся в истории.

## Что означают проверки

- Ответ модели — предложение, которое следует просмотреть.
- Статическая проверка относится к конкретной версии текста. После ручной правки её нужно повторить.
- Выполнение в платформе 1С не производится. Статический анализ не доказывает правильность реквизитов, наличие объекта в вашей конфигурации или успешное выполнение в базе.
- Учебные решения — текстовые примеры. Ожидаемые результаты не выдаются за запущенные тесты.

Сейчас доступны свои BSL, OS, TXT и MD-файлы. CF/CFE/EPF/ERF требуют настоящего внешнего сборщика и не создаются переименованием текста. OneScript здесь не исполняется: для этого нужен отдельный проверенный профиль изоляции.

## Сохранение

Изменения сохраняются автоматически и по Ctrl+S. В проекте хранятся задачи, исходники, предложения, проверки и контрольная точка обработки. «Пауза» освобождает модель через общую механику фоновых задач; «Продолжить» использует готовые этапы. Остановка или закрытие не применяют правку к файлу автоматически. Отправка программы в трей не мешает текущей задаче.

Собственные файлы сохраняются неизменяемыми ревизиями, реестр проекта — атомарно с последней резервной копией. При внешнем изменении файла ЛОПАТА сообщает о конфликте и сохраняет внешний текст. Не удаляйте каталог проекта и служебный реестр владения вручную. Это локальный проект; импорт произвольного переносимого архива с правами записи пока не предоставляется.

## Доработка

Кнопки справки открывают исходники этого модуля и отдельное руководство DEVELOPMENT.ru.md. В нём приведены реальные точки расширения, пример адаптера папки и команды проверки. Текущий цикл — открытая рабочая заготовка, а не полная замена Конфигуратора или EDT.
