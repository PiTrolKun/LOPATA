Два успешных последовательных запуска штатного исполнителя, без изменения
пользовательского архива. Тестовый ПК:RTX4090/24ГБ,128ГБ RAM,i9-13900KF,
драйвер617.42. В момент испытаний установлена ЛОПАТА0.6.83-dev.
Сведения карточек обновлены по этим результатам в0.6.84-dev.

Одинаковая задача:480×864,124 кадра/24fps (5,1667с по сетке H3),8 шагов,

## Полученные пики

Числа в GiB (двоичные ГБ,как шкала Windows). Все показатели — разные виды
памяти; их нельзя складывать между собой как независимые требования.

| Показатель | H3 INT8 + Qwen32B | H3 W4A8 + Qwen4B |
|---|---:|---:|
| Dedicated GPU memory дерева процесса, Windows PDH | 20,10 | 18,61 |
| Пиковый working set отдельного процесса, Windows PeakWorkingSet | 27,89 | 17,63 |
| Наибольшая одновременно наблюдавшаяся сумма working set дерева | 26,55 | 17,39 |
| Private committed memory дерева процессов | 47,98 | 41,95 |
| Shared GPU allocations дерева, Windows PDH | 24,08 | 0,08 |
| Пик использованной RAM всей системы | 54,08 | 38,00 |
| Пик использованной VRAM всей видеокарты, NVML | 23,60 | 23,33 |
| Медиана RAM системы перед запуском | 20,59 | 22,24 |
| Медиана VRAM видеокарты перед запуском | 4,11 | 4,11 |

Working set показывает физически находящиеся в памяти страницы процесса;
PeakWorkingSet фиксирует и короткие всплески между отсчётами. Private commit
не равен физической RAM:под выделения нужна ёмкость RAM/файла подкачки.
Shared GPU allocations также не следует добавлять к working set:это иной
учёт отображений GPU,частично перекрывающийся с RAM/commit. По нему нельзя
утверждать,что ещё24ГБ физической RAM постоянно заняты вычислением.

Для W4A8 штатный Torch отдельно зафиксировал max allocated15,79GiB,
reserved-снимок18,20GiB. Драйвер/контекст/другие буферы не входят в allocated.
У старшего пути аналогичных ресурсов-событий нет:их отсутствие записано как
unknown/null,не как нулевое потребление. Общие измерения Windows/NVML есть
для обоих наборов.

Короткий memory-тест не подтверждает художественное качество или универсальную

в чистое время инференса. Штатный ComponentAudit не обходился:свежий отдельный
store каждого стенда требовал полного первого аудита.

PeakWorkingSet64,PrivateMemorySize64,GlobalMemoryStatusEx,NVML MemoryInfo.

Исходники коллектора,JSONL,таймлайн стадий,запросы,TRX и MP4:
`_tmp/video-memory-measurement-20261030/`. `measurements.json` содержит

## Практический предел вывода

этими запусками не квалифицированы. Здесь оба профиля выделяли больше16ГБ
dedicated GPU memory,private commit превышал32ГБ. На другой карте Auto
может иначе управлять памятью; для подтверждения нужны отдельные испытания.

объём,а не только номинал карты. Более длинный проход/разрешение/upscale
требуют новых замеров. Установщик/публикация не выполнялись.
