# Наборы движков ЛОПАТЫ

Первый состав: 001 — 17.10.2026 (прежние движки), 002 — 18.10.2026 (новые).
Веса и неизменившиеся исполнители хранятся отдельно. Полный набор проверяется
по подписанному файловому манифесту; активация и доставка — разные действия.

## Размещение и сборка

В dev: `Runtime/EngineSets/{id}/{family}/{flavor}`. Семейства: `llama/cpu`,
`llama/vulkan`, `sd/cpu`, `sd/vulkan`, `sd/cuda12`, `studio/native`.
Новая поставка приложения содержит только `EngineSets/002`; необязательные
загрузки хранятся в пользовательском Runtime/EngineSets, без записи в Program Files.
Оригинальные лицензии, CargoSources, исходники и patch Studio находятся внутри набора.

- Подготовка native: `Инструменты/package-engine-set-native.py`; фактические
  источники первого цикла и их проверка закреплены в `Runtime/EngineSetBuild/native-staging.json`.
- Studio: `Инструменты/MusicStudio/prepare-3.6.ps1`; старый каталог не перезаписывать.
- Подготовить оба полных дерева, затем запустить `Pack/EngineSetPack.csproj`:
  аргументы — корень проекта, каталог пакетов, путь каталога, версия будущего
  публичного выпуска и точный commit исходников. Используется существующий
  локальный ключ подписания; его содержимое не выводится и не входит в артефакты.
- Каталог приложения: `Исходники/AIHub/ContentEngineSets/catalog.json`, embedded
  resource `AIHub.EngineSets.Catalog`. Каждый набор содержит проверяемый SignedManifest.
- Пакеты первого цикла: `Runtime/EngineSetBuild/packages`. Это локальная подготовка,
  не публикация. Ссылки закреплены на будущий v0.5.79-beta; до выпуска удалённая
  загрузка может вернуть 404, что не должно менять активный набор.

`prepare-licenses.ps1` создаёт новые карточки и применяет штатный AppendEntries.
Исторические Terms не пересоздаются. Перед повторным изменением текста лицензий
проверить новые Terms и сохранить backup; старые согласия не подменять.

## Поставка и первый переход

Прежний обновлятор не знает защиты наборов. Для перехода нужны два подписанных
манифеста: `lopata-files.json` сохраняет прежний плоский Studio для старого worker,
а `lopata-fresh-files.json` содержит актуальный состав для новой установки и
нового обновлятора. Фактическую политику и guard см. в `LOPATA.Updates` и сценариях
build/publish-file-update. Полный установщик выбирает fresh-манифест.
Обычные пакеты обновления и самостоятельные пакеты наборов имеют разные пути
внутри ZIP; при публикации необходимы оба состава с проверкой хешей и подписей.

Не публиковать частичный комплект. Не удалять пакеты и манифесты старых наборов.
Номер опубликованного набора не переиспользовать. Для следующих выпусков сохранять
первоначальные подписанные манифесты и URL прежних наборов; не привязывать их молча
к новой версии приложения. Старый миниустановщик не знает fresh-маршрута; для
минимальной новой установки используется актуальный миниустановщик.

## Состояние и проверка

`engine-sets.json` в данных приложения хранит активный набор, ручной выбор и отказ
от конкретной рекомендации. Патч не перезаписывает этот файл. Перед активацией
проверяются подпись, файлы, совместимость; UI берёт общую блокировку операций и
выгружает собственные модели. Ошибка сохраняет прежний выбор.
