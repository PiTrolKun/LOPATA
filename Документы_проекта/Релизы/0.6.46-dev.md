# 0.6.46-dev — сохранение подготовки видео

Служебная версия программы для OutputProvenance теперь генерируется при сборке
из того же VERSION/AIHubVersion, что AssemblyInformationalVersion. Конструктор
каждой записи истории больше не вызывает native reflection/type loader.
Старые сохранённые ProgramVersion не подменяются; текущие экспорты получают .46.

При обычном сохранении мастер обновляет путь, статус и счётчики истории,
сохраняя существующие поля, курсор, выделение и native undo. Пересоздание
страницы освобождает прежние spelling-компоненты на UI-dispatcher. Общий
helper также освобождает их при Unloaded и возобновляет на Loaded; намеренно
отключённая проверка сама не включается. RU/EN suggestions остаются штатными.

Связанный дефект открытия .45: синхронный автопрогрев блокировал OpenPath до
загрузки архива. Теперь Loaded/configure планируют один прогрев следующим
проходом UI-dispatcher: сначала файл и его выбор модели, затем загрузка весов.
Правила полного GPU/гибрида и постоянной resident-сессии не менялись.
Если запрос открытия приходит после начала прогрева, отменяется только прогрев,
затем открывается файл и готовится выбранная в нём модель. Генерация не прерывается.
Прогрев больше не создаёт фиктивную правку/пустое восстановление проекта.

Основание: пользовательский APPCRASH .45 27.10.2026 15:22:06, PID20828.
Exception stream/точный Microsoft PDB указывают ClassLoader::LoadTypeDefOrRefThrowing,
clsload.cpp:2037, RVA5d228, при чтении assembly attributes из JSON default ctor.
В .44 PID8524 тот же RVA/managed путь. Параллельный SpellChecker.Finalize
оказался другим потоком: первоначальная гипотеза о нём как единственной причине
исправлена после проверки exception stream. Исправление lifecycle оставлено
как самостоятельная защита от освобождения native-ресурсов вне UI.

На диагностических копиях пользовательского .lopataAIVid штатный Load
проверяет manifest, все истории и восемь карточек. Исходник и recovery целы,
не переписывались. Системный .NET, драйверы, веса и настройки GPU не менялись.
Базовый стенд .45 также прошёл 108 сохранений: сам исходный плавающий сбой
не удалось отдельно воспроизвести, поэтому отсутствие повторения не является
доказательством установленной ошибки стороннего runtime.

Проверки и итоговые журналы: _tmp/video-save-crash. Дампы/тексты проектов —
только локальная диагностика, в публикацию не входят. Установщик не собирался,
публикация и приёмка не выполнялись; ТЗ остаётся активным.
