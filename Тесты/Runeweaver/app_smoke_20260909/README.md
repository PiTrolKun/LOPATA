Этот стенд запускает только собственный временный модельный процесс и пишет тестовый набросок в свою папку, не в пользовательский проект. Требуются установленный backend и локальная регистрация проверенного GGUF.

Пики процесса модели на i9-13900KF, 128 ГБ RAM, RTX 4090: RAM working set 7.097 GiB, private bytes 11.737 GiB, dedicated GPU 11.006 GiB, shared GPU 0.121 GiB. Показатели RAM не складываются. Это короткая проверка и не доказательство работы на 10 ГБ VRAM; текущему профилю практически нужен класс 12–16 ГБ с запасом на остальные приложения. При длинном контексте параметры проверены отдельно в `../app_unified_20260909` (6989/14486 входных токенов, возврат к обоим слотам с сохранённым кэшем).

Первый диагностический проход нашёл отдельную особенность backend: 60000 подряд идущих латинских букв `x` вызывают HTTP500 `Failed to process regex` при токенизации (regex_error/error_stack). Это не цикл генерации; исключение возвращается, процесс завершается стендом. Реалистичный длинный текст из отдельных слов проверен отдельно и отклонён штатным лимитом. Ошибка токенизации теперь записывается в подробную диагностику; native regex не исправлялся.

Источник истины: `summary.json`, копии JSONL и журнала сервера в `diagnostics`, ответы `.txt`. Незавершённые ответы не добавляются в историю критика. Переписка по-прежнему временная, набросок — отдельный `working-draft.txt` проекта, не канон.
