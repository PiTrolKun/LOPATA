# ТЗ — отображение рассуждений ИИ в музыкальном чате

Дата: 13.10.2026. Статус: реализация по прямому заданию пользователя. Связано с ТЗ управления рассуждениями; ядро Qwen3-8B — on/off, бюджет 2048 при включении, сохранённый выбор не менять.

## Требуемое поведение

- Реальные рассуждения из поддерживаемого отдельного канала llama.cpp показывать потоково внутри существующей переписки перед итоговым ответом, в одном блоке на попытку ответа. Не создавать вымышленных мыслей или отдельного окна/панели. По уточнению 13.10.2026 разрешён ползунок шрифта через ПКМ.
- Активный текст: по умолчанию 300% обычного размера (+200%); ПКМ позволяет выбрать увеличение +0…+400%. Цвет слегка зелёный. Поступающий текст — основной визуальный индикатор; без отдельной анимации ожидания при наличии текста.
- При переходе к финальному ответу размер/цвет становятся обычными; блок автоматически сворачивается до заголовка «Рассуждения модели». По нажатию раскрывается обычным шрифтом; вручную раскрытый завершённый блок повторно не сворачивать.
- Использовать реальные поступающие части без искусственных задержек/этапов. Обновления UI объединять только в рамках обычного прохода Dispatcher, не тормозя чтение потока и не перестраивая всю переписку на каждом токене.
- Следовать за текстом, пока пользователь внизу. Ручная прокрутка отключает слежение до возврата вниз. При сворачивании/раскрытии/перестроении сохранять видимый якорь и положение чтения.
- Финальный JSON не выводить как мысли и не применять до завершения и проверки. Рассуждения не включать в песню, параметры, протокол или будущий контекст модели. Без отдельного канала — только обычный статус работы, без пустого блока мыслей.
- Ошибка/отмена/обрыв до конца мысли: снять активное оформление, явно обозначить прерывание. Завершённая мысль не является подтверждением успешного ответа. Частичный JSON не применять.

## Реализация и совместимость

- Отдельный SSE-парсер музыкального пути, события reasoning и перехода к content. Потоковая выдача включается только там, где включены поддерживаемые рассуждения и есть получатель в чате; остальные пути сохраняют прежний запрос.
- Сохранить лицензионные/ресурсные проверки, GPU→hybrid→CPU и выбор пользователя. При recovery перед первым видимым токеном не сбрасывать reasoning; после видимых мыслей не переигрывать запрос молча.
- Блоки хранить отдельно от Messages: ID, turn/attempt, якорь сообщения, реальный текст, статус, ручное раскрытие. Legacy-сессии получают пустой список; схема песни/действий прежняя. Повтор после отклонённого JSON получает отдельный блок той же попытки, старый не перезаписывается.
- Сохранять прогресс периодически существующим механизмом сессии. Восстановленный после закрытия активный блок показывать прерванным, не выдавая за продолжающийся поток. Завершённые раскрытые блоки сохраняют состояние.
- RU/EN и обе темы; обычный шрифт брать из текущего чата, активный умножать на три. Ширина блока следует ширине чата.

## Проверки готовности

1. Разделение SSE-каналов, кириллица, граница reasoning/content, отсутствие канала, ошибка, обрыв, length, отмена; промежуточные события приходят до завершения потока.
2. UI: 3× активный шрифт, уменьшение/сворачивание, ручное раскрытие без повторного схлопывания, прерывание, no-thought fallback, два блока при repair.
3. Сохранение/загрузка и отсутствие мыслей в контексте/песне/параметрах; старые сессии совместимы.
4. Прокрутка внизу/вручную вверх, сохранение якоря при сворачивании и при ручном раскрытии, узкое/широкое окно, RU/EN/обе темы.
5. Реальный установленный сервер: поток reasoning, затем проверяемый финальный JSON; off не создаёт блок. Штатная сборка/safe-start, отсутствие новых warnings, UTF-8/diff-check.
