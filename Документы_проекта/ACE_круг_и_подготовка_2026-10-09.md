# ACE XL Turbo — круг LM и подготовка, 0.4.28-dev

Дата: 09.10.2026. Выполнено по активному ТЗ. Музыкальные тесты не запускались:
качество исполнения и полезность траектории проверяются пользовательским прослушиванием.

## Поведение интерфейса

Основной круг «Музыкальный замысел» связан с lm_temperature/lm_top_p/lm_cfg_scale.
Центр 0.85/0.9/2; lm_top_k и все остальные настройки не меняются движением.
Все направления и числовые границы соответствуют ТЗ. Ручные числовые изменения
закрепляются; сброс круга сохраняет закрепления. При экспертных значениях вне
траектории отображается приблизительное положение, реальные значения сохраняются.
При выключенных thinking и трёх use_cot-флагах круг недоступен; при одном CoT без
thinking поясняется влияние только на метаданные. Рецепты и эксперт открываются
в отдельных окнах. ACE не получает YuE-рецепты или YuE CFG.

Профиль ACE15.XLTurbo4B.LM.Bubble v1 хранит координаты, закрепления и происхождение
пресета. Новые ACE-пресеты имеют schema 5; старые schema 4 без круга читаются без
изменения чисел. Проекты остаются общими, настройки модельными. Tuning включён
в исходный request receipt и существующий тег LOPATA_TUNING, задания и снимки проекта.

DCW остаётся внутренним кандидатом Sound v1. Только dcw_scaler и dcw_high_scaler;
второй меняется лишь в double, отключённый DCW не включается автоматически.
Публичного второго круга нет до практической оценки пользы.

Карточка модели содержит согласованную память по скриншотам: RTX4090 24 ГБ,
ПК со 128 ГБ RAM; общая выделенная VRAM 20,1/22,6/3,8 ГБ и RAM 47/47/36 ГБ
для нагрузки/пика/простоя. Это показатели всего ПК, не замер памяти процесса ACE.

## Подготовка

Открытие рабочего окна ACE теперь вызывает одну полную проверку worker,
успешный probe возвращает UI проверенные карточки и аппаратный результат.
Статус Installed из прошлого вызова не является разрешением исполнения.
Source, компоненты, лицензии, wheels, распакованные библиотеки, GPU/CPU и API
проверяются заново. Тайм-аут API не увеличен. Нет постоянного кэша целостности.

PinnedFileTreeVerifier хеширует каждый файл, проверяет состав дерева до и после,
отвергает ссылки и удерживает каталоги Windows-дескрипторами от переименования
во время проверки. После завершения/ошибки/отмены дескрипторы освобождаются.
Ограниченная параллельность — два файла. GPU bundle verifier использует тот же
контракт с сохранённым закреплённым digest его manifest.

ACE manifest построен офлайн Инструменты/prepare-ace-file-manifest.py из
88 проверенных SHA256 wheels закреплённого каталога. 19937 файлов, 593256310 байт.
Манифест встроен как AIHub.AcePythonManifest; локальный files.json не доверенный.
SHA256 Tools/ace-xl-python-files.json:
B20EA4F527E3AB7203B8F156EAA5738864661A1EAA0403B041ADDCF205240F21.

ОС-кэш тёплый; это выбор ограниченной степени параллельности на текущем ПК,
не обещание такой скорости на всех дисках.

## Границы готовности

Контрактные проверки: три LM-поля, закрепления и сброс, неизменность других
настроек, обратная проекция, LM/CoT off, DCW off/режим, старые пресеты,
request/metadata/job/project roundtrip, RU/EN и две компоновки/темы.
Проверки verifier: порча при тех же размере/дате, добавление/удаление файла,
unsafe path, junction, отмена и блокировка подмены каталога во время проверки.
Финальные restore/build приложения: 0 ошибок/0 предупреждений. Полный набор:
1361 успешно / 80 специальных пропущены / 0 сбоев, всего 1441. Тестовый проект
имеет четыре прежних предупреждения в неизменённых ImageReferenceTests и
ImageUtilityIntegrationTests; новых предупреждений нет. RU/EN 4458 ключей,
Python AST, UTF-8/scanner и git diff --check успешны. Восемь render-снимков круга
сохранены в _tmp/ace-circles-tests/ui-final; обе темы/языка и ширины 360/620.
Полный TRX: _tmp/ace-circles-tests/full-final.

Первый полный прогон имел один тайм-аут прежнего CPU hardware теста с лимитом
30 с, ещё один отдельный повтор достиг лимита. Третий отдельный вызов того же
кода с тем же лимитом прошёл за 6,473 с; финальный полный прогон успешен.
Первый тайм-аут был внутри проверки файлов, второй — на hardware probe после
чтения файлов. Данные согласуются с прогревом ОС-кэша; причина холодной задержки
отдельно не локализована. Лимиты теста/приложения не менялись. Успех повторного
прогона не доказывает укладывание холодной CPU-подготовки в 30 с.
Штатный start-aihub.ps1 завершился успешно; ЛОПАТА 0.4.28-dev запущена, отвечает.
