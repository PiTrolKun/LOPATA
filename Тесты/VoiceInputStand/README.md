## Продуктовая интеграция 0.6.1-dev

Parakeet внедрён в основную ЛОПАТУ через C# / sherpa-onnx CPU, без Python в продукте.
Рабочее ТЗ ожидает приёмки. Ниже сохранены сведения отдельного исследовательского
стенда; его WAV/логи и прежний статус интерфейса относятся именно к стенду.

# Стенд голосового ввода — выбран Parakeet

22.10.2026: пользователь выбрал **Parakeet TDT 0.6B v3 INT8 / sherpa-onnx 1.13.8,
CPU**. [Результат, измерения и очистка](Результат_выбора.md).
Остальные модели исключены из выбора/подготовки. Веса BitNet удалены;
общий Whisper ЛОПАТЫ сохранён для существующих сценариев. Основной ТЗ открыт.

## Как пробовать

Запуск: `Запустить_стенд_голосового_ввода.cmd` в корне проекта.
Выбрать микрофон/потоки/интервал, нажать «Загрузить модель», затем «Запись».
До явного нажатия микрофон выключен. «Остановить» завершает диктовку.
«Повторить запись» и «Открыть WAV» позволяют проверить звук без новой диктовки;
исходник не меняется, создаётся нормализованная копия PCM16/16кГц/моно.
«Выгрузить» и закрытие завершают собственный worker.

Текст уточняется короткими окнами, это не нативный аудиостриминг модели.
По умолчанию 4 потока/1с; на тестовом ПК проверены также 8 потоков/0.5с.
RMS-порог 0.008, пауза 0.7с, окно до 12с; первая гипотеза не раньше 0.6с звука.
Устаревшие промежуточные окна объединяются, окончательные не выбрасываются.
Известный недочёт: статус «Завершается распознавание» остаётся при пустой очереди;
фактическое состояние видно по очереди и логам. Он зафиксирован в отчёте.

## Журнал и компоненты

Данные: `_tmp/voice-input-stand/`, сеансы: `sessions/<время-id>/`.
Сохраняются полная запись и каждое окно WAV, гипотезы/результаты, stdout/stderr,
PID/команды, CPU/RAM, задержки и очередь. «Открыть логи» показывает сеанс.
Экран содержит последние события, диск не обрезается вместе с экраном.
Передачи аудио в облако нет. Полные тексты — разрешённая диагностика только стенда.

Модель закреплена SHA256/ревизией в models.json, Python — requirements.freeze.txt.
Общий ComponentAudit читает ON/OFF ЛОПАТЫ без записи настроек; квитанции изолированы.
Первый/изменённый инвентарь проверяется полностью, OFF после успеха — наличие.
После изменения worker/окружения пересоздать инвентарь:
`.venv/Scripts/python.exe finalize_assets.py --inventory-only`.
`prepare.ps1` подготавливает только выбранный Parakeet; отклонённые модели не скачивает.

Это исследовательский стенд. Продуктовые виджет/поля ввода/каталог/лицензионный шлюз
ещё предстоит реализовать; основной код и VERSION 0.6.0-dev не менялись.
Возможный C# путь и размер будущего компонента описаны в результате выбора.
