# ЛОПАТА — единая коллекция произведений в Проводнике Windows

**Дата идеи:** 17.10.2026  
**Статус:** сохранённая концепция для будущего обсуждения; **не ТЗ и не команда на реализацию**.

## 1. Исходная проблема

Пользователь создаёт музыку, изображения, документы и другие результаты в разных сценариях ЛОПАТЫ. Файлы сохраняются в многочисленных папках, иногда на разных дисках. Со временем становится трудно вспомнить, куда именно был сохранён нужный результат.

Нужна одна удобная точка входа ко всем созданным произведениям — без переноса файлов и без собственного файлового менеджера.

## 2. Основной замысел

**ЛОПАТА появляется в штатном Проводнике Windows с собственной точкой входа, по аналогии с интеграцией Яндекс Диска.** Нажатие открывает готовую подборку произведений ЛОПАТЫ в обычном интерфейсе Windows.

Главный принцип:

> **ЛОПАТА задаёт Windows условие отбора файлов. Windows выполняет поиск и показывает результат своими штатными средствами.**

Не создавать второй Проводник, собственную систему отображения папок, отдельную службу индексации или независимую базу результатов без доказанной необходимости.

## 3. Минимальная функциональность

1. **Точка входа «ЛОПАТА» в Проводнике Windows.** Внешний вид и способ вызова — максимально привычные, наподобие Яндекс Диска. Конкретный поддерживаемый механизм размещения (панель навигации, команда контекстного меню или иной штатный переход) определяется после технической проверки Windows 11.
2. **Готовая выборка при открытии.** Никакого ручного поискового запроса от пользователя.
3. **Отбор строго по внутренним метаданным происхождения ЛОПАТЫ**, а не по слову «LOPATA» в имени файла, имени папки или пользовательском содержимом. В качестве примера уже существующих записей: `LOPATA_VERSION`, `LOPATA_MODEL`, `LOPATA_JOB` в поддерживаемых форматах. Конкретный надёжный признак нужно согласовать по реальным выходным файлам разных сценариев.
4. **Группировка результатов по типу файла** штатными средствами Проводника: аудио, изображения, документы, видео и другие типы по мере появления.
5. **Оригинальные файлы остаются на своих местах.** Никакого автоматического копирования, переноса, переименования или преобразования.
6. **Будущие сценарии поддерживаются без индивидуальной интеграции:** если результат содержит распознаваемую Windows отметку происхождения ЛОПАТЫ и расположен в доступной для поиска области, он появляется в общей подборке независимо от сценария, создавшего файл.

## 4. Что уже проверено пользователем

В штатном поиске Проводника Windows пользователь ввёл просто `LOPATA` и увидел музыкальные композиции, изображения, а также рабочие файлы с этим словом в названии.

**Подтверждено:** Windows уже обнаруживает разные категории файлов по такому запросу.  
**Пока не подтверждено:** какие именно совпадения получены из *встроенных метаданных*, а какие — из имён файлов, путей или их содержимого; доступно ли отдельное условие поиска по нужным служебным полям во всех выходных форматах ЛОПАТЫ.

Именно поэтому нужен строгий фильтр происхождения, который не засоряет выдачу рабочими файлами и документами, случайно содержащими название программы.

## 5. Принципиальные ограничения

- **Не менять внешний вид штатного Проводника Windows.** Обычные значки, миниатюры, сортировка, группировка, навигация и операции с файлами остаются системными.
- **Не строить собственный индексатор**, пока штатный индекс Windows решает поставленную задачу.
- **Не делать отдельное окно-библиотеку в ЛОПАТЕ** как обязательный интерфейс.
- **Не создавать специальную интеграцию для каждой будущей модели или сценария.** Критерий отбора — метаданные результата, а не перечень его создателей.
- **Не использовать имя файла как доказательство происхождения.** Файл с названием «LOPATA» не должен попадать в подборку лишь из-за названия.
- Не сканировать тайно весь ПК или внешние диски. Область поиска определяется доступностью расположений штатному Windows Search и настройками системы.
- Интеграция должна корректно устанавливаться и удаляться, не нарушая работу Проводника.

## 6. Ключевая техническая проверка перед ТЗ

Проверить на настоящих результатах музыкального, графического и других доступных сценариев:

1. Находит ли Windows файл по **служебному метаданному происхождения**, если убрать `LOPATA` из имени и пути и не упоминать его в обычном тексте.
2. Можно ли составить **штатный поисковый запрос**, ограниченный именно этим свойством, и сохранить его для повторного открытия без ввода пользователем.
3. Поддерживается ли такой запрос для MP3 / FLAC / Opus / PNG и других фактических выходных форматов без дополнительных обработчиков.
4. Можно ли штатно включить **группировку по типу** и повторно открывать тот же вид.
5. Как разместить понятную точку входа «ЛОПАТА» в Проводнике Windows, не заменяя его интерфейс.
6. Какие границы применяются к неиндексируемым местам: перенос файла на другой диск, отключённая индексация, сетевой каталог, незнакомый формат.

**Важно:** пользовательский опыт с запросом `LOPATA` ещё не доказывает, что Windows Search поддерживает адресный запрос ко всем кастомным тегам `LOPATA_*`. Если система не умеет распознавать эти поля, это нужно показать как ограничение концепции, а не тайно подменять задачу поиском по имени или разработкой собственного индексатора.

## 7. Связь с другими идеями

Будущий **универсальный просмотрщик и редактор метаданных** может запускаться для выбранного файла из контекстного меню ЛОПАТЫ, но **не является условием** работы подборки. Утилиты решают разные задачи:

- Эта идея — **найти и показать произведения** через Windows.
- Просмотрщик метаданных — **изучить и при поддержке формата безопасно изменить свойства файла**, не редактируя служебные записи ЛОПАТЫ.

## 8. Критерий удачной реализации

Пользователь создаёт песню или изображение, сохраняет его в привычную папку, может забыть расположение и впоследствии открыть штатный Проводник → «ЛОПАТА», чтобы увидеть **готовую сгруппированную подборку своих результатов**. Рабочие файлы, совпадающие с названием программы только по имени, туда не попадают.

**Короткая формула идеи:** «ЛОПАТА знает, что создала; Windows знает, где это искать и как показать».
