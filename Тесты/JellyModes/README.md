# Исполнители «желе» и независимые условия ролей — 0.1.94-dev

Изолированные проекты в `runs`, пользовательские проекты не изменяются. Модели и базовый Python переиспользуются после проверки. Headless-стенд использует предусмотренную политикой ComponentLicenseGate работу без desktop-host; пользовательские согласия не создаёт и не изменяет. Отдельный тест отказа проверяет блокировку установки.

Команды из корня:

```powershell
dotnet run --project Тесты/JellyModes/Probe.csproj -- Тесты/JellyModes/runs/new-ui --ui
dotnet run --project Тесты/JellyModes/Probe.csproj -- Тесты/JellyModes/runs/new-models --models
dotnet run --project Тесты/JellyModes/Probe.csproj -- Тесты/JellyModes/runs/new-recovery --prepare --recovery
```

Каждый запуск требует нового каталога. `--models` ограничен 12 минутами, `--recovery` — пятью. Обычная проверка без флагов не запускает модели.

## Результаты 2026-09-12

- `ui-01`: старый якорь, два поля и общий лимит 3000, независимость ролей, устаревшая правка, сохранение выбранного исполнителя и начальных якорей. RU/EN: три режима и оба окна, снимки сохранены.
- `physical-budget`: реальные Runeweaver, GLiNER2.5 Multi, NuExtract3. Runeweaver оставалась тем же процессом в основном режиме. GLiNER сосуществовала с ней в VRAM, вычисления были строго последовательными. Для NuExtract потребовалась выгрузка Runeweaver.
- На RTX 4090 драйвер показал около 6.3 ГиБ свободной VRAM при загруженной Runeweaver, тогда как CUDA сообщала около 22.5 ГиБ. Поэтому бюджет использует минимум CUDA и физической памяти по nvidia-smi; при недоступной внешней оценке не предполагает возможность совместного размещения. Порог с запасом: GLiNER 3 ГиБ, NuExtract 12 ГиБ. После выгрузки также проверяется доступная VRAM. На RTX 4080 этот проход не выполнялся.
- NuExtract: сохранены и восстановлены 498 и 684 токена двух нативных слотов, файлы около 78 и 107 МиБ. HTTP API подтвердил `n_restored == n_saved`. Логическое состояние диалогов/якорей отдельно сохранено в `Dialogs/RuntimeCache/checkpoint.json`. После полного перезапуска приложения свежий запрос собирается из постоянных файлов, не зависит от временного KV.
- GLiNER: загрузка около 14.7 с, короткое извлечение 0.41 с; пик выделенных tensor-буферов около 1.10 ГиБ. NuExtract: загрузка около 5.0 с, извлечение 8.39 с; пик около 8.66 ГиБ. Это один короткий пример, не сравнительный бенчмарк; время чтения/импортов и память драйвера учитываются отдельно в диагностике.
- `recovery-01`: все девять компонентов подготовки готовы; обе лицензии моделей обязательны независимо от выбора. Отказ останавливает установку. После ошибки и отмены уже выполненного тяжёлого извлечения worker завершён, Runeweaver восстановлена, блокировка снята, следующий чат отвечает.
- `storage-02`: 18 проверок транзакций, подтверждения, ручных правок, возобновления и диагностики. `workspace-01`: четыре комбинации RU/EN и светлой/тёмной темы, доступность редактора после подготовки и завершения части.

Качество отделено от механики: GLiNER на коротком примере перепутала связи/типы и цитаты. Runeweaver и NuExtract потеряли получателя ключа в поле значения, хотя он есть в цитате. Не исправляли результат скрыто и не объявляли точным. Все предложения проходят прежнее окно проверки; для окончательных фактов остаётся необходимой авторская правка.

Вначале старый Jelly probe включил в сборку `.cs`-копии из `runs/buttons-utf8`; добавлено исключение только каталога результатов. Штатные тесты приложения: 545/545. Установщик не пересобирался.

Документация моделей: [GLiNER2.5 Multi](https://huggingface.co/fastino/gliner2.5-multi-v1), [NuExtract3](https://huggingface.co/numind/NuExtract3). В продукте закреплены прежние проверенные ревизии из стенда, а не плавающий `main`.

Финальные проходы 0.1.94: `final-recovery` повторил ошибку/отмену после тяжёлого извлечения с восстановлением; `final-ui` повторил новые поля RU/EN; `final-stop` подтвердил передачу общей команды Stop профильному обработчику и освобождение блокировки. Safe-start: build 0 ошибок/предупреждений, окно отвечает. UTF-8 scanner: 407 исходников, 102 ТЗ, 47 документов и отдельная проверка корневых журналов — чисто.
