# Публикатор разработчика GitHub → ВК

Дата: 10.10.2026. Статус: выполнено, проверено и принято пользователем; архивировано.

## Цель и границы
Отдельная утилита ЛОПАТЫ: опубликованные Releases публичных GitHub-репозиториев → записи от имени сообщества ВК, подключённого создателем/уполномоченным менеджером. Несколько направлений, без LLM, своего сервера и иных соцсетей. Бета-релизы поддерживаются. Коммиты, черновики и приватные репозитории не входят.

## Согласованный интерфейс
- Таблица направлений: откуда, куда, режим, последнее изменение источника (появление Release), последняя успешная публикация/ссылка и состояние. Добавление и удаление направления.
- Мастер: сначала куда (ВК, ключ, мини-инструкция, проверка без поста), затем откуда (GitHub, инструкция, проверка), затем режим и интервал проверки. Ручной режим по умолчанию; автоматический включается отдельно с явным предупреждением публичной отправки.
- Список выпусков: «Показать все» открывает всю опубликованную историю; галочками выбираются выпуски. Отправленные имеют отметку и требуют подтверждения для повтора.
- Ручная отправка с предпросмотром; выбранные выпуски можно отправлять постепенно, от старых к новым, например по одному в сутки. Очередь сохраняется, приостанавливается/очищается. После простоя не догонять пропущенные ежедневные посты массовой отправкой.
- Проверка в трее работает независимо от тяжёлых модельных операций. Автопубликация новых выпусков только у направления, где она включена. Первое подключение устанавливает исходную точку, старую историю без выбора не отправляет. Новые выпуски при включённой очереди добавляются в конец; после завершения очередь возвращается к обычному режиму.

## API и безопасность
- Схема VKCOM 5.199 у wall.post перечисляет user token; текущий интерфейс сообщества предлагает разрешение стены. Различие не объявлять решённым по документации. Проверить ключ сообщества с доступом к стене на реальном минимальном посте; при отказе исследовать поддерживаемую пользовательскую авторизацию.
- Настоящий тестовый пост требует отдельного разрешения. Ключ вводится только локально, не через Codex. Проверка подключения не публикует и не считается доказательством возможности wall.post.
- DPAPI CurrentUser: ключ зашифрован, поле скрыто, отсутствует в обычных настройках/экспорте/логах. Нет обещания защиты от вредоносного ПО с правами пользователя. Минимальные права, отзыв/замена ключа. Не раскрывать сырые ошибки VK с request_params.
- Отправлять по HTTPS в теле запроса, без токена в URL/командной строке; не следовать перенаправлениям с секретом.
- Устойчивая связь Release ID → VK post ID, дата, состояние отправки. Сначала долговечная запись попытки, потом HTTP POST. Обрыв/перезапуск во время отправки — «Требуется проверка», без слепого повтора. Сохранение истории атомарное; повреждённое хранилище не сбрасывать молча.
- Удаление с подтверждением удаляет локальную связку и секрет, опубликованные посты остаются.

## Архитектура
Отдельные модели, хранилище, защита секретов, GitHub/VK клиенты, форматирование постов, координатор/планировщик и окна утилиты. Общая навигация/теги, RU/EN, существующий трей и завершение приложения. Не менять контракт единственной тяжёлой операции. GitHub читатель без фильтров версии/подписи установщика ЛОПАТЫ, с пагинацией и ограничениями API.

## Приёмка и проверки
1. Restore/build, проверки UTF-8 и локализации, diff-check, UI RU/EN/темы/узкое окно, штатный dev-start.
2. Тесты публичных URL, полной истории, форматирования, DPAPI/секретов, перезапуска, дедупликации, отдельных направлений, очереди и неопределённого ответа. Поддельные HTTP ответы не заменяют реальный VK тест.
3. Проверка реального чтения Releases ЛОПАТЫ без GitHub-ключа.
4. Отдельно: локальный ввод ключа, проверка без публикации, разрешённый реальный пост от имени сообщества и повторная проверка без дубля. До этого функциональность VK не объявлять принятой.
