# Метаданные файлов

Принятая версия: 0.5.74-dev; первоначальное внедрение: 0.5.72-dev.
Выполнено и принято пользователем 17.10.2026;
[рабочее ТЗ](../ТЗ/Архив/2026-10-17_Универсальный_просмотрщик_метаданных.md) архивировано.

Открывается карточкой «Метаданные файлов» в «Обработка / утилиты → Базы знаний».
Утилита работает с одним или несколькими файлами, добавленными кнопкой или
перетаскиванием. Повторно добавленный путь не дублируется. Слева — файлы и
индивидуальные результаты; справа — обычные поля, предпросмотр и раскрываемые
группы технических, служебных, прочих и файловых сведений. Есть поиск.

## Как редактировать

Выделите файлы. Одинаковое значение показывается как есть, неодинаковое —
«Различается». Изменение текста включает применение этого поля; переключатель
рядом позволяет исключить правку из сохранения. Число у названия поля показывает,
для скольких выбранных файлов доступна запись. Само выделение или пустое общее
отображение не изменяют файлы. Несовместимый файл получает отдельный результат;
остальные могут быть сохранены. В этой версии несовместимый набор полей
пропускается для такого файла целиком, а не сохраняется молча частично.

Прямых действий удаления нет. Обычное поле можно очистить, удалив его текст
клавиатурой. Историю создания таким способом изменить нельзя.
Двойное нажатие дополнительного поля открывает полное значение для чтения
и копирования; в таблице длинные значения сокращены только для отображения.
В 0.5.73-dev таблица прокручивается по пикселям, поэтому можно просмотреть
середину длинного многострочного поля. На верхней/нижней границе таблицы
колесо продолжает прокручивать окно. Виртуализация таблиц сохранена.

«Сохранить изменения» предупреждает об изменении исходных файлов и показывает
их список и поля. «Сохранить копию» нет. Подготавливается служебный временный
результат, проверяются поля и сохранность содержимого, затем выполняется замена
исходника. Если файл занят или изменён другой программой, он не перезаписывается.
Остановка действует между файлами и на отменяемых шагах; уже сохранённые файлы
остаются изменёнными. Закрытие при активной записи сначала останавливает работу.

## Обложки и картинки

Основное изображение имеет миниатюру. Видео показывает третий декодированный
кадр от начала; для роликов с одним/двумя кадрами — первый. Это не третья секунда.
Предпросмотр сохраняет пропорции и учитывает доступные сведения об ориентации.

Встроенные картинки показаны отдельно с указанием файла. Их можно увеличить
и извлечь через «Сохранить изображение» без пересжатия исходных байтов.
Извлечение не позволяет перезаписать один из открытых исходников. Кадр видео
служит предпросмотром, не выдаётся за встроенную картинку. Предпросмотры
подгружаются порциями по 24 элемента, далее — «Показать следующие изображения».

Обычную обложку аудиофайла, включая результат ЛОПАТЫ, можно заменить. В отдельном
окне видна выбранная картинка и требуется явно выбрать рисующую модель ЛОПАТЫ
либо ввести происхождение вручную. Для выбора модели скачивать её не нужно.
История создания самого аудио не переписывается. Происхождение новой обложки
обозначается как указанное пользователем, а не независимо проверенное.

Для новых замен обновляются LOPATA_COVER_MODEL и LOPATA_COVER_SOURCE=user-declared.
При первой замене прежние записи обложки сохраняются в LOPATA_COVER_ORIGINAL;
следующие замены этот первоначальный снимок не затирают. LOPATA_MODEL, исходные
задания, параметры и караоке сохраняются. Никаких новых сведений о создании
стороннего аудио самой ЛОПАТОЙ не добавляется.

## Поддержка первого выпуска

| Семейство | Чтение | Запись | Предпросмотр |
|---|---|---|---|
| MP3, Opus, FLAC, WAV | Теги, технические сведения, картинки, данные ЛОПАТЫ | Название, исполнитель, альбом, жанр, дата, дорожка, комментарий, права, композитор; замена единственной обложки | Встроенные картинки |
| PNG | Доступные ExifTool сведения и текстовые блоки | Title, Author, Description, Keywords, Copyright; исходный Description генерации ЛОПАТЫ защищён | Само изображение и обнаруженные картинки |
| JPEG, WebP / Extended WebP | Доступные EXIF/XMP и прочие сведения | XMP-dc Title, Creator, Description, Subject, Rights; исходное описание ЛОПАТЫ защищено | Само изображение и обнаруженные картинки |
| DOCX | Доступные свойства пакета и документа | Заголовок, автор, описание, ключевые слова в части core-properties по её реальной связи | Обнаруженные ExifTool картинки, если имеются |
| PDF | Доступные свойства и технические сведения | Только чтение | Обнаруженные картинки, если имеются; извлечение всех картинок PDF не заявляется |
| MP4, MKV/WebM и другие распознаваемые видео | Доступные контейнерные сведения | Только чтение | Третий кадр для поддерживаемых H.264 / VP9; другие кодеки могут не декодироваться |
| Прочие форматы | То, что достоверно читает ExifTool; свойства файла | Только чтение | По доступности декодера |

Точный набор зависит от содержимого. Для MP3/WAV неоднозначные, дублированные
или особые ID3-записи могут остановить запись с объяснением; сложные/мультиплексные
Opus-контейнеры не переписываются. При нескольких встроенных аудиокартинках
обычные теги редактируются с сохранением всех картинок, замена картинки пока
недоступна, чтобы не удалить соседние вложения. Lyrics пока только читается:
защита исходного задания и караоке имеет приоритет перед его редактированием.

DOCX с подписями, включая нестандартное размещение части подписи, не записываются.
Распознанные C2PA/JUMBF и цифровые подписи изображений также отключают запись.
Это предосторожность при обнаруженных сведениях, не универсальная криптографическая
проверка всех существующих форматов подписей. Подписанные PDF и программы и так
не имеют пути записи в этой утилите.

## Ограничения ресурсов

Чтение списка: до двух файлов одновременно. Вывод одного внешнего процесса —
до 32 МиБ, диагностика — до 64 КиБ, время одного вызова — 45 секунд.
Безопасная запись аудио ограничена 128 МиБ, изображений/DOCX — 512 МиБ.
Значение редактируемого поля — до 64 000 символов без NUL.
Миниатюра исходного изображения и заменяемая картинка — до 16 МиБ,
до 64 млн пикселей и до 32 768 пикселей по стороне; при превышении миниатюра
может отсутствовать, а метаданные остаются доступны. На замены принимаются JPEG/PNG.
Третий кадр видео декодируется на CPU с длинной стороной до 256 пикселей.
Это пределы первой реализации, не требования к объёму памяти тестового ПК.

## Зависимости и сохранность

Широкое чтение и точечная запись XMP: официальный Windows x64 комплект
ExifTool 13.59. При первом использовании действует общий ComponentLicenseGate.
Поставка локальная в MetadataRuntime, без установки Perl/Python в систему
и без сетевой работы утилиты. Закреплены SHA256 официального архива и 510 файлов;
проверка выполняется перед первым запуском в процессе. Рецепт восстановления:
[Инструменты/MetadataRuntime](../Инструменты/MetadataRuntime/README.md).
Сохраняются оригинальные лицензии ExifTool/Perl/launcher и архив лицензий Perl.

Музыка использует штатный MusicAudioRuntime и существующие механизмы тегов,
обложек и хеша звуковых пакетов. DOCX меняет только разрешённые core-properties;
остальные ZIP-части сверяются по хешам. PNG сохраняет сжатые пиксели; JPEG/WebP
проверяются по неизменённым блокам изображения. Видео использует отдельный
штатный CaptureRuntime. Сети, ИИ, новых весов и перекодирования содержимого нет.

## Проверки

Выполнены реальные файловые проходы с искусственными короткими материалами:
Unicode и emoji, обычные теги, неизвестные поля, смена обложки и её происхождения,
первоначальная история, две картинки, извлечение EXIF-картинки, DOCX, PDF,
ошибки доступа, изменившийся исходник, отмена, H.264/VP9 и короткое видео.
WPF проверяется в RU/EN, светлой/тёмной темах, ширинах 760/1200; изображения
результатов проверок осматриваются. Пройдено 98 профильных и смежных тестов, 0 ошибок/пропусков. Restore, сборки
Release/Debug и штатный safe-start успешны; окно 0.5.72-dev отвечает.
Строгий UTF-8/scanner без замечаний; 5559 ключей RU/EN совпадают.
Подробности фиксируются
в истории и протоколе _tmp/metadata-implementation-20261017/validation.json.
Пользовательские исходники не применялись для разрушительных тестов.

Полный/миниустановщик не пересобираются. ТЗ принято и архивировано;
готовится файловое обновление, его публикация подтверждается отчётом выпуска.
