# Отдельный разбор рассуждений Katarau 9B и Gemma 4 Russian Poetry 31B

13.10.2026. Рабочее исследование оставшихся двух моделей по уточнению пользователя: «Осталась ещё две модели, в которых нужно разобраться отдельно». Приёмка 0.5.35-dev относится к шести уже подключённым моделям, не означает готовность thinking этих двух.

## Подтверждённая исходная точка

В инвентаризации _tmp/music-reasoning-inventory-20261013 проверены установленные GGUF metadata/templates без загрузки весов. Katarau-9B-ru-RP-nsfw.Q4_K_M.gguf имеет template без enable_thinking, заранее добавляющий закрытый пустой <think>. Копирование тумблера ядра не переключает этот шаблон. Это не доказывает отсутствие способности весов рассуждать.

Gemma4_rap_q4_k_m.gguf имеет enable_thinking, но родные <|think|>/<|channel>thought/<channel|> и другую границу мысли/ответа. Формат deepseek API и native маркеры — разные уровни; не объявлять несовместимость по одному имени внешнего формата.

## Порядок

1. Сначала уточнить механизмы отдельно для каждой установленной модели: рекомендованный автором шаблон и обучения, pinned llama.cpp, реальные границы thought/final и влияние выключения. Не менять production template на guessed ChatML/Qwen и не подменять отдельные мысли обычным ответом «рассуждай пошагово».
2. Зафиксировать подтверждённый способ включения, ограничения бюджета и разделения ответа, либо честную невозможность штатного управления. До этого не включать новые элементы управления/defaults.
3. Затем составить сопоставимые native-проверки on/off/2048 (4096 отдельно при необходимости), один выбранный native template, достаточный финальный reserve, по три seed на основное задание «Кот и рассвет», реальные запросы/полные ответы/мысли/логи/полное время. Reference не показывать. Перед длительной серией обсудить отличающуюся механику и набор проверок, как было согласовано для особых моделей.
4. Если отдельный канал подтверждён, проверить streaming/off/исчерпание бюджета/JSON, сохранение настроек, язык интерфейса, память прошлых мыслей только при её native поддержке. Качество текста и работоспособность протокола оценивать отдельно.

GPU/гибрид/CPU — через штатный safe-start с изолированным размещением, один owned worker, retirement и checkpoint. Не менять пользовательский последний удачный режим и не запускать скачивания/опасное заполнение VRAM. Старые результаты и настройки сохранять. Новую реализацию делать только после проверки специфики; этот ТЗ не является автоматическим подключением оставшихся моделей.

Статус: отдельная задача сформулирована; новая inference-серия пока не запускалась. Разбор лицензий/карточек и metadata не является физическим тестом генерации. Модели и runtime уже установлены; новые зависимости пока не назначены.
