## Реальная модель

Runeweaver через штатный LiteraryChatRuntime, прежние контекстные окна/резерв ответа/sampler/защита от повторов. Два прогона по 8 запросов, в каждом три пары «добавь кота → уточни продолжением», затем два запроса Советнику с изменением его якоря между ними. Якорь Писателя обозначает уже случившееся перемещение молнией, следующую сцену в доме и обычного неговорящего кота; якорь Советника — отдельная задача проверки. Контрольные метки различаются.

| Проверка финальных API-запросов | Результат |
|---|---:|
| Свой якорь присутствует, якоря другой роли нет | 16/16 |
| Исходная команда и предыдущий ответ дословно сохранены при уточнении | 6/6 |
| Изменённый якорь Советника пришёл вместо старого | 2/2 |
| Копия полного пользовательского наброска 2245 символов дошла без изменений | 8/8 во втором прогоне |
| Область чтения editor для локального задания | 15/16 |

`runs/live-01` — короткий искусственный набросок. В одном уточнении ответ дословно повторён; два других продолжают сцену, но модель свободно изобретает правила игры. Советник верно назвал первую метку, после изменения использовал новую задачу, но вместо новой метки процитировал само правило. Это не потеря файла: новая метка находится в фактическом API-запросе.

`runs/live-exact-01` — неизменённый пользовательский набросок из диагностического резерва и точные прежние запросы, включая опечатки: кот прыгает на грудь, статика и воспоминание о молнии; уточнение «Нужно было, что бы это было продолжением уже написанного нами сюжета». Это проверка контекста/уточнений в изолированном проекте, **не полная копия пользовательского проекта с его исходной книгой и RAG-каталогами**.

В трёх уточнениях первая команда присутствует, Writer получил четыре сообщения вместо прежних двух. Два ответа сохраняют кота/статику, третий уходит к игре и пропускает кота. Один ответ снова включает начало редактора. Встречаются незаданные свойства кота и неверное старшинство карт. Поэтому исправление доставки не считается полным исправлением художественного поведения. При вопросе Советнику о своей метке на полном наброске маршрутизатор один раз ошибочно выбрал reference; корпуса нет, ограничение передано, но ответ по своему плану получен. Прежняя проблема ложного выбора RAG остаётся открытой.

Сводка аудита: `runs/audit.json`; входы/ответы: `answers.json` каждого прогона и `AnchorProbe/Diagnostics/LiteraryDetailed`. Новые якоря каждый запрос перечитываются с диска; сброс/перезагрузка весов для применения редакции не требуется. Поведение не проверено как статистически гарантированное — это небольшая проверка механики и регрессии.

## Повторный запуск

Из корня репозитория; папка результата должна быть новой:

```powershell
dotnet run --project Тесты/LiteraryPlotAnchor/Probe.csproj -- ui Тесты/LiteraryPlotAnchor/runs/ui-new
dotnet run --project Тесты/LiteraryPlotAnchor/Probe.csproj -- live Тесты/LiteraryPlotAnchor/runs/live-new
```

Необязательный третий аргумент после `live` и папки результата — путь к копии пользовательского наброска; тогда используются точные запросы регрессии. Общий срок генерационного прогона ограничен шестью минутами, процесс модели закрывается при завершении. Стенд ничего не скачивает и не меняет основную регистрацию проектов.
