## Комплекты исполнителя

Общий каталог: `Runtime/Backends/yue2.cpp/11c1ecb084329200e22fcb286e252b847442ea5c/`.
`win-x64` — сохранённый CPU AVX2; `win-cuda128-x64` — CUDA 12.8, архитектура SM89
для тестовой RTX 4090. При наличии GPU-комплекта новые задания выбирают его.

в `%LocalAppData%/AI_HUB/Music/Jobs/<id>/job.json`.

Манифест CPU проверяет пять файлов, GPU — девять, включая CUDA runtime/cuBLAS.
Сохранены оригинальные лицензии и уведомления. Системные MSVC DLL не копировались.
Компилятор и заголовки остаются developer tooling и не входят в приложение.
GPU-сборка выполнена локально для данной видеокарты; комплект для иных архитектур
и доставка через обновление/установщик этим проходом не подготовлены.

## Сборка и русские пути

Исходники: `_tmp/music-yue2-src`; CPU: `_tmp/music-yue2-msvc`; GPU: `_tmp/music-yue2-cuda`.
Команды GPU сохранены в `_tmp/configure-music-cuda.cmd` и `_tmp/build-music-cuda.cmd`;
журнал — `_tmp/music-cuda-build.log` (185/185, exit 0).

Общие CMake параметры: Release, BUILD_SHARED_LIBS=ON, GGML_NATIVE=OFF,
GGML_OPENMP=OFF, GGML_BACKEND_DL=ON, GGML_CCACHE=OFF, GGML_VULKAN=OFF.
GPU: GGML_CUDA=ON, CMAKE_CUDA_ARCHITECTURES=89; toolkit root — локальная папка.
Сначала выполнить обычную конфигурацию для проверок компилятора, затем повторить
с `/MANIFEST:EMBED /MANIFESTINPUT:<windows-utf8.manifest>`.
Иначе первый CMake try-compile конфликтует с Windows manifest tool.

Manifest включает activeCodePage=UTF-8 и longPathAware для narrow argv/fopen.
Русские пути модели, задания, ABC и WAV подтверждены реальным CPU/GPU запуском.
Upstream native warnings сохранены: MSVC option overrides, -fno-lto,
CUDA constant conversion warnings, отсутствие NCCL для нескольких GPU.
Приложение новых предупреждений не получило.

## Контракт исполнения и границы паузы

Правая панель содержит название, 1–8 вариантов, авто/30 секунд/1–6 минут,
круглую красную кнопку запуска/паузы, нейтральную отмену и неактивный значок
чата стихов. Перед запуском проверяются текущие счётчики и лицензионные согласия;
резерв ABC 4096 + до 9000 музыкальных токенов учитывается вместе с запасом 5%.
Короткие задания уменьшают min_tokens вместе с max_tokens; иначе native валидатор
отклоняет semantic preset ещё до генерации. Стандартные значения не раскрываются в UI.

Исполнение включено в общий ApplicationBackgroundOperations. Процессы принадлежат
OwnedProcessRegistry, запускаются без консоли; отмена ждёт реального выхода.
Надёжные контрольные точки — готовый ABC-план и проверенный WAV.
Незавершённый синтез AR/NAR/VAE после паузы повторяется целиком, уже готовый план
и треки не дублируются. `yue-synth --score/--tokens/--latent` экспортирует промежуточные
данные только после всего pipeline: самостоятельного восстановления из них нет.
Результат публикуется через проверенный временный файл без перезаписи существующего.
Повтор использует сохранённый снимок и seed, а не изменённый редактор.
Журнал/этапы получают реальные события; неизвестный общий процент не выдумывается.
